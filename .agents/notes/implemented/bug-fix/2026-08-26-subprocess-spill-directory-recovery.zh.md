# Agent Note: 在 spawn 时重建被删除的 spill 目录

Status: implemented

[English](2026-08-26-subprocess-spill-directory-recovery.md) | 中文

本地 subprocess 提供方只解析一次 spill 目录，并假定它在宿主进程存续期间始终存在。任何清空平台临时根目录的行为——系统临时文件清理、手动删除、共享同一根目录的另一个 harness 实例——都会让已记录的路径悬空，下一次 spawn 会使宿主崩溃而不是降级。

## 决策

### spawn 确保目录存在；检查按每次启动执行

只要配置的 spill 目录在启动时缺失，`spawn.ts` 就会以与首次创建相同的私有权限重建它。没有监视器，也没有写入时重试：若目录在 spawn 与输出收集之间被删除，该命令的完整输出恢复仍然会丢失——这与既有的有损读取契约一致。此修复只针对崩溃：目录缺席现在成为提供方能控制的唯一节点上的可恢复条件。

### 空 collector 回调补上花括号

collector 的空回调分支加上显式花括号，避免未来某条语句悄无声息地变成它的函数体；行为不变。
