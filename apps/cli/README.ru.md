# `@deepseek-ai/dsh`

[English](README.md) | [中文](README.zh.md) | Русский

Команда `dsh` — продуктовый лончер профилей: упорядоченных стопок патч-слоёв plugin-бандлов поверх собственных переопределений пользователя. [`src/args.ts`](src/args.ts) владеет грамматикой команды, а [`src/bin.ts`](src/bin.ts) загружает только выбранный раннер. Неверные команды, опции чужого режима, ошибки конфигурации и сбои загрузки завершают процесс с ненулевым кодом.

## Режимы входа

| Команда | Назначение |
|---|---|
| `dsh --profile <name>` | Загружает названный профиль под `$DSH_HOME/profiles/<name>`. |
| `dsh --profile headless "job"` | Запускает одну свежую персистентную сессию, печатает финальный ответ и выходит. |
| `dsh web` | Псевдоним `--profile web`. |
| `dsh plugin --profile <name> <pnpm args>` | Управляет плагинами профиля, пересылая вызовы pnpm в каталоге профиля. |

Вызывающий каталог — корень рабочего пространства по умолчанию. Профили `web` и `headless` самоинициализируются при первом использовании из поставляемых шаблонов; всякий другой профиль должен быть создан через `dsh plugin`.

## Аргументы приложения

Лончер разбирает только собственные флаги и передаёт всё, что следует после них, загруженному профилю, где любой внедрённый app-плагин может разобрать общий неизменяемый снапшот ([`dsh-cmdline`](../../packages/boot/cmdline/README.ru.md)). Поэтому флаги лончера стоят первыми, и первый токен, который лончер не распознал, открывает аргументы приложения:

```sh
dsh --profile web --port 8080       # --port belongs to the web app
dsh --profile tui --resume <id>     # example, assuming the tui profile is installed; --resume belongs to the terminal app
dsh --profile headless "run the tests"
dsh --profile web --help            # the web app's flags, not the launcher's
dsh --help                          # the launcher's own help
```

## Профили

Каталог профиля хранит `package.json` (вне-деревые зависимости плагинов плюс манифест профиля `dsh.profile` со своим упорядоченным списком `bundles`) и `cordis.patch.yml` (собственный патч-слой пользователя).

Дерево компонуется над пустым корнем:
- патч каждого бандла в порядке `dsh.profile.bundles`
- затем `cordis.patch.yml` профиля, затем домашний `$DSH_HOME/cordis.patch.yml`
- затем оверлеи `--patch`

Бандлы, названные в `dsh.profile.bundles`, разрешаются сначала из установки dsh (`@deepseek-ai/dsh-base`, `@deepseek-ai/dsh-web-app`, `@deepseek-ai/dsh-headless`), затем из собственного `node_modules` профиля, куда pnpm устанавливает вне-деревые плагины.

Воспользуйтесь `--dump-default-config` и `--dump-config`, чтобы осмотреть скомпонованное дерево без его загрузки.

[Справочник по поведению CLI](reference/README.ru.md) владеет точным приоритетом слоёв, флагами, поведением при выключении, умолчаниями развёртывания и исполнением из исходников.

## Разработка

Продуктовые запуски требуют собранных артефактов пакетов и фронтенда. Из корня репозитория выполните отдельно `pnpm run build`, затем запускайте TypeScript-вход командой `pnpm dsh <args...>` с пересылкой всех аргументов; [справочник запуска из исходников](reference/README.ru.md#запуск-из-исходников) владеет контрактом разрешения модулей.
