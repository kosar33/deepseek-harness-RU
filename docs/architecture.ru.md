# Архитектура DeepSeek Harness

[English](architecture.md) | [中文](architecture.zh.md) | Русский

Прочтите это перед любыми изменениями под `packages/`. Предполагается знание Cordis; если его нет — начните с [primer](cordis-primer.ru.md) или [туториала](cordis-tutorial/index.md).

Рекомендуем исследовать кодовую базу и её архитектуру силами агента.

## Cordis

[Cordis](cordis-primer.ru.md) — фреймворк под dsh: плагины добавляют в общий контекст сервисы, типизированные события и обратимые эффекты. Каждая часть продукта — плагин, включая адаптер модели, реестр инструментов, журнал сессии и сам агентский цикл, поэтому каждая часть замещаема из конфигурации.

Привилегированного ядра для патчей нет: вы расширяете dsh, монтируя плагин рядом с остальными, а регистрации являются эффектами, которые разворачиваются при выгрузке плагина.

## Профили и бандлы

Запущенный `dsh` — дерево плагинов, собранное при загрузке из упорядоченных слоёв.

**Профиль** — именованная композиция в домашнем каталоге Harness. Он перечисляет накладываемые бандлы, держит установленные внешние плагины и собственный `cordis.patch.yml` пользователя. `web` и `headless` поставляются как шаблоны.

**Бандл** — формат дистрибуции строк конфигурации Cordis и монтируемого ими кода, так что всё вставленное им остаётся патчируемым вышележащими слоями.

Каждый объявляет себя в собственном `package.json` под полем `dsh`: `dsh.profile` перечисляет бандлы профиля, а `dsh.bundle` указывает на patch-файл бандла.

[`dsh-base`](../packages/bundle/base/README.md) — первый слой каждого профиля: адаптеры моделей, инструменты, персистентность, политика песочницы и одобрений, настройки, учётные данные, телеметрия. [`dsh-web-app`](../packages/bundle/web-app/README.md) добавляет браузерное приложение; [`dsh-headless`](../packages/bundle/headless/README.md) — одноразовый раннер вовсе без сервера.

Слои применяются к пустому списку записей в этом порядке: каждый бандл в порядке списка профиля, затем `cordis.patch.yml` профиля, затем домашний, затем любой оверлей `--patch`. Патч нацеливается на запись по id и заменяет её конфигурацию целиком или вставляет новые записи.

Увидеть дерево, которое реально грузится на вашей машине:

```sh
dsh --profile web --dump-config
```

Любая напечатанная строка может быть заменена вашим собственным патчем.

Механика композиции — в [app-boot](../packages/boot/app-boot/README.md#profiles); поля конфигурации — в сгенерированном [каталоге конфигураций](config-catalog.md).

## События

События — точки расширения, и выбор правильного домена — первое решение большинства изменений.

- **События сессии** — долговременные факты, дописываемые в журнал и транслируемые через `session/event`. Берите их, когда факт должен пережить перезагрузку.
- **События агента** (`agent/*`) несут живого `Agent`: входящие, шаг, статус, запрос, валидация, продолжение. Берите их, чтобы наблюдать или перехватывать работу в полёте.
- **События возможностей** прикрепляют политики и адаптеры к seam'у (`fs/*`, `tools/*`, `telemetry/*`) без импорта цикла.

[Карта событий](event-producer-consumer.md) перечисляет производителей и потребителей каждого события.

## Поток хода

**Шаг** — один запрос к модели плюс вызываемые им инструменты. **Ход** — ноль или более шагов: открывается до клеймления первого входа и закрывается, когда ничего не должно.

```text
turn/start
  claim next-step input plus one queued message
  assemble prompt sections + tool schemas
  -> agent/pre-step                   reject | enter(messages)
     reject, or a first enter rewritten empty -> close the turn with no step
     step/start
     append entered messages as user/message
     derive model history from the log
     agent/request -> llm/stream -> assistant/chunk* -> assistant/message
     tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*
     step/end
     tools owe another request, or next-step input arrived -> claim -> next step
  -> agent/turn-stopping
turn/end
```

`turn/*`, `step/*`, `user/message`, `assistant/*` и `tool/*` — долговременные события сессии; остальные — живые точки расширения трёх доменов. `agent/pre-step`, `agent/request`, `llm/stream` и три события `tools/*` — каскады, чьи слушатели обязаны вызывать `next()` для передачи дальше; `agent/turn-stopping` — serial и не имеет `next()`.

Вход достигает драйвера через один почтовый ящик. Некоторые сообщения будят его немедленно; внедрённый контент ждёт в ящике, пока его не разбудит другое сообщение.

`agent/pre-step` решает, что видит модель. Слушатели могут переписать клеймленные сообщения или отклонить их; отклонённый или опустошённый первый клейм всё равно закрывает долговременный ход, не потративший ни шага, поэтому журнал фиксирует попытку. Каждый шаг читает секции промпта и схемы инструментов, зарегистрированные плагинами.

Подробности: [диаграмма последовательности](agent-lifecycle.md), [конвейер инструментов](tool-execution-pipeline.md) и [отмена и восстановление после ошибок](subsystems/core.md#the-agent-handle).

## Журнал сессии

Журнал сессии — источник контекста, который видит модель. `deriveMessages()` проецирует историю модели из него, а сырые события `assistant/chunk` сохраняют точность воспроизведения и UI. Форк, возобновление, транскрипты, телеметрия и персистентность выводятся из этого потока.

**Видимое модели означает записанное.** Всё, что попадает в запрос к модели, должно быть восстановимо из журнала, и рантайм-инвариант это утверждает. Именно поэтому новый видимый модели ввод требует нового события сессии: расширьте `SessionEventMap` и рендерьте из журнала.

## Capability seam'ы

**Seam** — замещаемая возможность с тремя ролями: **Service Definition**, объявляющая интерфейс, **Service Provider**, реализующий его, и **Consumer**, использующий его, обычно инструмент, вызываемый моделью. Пакет может совмещать роли, но одна роль сама по себе не seam; добавить возможность — значит спроектировать все три ([граф возможностей](capability-seams.md)).

Seam'ы — причина, по которой одна подмена провайдера меняет весь продукт. Провайдеры файловой системы и субпроцессов делят один мир исполнения, поэтому направление их на удалённую песочницу переносит Bash, PTY и LSP вместе, без форков провайдеров. [Провайдеры субагентов](subsystems/subagent.md) варьируются так же широко за одним интерфейсом — от свежего дочернего агента до делегированного хода в другом продукте.

[Экспериментальные Agent Teams](subsystems/agent-team.md) — приватная opt-in координация seam'а на `ctx.agentTeams`, с долговременным ростером, доской задач и почтовыми ящиками поверх продолжаемых субагентов.

## Куда идёт новое поведение

Новое поведение присоединяется к документированной точке расширения. Изменение самого цикла обновляет эту карту.

| Цель | Механизм |
|---|---|
| Добавить провайдера моделей | зарегистрируйте его адаптер на `ctx.llm` |
| Добавить видимую модели возможность | зарегистрируйте на `ctx.tools`; её схема входит в сборку промпта |
| Дать одной сессии другой набор возможностей | соберите пресет агента; строке сервиса там нужна область `isolate` |
| Добавить исполнение shell | зарегистрируйте бэкенд `ctx.shell`; локальный спавнится через `ctx.subprocess` |
| Добавить постоянное исполнение терминала | зарегистрируйте бэкенд `ctx.terminals` плюс `dsh-tool-terminal` |
| Добавить человеческую команду | зарегистрируйте на `ctx.commands`; она диспатчится без хода модели |
| Добавить фоновую работу | зарегистрируйте на `ctx.jobs`; инструменты `job_*` собирают или останавливают её |
| Добавить доступ или политику файловой системы | зарегистрируйте провайдера `ctx.fs` или слушайте события `fs/*` |
| Ограничить порождаемые процессы | используйте бэкенд `ctx.sandbox`; потребители оборачивают argv перед спавном |
| Перехватить запрос, инструмент или ход | используйте его событие `agent/*` или `tools/*`; `agent/turn-stopping` останавливает ход |
| Добавить видимый модели контекст | вызовите `agent.inject()`; он попадёт в следующий допущенный запрос |
| Добавить интеграцию с UI или редактором | управляйте `ctx.agents` и рендерьте из `session/event` |
| Добавить узел Web Client Chat | зарегистрируйте `ConversationNodeDefinition` + ключевой рендерер |
| Добавить долговременное состояние сессии | расширьте `SessionEventMap`; рендерьте и воспроизводите из журнала |
| Генерировать заголовки сессий | зарегистрируйте единственного провайдера `ctx.sessionTitle` |
| Управлять внутрисессионной целью | используйте `ctx.goals`; продолжайте через `agent/*` |
| Форкнуть живую сессию | `ctx.sessions.fork(source, boundary?, childSessionId?)` |
| Скоупировать регистрацию на одного агента | используйте `agent.ctx` этого агента |

[Книга расширений](cookbook/extension-cookbook.md) сопоставляет функции возможностям и индексирует пошаговые руководства для [пакетов](cookbook/adding-a-package.md), [инструментов](cookbook/adding-a-tool.md), [LLM-адаптеров](cookbook/adding-an-llm-adapter.md), [узлов Chat](cookbook/adding-a-conversation-node.md) и [карточек настроек](cookbook/adding-a-settings-card.md).
