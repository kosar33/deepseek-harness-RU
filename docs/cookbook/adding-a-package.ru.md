# Cookbook: добавление workspace-пакета

[English](adding-a-package.md) | [中文](adding-a-package.zh.md) | Русский

Чек-лист создания нового пакета `@deepseek-ai/dsh-<name>` файл за файлом. Чек-лист выверен по пакетам bash и адаптера как по образцам; если он от них отклоняется, исправьте его здесь.

## 1. Создайте пакет

```
packages/<group>/<pkg>/
  package.json     # copy from packages/core/tools, adjust name/description/deps
  tsconfig.json    # extends ../../../tsconfig.base.json, rootDir src,
                   # outDir lib/types, references: ../../../vendor/cosmokit,
                   # ../../../vendor/cordis (+ ../../../vendor/schemastery if
                   # you use Config, + ../../<group>/<dep> for each dsh dep)
  src/index.ts     # service default export or plugin (name/inject/apply/Config)
  README.md        # service API, events, extension points, design notes,
                   # + gated Model Experience context blocks or short form
                   # + the gated "Known Limitations and Deferred Work" section
                   # (or a whitelist entry in scripts/verify-package-readme-limitations.ts)
```

Выбирайте существующую группу, когда она отвечает роли пакета (`core`, `llm`, `bash`, `compact`, `subagent`, `todo`, `session-persistence`, `ui`, `util` или `support`). Новая группа допустима, но это чистый контейнер: без `package.json`, без исходных файлов, и пакеты по-прежнему располагаются ровно на один уровень под ней.

Инварианты package.json (проверяются командой `pnpm run constraints` / скриптом `scripts/check-workspace-constraints.ts`): `private: true`; `version`, совпадающая с корневым `package.json`; `type: module`; `main: "lib/index.js"`; `types: "lib/types/index.d.ts"`; `exports["."].types: "./lib/types/index.d.ts"`; `exports["."].default: "./lib/index.js"`; `@deepseek-ai/cordis` одновременно в peerDependencies и devDependencies (одинаковый диапазон). Каждую dsh peer-зависимость зеркально повторяйте в devDependencies. `@deepseek-ai/schemastery` идёт в `dependencies` (это рантаймный валидатор), как у agent-loop. Список `files` содержит ровно `lib/index.js`, `lib/invariant.js`, `lib/types/**/*.d.ts` и распознаваемые этой проверкой пакетные артефакты рантайма; пакет, чей рантаймный экспорт указывает внутрь порождаемого дерева, также включает `lib/types/**/*.js`. Не публикуйте `src`, карты деклараций, JS-карты или устаревшие корневые файлы деклараций. Пакеты CLI-приложений с полем package `bin` включают `lib/bin.js` сразу после `lib/index.js` в `files`.

Внутрипакетные относительные импорты в исходниках используют явные спецификаторы `.ts` (например, `export * from './types.ts'`). Компилятор переписывает их на `.js` в порождаемом JS и оставляет явные спецификаторы `.ts` в декларациях, которые стандартные потребители TypeScript NodeNext/Node16 разрешают до соседних файлов `.d.ts`.

## 2. Зарегистрируйте его в корневых конфигурациях

| Файл | Изменение |
|---|---|
| `tsconfig.base.json` | без правок для существующей группы; для новой группы добавьте кандидата `./packages/<group>/*/src` в wildcard `@deepseek-ai/dsh-*` |
| `tsconfig.host.json` (Host-пакет) или `tsconfig.client.json` (Client-пакет) | добавьте `{ "path": "./packages/<group>/<pkg>" }` в `references` — обычный пакет принадлежит ровно одному агрегату, никогда обоим. `api/remotes` использует специфичное для репозитория разделение, потому что Host порождает контракт, который Client потребляет на более поздней фазе; новые пакеты не должны его копировать ([структура](../development.md#typescript-project-layout)) |
| `knip.json` | только если у пакета есть точки входа, которые автоматическое обнаружение репозитория ещё не покрывает |

Пакет `packages/client/*` дополнительно наследует `tsconfig.base.client.json` вместо `tsconfig.base.json`, а клиентский плагин объявляет `dsh.client` в package.json, экспортирует `./client` и использует общий пресет tsdown (`packages/client/tsdown.client.ts`) — клиентская сторона контракта описана в [packages/client/AGENTS.md](../../packages/client/AGENTS.md).

Покрывается автоматически globs-паттернами или обнаружением через манифесты пакетов — правки не нужны: корневые workspaces в `package.json`, `scripts/publint-all.ts`, `tsdown.config.ts`, `.oxlintrc.json`, `scripts/check-workspace-constraints.ts`.

## 3. Определите топологию пакета

Для заменяемой возможности разделяйте роли Service Definition / Service Provider / Consumer по разным пакетам, когда они развиваются независимо (см. docs/architecture.md, раздел «Capability seams» — трио shell служит образцом). Одноцелевой плагин остаётся одним пакетом.

### Назовите ту роль, которая существует

Называйте устойчивую текущую ответственность. Не называйте первую реализацию, возможное будущее расширение или базовый класс Cordis. Пакет интерфейса называет возможность. Пакет реализации добавляет механизм, протокол, окружение или вендора, которые её отличают. Используйте `local`, только когда исполнение на том же хосте входит в контракт.

Используйте ключ `ctx` в единственном числе для одного движка, рантайма, политики, контроллера, резолвера, хранилища или текущей конфигурации. Ключ во множественном числе — для реестра или сервиса, владеющего несколькими именованными членами. Роль класса и число ключа должны совпадать. Не используйте один ключ Cordis `Context` для несовместимых деклараций host и client. Слияние деклараций TypeScript видит обе стороны, даже когда они пользуются отдельными рантаймными контекстами. Добавляйте суффикс роли, когда естественное множественное число уже занято другой стороной.

| Слово | Когда использовать | Когда не использовать |
|---|---|---|
| `Controller` | Принимает команды или намерение пользователя и изменяет одно существующее доменное состояние или состояние представления. | Исполняет произвольную работу, владеет парком провайдеров или лишь преобразует значения для отображения. |
| `Store` | Владеет одним набором данных и главным образом предлагает для него операции CRUD, снапшота или подписки. | Проверяет конечный автомат, разбирает споры о полномочиях, распределяет работу или владеет приоритетом провайдеров. Map сам по себе не делает класс хранилищем. |
| `Directory` | Предоставляет записи и метаданные для обнаружения или выбора. | Провайдеры регистрируют в него произвольные реализации или вызывающие исполняют через него работу. |
| `Presenter` | Это чистое преобразование доменных значений или аргументов инструмента в намерение рендера. | Выполняет I/O, подписывается, изменяет состояние или владеет жизненным циклом. |
| `Registry` | Владеет динамическим набором именованных регистраций, включая поиск, правила дубликатов и приоритета, время жизни и освобождение ресурсов. | Его главный контракт — диспетчеризация, исполнение, отмена, политика или оркестрация. |
| `Runtime` | Исполняет живую работу и владеет диспетчеризацией, отменой, координацией провайдеров или жизненным циклом операций между вызовами. | Лишь хранит записи, возвращает каталог, вычисляет одно значение или держит конфигурацию. |
| `Resolver` | Вычисляет или находит один ответ из предоставленных входов, не владея жизненным циклом этого ответа. | Владеет изменяемой коллекцией или долгоживущим исполнением. |
| `Binder` | Привязывает один объявленный интерфейс к контексту или жизненному циклу вызывающего и возвращает привязанное значение. | Владеет значением как коллекцией, управляет его доменным состоянием или лишь преобразует данные. |
| `Engine` | Реализует доменный алгоритм или модель исполнения с состоянием. | Лишь выбирает провайдера или пересылает через границу протокола. |
| `Policy` | Решает, что разрешено, выбрано, ограничено или наблюдаемо. | Исполняет тот механизм, который решение разрешает. |
| `Executor` | Исполняет один явный запрос или разрешённую спецификацию в одной возможности. | Владеет широким жизненным циклом приложения или каталогом провайдеров. |
| `Gateway` | Адаптирует границу процесса, сети, RPC или API. | Лишь регистрирует внутрипроцессные сервисы или хранит метаданные. |
| `Provider` | Поставляет одну реализацию определения возможности. Добавьте уточнение механизма или вендора, когда реализаций может быть несколько. | Это само определение возможности, реестр провайдеров или рантайм потребителя. |
| `Backend` | Реализует заменяемые низкоуровневые персистентность, транспорт или исполнение за определённым интерфейсом. | Это пользовательский сервис или единственная возвращаемая ссылка на живой ресурс. |
| `Handle` | Ссылается на один живой ресурс и управляет им или наблюдает его. | Создаёт весь пул ресурсов целиком и управляет им. |
| `Config` | Владеет одним разрешённым значением конфигурации или одной тесно ограниченной записью и её контрактом обновления. | Хранит общую коллекцию, исполняет работу или выставляет несвязанные настройки. |
| `Service` | Владеет цельным доменным сервисом, который ни одна из более точных ролей выше не называет честно. | Имя существует только потому, что класс наследует Cordis `Service`. |

Используйте `SDK` только для клиент-серверного протокола JSON-RPC, которым пользуются поддерживаемые Python- и TypeScript-SDK. Сам DeepSeek Harness — agent harness, а не SDK-проект. Используйте каноническое продуктовое написание `Typert`, никогда `TypeRT` или `typeRT`.

## 4. Напишите README пакета

Сначала держите специфичные для пакета сервисный API, конфигурацию, события, точки расширения и заметки о дизайне. Раздел ограничений фиксирует долговременные пробелы потребителей и неочевидные ограничения сопровождения, которыми владеет этот пакет; обычная уборка остаётся в TODO исходника или Agent Note. Косвенное предложение Model Experience может назвать потребителя, который показывает вклад этого пакета, но не пересказывает реализацию того потребителя. Завершайте README пакета этой канонической последовательностью:

````markdown
## Model Experience

### Request context and condition

#### What the model sees

The exact data-dependent fields, an anchored generated-catalog link, or an introduction to the verbatim literal below.

##### Verbatim text for this field, when needed

```markdown
Stable system-prompt prose of any length, or another long non-generated literal, copied exactly from source.
```

#### Token effect

Fixed, conditional, retained, replaced, capped, or zero-direct token effect.

#### KV Cache effect

Append-only, prefix-stable, replacing, or independent behavior, including the exact conditions that may invalidate reuse.

## Known Limitations and Deferred Work

- **Consumer-visible gap** — exact missing operation or case, its consequence, and any maintainer constraint.
````

Заполняйте Model Experience по реализации. Один H3 на каждую прямую, условную, ограниченную, пожизненную или вспомогательную запись модельного контекста, с тремя упорядоченными полями H4, показанными выше, и одним прозаическим абзацем под каждым. Цитируйте стабильный текст, которым владеет пакет: проза системного промпта идёт в именованный H5 плюс fence `markdown` под представляющим её полем — обычно `What the model sees`; другие короткие литералы остаются инлайном с именованными placeholder'ами, а прочие длинные литералы используют ту же вложенную форму. Пересказывайте только зависящий от данных текст или текст, которым владеет провайдер. Запись со схемой инструмента ссылается на свой якорный раздел в порождаемом [каталоге инструментов](../tool-catalog.md) и сообщает только отличия, которых там нет. Держите записи промпта и схемы раздельно, когда scoping может скрыть одну без другой. В `KV Cache effect` различайте append-only рост, стабильный повторяющийся префикс, замещение более ранних токенов запроса и независимый запрос модели, затем назовите изменения, которыми владеет пакет и которые могут сделать переиспользование недействительным. «Не делает недействительным» означает, что пакет сохраняет уже переиспользуемый префикс; доступность кэша провайдера и его вытеснение остаются вне контракта пакета. [Прозаический стандарт](../../.agents/skills/dsh-prose-standard/SKILL.md) управляет полнотой и владением; верификатор требует обязательную структуру разделов.

Пакет без влияния на контекст или с одним путём, которым владеет потребитель, использует аудированное предложение `None, as ` или `Indirectly, through ` из [`SENTENCE_MODEL_EXPERIENCE`](../../scripts/verify-package-readme-model-experience.ts), за которым следуют H4 `KV Cache effect` и один непустой абзац; универсальный пакет, независимый от модели, вместо этого может войти в `NO_MODEL_EXPERIENCE_SECTION`. Ни один из этих случаев не разворачивайте в описание работы другого пакета. [Разрешённый список](../../scripts/verify-package-readme-limitations.ts) ограничений независим. Обоснование записано в [Agent Note о Model Experience](../../.agents/notes/implemented/process/2026-07-12-package-model-experience-contract.md).

## 5. Проверьте

```sh
pnpm install        # registers the workspace
pnpm run doc-sync
pnpm run constraints && pnpm run typecheck && pnpm run lint
pnpm run build && pnpm run hygiene
```

Следуйте [тестовой политике репозитория](../testing.md) ради специфичных для поведения проверок и покрытия, которые требуются новому пакету.
