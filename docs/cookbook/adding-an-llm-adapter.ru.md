# Cookbook: добавление LLM-адаптера

[English](adding-an-llm-adapter.md) | [中文](adding-an-llm-adapter.zh.md) | Русский

Как подключить нового провайдера моделей. Эталонные реализации: `packages/llm/llm-deepseek` (прямой HTTP, SSE в обрамлении `eventsource-parser`) и `packages/llm/llm-pi-ai` (обёртка над LLM-библиотекой). Сначала прочитайте документацию `StreamChunk` в `packages/llm/llm/src/types.ts` — она фиксирует соглашения протокола, по которым проверены оба адаптера.

## Форма

```ts ignore-check
class MyAdapter extends LlmAdapter {
  async * stream(options: GenerateOptions): AsyncIterable<StreamChunk> { … }
}

export const name = 'llm-myprovider'
export const inject = ['llm']
export const Config: z<Config> = z.object({ apiKey: z.string(), … })

export function apply(ctx: Context, config: Config) {
  ctx.llm.registerAdapter(['my-provider'], new MyAdapter(…))
}
```

Регистрация основана на эффектах (безопасна при HMR); один адаптер на маршрут провайдера — дубликаты бросают исключение, а многомаршрутная регистрация атомарна: всё или ничего. `options.provider` выбирает адаптер, а `options.model` — идентификатор модели у провайдера, поэтому адаптер с динамическим каталогом может обслуживать новые модели без перестройки жизненного цикла. Секреты нативны для cordis: schemastery Config с env-фолбэками, подаваемый из cordis.yml через `!!js process.env.MY_KEY`. Никогда не читайте ad-hoc файлы ключей в коде.

## Обязательства протокола (контракт, который проверили две реализации)

- Выдавайте `usage` ДО `finish`; после `finish` не выдавайте НИЧЕГО. Надёжный способ: буферизуйте finish/usage до маркера конца потока у провайдера, затем сбрасывайте буфер (обрабатывает провайдеров, присылающих завершающие куски только с usage).
- `arguments` вызова инструмента — СЫРЫЕ строки JSON на всём пути; фрагменты потока передавайте как `argumentsDelta`. Если провайдер возвращает уже разобранные объекты, заново сериализуйте их на `block-end`.
- Раздавайте `index` блоков в порядке первого появления в потоке; для каждого delta одного и того же блока используйте тот же индекс.
- У ошибок ровно два санкционированных пути: БРОСОК из `stream()` (сбои транспорта и протокола — используйте `LlmError` со стабильным кодом) или завершение потока через `finish {kind: 'error' | 'aborted'}` (in-band сбои провайдера). Потребители обрабатывают оба; выбирайте по классу отказа и документируйте выбор.
- Уважайте `options.signal` (передавайте его в fetch / свой SDK).
- Поле `GenerateOptions`, которое ваш провайдер не может исполнить (например список `stop` у провайдера без стоп-последовательностей): бросайте `LlmError(..., 'UNSUPPORTED')`, а не молча отбрасывайте.
- Если провайдер требует идентификаторы ответов, подписи или прочие нативные метаданные в последующих вызовах, выдавайте минимальную lossless-JSON проекцию как `finish.replayState`. При восстановлении истории валидируйте её. `LlmRuntime` передаёт её только когда исторический маршрут провайдера и целевой маршрут провайдера в данный момент принадлежат одному и тому же экземпляру адаптера; ваш адаптер решает, законно ли восстановление той же модели, между моделями или между провайдерами. Никогда не выводите нативное воспроизведение из одних лишь имён провайдера/модели, когда состояние отсутствует.

Переключатели режима рассуждений, специфичные для провайдера, остаются в Config адаптера. Точные метаданные модели идут через одну независимую от провайдера capability seam: реализуйте `resolveModel()` с идентификацией провайдер/модель и необязательными полями `context` и `reasoning`, объявляйте настроенный `defaultEffort`, только когда он существует, и уважайте необязательный `AbortSignal` резолвера. Уровни рассуждений — упорядоченные непрозрачные идентификаторы, которые адаптер отображает на запросы провайдера. Сохраняйте авторитетный выбираемый список адаптера, включая определённый адаптером `off`, когда он поддерживается, не раскрывая итоговых написаний формата протокола и не ограничивая неподдерживаемые значения; идентификатор не обязан совпадать со своим представлением в протоколе.

## Структура реализации

Держите типы протокола, сериализацию запросов, разбор транспорта, перевод кусков и класс адаптера отдельными ответственностями; [`llm-deepseek`](../../packages/llm/llm-deepseek/README.md) — эталонная компоновка.
