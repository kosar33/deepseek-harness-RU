# Primer по Cordis

[English](cordis-primer.md) | [中文](cordis-primer.zh.md) | Русский

Cordis — вендоренный плагинный фреймворк под DeepSeek Harness. Этот primer объясняет идеи Cordis, которые нужны автору плагина harness до чтения сгенерированного справочника сервисов/событий на [страницах подсистем](subsystems/core.md); [туториал по Cordis](cordis-tutorial/index.md) — практический проход по тем же идеям. Вендоренные исходники и процедура синхронизации — в [vendor/README.md](../vendor/README.md).

## Cordis в пяти идеях

- **Плагин — объект, реализующий Service.** Это может быть функция с необязательными полями `inject` и `apply(ctx)` или подкласс `Service`, чей жизненный цикл Cordis монтирует в текущий контекст.
- **Контекст — хранилище сервисов.** Сервис заявляет стабильный ключ `ctx.<key>` — например, `ctx.tools`, `ctx.llm` или `ctx.sessions`; другие плагины находят сервисы по ключу, а не импортом конкретной реализации.
- **Объявляйте зависимость от сервиса через `inject`.** Плагин, назвавший требуемые сервисы, ждёт их появления, поэтому порядок загрузки выражается требованиями к сервисам, а не ручным заданием порядка запуска.
- **Типизированные события для взаимодействия.** Сервисы объявляют имена событий через declaration merging в TypeScript, затем диспатчат их как `emit`, `waterfall`, `parallel` или `serial` — в зависимости от того, наблюдают слушатели, оборачивают, рассылают веером или исполняют по порядку.
- **Регистрации — обратимые эффекты.** Секции промпта, схемы инструментов, адаптеры, провайдеры и слушатели устанавливаются через `ctx.effect()` или `ctx.on()`, поэтому перезагрузка и разборка разворачивают их предсказуемо.

## Режимы диспатча

У каждого события один из следующих режимов диспатча, и диспатчить его можно только соответствующими методами.

| Режим | Ожидается? | Порядок доставки | Есть возвращаемое значение? |
|---|---|---|---|
| `emit` | Нет | слушатели наблюдают в порядке регистрации | Нет |
| `waterfall` | Нет | слушатели наблюдают в порядке регистрации | Да |
| `parallel` | Да | все слушатели наблюдают событие параллельно | Нет |
| `serial` | Да | слушатели наблюдают в порядке регистрации | Да |

Режим диспатча — часть публичного контракта события. Новые события harness документируют его тегом `@mode`, чтобы сгенерированный каталог сверял декларации с местами диспатча.

## Семантика waterfall в Cordis

`ctx.waterfall` — around-middleware. Слушатель получает `(...args, next)`. Вызовите `next()`, чтобы передать следующему сервису возможно обёрнутый результат; верните значение без `next()` — это короткое замыкание цепочки. Значения распространяются через возвращаемое значение `next()`.

Кооперативные слушатели обычно мутируют общий объект запроса или решения и затем делегируют. Слушатель может и полностью заменить результат — тогда последующие слушатели увидят только результат после замены. `prepend: true` используйте, только когда слушатель обязан выполниться раньше обычных регистраций.

Для событий с одним решением короткое замыкание предусмотрено дизайном: слушатель политики может вернуть значение без `next()`, когда решение принадлежит ему, а слушатель, лишь аннотирующий или наблюдающий, обязан делегировать.

## Конфигурация лоадера

`@deepseek-ai/cordis-plugin-include` парсит `!!js` в узлы выражений. Загрузчик интерполирует `config` записи (после активации объявленных внедрений, в контексте того плагина — `ctx.serviceName`) и её поле `disabled` (при каждом решении о монтировании, в контексте загрузчика); Include сохраняет вложенные строчные выражения до активации цели. Остальные метаданные записи остаются литеральными. Когда среда выбирает плагины — используйте оверлеи.

## Практические правила

Инкапсулируйте поведение в плагины: событие конвейера инструментов относится к `ctx.tools`, потоковая передача модели — к `ctx.llm`, живая координация агентов — к `ctx.agents`. Для перехвата и политик предпочитайте события; для прямых вызовов возможностей — методы сервисов.

У каждой регистрации должен быть disposer — возвращённый из `ctx.effect()` или обеспеченный хелпером Cordis. Если важен порядок teardown, держите связанную работу в одном эффекте, чтобы освобождение ресурсов шло в задуманной последовательности.
