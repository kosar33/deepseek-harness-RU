# Туториал по Cordis

[English](index.md) | [中文](index.zh.md) | Русский

Cordis — плагинный фреймворк под DeepSeek Harness: небольшой рантайм, где каждая возможность — инструменты, LLM-адаптеры, доступ к файлам, сам цикл агента — это плагин, смонтированный в общий контекст. Этот туториал учит Cordis на практике: каждая глава — работающий пример, который вы собираете в черновом каталоге внутри репозитория, и завершается всё плагином, подключённым к настоящим сервисам harness.

Аудитория — разработчики агентов. Глубокий опыт TypeScript не требуется: [заметки о TypeScript](#typescript-notes) ниже разбирают синтаксис, который может быть вам незнаком, а каждая глава показывает точные команды и ожидаемый результат.

Если вместо пошагового прохождения вам нужен сжатый концептуальный справочник, прочитайте [Primer по Cordis](../cordis-primer.ru.md). Исчерпывающий справочник API живёт в генерируемых секциях `cordis-surface` на [страницах подсистем](../subsystems/core.ru.md) и на страницах [Cordis core API](../cordis-api/context.md).

Чтобы писать плагины для самого harness — загружаемые из `cordis.yml` и управляемые через Web UI, а не через лаунчер ниже, — начните с руководства [«Ваш первый плагин Harness»](../user/develop/basic/index.ru.md).

<a id="настройка"></a>

## Настройка

Вам нужен клон этого репозитория с установленными зависимостями; предварительные требования перечисляет [руководство по разработке](../development.ru.md#туториал-по-установке). Для этого туториала API-ключ не нужен: каждый пример работает без ключа.

```sh
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
```

Создайте черновой каталог, в котором будут работать главы. `tmp/` игнорируется git, поэтому всё, что вы там пишете, не попадает под контроль версий:

```sh
mkdir -p tmp/cordis-tutorial
cd tmp/cordis-tutorial
```

Каждая глава запускается из этого каталога одной и той же командой:

```sh
node --import tsx ../../vendor/cordis/bin.js
```

Этот однофайловый лаунчер (см. [vendor/cordis/bin.js](../../vendor/cordis/bin.js)) создаёт корневой `Context`, монтирует плагин Loader и поручает ему загрузить `./cordis.yml` из текущего каталога. Всё остальное — какие плагины существуют и как они сконфигурированы — берётся из того YAML-файла, который вы через минуту напишете. Флаг `--import tsx` позволяет Node исполнять TypeScript-файлы, на которые указывает конфигурация, без шага сборки.

<a id="typescript-notes"></a>

## Заметки о TypeScript

В примерах используются три возможности TypeScript сверх обычного современного JavaScript:

- **Аннотации типов** описывают значения, не меняя поведение в рантайме: `ctx: Context` говорит, что у `ctx` есть API контекста Cordis, `who: string` принимает текст, а `string[]` означает массив строк.
- **`import type { Context } from '@deepseek-ai/cordis'`** импортирует только информацию о типах. В рантайме она исчезает, поэтому файл плагина, которому `Context` нужен исключительно для аннотаций, не добавляет зависимости в рантайм.
- **Declaration merging** (`declare module '@deepseek-ai/cordis' { ... }`) добавляет ваши записи в интерфейсы, уже объявленные Cordis, — например, тип нового свойства `ctx.greeter` или имя события. Он не порождает никакой рантайм-обвязки; сервис или испускание события — задача самого плагина. Полностью этот паттерн показан в главе 3.

Глава 5 также использует `interface` для описания полей объекта конфигурации и обобщённый тип вроде `Schema<Config>`, чтобы указать, какие поля объекта валидирует схема. Эти объявления можно копировать как есть; окружающий текст объясняет, что каждое из них связывает.
