# Терминология (русский)

[English](terminology.md) | Русский

Эта таблица фиксирует единую русскую передачу терминов репозитория. Она дополняет англо-китайскую таблицу [terminology.md](terminology.md) и не изменяет её.

**Общие правила:**

- Колонка «Русский» задаёт слово по умолчанию для основного текста русской версии. Если в колонке английское слово, в тексте оно сохраняется без перевода.
- Термины внутри кода (`` `так` ``), пути, команды, идентификаторы и ключи конфигурации никогда не переводятся.
- Модальности RFC 2119: MUST → ДОЛЖЕН, MUST NOT → НЕ ДОЛЖЕН, SHOULD → СЛЕДУЕТ, MAY → **МОЖЕТ**.
- Ссылки из `.ru.md`-файла сохраняют цель исходной стороны, кроме ссылок на документы корпуса, у которых существует русский аналог: тогда целью становится его `.ru.md`-путь.
- Строка переключателя языка в `.ru.md`: сразу после H1 — `[English](foo.md) | Русский`; если китайская версия тоже существует, `[English](foo.md) | [中文](foo.zh.md) | Русский`. При наличии `.ru.md`-версии стороны EN и ZH добавляют в свои строки сегмент `| [Русский](foo.ru.md)`.

## Учёт актуальности русского слоя

Русский слой (`*.ru.md`) не входит в гейт EN/ZH-парности — у него собственный контракт и трекер:

- Проверка статуса: `node scripts/russian-docs/check.mjs` — печатает статусы всех пар (`ok`, `unrecorded`, `outdated`, `missing`, `orphan`, `structural`) и счётчики.
- После перевода или синхронизации пары подтвердите её: `node scripts/russian-docs/check.mjs --write <путь/к/файлу.ru.md>` — скрипт запишет blob-хэши обеих сторон в `scripts/russian-docs/manifest.json`.
- CI `.github/workflows/russian-docs.yml` выполняет проверку на каждый push, PR (строгий режим: устаревшие или неподтверждённые пары краснят PR) и еженедельно по расписанию; отчёт появляется в summary прогона.
- Правило обновления: при изменении английского источника правьте перевод минимально, по диффу источника, затем выполняйте `--write`; полного повторного перевода файла избегайте так же, как требует контракт ZH-пар.
