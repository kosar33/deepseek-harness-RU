# Политика тестирования

[English](testing.md) | [中文](testing.zh.md) | Русский

Как этот репозиторий тестирует код — ярус за ярусом — и правила, из-за которых зелёный набор тестов что-то значит. Команды живут в корневом [AGENTS.md](../AGENTS.md); обоснование несут связанные Agent Note.

## Ярусы

- **Юнит** (`pnpm run test`): vitest над спеками пакетов и примеров в их каталогах `tests/**` плюс спеки репозитарных скриптов под `scripts/**/*.spec.ts`; тесты живут рядом с проверяемой областью кода. Каждый реестр получает HMR-безопасный тест (освободите внёсший вклад fiber и проверьте очистку). Предпочитайте граничные случаи, пути ошибок, порядок событий, гонки конкурентности и постоянные тесты для контрактных регрессий (см. `packages/core/agent-loop/tests/contract-regressions.spec.ts`).
- **Гейт покрытия** (`pnpm run test:coverage`): блокирующий прогон, 100% по каждому файлу в `packages/*/*/src`. Непокрытая строка — часто мёртвый код, который гейт справедливо помечает на удаление, а не отсутствующий тест, который надо приделать. Покрытие строк необходимо, но никогда не достаточно — оно доказывает, что строки исполнялись, а не что функциональность работает так, как поставляется. 100% по каждому файлу в `packages/shell/pwsh-local/src` требует настоящего `pwsh`: без него наборы тестов его исполнителя пропускают себя сами, а `vitest.config.ts` исключает файл, чтобы хосты без pwsh оставались зелёными; раннеры CI поставляются с pwsh и требуют полную планку.
- **e2e с реальным API** (`pnpm run test:e2e`): тесты с ключом против живых API провайдеров — модель DeepSeek плюс смоуки конкретных провайдеров, гейтящиеся собственными ключами (`EXA_API_KEY`, `PERPLEXITY_API_KEY`, …); каждый набор без своего ключа пропускает себя сам, поэтому CI без ключей остаётся зелёным ([Agent Note о e2e с реальным API](../.agents/notes/implemented/testing/2026-06-19-real-api-e2e-ci.md)).
- **Снапшот** (`pnpm run test:snapshot`): ожидаемые результаты без ключа покрывают внешнее поведение — транспортные контракты и представление, а персистентные журналы фиксируют собранное поведение бэкенда. ACP поднимает настоящий пример automation-server, воспроизводит записанную сессию и сравнивает нормализованный JSON-RPC и повторно записанный журнал ([Agent Note об ACP-снапшотах](../.agents/notes/implemented/testing/2026-06-19-acp-snapshot-tests.md)); headless-сценарии бэкенда поднимают свою явную композицию примера через неэкспортируемый JSONL-драйвер тестов, а `apps/cli` отдельно отвечает за приёмку продуктового `dsh --profile headless`. Используйте `pnpm run test:snapshot:record`, когда меняется транскрипт модели, и `pnpm run test:snapshot:refresh`, когда вход воспроизведения остаётся валидным; просматривайте каждый дифф JSONL и ожидаемых результатов. Один сценарий ACP (`text-turn`) фиксирует полное содержимое системного промпта и схем инструментов; остальные фикстуры токенизируют его, чтобы правка изменяла ровно одну строку ([Agent Note о зафиксированном заголовке](../.agents/notes/archived/testing/2026-07-06-pin-request-header-content-in-one-scenario.md)).
- **Снапшот веб-браузера** (`pnpm run test:web`; обязательный PR-гейт Linux): Chromium сравнивает воспроизведённый вывод браузера с `apps/web/tests/snapshots/`. CI принудительно ставит read-only `DSH_SNAPSHOT=replay` и никогда не пишет ожидаемые результаты; запись и обновление остаются локальными, и каждый дифф просматривается ([lane браузерного e2e](../.agents/notes/implemented/testing/2026-07-24-web-gui-browser-e2e-lane.md), [решение о CI-гейте](../.agents/notes/implemented/testing/2026-07-30-web-browser-snapshot-ci-gate.md)). `test:web` [сначала собирает проект](../.agents/notes/implemented/bug-fix/2026-07-28-themed-scrollbars-and-reserved-gutter.md), чтобы подхватить CSS плагинов.

Фикстуры сессий сохраняют заголовки и полезные нагрузки, но опускают конверты последовательности и времени тела. Воспроизведение синтезирует их; персистентность рантайма не меняется. Фикстуры используют канонические упакованные строки; [мигратор](../scripts/migrate-packed-session-fixtures.ts) переписывает старые раскладки.

## Политика «с ключом»: инференс здесь дёшев

Мы — DeepSeek, и реальные-API тесты мы не нормируем. Тест без ключа доказывает лишь целостность проводки; только прогон с ключом доказывает, что агент работает против настоящей модели. Покрывайте промпты с записью файлов, многоходовые беседы, использование инструментов и отмену посреди потока. Наивысшую ценность несут **смоук-тесты**, которые поднимают настоящий пример, отправляют один промпт и проверяют внешний мир — они ловят класс «зелёные юнит-тесты, сломанный продукт», недоступный мокам ([постмортем 0001](postmortem/0001-acp-default-export-drops-inject.md)). Самопропуск оставляет разблокированными CI без секретов и контрибьюторов без ключей; это не сигнал стоимости. Каждый пример поставляет и смоуки без ключа, и смоуки с ключом ([examples/AGENTS.md](../examples/AGENTS.md)).

## Предпочитайте настоящую реализацию моку

Мокайте только дорогую или недетерминированную границу (LLM-адаптер, сеть, часы); всё нижележащее держите настоящим. Самодельная подмена доказывает лишь, что мост двигает байты, а не что поставляемый инструмент ведёт себя как заявлено. Тесты Bridge-вызовов инструментов используют скриптованную мок-модель вместе с настоящими инструментом и исполнителем: `makeBridgeHarness({ withBash: true })` подключает `dsh-bash-local` и `dsh-tool-bash`, затем исполняет `echo`.

Тесты восстановления разделяют отказы до и после чанка по шагам и доказывают, что отказавшие чанки не порождают ни сообщений, ни побочных эффектов инструментов. Покрывайте исчерпание, отмену, композицию политик, персистентность, статус, счётчики формата протокола, idle-таймауты, закрывающие транспорт, и поставляемую композицию Loader.

## Проверяйте внешний мир, а не самоотчёт

Утверждение e2e перезапускает команду или заново читает файл извне; зонд по ключевому слову в собственном выводе агента позволяет пройти жуликоватому агенту. Утверждайте, что нетронутые файлы байт-в-байт идентичны. e2e-тесты владеют своими ресурсами: создавайте harness в самом тесте и освобождайте его в `afterEach` (даже при сбое, повторе или таймауте); общие фикстуры живут в простом `tests/harness.ts`, но никогда в очередном `*.e2e.ts` (импорт спеки повторно регистрирует её `describe` и дублирует реальные вызовы API).

## Тестируйте настоящий путь входа

- Плагины, видимые продукту, требуют не-юнитового теста настоящей композиции. Вручную собранные наборы `ctx.plugin(...)` недостаточны: поднимайте тестовый `cordis.yml` через Loader и app/process, мокайте только внешние сервисы или недетерминированные входы и утверждайте видимый модели запрос или журнал, долговременное состояние либо видимый пользователю вывод. Держите opt-in'ы вне поставляемых значений по умолчанию.
- Guard работает как защита, только если регрессия действительно его ломает. Для плагина без `inject` (бандл- и композиционные плагины) Loader-смоук остаётся зелёным, когда default-экспорт заменяет требуемые именованные экспорты, — добавьте явное `expect('default' in mod).toBe(false)` плюс утверждение round-trip через `unwrapExports` и докажите это: внесите регрессию, убедитесь, что тест краснеет, затем откатите.
- «Настоящий путь входа» означает опубликованный артефакт: `bin` пакета запускается как собранный `lib/bin.js` под обычным `node`, вскрывая сбои, которые маскирует tsx (гонки settle, разрешение модулей, проглоченные сбои загрузки). То же относится к точкам входа рантайма помимо index (worker-thread-сосед `lib/worker.cjs`) и к модулям-синглтонам, разделённым между бандлами (`packages/sdk/server/tests/built-scope-carrier.e2e.ts`). Держите зелёными смоуки собранных артефактов (`packages/examples/*/tests/built-bin.e2e.ts`, `packages/code-runtime/code-runtime-worker-thread/tests/built-lib.e2e.ts`) и утверждайте, что по-настоящему отсутствующий конфиг завершается с ненулевым кодом.

## Резолюция в тестах: только плоскость исходников

- Каждая конфигурация vitest направляет vite-tsconfig-paths на `tsconfig.base.json`; голые импорты воркспейса резолвятся в `src` ([структура](development.ru.md#структура-typescript-проектов)), никогда через `exports` пакета в собранный `lib/` — устаревшие артефакты там загружают вторую копию модулей-синглтонов. Собранные артефакты потребляются только явно: субпроцессы в режиме `lib` и описанные ниже built-смоуки.

## Режимы запуска субпроцессов в тестах

- CI и тестовые lane'ы, у которых есть сборка, запускают каждый субпроцесс примера или Cordis-конфига из собранного `lib/` через общий dual-mode лаунчер. Не пишите руками `--import tsx` для этих субпроцессов.
- Фикстуры протоколов и операционной системы, не загружающие Cordis, запускаются напрямую как erasable `.ts` под Node, без tsx и корневой карты путей.
- Только тест, чей предмет — резолюция исходных путей, может выбрать `src`; сформулируйте этот контракт в самом тесте.

## Когда обязателен снапшот-тест

Каждое нетривиальное изменение, видимое модели, протоколу или человеку, добавляет или обновляет сценарий без ключа в том же PR через владеющий снапшот-набор запускаемого примера. Тесты пакетов, утверждения e2e, мок- и только-тестовые композиции, равно как обоснование в PR, не заменяют собранный транскрипт; при необходимости расширяйте harness. Сценарии автоматизации ACP используют `examples/<name>/tests/snapshots/` — таблицу сценариев поверх фабрики наборов [`dsh-acp-snapshot`](../packages/test-support/acp-snapshot/README.md) (первичный пример — `examples/acp-agent`); `examples/headless-agent` владеет внутренними JSONL-снапшотами канонических событий и фикстурами воспроизведения. Сценарий ACP `pwsh-tool-turn` поднимает настоящий `pwsh` и пропускается там, где его нет. Завершённые интерактивно-терминальные сценарии использования идут JSONL-управляемыми сценариями под `apps/cli/tests/snapshots/`; переходное представление использует пакетно-локальную семантическую матрицу, с PTY-случаем, когда меняются ввод, выбор Loader или разборка терминала. Отрисовываемые браузером web GUI-сценарии использования используют `apps/web/tests/snapshots/`. Оба SDK независимо проецируют цикл агента, жизненный цикл сессии и `SessionEventMap`, поэтому изменение любого из них обновляет оба: `examples/jsonrpc-agent/tests/snapshots/` владеет TypeScript-клиентом; `scripts/snapshots/python-sdk-single-exe/` владеет Python-клиентом, который исполняет только обязательное CI-задание `python-runtime`. Новые capability seam'ы, варианты жизненного цикла или поверхности транскрипта называют каждый ярус покрытия ещё на этапе планирования и до реализации проверяют, что harness умеет его выразить.
