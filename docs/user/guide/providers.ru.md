# Настройка моделей

[English](providers.md) | [中文](providers.zh.md) | Русский

В этом руководстве предполагается, что вы запустили веб-интерфейс согласно [корневому README](../../../README.ru.md#запуск). Изменения модели вступают в силу при следующем запросе, без перезапуска сервера.

## Настройка DeepSeek

Откройте **Settings → Models**. Карточка DeepSeek содержит единственное поле API-ключа; введите ключ и сохраните его.

![Страница Models: карточка DeepSeek, под ней Add provider и Add a custom provider](providers-models-page.png)

Ключи доступны только для записи. После сохранения страница получает маскированный дескриптор, но никогда сам секрет. Ключ хранится в `$DSH_HOME/.credentials.yaml`, а в настройках остаётся лишь ссылка на учётные данные.

## Добавление провайдера из каталога

Выберите **Add provider**, укажите провайдера, например Anthropic или OpenAI, введите его API-ключ и сохраните. Установленный каталог поставляет эндпоинт, протокол и список моделей.

Провайдерам с нативной аутентификацией нужны их нативные учётные данные. Bedrock, Vertex, Azure и Codex используют, соответственно, учётные данные AWS и регион, проект ADC, `api-version` и OAuth; заполнение одного лишь поля API-ключа их не настраивает.

## Добавление пользовательского провайдера

Выберите **Add a custom provider** для корпоративного шлюза, самостоятельно размещённого сервера или провайдера, отсутствующего в установленном каталоге. Укажите Provider ID в нижнем регистре, базовый URL, протокол API, учётные данные и минимум одну модель.

![Форма пользовательского провайдера: Provider ID, отображаемое имя, базовый URL, протокол API и API-ключ](providers-custom-form.png)

Provider ID постоянен, потому что его используют запросы, сохранённые сессии, модель по умолчанию и ссылки на учётные данные. Чтобы переименовать провайдера, добавьте нового и удалите старого. Отображаемое имя, базовый URL, протокол, учётные данные и модели остаются редактируемыми.

В разделе **Model catalog** выберите **Fetch available models**, чтобы опросить базовый URL и учётные данные, показанные в форме. Выбор кандидатов обновляет черновик; провайдер не сохраняется, пока вы не нажмёте кнопку сохранения. Провайдеры из каталога используют установленный каталог без сетевого запроса.

### Ввод изображений

Модель, введённая вручную, считается текстовой, пока не объявлено иное, потому что ни один механизм не может спросить эндпоинт, какие модальности он принимает. Прикрепление изображения к такой модели отклоняется до отправки с указанием имени модели.

Поэтому для vision-модели на пользовательском провайдере нужна одна строка. В форме для неё нет поля; добавьте `input` к модели в `$DSH_HOME/settings.yaml`:

```yaml
llm-pi-ai:
  providers:
    my-gateway:
      apiKeyEnv: GATEWAY_API_KEY
      api: openai-completions
      baseURL: https://gateway.example/v1
      models:
        - id: legacy-chat
        - id: vision-preview
          input: [text, image]
```

`input` принимает `text` и `image` и относится только к этой модели, так что один маршрут может обслуживать оба вида. Пропуск поля — или пустой список, что означает то же самое, — сохраняет то, что записано для модели в установленном каталоге, а для модели, которой в каталоге нет, действует `defaultInput` маршрута.

Если все введённые вручную модели принимают изображения, задайте fallback один раз на маршруте, а не на каждой из них:

```yaml
llm-pi-ai:
  providers:
    vision-gateway:
      apiKeyEnv: GATEWAY_API_KEY
      api: openai-completions
      baseURL: https://vision.example/v1
      defaultInput: [text, image]
      models:
        - id: first-model
        - id: second-model
```

`defaultInput` — это fallback, а не переопределение; по умолчанию он равен `[text]`. На провайдере из каталога он отвечает только за модели, которых в каталоге нет, поэтому никогда не убирает изображения у каталожной модели, которая их имеет. Сузьте модальности такой модели её собственным `input`. У провайдера из каталога нет списка `models`, куда это можно поместить, поэтому пишите в `modelOverrides` с ключом по id модели:

```yaml
llm-pi-ai:
  providers:
    anthropic:
      modelOverrides:
        claude-sonnet-4-5:
          input: [text]
```

Каждый список должен называть хотя бы одну модальность, кроме собственного списка модели, где пустой список означает то же, что и пропуск. Неизвестная модальность отклоняется везде, где бы она ни была записана.

Оба поля утверждают свойства вашего эндпоинта, а не проверяют их. Модель, которая объявляет изображения, которые её эндпоинт не обслуживает, здесь не выявляется; вместо этого провайдер отклонит запрос.

### Совместимость запросов

Шлюз может держать рабочий ключ по достижимому адресу и всё равно отклонять каждый запрос. pi-ai определяет форму запроса — какая роль несёт системный промпт, какое поле ограничивает вывод, как передаётся уровень рассуждений — по URL эндпоинта, и адрес, который он не распознаёт, обслуживается так, будто это сам OpenAI. Большинство шлюзов, совместимых с OpenAI, отклоняют хотя бы одно из того, что OpenAI принимает.

Две причины покрывают большинство случаев. У модели, объявляющей рассуждения, системный промпт отправляется как `role: "developer"`, что многие шлюзы сразу отклоняют, а лимит вывода отправляется как `max_completion_tokens`, который сервер, знающий только `max_tokens`, отвергнет. В форме нет полей ни для того, ни для другого; исправьте их на маршруте в `$DSH_HOME/settings.yaml`:

```yaml
llm-pi-ai:
  providers:
    my-gateway:
      apiKeyEnv: GATEWAY_API_KEY
      api: openai-completions
      baseURL: https://gateway.example/v1
      compat:
        supportsDeveloperRole: false
        maxTokensField: max_tokens
      models:
        - id: my-model
```

`compat` маршрута является значением по умолчанию для его моделей, а собственный `compat` модели имеет приоритет по каждому полю, так что одну модель можно исправить, не повторяя весь маршрут:

```yaml
      models:
        - id: my-model
        - id: my-reasoner
          compat:
            thinkingFormat: deepseek
```

Что не задано ни в маршруте, ни в модели, берёт значение установленного каталога для этой модели, а то, чего в каталоге нет, отдаётся автоопределению pi-ai. Каждому названному переключателю давайте значение: ключ, оставленный пустым (`supportsDeveloperRole:`), отклоняется, а не игнорируется, потому что пустое значение стёрло бы знание каталога, ничего не сообщив взамен. Имя, которое не принимает ни один протокол, тоже отклоняется, и сообщение перечисляет доступные.

Каждый переключатель принадлежит протоколам, которые его декларируют, поэтому переключатель, корректный на одном `api`, может быть отклонён на другом — в сообщении названо то, что этот протокол предлагает. Как и `input` выше, переключатель утверждает свойства вашего эндпоинта, а не проверяет их: установка того, что вашему шлюзу на самом деле не нужно, просто меняет форму запроса.

Каждый переключатель, его допустимые значения и принимающие его протоколы перечислены под `PiAiCompatProfile` в [сгенерированном справочнике конфигурации `dsh-llm-pi-ai`](../../config-catalog.md#deepseek-aidsh-llm-pi-ai) — он порождается из исходников, поэтому не может отстать от того, что принимает адаптер.

## Выбор модели

Настроенные провайдеры появляются в селекторе моделей. Выбор модели также делает её моделью по умолчанию для новых сессий. Сессия, уже отправившая запрос, сохраняет модель, записанную в собственном журнале.

Если сохранённая по умолчанию модель указывает на провайдера, который был удалён, компоновщик показывает **Select model** и блокирует ввод, пока не выбрана другая модель.

## Устранение неполадок

- **`MISSING_CREDENTIAL`** — Сохраните ключ провайдера через страницу Models или предоставьте указанную переменную окружения.
- **`UNKNOWN_MODEL`** — Выберите настроенную модель или добавьте отсутствующую модель к пользовательскому провайдеру.
- **Получение доступных моделей возвращает 401** — Проверьте ключ. Обнаружение моделей вызывает совместимый с OpenAI эндпоинт `GET /models`; вводите модели вручную для эндпоинтов, которые его не предоставляют.
- **Шлюз отклоняет каждый запрос, хотя ключ и URL верны** — Форма его запросов отличается от OpenAI. Начните с `compat.supportsDeveloperRole: false` и `compat.maxTokensField: max_tokens` на маршруте.
- **Сбой дают только модели с рассуждениями** — pi-ai отправляет их системный промпт в роли `developer`, которую шлюз отклоняет. Задайте `compat.supportsDeveloperRole: false`.
- **Переключатель compat отклонён как не имеющий значения** — Ключ записан без значения после двоеточия. Дайте ему значение или удалите ключ, чтобы осталось значение установленного каталога.
- **Изображение отклонено до отправки** — Модель не объявляет модальность изображения. Дайте модели пользовательского провайдера `input: [text, image]`; собственный маршрут chat-completions у DeepSeek чисто текстовый и иначе не настраивается.
- **Провайдер отклоняет запрос с изображением** — Модель объявляет изображения, которые её эндпоинт на самом деле не обслуживает. Уберите `image` из того списка, который дал его модели, — её `input` или `defaultInput` маршрута, — затем начните новую сессию: прикреплённое изображение остаётся в журнале сессии, поэтому тот же запрос повторяется, пока сессия не уйдёт с него.

## Расширенная конфигурация

Сгенерированный [каталог конфигураций плагинов](../../config-catalog.md) перечисляет все поддерживаемые поля и значения по умолчанию для каждого плагина; [`dsh-llm-pi-ai`](../../config-catalog.md#deepseek-aidsh-llm-pi-ai) — раздел про провайдеров, который настраивает эта страница. Справочники [`dsh-llm-pi-ai`](../../../packages/llm/llm-pi-ai/README.md) и [`dsh-llm-deepseek`](../../../packages/llm/llm-deepseek/README.md) владеют темами прямой настройки `settings.yaml`, разрешения каталога, управления рассуждениями, учётных данных и ошибок адаптера.
