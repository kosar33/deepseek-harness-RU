# Пример acp-agent

[English](README.md) | [中文](README.zh.md) | Русский

Ориентированный на автоматизацию сервер [Agent Client Protocol](https://agentclientprotocol.com) поверх JSON-RPC stdio. Он предназначен для родительских агентов, провайдеров субагентов и других программных клиентов, а не в качестве пользовательского интерфейса продукта.

```sh
pnpm run demo:acp             # needs DEEPSEEK_API_KEY (repo-root .env or env)
pnpm run demo:code-mode       # same protocol with the Code Mode tool transport
```

Лист загружает ACP-приложение, адаптер DeepSeek, стеки bash и файловой системы под песочницей, политику однократного одобрения, компакцию, субагентов, воркфлоу, хуки, производный индекс session-query и защиту от повторов. Приложение создаёт по одному свежему агенту на каждый `session/new`, сохраняет сессии в JSONL и держит stdout чистым для протокола. Опциональные оверлеи добавляют запросы к сессиям, spill-хранилище файловой системы, Code Mode или загрузку веб-ресурсов.

## Протокольный канал

Stdout передаёт только ACP-сообщения JSON-RPC, разделённые переводами строк. `@deepseek-ai/dsh-acp-demo` не устанавливает логгер для stdout; дополнения листа обязаны выводить диагностику в stderr.

Контракт автоматизации — поддерживаемые методы, содержимое базового промпта, вывод зафиксированного текста и намеренно отсутствующие поверхности UI — описан в [`@deepseek-ai/dsh-acp`](../../packages/acp/acp/README.ru.md).

## Рабочие пространства сессий и разрешения

Каждый `session/new` передаёт абсолютный `cwd`. Изменения в песочнице bash и в файловой системе разрешают `workspace-write` относительно cwd этой сессии, поэтому параллельные сессии могут использовать отдельные корни проектов; временные корни платформы остаются общим доступным на запись черновым пространством ([контракт песочницы](../../packages/sandbox/sandbox/README.ru.md)). Переменная `DSH_PERMISSION_MODE` выбирает `workspace-write` или `danger-full-access` для развёртывания.

В режиме `workspace-write` повторная попытка модели, запрашивающая более широкий доступ к песочнице, вызывает `session/request_permission` с вариантами `allow_once` и `reject_once`. Клиент решает программно; отклонение запроса или недоступность ответа трактуется как отказ (fail-closed). Выбранный исход применяется только к этой повторной попытке и фиксируется через обычный путь «результат инструмента»/аудита. Сервер никогда не показывает выборщик разрешений и не сохраняет клиентскую политику.
