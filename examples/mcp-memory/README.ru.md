# Примеры сторонней памяти через MCP

[English](README.md) | [中文](README.zh.md) | Русский

Эти три **выключенные по умолчанию эталонные конфигурации** подключают одну систему памяти к DSH через [`@deepseek-ai/dsh-mcp-client`](../../packages/mcp/mcp-client/README.ru.md). Выберите одну из них или скопируйте ту же универсальную строку MCP для другого сервера.

Эти сторонние конфигурации предоставляются исключительно как примеры совместимости. Их включение не подразумевает одобрения, рекомендации, партнёрства или постоянной поддержки со стороны DeepSeek.

## Что делает DSH

DSH разбирает выбранный оверлей Cordis, запускает сконфигурированную stdio-команду или подключается к сконфигурированному URL Streamable HTTP, обнаруживает инструменты MCP и выставляет их как `mcp__<serverName>__<tool>`. DSH **не** скачивает сервер, не инициализирует его базу данных, не выбирает провайдера моделей или эмбеддингов, не создаёт облачный аккаунт, не переносит данные вендора и не присматривает за отдельным HTTP-сервисом. Для stdio универсальный клиент запускает дочерний процесс и останавливает его вместе с жизненным циклом плагина DSH; для HTTP вышестоящий сервис уже должен быть запущен.

Перед запуском дочернего процесса stdio-мост намеренно удаляет переменные окружения, чьи имена обычно обозначают учётные данные, и все переменные `DSH_*`; остальные переменные окружения наследуются. Каждый пример добавляет только ту базовую переопределяющую переменную, которая ему нужна. Если необязательная функция сервера требует ещё один секрет, добавьте эту переменную в `config.env` соответствующей строки вместо того, чтобы класть секрет прямо в YAML.

## Включите одну

Передайте один оверлей в DSH:

```sh
dsh web --patch "$PWD/examples/mcp-memory/memorix.cordis.yml"
```

Замените имя файла на `mcp-reference-memory.cordis.yml` или `engram.cordis.yml`. Путь может указывать на копию файла в любом месте диска. В поставляемой композиции нет ни одного сервера памяти, поэтому без `--patch` все три остаются выключенными.

Чтобы сохранить выбор между запусками, влейте единственный patch `insert` выбранного файла в пользовательский слой патчей — `$DSH_HOME/profiles/<name>/cordis.patch.yml` для одного профиля или `$DSH_HOME/cordis.patch.yml` для всех профилей машины. Не переписывайте поверх существующий файл: в нём могут уже находиться не относящиеся к делу пользовательские патчи.

## Настройка провайдеров

### Memorix

```sh
npm install --global memorix@1.3.0
dsh web --patch "$PWD/examples/mcp-memory/memorix.cordis.yml"
```

Memorix работает в локальном эвристическом режиме без LLM или сервиса эмбеддингов. Необязательные провайдеры настраиваются в собственных файлах Memorix `~/.memorix/config.toml` или проектном `memorix.toml`. Пример сохраняет Git-идентичность проекта Memorix из рабочей папки DSH и использует стандартный путь Memorix `~/.memorix/data`. Задайте `MEMORIX_DATA_DIR` перед запуском DSH, чтобы переопределить его.

### MCP Reference Memory

```sh
npm install --global @modelcontextprotocol/server-memory@2026.7.4
dsh web --patch "$PWD/examples/mcp-memory/mcp-reference-memory.cordis.yml"
```

Этот эталонный сервер хранит локальный граф знаний и выставляет инструменты entity, relation, observation, read, search и open. Модель или сервис эмбеддингов ему не нужны. Пример хранит его JSONL в `$HOME/.dsh-mcp-reference-memory.jsonl`, а не в каталоге установленного npm-пакета. Задайте `MEMORY_FILE_PATH` перед запуском DSH, чтобы переопределить это.

Поиск — это нечувствительное к регистру сопоставление подстрок по именам, типам и наблюдениям сущностей, а не семантический поиск. Сервер не добавляет эмбеддинги, автоматическое суммаризирование, разрешение конфликтов или политику забывания.

### Engram

```sh
go install github.com/Gentleman-Programming/engram/cmd/engram@v1.20.0
dsh web --patch "$PWD/examples/mcp-memory/engram.cordis.yml"
```

Engram сам владеет хранилищем и выбором проекта: по умолчанию он использует `~/.engram`, определяет Git-проект по рабочей папке DSH и принимает `ENGRAM_DATA_DIR` или `ENGRAM_PROJECT` как переопределения из окружения.

## Необязательная общая инструкция для модели

Если описания инструментов сервера ненадёжно побуждают модель пользоваться памятью, добавьте эту короткую, независимую от вендора инструкцию к вашим существующим инструкциям для модели:

> Когда пользователь просит вас что-то запомнить, вызовите инструмент записи памяти. Когда историческая информация может быть уместна, поищите в памяти и используйте релевантные результаты.

Это лишь дополнительное указание. Примеры не заменяют персону системного промпта DSH.

## Проверка записи, припоминания в новой сессии и использования

Используйте одно уникальное значение и не меняйте область хранения провайдера на протяжении всей проверки:

1. В сессии A DSH спросите: `Remember that my validation drink is lapsang-<unique suffix>.` Убедитесь, что модель вызвала инструмент записи провайдера и инструмент вернул успех.
2. Создайте сессию B DSH в том же работающем Host. Не копируйте беседу сессии A. Спросите: `What is my validation drink? Check memory.` Убедитесь, что модель вызвала инструмент поиска или припоминания провайдера и вернула значение.
3. Оставаясь в сессии B, спросите: `Use that preference to suggest one drink for the meeting.` Убедитесь, что ответ использует припомненное значение.

Нужна новая сессия DSH; перезапуск Host не требуется. Перезапуск или HMR нужны только после падения дочернего процесса MCP, потому что текущий универсальный клиент не переподключается автоматически: его регистрации инструментов остаются до освобождения ресурсов плагина или успешной повторной синхронизации, а вызовы могут терпеть неудачу на закрытом транспорте. Первичное обнаружение выполняется асинхронно, поэтому дождитесь инструментов `mcp__...` провайдера, прежде чем отправлять первый проверочный промпт.

## Подключение другого сервера MCP

Скопируйте те же поля записи и используйте уникальные `id` и `serverName`:

```yaml
- insert:
    - id: memory-my-server
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: my-memory
        transport: stdio
        command: my-memory-mcp
        args: []
        env: {}
        cwd: !!js process.cwd()
```

Для удалённого сервера используйте вместо этого `transport: streamable-http`, `url` и `headers`. Установка, идентичность, аутентификация, модели, эмбеддинги, персистентность и лицензирование, специфичные для провайдера, остаются ответственностью самого провайдера.
