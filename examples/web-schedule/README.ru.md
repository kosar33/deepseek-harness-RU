# Schedule, локальный для сессии

[English](README.md) | [中文](README.zh.md) | Русский

Этот оверлей подключает напоминания Schedule к одному процессу `dsh web`, не меняя поставляемую композицию Web по умолчанию:

```sh
dsh web --patch examples/web-schedule/cordis.yml
```

Текущий оверлей поддерживает напоминания, созданные с положительным целочисленным `after_seconds`, с абсолютной целью `at` или с интервалом фиксированной частоты `every_seconds` не короче 300 секунд. Модель управляет ими через `schedule_create`, `schedule_list` и `schedule_delete`; каждый результат помечает доставку как `session-local`.

Браузер прикладывает свою зону IANA к каждому промпту. Контекст времени велит модели интерпретировать даты и времена без явного указания зоны в зоне браузера данного запроса. Это допущение касается только интерпретации естественного языка: `schedule_create.at` должен быть либо строгой датой-временем RFC 3339 с `Z` или числовым смещением, либо `{ date, time, time_zone }` с явной зоной `UTC` или IANA Area/Location. Schedule не хранит и не выводит зону по умолчанию для Session. Разрывы перехода на летнее время отвергаются, при перекрытиях выбирается первый момент, а успешные записи сохраняют только итоговую цель в UTC.

Каждым напоминанием владеет журнал исходной Session. Живой корневой Agent дожидается полной незанятости, затем ставит в очередь обычный последующий ход в той беседе. Он никогда не вмешивается в текущую работу и не добавляет отдельной квитанции или карточки напоминания. Закрытие процесса или охлаждение Session останавливает её таймер в памяти, не удаляя запись; повторное открытие той же Session восстанавливает ожидание и доставляет просроченное напоминание. Чтение холодной истории никогда его не активирует, а fork не наследует напоминания родителя.

Все напоминания остаются привязанными ко времени своего создания. Если одно просрочено, показывается только его последняя наступившая итерация, а следующая цель остаётся на исходной последовательности фиксированной частоты. Все различные записи Every, просроченные к одному решению о незанятости, объединяются в один последующий ход — по одной итерации каждая; пропущенные интервалы не создают накопления долга. Наступившие однократные напоминания исполняются перед этой пачкой. Выражения Calendar и Cron не поддерживаются.

Операции создания и фактического удаления подтверждают успех только после того, как персистентность Session подтвердит их префикс событий. Schedule не предоставляет уведомлений через браузер, операционную систему, электронную почту, SMS или иной внешний канал. Долговременная запись отправки фиксирует, что последующий ход был поставлен в очередь; она не подтверждает успех модели или получение пользователем.
