# @deepseek-ai/dsh-api-gateway

[English](README.md) | [中文](README.zh.md) | Русский

Двусторонний Typert RPC-эндпоинт для окружений Cordis Host и Client. Вход Host предоставляет `ctx.typertGateway`, а `@deepseek-ai/dsh-api-gateway/client` предоставляет `ctx.remote`; оба используют один и тот же сгенерированный контракт `InvocationDescriptor`, отдавая выбор бизнес-методов API Remotes, а транспорт, корреляцию запросов, доверие и конверты ответов — Connection.

## Сервис хоста: `TypertGatewayService` (ключ ctx: `typertGateway`)

`ctx.typertGateway.invoke()` для каждого вызова разрешает текущий дескриптор и Cordis Service, валидирует точные именованные аргументы, разрешает зарегистрированные идентичности объектов или Context, вызывает публичный бизнес-метод и валидирует его результат. Бизнес-сервисы наследуют `TypertRemoteService` и помечают методы `@Remote` или `@RemoteScope` из [`dsh-typert-protocol`](../../typert/protocol/README.md); `bindTypertRemote()` остаётся доступным, когда наследование принадлежит другому базовому классу.

Строгий режим читает сгенерированные дескрипторы вызовов из `ctx.typert.local`. Lookup-параметры пользуются активным в данный момент резолвером из `ctx.typert.lookups`: бизнес-пакет регистрирует стабильную декларацию и политику по умолчанию, а композиция Host может перекрыть поведение разрешения эффект-scoped `configure()`; `@RemoteScope` разрешает целевой объект через зарегистрированный провайдер Host Context. Режим SRC — запасной путь разработки для эндпоинтов, никогда не имевших строгого определения; он разбирает простые имена параметров и принимает только JSON-безопасные значения не-lookup параметров. Отзыв наблюдаемого строгого определения отказывает, а не ослабляет валидацию.

Вход Host регистрирует доверенный хостовый перехватчик на общем FetchHandler `/api` у Connection. Connection проводит этот составной обработчик через свой HTTP-мост; обработчик направляет заявленные эндпоинты в Gateway, а незаявленные — в API Proxy. Прямые вызовы `invoke()` сохраняют бизнес-ошибки; `TypertGatewayError` различает отказы, принадлежащие диспетчеризации, привязке, провайдерам, lookup, Context, аргументам и кодекам. Резолвер может воспользоваться `TypertLookupFailure`, чтобы передать существующую RPC-ошибку, сохраняя её исходный код ошибки для отклонений политики вроде сбоев холодного возобновления или ограждений владения.

Remote-метод с поддержкой отмены объявляет `signal: AbortSignal` своим последним параметром на стороне Host. Сигнал — метаданные дескриптора, а не аргумент протокола: Connection подаёт его Gateway, а Gateway инъецирует его после декодированных бизнес-параметров. SRC узнаёт зарезервированное последнее имя, а строгая генерация дополнительно требует глобального типа `AbortSignal`.

## Сервис клиента: `ClientRemote` (ключ ctx: `remote`)

`ctx.remote.$mount()` валидирует и регистрирует сгенерированный вклад Host-for-Client, затем устанавливает конкретные прямые и скоупед-методы для вызывающего fiber Cordis. Каждый неймспейс — отслеживаемый дочерний сервис `remote.<namespace>` и разгружается после отзыва последнего своего метода. Дублирующиеся эндпоинты, столкновения неймспейсов и дескрипторы без строгих сгенерированных кодеков отказывают прежде, чем методы станут вызываемыми.

Каждый вызов валидирует позиционные входы, строит точные именованные `args` дескриптора и отправляет их через `ctx.connection.rpc.call('/api', endpoint, ...)`. Генерированные методы с поддержкой отмены принимают последний необязательный `AbortSignal`; Client комбинирует его со временем жизни mount вклада, прежде чем вызывать Connection. Возвращённое значение валидируется, прежде чем попасть в код приложения. Отзыв вклада снимает его дескрипторы и методы вместе, прерывает незавершённые вызовы и заставляет удерживаемые хендлы методов отказывать.

`ctx.remote.$on()` подписывается на одно пересылаемое событие Host. Его законные ключи — в точности выбор пересылки сборки Host, а тип слушателя — собственная декларация Cordis `Events` владеющего пакета, так что вторая сигнатура от неё не уплывёт. Каждая подпись принадлежит вызывающему fiber и исчезает вместе с ним. Доставка односторонняя и следует порядку регистрации; бросающий слушатель логируется и изолируется от остальных слушателей, что никогда не задевает цикл обработки кадров. `ctx.remote.$dispatch()` — вторая половина этой поверхности, и она принадлежит carrier: половина Client, владеющая приёмником кадров Host, передаёт каждый декодированный кадр дальше, а имя события, на которое никто не подписан, отбрасывается — при передаче переносится всё, что выбрал Host. Потребитель подписывается и никогда её не вызывает.

Генерированные слияния деклараций дают TypeScript API через общий контракт `TypertClientRemote`. Вход Client не содержит ни Host-сервиса, ни слияния Host Cordis-интерфейса, а поиск и вызов методов пользуются обычными объектами и функциями вместо JavaScript Proxy.

## Model Experience

Никакого: пакет диспетчеризует прикладные вызовы и не регистрирует ни промпта, ни инструмента, ни события сессии.

#### KV Cache effect

Прямого эффекта нет; вызываемые бизнес-сервисы владеют любым видимым модели результатом.

## Известные ограничения и отложенная работа

- Адаптер Connection отображает обычные отказы диспетчеризации и бизнес-исключения на RPC-код `internal` с пустыми деталями; ошибки lookup-политики, передаваемые через `TypertLookupFailure`, возвращаются без изменений. Структурированные категории `TypertGatewayError` остаются доступными только внутрипроцессным вызывающим.
- Режим SRC поддерживает параметры, являющиеся уникальными идентификаторами, без деструктуризации, умолчаний и rest-параметров. Он валидирует JSON-безопасность, а не сгенерированные бизнес-типы, и никогда не выводит необязательные поля.
- На клиентскую сторону монтируются только строгие сгенерированные вклады. У SRC-маркеров нет клиентского кодека и проекции типов.
- Пакет диспетчеризует только унарные методы. Инкрементальные данные Session передаются отдельным протоколом именованных потоков поверх той же Connection.
- Lookup-резолверы настраиваются по ключу; отдельный Remote-параметр или эндпоинт пока не может выбрать политику live-only под тем же ключом `agent`/`session`.
- Пересылаемые события доходят до `$on` ровно такими, какими Host их выпустил: без проекции полезной нагрузки и её редактирования, без подписок, привязанных к Scope, и без повтора после переподключения.
