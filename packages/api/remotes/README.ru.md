# @deepseek-ai/dsh-api-remotes

[English](README.md) | [中文](README.zh.md) | Русский

Двусторонний BFF для Host Remote-возможностей, отобранных этим приложением. Хостовая точка входа владеет политикой идентичности Agent/Session; клиентская точка входа импортирует сгенерированные артефакты `/remote` как рантаймные значения, монтирует каждый вклад через `ctx.remote.$mount()` и реэкспортирует их слияния объявлений. Клиентские бизнес-пакеты зависят от этого фасада, а не от реализации шлюза или отдельных рантаймных точек входа Remote.

`createApiRemoteAgentResolver()` переиспользует живых агентов, возобновляет обычные холодные сессии, дедуплицирует параллельные возобновления, сохраняет ограждение владения субагентами и настраивает один и тот же резолвер для Typert-поиска `agent` и `session`. Стандартный Web API Proxy поставляет его значения по умолчанию для агентов и настройку scope, а затем использует возвращённый резолвер для унаследованных методов, так что перенесённые и неперенесённые методы разделяют одну реализацию политики.

Текущая клиентская сборка монтирует вклад Goal Remote и вклад read-only-инвентаря плагинов хоста (`pluginInventory/list`). Владение эффектами в Cordis отзывает каждый вклад при выгрузке этой сборки, тогда как `@deepseek-ai/dsh-api-gateway/client` владеет валидацией дескрипторов, трассируемыми сервисами пространств имён, прямыми и скоупированными методами, вызовом и отменой. Клиентская точка входа потребляет общий интерфейс `TypertClientRemote` через Cordis и не импортирует конкретный шлюз. Она реэкспортирует слияния объявлений клиентской стороны шлюза только на уровне типов, поэтому потребитель, достигающий словаря перенаправляемых событий через этот фасад, не получает рантаймной связи с реализацией шлюза.

Этот пакет не содержит логики транспорта или обнаружения сервисов хоста. Его клиентскую сторону могут переиспользовать Web или будущий TUI, предоставляющие тот же не зависящий от React контракт `ctx.remote`.

## Перенаправляемые события хоста

`src/remote-events.ts` хранит `API_REMOTE_FORWARDED_EVENTS` — белый список cordis-событий хоста, которые это приложение перенаправляет потребителям дословно, без проекции, без цензуры и без переименования, а потому и допустимый набор ключей `ctx.remote.$on`; содержащий только типы `src/types.ts` выводит из него свою выбирающую сторону. Перенаправить ещё одно событие — значит добавить запись в этот массив и ничего больше: типовая проекция, ключевая сторона потребителя и хостовый цикл перенаправления все выводятся из него.

Сигнатура слушателя здесь не повторяется. Cordis-объявление `Events` каждого события из белого списка живёт в безопасном для клиента экспорте `./types` своего пакета-владельца (`dsh-agent-presets`, `dsh-commands`, `dsh-credentials`, `dsh-llm`, `dsh-settings`), и обе стороны этого пакета подтягивают эти объявления, так что «перенаправляется дословно» выполняется по построению, а не по доказательству. Хостовая сторона дополнительно проверяет список по `TypertForwardableEvent`, который отвергает имя, не являющееся объявленным событием, имя, привязывающее AgentScope, и событие, чья форма не однонаправленна.

## Граница сборки

Обычный пакет репозитория принадлежит одной стороне TypeScript: хостовые пакеты регистрируются в корневом `tsconfig.host.json`, клиентские — в корневом `tsconfig.client.json`. `api-remotes` — единственное сознательное исключение: его хостовая точка входа обязана участвовать в Typert-графе хоста, а `src/client/index.ts` не может скомпилироваться, пока хостовый tsdown не сгенерирует `/remote`-объявления бизнес-пакетов.

Корневой `tsconfig.json` этого пакета — только solution, ссылающийся на `tsconfig.host.json` и `tsconfig.client.json`. Хостовый агрегат и прямые хостовые потребители ссылаются на первый, клиентский агрегат и прямые клиентские потребители — на второй; solution в корне пакета не должен попадать в граф зависимостей ни одного из агрегатов. Два проекта владеют непересекающимися исходными файлами и файлами `.tsbuildinfo`, но разделяют выходной каталог `lib/types` с одним сознательным исключением: `src/remote-events.ts` и `src/types.ts` перечислены в `files` ОБЕИХ сторон, потому что белый список перенаправляемых событий — единственная точка контроля над тем, что может получать потребитель, а хостовому циклу перенаправления и ключевой стороне `ctx.remote.$on` клиента нужно читать одно объявление, а не два, способных разойтись.

Это исключение — не просто запись в `files`. Корневой `tsconfig.base.json` отображает `@deepseek-ai/dsh-api-remotes/types` на `src/types.ts` — исходную плоскость, как и всякий другой subpath рабочего пространства, в отличие от сгенерированных артефактов `/remote`, у которых записи в `paths` нет и которые резолвятся через `exports` в собранный вывод. Обе стороны поэтому допускают один и тот же белый список и типовую проекцию в свои программы и выдают побайтово идентичные выводы `remote-events` и `types` в `lib/types`; файлы `.tsbuildinfo` остаются независимыми. Ни один гейт не проверяет непересечение исходных файлов сторон — `scripts/project-reference-faces.ts` проверяет лишь, что ссылка на разделённый проект называет соответствующую сторону, — поэтому этот абзац фиксирует, почему двойное перечисление сделано намеренно.

Локальный для пакета `clientBundle(..., { hostPhase: true })` заставляет хостовый tsdown собирать хостовую точку входа, а последующий клиентский tsdown — только браузерную точку входа. Обычные клиентские плагины остаются одиночными клиентскими проектами и производят и свою Node-точку входа загрузчика, и браузерный бандл во время клиентского tsdown; не копируйте разделение этого пакета лишь потому, что у пакета есть и `src/index.ts`, и `src/client/index.ts`.

## Влияние на модель

Отсутствует: этот BFF выбирает прикладные методы Remote и политику идентичности, но не регистрирует ничего обращённого к модели.

#### Влияние на KV-кэш

Прямого влияния нет; смонтированные хостовые возможности владеют любым видимым модели поведением, которое сами запускают.

## Известные ограничения и отложенная работа

- Набор возможностей зафиксирован явными value-импортами времени сборки; клиент не обнаруживает активные сервисы хоста или определения Remote в рантайме.
- Дополнительные возможности требуют явного value-импорта `/remote` и монтирования в этой сборке.
- Стандартный веб-хост поставляет значения по умолчанию для возобновления и настройку Agent-scope из унаследованного API Proxy, пока оставшаяся конфигурация BFF не перенесена в `api-remotes`.
