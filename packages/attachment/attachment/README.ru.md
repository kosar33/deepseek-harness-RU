# @deepseek-ai/dsh-attachment

[English](README.md) | [中文](README.zh.md) | Русский

Capability seam долговечных вложений. `ctx.attachments` валидирует и долговечно фиксирует нормализованное изображение, независимое от провайдера, а затем возвращает сериализуемый `ImageAttachmentRef`; потребители никогда не сохраняют в событиях сессии браузерные пути, object URL, URL провайдеров или base64.

Неотправленные изображения композера остаются временными черновиками во владении браузера. `validateImage` выполняет полную политику допуска, ничего не сохраняя. `saveImages` владеет лимитами на число элементов в пакете и суммарный объём байтов, готовит каждое нормализованное вложение до публикации любого из них, затем фиксирует по порядку и возвращает ссылки лишь после успешного завершения всего пакета. Последующий сбой хранилища не возвращает частичных ссылок, хотя ранее созданный неизменяемый объект с адресацией по содержимому может остаться недостижимым, пока не появится учитывающая ссылки сборка мусора. `AttachmentError.code` использует закрытое строковое объединение `AttachmentErrorCode`. Его подмножество `ImageAdmissionErrorCode` помечает ошибки входных изображений, исправимые вызывающей стороной; `isImageAdmissionError` распознаёт это подмножество в рантайме, чтобы каждый протокольный адаптер мог отобразить его на собственный набор ошибок. `saveImage` фиксирует одно принятое изображение до публикации любого видимого модели события сессии и возвращает его `ImageAttachmentRef`. Когда нормализация уменьшает растр, ссылка записывает применённый с учётом ориентации исходный размер в `originalDimensions`. `readImage` сверяет нормализованное вложение с записанными в журнале метаданными. `readImageRequest` детерминированно порождает версию запроса для конкретного маршрута, идентичность которой охватывает идентификатор вложения, версию преобразования, пиксельный и байтовый бюджеты и настройки энкодера. Вызывающие стороны составляют упорядоченные пакеты через `Promise.all(refs.map(...))`; локальная реализация при этом по-прежнему ограничивает сжатие собственным лимитером экземпляра, кэшем и singleflight. Вызывающие стороны могут отменять чтения и проекции; реализации сохраняют отмену, а не превращают её в сбой хранилища.

`admitEncodedImages(attachments, images)` — общая точка входа уровня протокола, которую использует каждый RPC-эндпоинт, принимающий загрузки из браузера (эндпоинт промпта сессии и исполнитель команд): она требует канонический base64 у каждого элемента, а затем делегирует пакетный допуск — лимиты, валидацию, упорядоченную фиксацию — в `saveImages`. Форма загрузки base64 — `EncodedImageAttachment`, экспортируемая из `@deepseek-ai/dsh-attachment/types`, чтобы контракты протокола могли ссылаться на неё.

## Model Experience

Опосредованно — через нейтральный к ролям базовый `ImageBlock` и адаптеры провайдеров, которые разрешают его долговечную ссылку в точную версию запроса. Дескрипторы запросов раскрывают полный идентификатор вложения и фактические размеры запроса.

#### KV Cache effect

Добавление изображения меняет запрос к провайдеру и потому инвалидирует затронутый суффикс запроса.

## Известные ограничения и отложенная работа

- Первая версия принимает только PNG, JPEG, WebP и GIF.
- Удержание и сборка мусора отложены, поскольку возобновлённые сессии и их fork-копии могут разделять одни и те же неизменяемые объекты.
- Произвольные файлы, аудио, видео и постоянные неотправленные черновики требуют отдельных контрактов жизненного цикла и провайдеров.
