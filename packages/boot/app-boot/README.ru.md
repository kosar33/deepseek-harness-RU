# `@deepseek-ai/dsh-app-boot`

[English](README.md) | [中文](README.zh.md) | Русский

Общий загрузочный клей для бинов приложений ([`dsh`](../../../apps/cli/README.md) и [`dsh-acp-demo`](../../examples/acp-demo/README.ru.md)): каждый бин — тонкая самоисполняющаяся композиция поверх этих хелперов, параметризованная собственным диагностическим префиксом, так что поведение при отказе загрузчика имеет одного владельца вместо расползания между публикуемыми артефактами.

| Export | Role |
|---|---|
| `resolveConfigPath(path, snapshotMode, cwd?)` | Абсолютный путь к конфигурации; `snapshotMode === 'replay'` подменяет базовое имя `cordis.yml`/`.yaml` на соседний `cordis.snapshot.yml` |
| `loadEnv(binName, dir?, warn?)` | Загружает игнорируемый git-ом `.env` (через Node `process.loadEnvFile`); отсутствие файла допустимо, а незагружаемый предупреждает одной помеченной строкой (по умолчанию: stderr) |
| `loadLayeredEnv(binName, cwd?, warn?)` | Строит замороженный снапшот слоёв окружения продуктового CLI — унаследованное окружение > проектный `.env` > пользовательский `.env`, отвергает bootstrap-only переменные из файлов и материализует принятые файловые значения, не подменяя унаследованных |
| `installFailLoud(binName, proc?, release?)` | Превращает необработанный отказ при загрузке или поздний отказ Loader в одну помеченную строку stderr + `exit(1)`; необязательная разборка `release` ожидается между этими двумя шагами (с ограничением `FAIL_LOUD_RELEASE_TIMEOUT_MS`), чтобы владеющая терминалом поверхность восстановила терминал до выхода; возвращает функцию снятия обработчика |
| `FAIL_LOUD_RELEASE_TIMEOUT_MS` | Сколько `installFailLoud` ждёт свой hook `release`; зависший диспетчер освобождения задерживает фатальный выход, но никогда не отменяет его |
| `assertEntriesLoaded(ctx, binName)` | Бросает исключение, когда осевшее дерево хранит включённую запись без fiber, перечисляя каждое неразрешённое имя плагина как загрузочную ошибку Cordis |
| `assertEntriesActivated(ctx, binName)` | Включает проверку `assertEntriesLoaded`, а затем ожидает каждую включённую запись после того, как осядет Loader; бросает исключение с оригинальным стеком каждого отказавшего плагина либо с неразрешёнными сервисами каждого ожидающего плагина |
| `loadOptionalPatches(binName, file)` | Разбирает необязательный файл списка патчей (`cordis.patch.yml` профиля) — верхнеуровневый YAML-массив включаемых `PatchOptions` (перезаписи конфигурации по id, списки `insert`, разрешён `!!js`); отсутствующий файл даёт `undefined`, нечитаемый/неразбираемый/не-массивный файл бросает исключение |
| `loadOverlayPatches(binName, file)` | Разбирает обязательный верхнеуровневый YAML-массив с теми же включаемыми `PatchOptions`, что описаны выше; отсутствие файла тоже бросает исключение, потому что вызывающий назвал его явно |
| `mountRootInclude(ctx, absoluteConfigPath, patches?, bareModuleBaseUrl?)` | Регистрирует статически импортированные встроенные `cordis:include` и `cordis:group`, монтирует include и сохраняет точную корневую запись, которую использует HMR пользовательских патч-слоёв; необязательная база модулей якорит bare-имена пакетов к установленному хосту, тогда как относительные имена остаются относительно конфигурации |
| `watchUserPatches(ctx, options)` | Регистрирует именованный файл патчей в существующем HMR-сервисе Cordis; каждая транзакция add/change/removal пересобирает весь список патчей через замыкание `compose` вызывающего (принадлежащие приложению слои вокруг текущего пользовательского слоя) и возвращает асинхронный диспозер |
| `resolveProfileDir` / `initProfile` / `loadProfile` / `readProfileManifest` / `writeProfileManifest` / `resolveBundleDir` / `composeEntries` / `healProfilesModuleFallback` / `PROFILE_TEMPLATES` / `DEFAULT_PROFILE_BUNDLES` / `PROFILES_DIR` / `PROFILE_PATCH_FILENAME` | Механика профилей (см. [Профили](#профили)) |
| `boot(binName, absoluteConfigPath, patches?, prepare?, bareModuleBaseUrl?)` | Создаёт корневой контекст, открывает `dshHomePath(...segments)` для конфигурационных выражений `!!js` Loader, устанавливает Loader, выполняет необязательную хостовую подготовку до монтирования записей конфигурационного дерева (`prepare` может пользоваться Loader и предоставлять принадлежащие лаунчеру slot'ы контекста), затем монтирует и ожидает include-дерево, проверяет, что записи загружены и активированы, и возвращает корневой контекст — либо освобождает частичный контекст и отклоняется с помеченной ошибкой; необязательная база модулей имеет ту же семантику разрешения, что и `mountRootInclude` |
| `renderConfigDump(binName, absoluteConfigPath, layers, warn?)` | Автономно собирает базовую конфигурацию и помеченные оверлей-слои собственным парсером include и его патч-алгоритмом (`entryListSchema`/`applyEntryPatches`), так что результат равен тому, что монтирует `boot()`, и рендерит YAML с выражениями `!!js` дословно; перед каждым прогоном строк с одним исходным файлом и теми же патч-слоями ставится комментарий `# ==`, называющий этот файл и эти слои, чтобы вывод оставался одним загружаемым документом; патч, не совпавший ни с одной строкой, уходит в `warn` с меткой своего слоя (по умолчанию: одна строка stderr), а ошибки чтения, разбора или валидации полей бросают исключение |
| `addHarnessSourceSection(ctx, sourceRoot)` | Добавляет глобальную секцию промпта `harness:source` (упорядоченную сразу после идентичности harness, перед персоной), сообщающую агенту путь на диске к checkout'у реализации DSH и предупреждающую не выводить текущий рабочий каталог из этого пути, а использовать `pwd`; no-op, возвращающий `undefined`, если в загруженном дереве нет сервиса `systemPrompt`. Секция регистрируется против fiber этого сервиса, поэтому dev-HMR-перезагрузка системного промпта снимает её до следующей загрузки |
| `HARNESS_SOURCE_SECTION` | Имя секции `'harness:source'`, под которым её регистрирует `addHarnessSourceSection` |

Оседание Loader отклоняет отказы импорта и жизненного цикла вместе с отказавшей записью и этапом; `boot()` освобождает частичный контекст и оборачивает этот отказ именем бина. Оставленное оседанием записей аудит разбирает отдельно: `assertEntriesLoaded` превращает включённую запись без fiber в отклонение, называющее каждый неразрешённый плагин, а `assertEntriesActivated` ожидает каждую отказавшую fiber, чтобы включить её оригинальный стек в отклонение запуска, и называет неразрешённые сервисы каждой ожидающей записи. Перед броском аудит помечает эти точные причины отклонения через один чекпоинт процесса, поэтому `installFailLoud` схлопывает дублирующее уведомление Loader, тогда как каждый не относящийся к делу необработанный reject остаётся фатальным.

Loader монтирует записи параллельно, поэтому поверхность уже может владеть терминалом, когда отказывает что-то другое: выход без собственной разборки дерева оставил бы на shell пользователя включёнными raw-режим, bracketed paste и клавиатурный протокол, а ответ на незавершённый терминальный запрос упал бы буквальным текстом в следующем промпте. Отказ конфигурационного дерева оседает через `boot()`, чьё освобождение частичного контекста выполняет собственное выключение поверхности до помеченного отклонения. Для отклонений, которых `boot()` не видит, — отвалившейся асинхронной работы плагина, отвергающейся во время монтирования или после него, — владеющий терминалом бин передаёт `release`, чтобы разобрать дерево прежде, чем выход свершится; `dsh` захватывает корневой контекст в hook'е `prepare` функции `boot()`, а не из её возвращаемого значения, поэтому hook покрывает всё окно монтирования. Пока release в полёте, обработчик остаётся установленным и защёлкнутым: первым сообщается первое отклонение, а поздние (включая собственные ошибки разборки) проглатываются вместо того, чтобы стать необработанными и убить процесс посреди разборки.

`cordis:group` регистрируется рядом с `cordis:include`, чтобы композиция могла отдать один realm `isolate` провайдеру и его потребителям вместе. Оба грузятся через ambient-конвейер модулей, а не через собственное разрешение спецификаторов включаемого дерева, — именно это позволяет композиции вне этого workspace, например агентскому пресету под домашним каталогом Harness, вообще использовать строку group.

Bare-спецификаторы плагинов в конфигурации (`@deepseek-ai/dsh-*`, npm-пакеты) разрешаются через внутренний загрузчик модулей Cordis Loader. По умолчанию они разрешаются от каталога конфигурации; замкнутый рантайм передаёт `bareModuleBaseUrl` в `boot` или `mountRootInclude`, чтобы его установленное дерево пакетов оставалось авторитетным, даже когда конфигурация живёт внутри другого Node-проекта. Относительные спецификаторы всегда разрешаются относительно каталога конфигурации. Бины репозитория устанавливают необязательную peer-зависимость Loader `node-addon-require-builtin`; внешние вызывающие должны сами предоставить её или установить плагины там, где обычное разрешение импортов Node их найдёт. Собранный артефакт `dsh-app-boot` встраивает статически смонтированную реализацию Include, оставляя Loader внешним, поэтому include-дерево и хост связываются с одной peer-зависимостью Loader. Путь исходников `pnpm dsh` дополнительно отображает объявленные в манифесте workspace-пакеты на их TypeScript-исходники; его конфигурационный гейт требует, чтобы каждый поставляемый raw/Web bare-плагин фигурировал в `dependencies` резолвер-манифеста.

Этот пакет не несёт ни хуков загрузчика, ни поверхности dev-режима. Приложение [`dsh`](../../../apps/cli/README.md) владеет своим Node-хуком запуска из исходников и потребляет эти хелперы для загрузочной последовательности; собранные потребители продолжают пользоваться обычным разрешением пакетов Node.

## Профили

Профиль — это каталог под `$DSH_HOME/profiles/<name>` (домашний каталог Harness разрешается через [`resolveDshHome`](../../util/home-paths/README.md): `$DSH_HOME`, иначе `~/.dsh`), хранящий `package.json` — вне-деревные `dependencies` плагинов плюс манифест профиля `dsh.profile` с его упорядоченным списком слоёв `bundles` — и собственный `cordis.patch.yml` пользователя. Бандл — это npm-пакет, чей манифест объявляет `"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }`; `loadProfile` разрешает каждое имя из `dsh.profile.bundles` с двумя якорями (сначала установка dsh, затем каталог профиля) и отказывается с явной ошибкой, если перечисленный пакет не несёт объявления бандла. `composeEntries` применяет патч-слои к пустому списку записей через собственный `applyEntryPatches` include, поэтому композиция, вывод флагов и дампы конфигурации не могут разойтись с тем, что грузится. `healProfilesModuleFallback` поддерживает плоский каталог `$DSH_HOME/profiles/node_modules` — по одному symlink на пакет, от которого зависят приложение установки и бандлы, — поэтому bare-имена плагинов в любом профиле разрешаются обычным родительским обходом Node, без управления внутрикоробными пакетами со стороны pnpm. `PROFILE_TEMPLATES` (`web`, `headless`) автоинициализируются при первом использовании; прочие имена отказывают с явной ошибкой, пока `initProfile` их не создаст (путь `dsh plugin`). `loadProfile` нормализует точный принадлежащий установке кортеж бандлов к его поставляемому шаблону, сохраняя все прочие поля манифеста; любой лишний, отсутствующий или переставленный элемент делает список пользовательским и оставляет его нетронутым.

Пользовательские машинно-локальные настройки тоже живут в домашнем каталоге Harness:

- **`.env`** — обычные слои окружения продуктового CLI: файл вызывающего каталога старше файла домашнего каталога Harness, а оба стоят ниже унаследованного окружения. `loadLayeredEnv` фиксирует источник каждого значения, регистронезависимо отвергает [bootstrap-only файловые переменные](../../../.agents/notes/implemented/architecture/2026-08-04-configuration-source-ownership.md#decision) и материализует принятые значения в `process.env` для выражений Loader и сторонних библиотек. Управляемые учётные данные живут отдельно в [`.credentials.yaml`](../../credentials/credentials-local/README.md); учётные данные, оставленные в любом из `.env`, остаются fallback'ом с более низким приоритетом.
- **`cordis.patch.yml`** (уровень дома) и **`profiles/<name>/cordis.patch.yml`** — пользовательские патч-слои, применяемые после каждого слоя бандлов (сначала пер-профильный, затем файл уровня дома, который поэтому старше): патч, нацеленный на id, заменяет весь `config` названной записи (перечислите неизменённые поля заново), `insert` добавляет записи, а выражения `!!js` интерполируются при монтировании. Патч, называющий id записи, отсутствующей в собранном дереве, — это предупреждение в stderr. Пустой или состоящий из одних комментариев файл бросает исключение (он разбирается в ничто, а не в список); отключите слой значением `[]`.

Каждая загрузка профиля держит `cordis.patch.yml` живым через `watchUserPatches` (одноразовая поверхность освобождает наблюдателя через свою ограниченную разборку). Наблюдатель следит за точным путём, даже когда файла или непосредственного родителя не существует, сериализует всплески событий и пересобирает пользовательские патчи внутри порядка слоёв вызывающего (слои бандлов снизу, оверлеи сверху). Отвергнутое чтение, разбор или кандидат Loader оставляет работать последнее хорошее дерево, а HMR-сервис после журналирования рассылает `hmr/config-update-failed(filename, Error)`; отказы наблюдателей локализуются. Освобождение контекста закрывает наблюдателя и дожидается активного обновления.

## Model Experience

Косвенно — через дерево плагинов, которое он загружает и которое определяет промпты, схемы, сообщения и адаптер модели в получившемся приложении; единственный экспорт, добавляющий видимый модели текст, `addHarnessSourceSection`, делает это только когда потребитель вызывает его после загрузки.

#### KV Cache effect

Прямой инвалидации из `boot()` нет; потребитель, вызывающий `addHarnessSourceSection`, помещает одну короткую строку возле головы системного промпта, до контента каждого запроса, поэтому кэш между ходами не инвалидируется, а любое другое изменение префикса запроса принадлежит названному потребителю.

## Известные ограничения и отложенная работа

- **Bare-спецификаторы пакетов зависят от внутренностей Loader** — продуктовым бинам нужна необязательная нативная помощь Loader; вызывающий внутри процесса без неё должен использовать разрешимые относительные/файловые спецификаторы или предоставить собственный хук разрешения модулей.
- **Подмена при воспроизведении снапшота привязана к базовому имени** — только конфигурация, оканчивающаяся на `cordis.yml` или `cordis.yaml`, отображается на соседний `cordis.snapshot.yml`; пользовательские имена конфигураций требуют выбора силами вызывающего.
- **Обнаружение окружения ограничено запуском** — `loadLayeredEnv` читает только каталог вызова и домашний каталог Harness и лишь однократно; он не ищет в родителях и не следует за workspace, выбранным позже. `loadEnv` остаётся однокаталожным хелпером для непродуктовых бинов.
- **Пользовательский патч заменяет всю совпавшую конфигурацию** — патч, нацеленный на id, не выполняет deep-merge, поэтому профильное переопределение заново перечисляет сохраняемые им поля бандла.
