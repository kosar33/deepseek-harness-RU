# `@deepseek-ai/dsh-cmdline`

[English](README.md) | [中文](README.zh.md) | Русский

Командная строка, которую лончер dsh передаёт запускаемому им приложению. Лончер разбирает только собственные флаги (`--profile`, `--patch`, дампы конфигурации) и передаёт **всё, что следует после них**, дереву дословно, поэтому приложение владеет своим семейством флагов, текстом `--help` и ошибками разбора, а не лончер знает их за него.

## Значения от лончера

Лончер вызывает `provideCmdline(ctx, host)` до монтирования любой записи дерева; это даёт:

- `ctx.cmdlineArgs` — внутренние аргументы вызова. `get()` — весь интерфейс, и он возвращает снапшот: `dsh --profile tui --resume abc` даёт `['--resume', 'abc']`.
- `ctx.appExit` — ограниченный запрос завершения процесса, подключённый к контроллеру выключения лончера.

Встраивающий хост без командной строки даёт пустой список; это честный ответ, а не отсутствующее значение.

## Обычные провайдеры и внедряемая конфигурация

Любой плагин приложения может внедрить `cmdlineArgs`, разобрать его и опубликовать обычный сервис, принадлежащий приложению. `parseCmdline(ctx, program)` — лишь адаптер commander; валидацией и публикуемым сервисом владеет собственное action программы:

```ts ignore
export const name = 'web-startup'
export const inject = ['cmdlineArgs']

export function apply(ctx: Context): void {
  const program = webCommand()
  program.action(() => ctx.provide('webStartup', webValuesFrom(program)))
  parseCmdline(ctx, program)
}
```

Его строка в Loader не несёт маркера лончера или особого вида:

```yaml
- id: web-startup
  name: '@deepseek-ai/dsh-web-app/startup'
```

Каждая строка, конфигурируемая из этих значений, использует обычное внедрение сервисов и прямой ленивый доступ к конфигурации:

```yaml
- id: webserver
  name: '@deepseek-ai/dsh-host-webserver'
  inject: [webStartup]
  config:
    host: !!js ctx.webStartup.host ?? '127.0.0.1'
    port: !!js ctx.webStartup.port ?? 3080
```

`parseCmdline` отвергает при загрузке программу, в которой ни одна команда не объявляет action, маршрутизирует выход и вывод каждой команды через лончер (commander копирует эти настройки в подкоманды только при регистрации) и разбирает неизменяемые аргументы; при успехе commander исполняет синхронное action вызванной команды. Action отвергает некорректный вызов через `program.error(...)` — до публикации, ведь операторы до отказа уже выполнены. При `--help`, `--version`, ошибке разбора или этом отказе хелпер пишет текст commander и запрашивает завершение; провайдер ничего не публикует, поэтому зависимые строки никогда не активируются.

### Как внедрение упорядочивает конфигурацию

Loader откладывает интерполяцию `!!js` строки до момента, когда активны объявленные этой строкой внедрения, и затем вычисляет выражения в контексте плагина этой строки. Поэтому пример выше может читать `ctx.webStartup` напрямую: Cordis уже наполнил этот внедрённый сервис прежде, чем Loader запросит конфигурацию `webserver`. Деревья включений сохраняют вложенные узлы выражений, пока каждая целевая строка не достигнет этой точки. Замена провайдера и живая перезагрузка патча повторяют интерполяцию против текущих внедрённых сервисов, поэтому флаг запуска невозможно молча сбросить.

### Общие неизменяемые аргументы

`get()` не потребляет и не изменяет argv. Несколько плагинов могут разобрать один и тот же снапшот и независимо опубликовать сервисы. Лончер не ищет в композиции владельца командной строки; профиль без читателя просто игнорирует аргументы своего приложения.

Плагин вне дерева приносит собственную копию commander, поэтому управляющие ошибки commander распознаются структурно, а не по идентичности класса; проверка по идентичности превратила бы напечатанную справку в повторно брошенный фатальный сбой загрузки.

## Влияние на модель

Никакого: этот пакет резолвит собственную командную строку процесса до появления какой-либо сессии.

#### Влияние на KV-кэш

Никакого; этот пакет ни собирает, ни отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Флаги лончера обязаны предшествовать аргументам приложения.** Разделение позиционное: первый нераспознанный лончером токен открывает внутренние аргументы, поэтому `--patch`, стоящий после флага приложения, принадлежит приложению. Парсер лончера поглощает один `--`, поэтому аргумент приложения, который должен сохраниться литеральным `--`, требует `-- --`.
- **У сервиса, принадлежащего приложению, нет статически объявленного провайдера.** Потребляющие строки называют его обычным внедрением; бандл, опустивший его провайдера, падает при settlement с незакрытыми записями, называющими сервис, а не при загрузке.
- **Пользовательский патч, заменяющий весь `config` строки, теряет её выражения.** Флаг побеждает значение, записанное рядом с ним, но не литерал, подставленный пользователем вместо выражения; выражение сохраняется именно затем, чтобы флаг продолжал побеждать.
