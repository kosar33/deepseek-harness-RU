# `@deepseek-ai/dsh-base`

[English](README.md) | [中文](README.zh.md) | Русский

Общее ядро dsh в виде бандла профиля: [`cordis.patch.yml`](cordis.patch.yml) вставляет каждую базовую строку плагинов — адаптеры моделей, общий выбор [`agent-default-model`](../../core/agent-default-model/README.md), инструменты, персистентность, политики, настройки/учётные данные, телеметрию и стержневых провайдеров субагентов spawn/fork — поверх пустого корня профиля как первый слой списка `dsh.profile.bundles` каждого профиля. Опциональные провайдеры Codex и Claude Code остаются вне этого пакета и его замыкания production-зависимостей; профиль устанавливает любой из [бандлов продуктовых провайдеров](../../subagent/README.ru.md) только по необходимости. Производственное замыкание `@deepseek-ai/dsh` по умолчанию поэтому не включает ни одного продуктового провайдера, ни Claude Agent SDK, ни обёртки Codex с платформенными полезными нагрузками. Поздние слои бандлов (например, [`dsh-web-app`](../web-app/README.ru.md)) и пользовательский `cordis.patch.yml` профиля переопределяют эти строки по id; патч заменяет весь `config` строки целиком, поэтому специфичные для режима значения живут в бандлах режимов, а не здесь. У пакета нет рантайм-API; композитор профилей разрешает патч через поле манифеста `dsh.bundle.patch`, никогда через код.

Патч привязывает оба стека оболочки к платформе прямо на собственных строках: `bash-sandbox`/`tool-bash` несут `disabled: !!js process.platform === 'win32'` (у bash нет раннера для Windows), а их близнецы `pwsh-sandbox`/`tool-pwsh` монтируются на win32 только с обратным выражением — один общий файл патча, ровно один стек оболочки на хост. Поверхность разрешений остаётся в точности как на POSIX: `sandbox`/`sandbox-policy` обеспечивают соблюдение политики файловых эффектов через раннер ограниченного токена Windows ACL (win32-цепочка `dsh-sandbox-local` → `@deepseek-ai/dsh-sandbox-windows-acl`), переключатель разрешений и сервис подтверждений работают без изменений, а `fs-sandbox` продолжает ограждать записи `ctx.fs` — монтаж `dsh-fs-local` рядом с ним зарегистрировал бы `ctx.fs` дважды и сломал бы загрузку. Хост Windows, предпочитающий неограниченный локальный исполнитель pwsh или полный доступ, переопределяет эти строки через свой профильный или домашний `cordis.patch.yml` (рецепт возврата bash должен быть полным: отключить `pwsh-sandbox`/`tool-pwsh` И заново включить `bash-sandbox`/`tool-bash` — оба семейства исполнителей регистрируют один и тот же сервис `bash`, поэтому неполный рецепт падает с явной ошибкой при загрузке). Хосты POSIX видят строки pwsh отключёнными.

Состав строк и их обоснование задокументированы прямо в файле патча; [сгенерированный граф композиции](../../../apps/cli/composition.md) отображает его.

## Model Experience

Косвенно, через вставляемые строки: этот бандл выбирает поставляемую базу промпта без персоны, набор инструментов и адаптер DeepSeek, которые специализируют бандлы режимов, и сам не добавляет никакого видимого модели текста.

#### KV Cache effect

Напрямую — никакого; влияние принадлежит пакету каждой вставленной строки.

## Известные ограничения и отложенная работа

- **Патч заменяет конфигурации строк целиком** — переопределения профиля обязаны повторять каждое поле, которое хранит строка; слоя deep-merge нет.
- **Выдача временного каталога Windows — приватный подкаталог на сессию** — `workspace-write` ограничивает записи рабочей областью плюс собственным временным подкаталогом сессии (`<temp>\dsh-<hash>`, с переписанными TMP/TEMP для ограниченных дочерних процессов); `read-only` не выдаёт ничего. См. `@deepseek-ai/dsh-sandbox-windows-acl`.
