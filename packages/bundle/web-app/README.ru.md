# `@deepseek-ai/dsh-web-app`

[English](README.md) | [中文](README.zh.md) | Русский

Бандл браузерной поверхности dsh. [`cordis.patch.yml`](cordis.patch.yml) ложится поверх [`dsh-base`](../base/README.md): он задаёт coding-персону, вставляет строки Web-хоста (вебсервер, API-шлюз, workspace, кэш проекций, хранилище) и ростер браузерных плагинов, всегда включённую цепочку перезагрузки клиентских плагинов ([`dsh-client-hmr`](../../client/hmr/README.md), пребывающую в бездействии, пока вотчер пересборки не перепишет клиентские бандлы), и монтирует собственный клеевой плагин этого пакета `web-runtime` (конфиг `{openBrowser, printUrl, surfaceContext, trustedHosts}`). Этот плагин разрешает собранный dist фронтенда через exports пакета `@deepseek-ai/dsh-web-frontend`, единожды снимает зависящее от привязки LAN-доверие, отдаёт его как `webRuntime` ограде доверия браузера и ростеру клиентов, монтирует владельца фолбэка [`frontend-static`](../../host/frontend-static/README.md), а при истинном `surfaceContext` регистрирует секции промптов harness-source и web-surface плюс видимую bash переменную рантайма `DSH_WEB_URL`. Когда его дерево Loader устаканивается, он печатает строку URL `dsh web:` при истинном `printUrl` и открывает канонический URL хоста в браузере по умолчанию, когда истинен `openBrowser`, а унаследованные `SSH_CONNECTION` и `SSH_TTY` пусты или отсутствуют. Запуск по SSH сохраняет строку URL, но подавляет передачу браузеру, потому что локальным перенаправленным адресом владеет SSH-клиент или редактор. Непосредственно перед передачей рантайм печатает `dsh web: opening the default browser; pass --no-open to disable`. Короткоживущий Node-хелпер запускает поддерживаемый платформенный опенер с канонически вычищенным дочерним окружением. На Windows он живёт до выхода короткоживущего лаунчера PowerShell, потому что `open` сообщает о спавне раньше, чем тот лаунчер успел передать URL шеллу; в прочих системах хелпер останавливается, как только опенер принял спавн. Отказ хелпера пишет диагностику с его причиной и ручным URL в stderr, не останавливая сервер, и ни один путь не ждёт завершения браузера. Этот бандл также владеет командной строкой приложения: обычный провайдер `web-startup` ([`src/startup.ts`](src/startup.ts)) внедряет `ctx.cmdlineArgs` ([`dsh-cmdline`](../../boot/cmdline/README.md)), разбирает `--host`, `--port`, повторяемый `--trusted-host`, `--no-open` и `--help` приложения, затем предоставляет `webStartup`; открытие браузера по умолчанию включено для локальных запусков, а `--no-open` выключает его на это вызов. Он отвергает `--host 0.0.0.0` до публикации того сервиса, поскольку CLI пока намеренно не поддерживает привязку ко всем интерфейсам. Настраиваемые флагами строки внедряют сервис и читают его прямо из lazy-конфигурации, поэтому ничего не занимает порт до разрешения аргументов, и `dsh --profile web --help` не запускает сервер. [`dsh-headless`](../headless/README.md) — соседняя поверхность над той же базой; этот бандл она не монтирует.

## Дефолты повторных попыток модели

Web использует общий ограниченный обычный дефолт из пяти допустимых повторных попыток после начального запроса. Маршрут `deepseek-official` и добавленные через настройки маршруты pi-ai применяют этот дефолт, когда опускают `retryPolicy`; явные политики провайдеров всё равно побеждают. Web не добавляет специфичного для повторов переопределения композиции, поэтому то же поведение при опускании действует и в профилях без Web.

## Влияние на модель

### Контекст harness-source и Web-поверхности

#### Что видит модель

При истинном `surfaceContext` секция `harness:source` опознаёт лежащую на диске реализацию Harness, не утверждая, будто это рабочая директория, а глобальная секция `app:web-surface` (порядок −98) ориентирует модель в GUI: канонический локальный URL, референт «эта страница», контракт обновления (приёмник перезагрузки включён всегда; перезагрузка без обновления страницы дополнительно требует вотчера `pnpm run dev:web`) и указание не запускать замещающие серверы. Сверх того, `DSH_WEB_URL` появляется в управляемом bash-окружении со своим описанием, разрешаясь при каждом вызове из живого сервера. Когда `surfaceContext` ложен, не регистрируются ни секция, ни переменная.

#### Влияние на токены

Одна строка об источнике и один абзац промпта на сессию плюс две строки переменных управляемого окружения; константа на процесс.

#### Влияние на KV-кэш

Секция промпта располагается близко к голове системного промпта и стабильна всю жизнь процесса (порт — факт загрузки), поэтому не инвалидирует кэш между ходами.

## Известные ограничения и отложенная работа

- **Нет фолбэка с раздачей исходников** — dist фронтенда **ДОЛЖЕН** быть собран: `require.resolve` dist громко падает при активации с подсказкой о сборке.
- **`lanAddresses` — снимок момента загрузки** — изменения интерфейсов после загрузки не анонсируются заново; печатаемый LAN URL всегда соответствует настроенной ограде доверия.
- **Наблюдаем только старт передачи** — наблюдение заканчивается, когда платформенный опенер принимает спавн, исключение — Windows, где ожидается выход короткоживущего лаунчера PowerShell; последующий выход браузера не сообщается, а напечатанный URL остаётся ручным запасным вариантом.
- **URL браузера принадлежит SSH-перенаправлению** — печатаемый канонический URL называет endpoint loopback удалённого хоста; автоматическая передача подавляется, а SSH-клиент или редактор **ДОЛЖНЫ** показать и открыть свой локальный перенаправленный адрес.
- **Переопределения команды браузера действуют только при запуске** — обнаруженный `.env` не задаёт `BROWSER`; до пути опенера, чтящего эту переменную, может дойти лишь унаследованное значение, поэтому checkout не может выбрать исполняемый файл для автоматической передачи.
