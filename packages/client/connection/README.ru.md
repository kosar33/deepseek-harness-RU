# @deepseek-ai/dsh-client-connection

[English](README.md) | [中文](README.zh.md) | Русский

Слой протокольного потребителя: apply клиентского плагина монтирует `ctx.connection` (общий api-клиент + состояние loopback текущей страницы + наблюдаемое значение `hostDescription`, привязанное к поколению, + запускатель потокового цикла с единственным потребителем); экспортная грань несёт типы протокольного контракта, абстракцию `AbstractApiClient` и типы sink/config цикла. Каждое успешное рукопожатие готовности публикует точное значение `host.describe` до вызова `onConnected`; утрата поколения и явная остановка стирают его, так что потребители нативных возможностей никогда не удерживают ответ от отключённого соединения. Браузерный носитель использует HTTP POST для унарных операций и respond и открывает по одному WebSocket, работающему только на приём, для `events.mux` и `events.host`; внутрипроцессный носитель удовлетворяет той же абстракции двух потоков. Экспортируемый тип `ClientTransportHooks` называет глобальный объект страницы `__DSH_TRANSPORT__`, который заменяет браузерный носитель целиком: обслуживаемое веб-приложение оставляет его неустановленным и получает HTTP + WebSocket, а оболочка, владеющая другим физическим транспортом (postMessage-туннель предпросмотра в воркере), предоставляет `createApiClient` и `fetch` — плюс `loadBundle`, когда она владеет и байтами бандлов, — вместо того чтобы форкать плагин. Половина Host владеет единственным маршрутом `/api` и его Fetch-мостом; зарегистрированный перехватчик Typert отбирает свои Remote-эндпоинты до отката к API Proxy. Классификация имён хостов как loopback остаётся внутренним делом пакета: ограждение Host маршрута `/api` и обновления до WebSocket используют её напрямую, а прочие клиентские плагины потребляют производное состояние `ctx.connection.isLoopback`. Маршрут `/api` узловой половины закрепляет набор привилегированных методов за loopback, пропуская ограждение доверия с пустым списком доверия: это `host.pickDirectory`, `host.openPath` и вся конфигурационная плоскость — `settings.describe`/`openDocument`/`update`/`replace`/`mutate` и `credentials.describe`/`set`/`unset`, включая чтения и нативные действия, поскольку describe возвращает предоставляемую конфигурацию, open действует на рабочий стол Host, а зондирование произвольной ссылки сообщает происхождение учётных данных, — и авторская плоскость agent-preset, `agentPreset.read`/`copy`/`openDocument`/`remove`, поскольку композиция называет плагины, которые запускает сессия, так что чтение композиции — разведка, а copy/remove/openDocument управляют составом пресетов и действуют на рабочий стол хоста (авторинг идёт только через copy, поэтому ни один из этих методов не принимает текст композиции или путь); `agentPreset.list` и `agentPreset.select` остаются вне набора — список несёт лишь идентификаторы и признак доверия, а выбор пресета не даёт ничего сверх того, что давал собственный параметр `agentPreset` вызова `session.create`, поверх умолчания, которое уже включает bash. Объявленный authority из `trustedHosts` открывает доступ ко всем остальным методам, а эти остаются локальными для loopback, пока не появится настоящий слой аутентификации. Носители платформы и цикл ConnectionController остаются внутри пакета; их выбирает и ведёт apply. Граница приёма задокументирована в [Agent Note о downlink-носителе WebSocket](../../../.agents/notes/implemented/architecture/2026-08-04-websocket-downlink-carrier.md).

## Ограда browser-trust для /api

Узловая половина проверяет каждый вход под `/api` до мостинга или обновления (`src/api-request-trust.ts`). Каждый запрос — помечен он браузером или нет — **ДОЛЖЕН** предъявить заголовок `Host`, который является loopback-authority или совпадает с записью `trustedHosts`: точное сравнение для записей вида `host:port`, любой порт для записей без порта, обе стороны сопоставляются после WHATWG-нормализации (защита от DNS-rebinding). Для непомеченных HTTP-запросов обхода нет намеренно: поверх обычного HTTP браузер не прикрепляет ни `Origin`, ни Fetch-Metadata к чтениям картинок и навигации, поэтому непомеченный запрос всё ещё может оказаться чтением со стороны переназначившего DNS браузера с читаемым ответом, а `Host` — единственный заголовок, который rebinding не способен подделать; рукопожатие WebSocket браузера несёт `Origin` и проходит то же сравнение. Не-браузерные клиенты проходят то же ограждение через loopback, выведенные при развёртывании LAN IP-литералы или объявленный authority. Когда маркеры присутствуют, приложенный `Origin` **ДОЛЖЕН** равняться authority из `Host`, а явный маркер `sec-fetch-site: cross-site` отвергается. Запись `trustedHosts`, которая не является голым каноническим authority вида `host[:port]` — таким, что один проход WHATWG-парсинга возвращает её ровно как написано, — прерывает загрузку плагина с явной ошибкой: иначе парсинг тихо авторизовал бы имя хоста внутри `harness.internal/path` либо расширял порт с висячим двоеточием или нулевым дополнением до права «любой порт». Неудачи HTTP отвечают простым 403 до какой бы то ни было диспетчеризации RPC; неудачи обновления отклоняют рукопожатие до старта какого-либо потока событий. Композиции вне loopback **ДОЛЖНЫ** явно объявить доверие тем authority, которые их обслуживают: веб-рантайм выводит LAN IP-литералы из конфигурации сервера, слушающего все интерфейсы, а `trustedHosts` в cordis.yml и флаг CLI `--trusted-host` объявляют именованные authority. `dsh web --host 0.0.0.0` намеренно не поддерживается, пока у удалённого доступа не появится слой аутентификации. Ограждение — это политика достижимости, а не аутентификация; веб-носитель слоя аутентификации не предоставляет. Запись решения: [Agent Note о границе browser-trust для api](../../../.agents/notes/implemented/architecture/2026-07-28-api-browser-trust-boundary.md).

## Даунлинки WebSocket `/api`

Каждый из путей `/api/events.mux` и `/api/events.host` принимает обновление до WebSocket и отправляет браузеру только соответствующие текстовые сообщения `ServerRequest`; клиент не передаёт по этим сокетам никаких данных приложения. Если какой-то из сокетов обрывается, текущее поколение соединения считается упавшим и перестраивает оба потока; готовность по-прежнему требует открытости обоих сокетов и успешного HTTP-вызова `host.describe`. Остановка Host завершает оба сокета, прерывает их источники и ждёт очистки источников перед возвратом. Обычные сетевые GET на эти пути отвечают 426 без отката к SSE; SSE-кодек `toFetchHandler` обслуживает только изоморфный внутрипроцессный носитель.

## Влияние на модель

Отсутствует: слой протокольного потребителя переносит уже собранные сообщения между браузером и хостом; ничто здесь не достигает запроса к модели.

#### Влияние на KV-кэш

Нулевое; этот пакет не собирает и не отправляет запрос провайдеру.

## Известные ограничения и отложенная работа

- **История возобновляет неподключённую сессию** — открытие истории может создать агент на стороне хоста и добавить задержку первому открытию; пути чтения только из хранилища нет.
- **Мост `/api` буферизует тело каждого запроса в памяти** — `maxRequestBodyBytes` (по умолчанию 300 МиБ, размер подобран под действующий по умолчанию агрегатный лимит изображений 200 МиБ после расширения base64 плюс запас на конверт) является поэтому же пределом резидентной памяти одного запроса; чтобы снизить его, не ужимая лимиты изображений, понадобился бы путь потоковой передачи тела.
