# @deepseek-ai/dsh-client-hmr

[English](README.md) | [中文](README.zh.md) | Русский

Горячая перезагрузка клиентских плагинов, загружаемых как скрипты. Веб-бандл монтирует эту строку безусловно; пока процесс наблюдения за пересборкой (`pnpm run dev:web`) не перезаписывает клиентские бандлы, опрос не видит изменений и цепочка остаётся простаивающей.

Браузерная половина подписывается на системный SSE-канал (`GET /plugins/events`) и перезагружает один плагин на каждый кадр `rebuilt` через сериализованную очередь. Последовательность на каждый кадр — `invalidate`, `prefetch` (загрузка и регистрация нового бандла, пока старый fiber всё ещё обслуживает), `registry.delete` (до fiber: голое освобождение fiber задевает ветку самоосвобождения вендоренного Loader, которая пометила бы запись отключённой), осушение старого fiber, удаление `entry.fiber`, снятие принадлежащих плагину тегов `<style data-plugin>`, повторный импорт и перемонтирование в `entry.refresh()`, а `fiber.await()` громко перебрасывает наверх сбои запуска. Зависимые перезагружаются средствами самого cordis: activation epoch fiber нанизывает uid провайдеров её сервисов, поэтому замена fiber провайдера каскадно обновляет каждого зависимого без малейшего клиентского анализа графа. Узловая половина обнаруживает пересборки одним интервалом, который опрашивает stat'ом каждый бандл графа от синхронной базовой линии, сразу пересчитывает хэши после добавления строки, удерживает отсутствующие строки помеченными как dirty и рассылает оповещения только при реальных изменениях ревизии; поэтому любой следящий процесс tsdown, порождающий бандл, запускает HMR без отдельного канала builder→host.

## Model Experience

Отсутствует: драйвер перезагрузки — браузерная механика; ничто из этого пакета не попадает в запрос к модели.

#### KV Cache effect

Отсутствует; этот пакет не собирает и не отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Перезагрузка по дизайну груба** — новый fiber и новые компоненты; состояние React внутри перезагруженного плагина теряется, тогда как слой данных (fiber connection/runtime, объекты Session) остаётся нетронутым. Сохранение состояния уровня react-refresh противоречит принципу «повторное исполнение бандла заново запускает фабрику» и сознательно исключено.
- **Отката при сбое нет** — неудавшаяся перезагрузка оставляет запись в состоянии FAILED и видимой в проекции статуса загрузчика; предыдущий бандл автоматически не восстанавливается.
- **Кадры `rebuilt` не обновляют ревизию графа** — устаревшая ревизия безвредна, потому что эндпоинт бандла отдаёт ответ с no-cache; обновляет её только переподключение.
