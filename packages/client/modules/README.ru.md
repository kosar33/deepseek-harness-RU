# @deepseek-ai/dsh-client-modules

[English](README.md) | [中文](README.zh.md) | Русский

Клиентская система модулей: браузерный аналог внутреннего ESM-загрузчика Node, построенный как ленивая CJS-таблица. Веб-оболочка монтирует вендоренный Loader из cordis для управления входами (жизненный цикл fiber'ов, ожидание inject, update/refresh) и внедряет `ClientModuleLoader` этого пакета через его контракт `internal` — единственное место, где вендоренная сторона его использует, — это `EntryTree.import`, поэтому замена `internal` меняет ровно «то, как доставляется код плагинов», и ничего больше.

Ленивая CJS-модель (web2): исполнение бандла плагина только РЕГИСТРИРУЕТ его фабрику (`window.__ModuleLoader__.load({id, factory})`); каждый побочный эффект тела модуля — включая инъекцию CSS — живёт в замыкании фабрики и исполняется при материализации (`factory(require)` → экспорты, мемоизируемые в `loadCache`), а не при исполнении скрипта. Фабрика, требующая другой зарегистрированный, но ещё не материализованный модуль, материализует его рекурсивно; композиция графа ставит объявленные динамические запросы перед их потребителями, а циклы require бросают исключение, потому что CJS в форме фабрик не может выдать частичные экспорты. `<id>/client` и голый id резолвятся в одни и те же экспорты (бандл плагина ЕСТЬ клиентская половина своего пакета).

Хост устанавливает `window.__ModuleLoader__` до запуска предзагрузок парсера. Его `load()` в режиме очереди удерживает ранние регистрации; `create()` материализует фабрику этого пакета с bootstrap-require, отвергающим внешние запросы, и вызывает её экспорт `createClientModuleSystem`. Конструирование кэширует те же экспорты как запись modules, переключает тот же фасад на живую регистрацию и опустошает остаток очереди. Бандл удерживает полученную систему в замыкании модуля, поэтому последующий Cordis `apply()` предоставляет тот же самый экземпляр как `ctx.modules` без ещё одной глобальной переменной страницы.

Порядок ветвей резолва (`import(specifier)`): seed-слово платформы → экземпляр оболочки; мемоизированная запись → экспорты; запись графа (`window.__DSH_BOOT__`) → зарегистрировать её фабрику classic-script; зарегистрированная фабрика → материализовать; во всех остальных случаях — исключение, рантайм-зеркало гейта чистоты бандла времени сборки. Синхронный `require`, передаваемый фабрикам, проходит тот же порядок минус асинхронную загрузку записи графа и записывает наблюдаемые рёбра в запись модуля. `prefetch` — хук появления первой ступени (только загрузка скрипта и регистрация фабрики; параллельные вызовы разделяют одну задачу in-flight); `invalidate` сбрасывает не-bootstrap фабрику и материализованную запись, так что следующий prefetch/import перезагружает скрипт (это HMR-хук).

Node-половина сканирует включённые входы Loader на предмет веб-пакетов с `dsh.client`, резолвит каждый `exports["./client"]`, хэширует собранный бандл в граф загрузки, переносит специфичные для пакетов запросы `dsh.client.external`, упорядочивает динамических провайдеров перед потребителями и раздаёт каждый бандл с его source map под `/plugins`. Запуск из исходников отображает импорты хоста в исходники TypeScript, но всё ещё использует этот собранный клиентский экспорт; отсутствующие файлы дают одну инструкцию сборки со списком пакетов/путей, тогда как несвязанные ошибки файловой системы остаются отдельными сбоями.

`dsh.client.external` — необязательный список запросов с точными спецификаторами сверх неявной базовой линии: React, Cordis и статические UI-библиотеки, добавляемые оболочкой, плюс предзагруженный парсером рантайм. Запрос удовлетворяет названная им динамическая запись пакета или точный ключ статической таблицы; только завершающий `/client` служит псевдонимом записи пакета, а объявления провайдера-псевдонима нет. Импорты только типов стираются и не создают запроса. Композиция отвергает некорректные запросы, отсутствующих поставщиков, запросы к самому себе и синхронные циклы запросов; import и prefetch рекурсивно регистрируют динамических поставщиков прежде, чем материализуются их потребители. См. [общие модули и граф модулей](../AGENTS.md#shared-modules-and-the-module-graph).

## Влияние на модель

Никакого: загрузчик модулей — ключевая браузерная механика; ничего из этого не попадает в запрос к модели.

#### Влияние на KV-кэш

Никакого; этот пакет не собирает и не отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Плоский граф модулей сделан намеренно** — каждый бандл — один узел модуля, чьи рёбра указывают только на листья таблицы; интерфейс (`loadCache`/`edges`/`invalidate`) уже поддерживает общий граф модулей, поэтому гранулярность выноса внешних зависимостей может измениться без изменения интерфейса.
- **Нет собственного учёта выгрузки** — удаление стилей и порядок остановки fiber обеспечивает драйвер HMR (`@deepseek-ai/dsh-client-hmr`); загрузчик лишь ведёт перечень принадлежащих ему id тегов стилей в каждой записи.
