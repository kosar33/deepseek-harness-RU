# @deepseek-ai/dsh-client-ui-deliverables

[English](README.md) | [中文](README.zh.md) | Русский

Владелец возможности созданных файлов и кликабельных ссылок. Половина для Node регистрирует руководство по финальному ответу в реестре системных промптов; браузерная половина регистрирует строку deliverables, которой заканчивается завершённый ход, в отверстие `conversation.chat.turnTail` представления чата и проставляет ссылки на совпадающие упоминания в inline code закрывающего текста. Поставляемый Web-патч — единственная композиция, загружающая этот пакет. Удаление его единственной записи в cordis.yml убирает заодно руководство, строку и ссылки в тексте.

`deliverablesDefinition` сворачивает успешные вызовы мутаций каждого хода в публикуемые движком `DeliverablesTurnData`; `producedForClosing` читает эти данные вместе с seq замыкающего сообщения ассистента. Словарь — собственные сопроводительные `locations` инструментов мутаций, но никогда не закрывающий текст: созданный файл попадает в список независимо от того, вспомнила ли модель его назвать. Мутация опознаётся по намерению рендера, а не по имени инструмента — карточка diff либо универсальная карточка с `kind: edit` (форма, которую предъявляет insert у `str_replace_editor`), — поэтому новый инструмент мутаций присоединяется, объявляя, что он делает. Чтения, удаления и неудавшиеся вызовы не дают ничего; путь появляется один раз за ход в порядке первого появления. Индекс Conversation Location владеет принадлежностью к ходу, поэтому ход, который выполнил мутации, а затем завершился без содержательного текста, не может пролиться в строку следующего хода.

`ProducedFiles` рендерит строку между телом замыкающего сообщения и его подвалом IconActions: неброская подпись и одна измеренная дорожка файлов. Он показывает самый крупный помещающийся ведущий префикс (до шести чипов; текст basename, полный путь в `title`), резервируя точную локализованную ширину `+ N files`, так что остаток остаётся видимым без переноса строк и горизонтальной прокрутки. Каждый чип открывается через предоставленный владельцем `openFile` — тот же Host-опенер, которым пользуются строки инструментов, причём представление чата разрешает относительные пути от cwd сессии. Когда файлы скрыты, действие второй строки **Показать в папке** открывает workspace сессии через тот же путь владельца, но только пока страница обслуживается на loopback, а текущее рукопожатие Host сообщает `canOpenPath`; прямой удалённый Web и headless/container Linux Hosts по умолчанию опускают это действие. Обоснование дизайна: [Agent Note о ссылках на файлы workspace](../../../.agents/notes/implemented/feature/2026-07-31-web-workspace-file-links.md).

Закрывающий текст несёт тот же словарь. Этот плагин предоставляет сервис `chatFileMentions`, к которому представление чата обращается по каждому замыкающему сообщению: `producedFileMentions` разрешает токен в inline code по точному пути или по точному совпадению с basename ровно одного созданного пути — basename, который делят два пути, остаётся инертным вместо угадывания, так что ссылка-упоминание никогда не откроет неверный файл и не выдаст 404. Разрешённое упоминание сохраняет свой кодовый чип и принимает язык ссылок markdown-листа — синий цвет ссылки в покое, подчёркивание при наведении, в точности как у inline code, повышенного до URL, — с полным путём в `title`; упоминания никогда не рендерятся внутри якорей или потокового текста. Запись решения: [Agent Note о встроенных упоминаниях файлов](../../../.agents/notes/implemented/feature/2026-08-07-web-inline-file-mentions.md).

Половина для Node регистрирует статическую секцию системного промпта `ui:deliverable-file-references`. Она просит модель упомянуть основные файлы, успешно созданные или изменённые ею, и записать их и любые другие ссылки на изменённые файлы как Markdown inline code, используя точный путь файлового инструмента либо basename только тогда, когда он уникален в пределах хода. Руководство делает явным принятый рендерером синтаксис; оно не управляет посторонними обсуждениями путей и не расширяет словарь успешных мутаций рендерера.

## Влияние на модель

### Руководство по кликабельным ссылкам на файлы

#### Что видит модель

Один фиксированный абзац предписывает модели назвать в финальном ответе основные файлы из успешных вызовов создания или изменения и оформить их и любые другие ссылки на изменённые файлы как Markdown inline code с точным путём или уникальным basename, например `out/report.html`.

#### Влияние на токены

Один фиксированный абзац промпта всегда, когда пакет загружен; ни схема инструмента, ни результат инструмента, ни контекст на ход не добавляются.

#### Влияние на KV-кэш

Секция статична с порядком 190 на всё время жизни монтирования пакета, поэтому остаётся в повторно используемом префиксе промпта и не меняется между ходами.

## Известные ограничения и отложенная работа

- **Сопоставление упоминаний — только точный путь или уникальный basename.** Суффиксное упоминание (`out/index.html`, записанное как `index.html`, разрешается; `deep/out/index.html`, записанное как `out/index.html`, — нет) остаётся инертным; расширение сопоставителя отложено, пока реальная форма замыкающих сообщений его не потребует.
- **Файлы, косвенно созданные терминальными командами, остаются вне словаря сопоставления.** Называние такого файла в inline code не сделает его кликабельным, если только location успешной мутации также не запишет этот путь.
- **Нативная передача папки адресует рабочий стол Host.** Браузер, достигнутый через не-loopback авторитет, опускает действие, равно как и развёртывание, сообщающее об отсутствии нативного опенера. SSH-перенаправление, делающее удалённый Host выглядящим loopback-локальным, **ДОЛЖНО** выставить `nativeOpen: false` у шлюза; то же требуется headless Host на macOS/Windows, развёртыванию WSL без работающего Windows interop и любому Linux-десктопу, чья проба дисплея/опенера даёт ложноположительный результат. Опознание видимого оператору рабочего стола остаётся политикой развёртывания.
