# @deepseek-ai/dsh-client-ui-goal

[English](README.md) | [中文](README.zh.md) | Русский

Плагин поверхности Goal, браузерная половина: полоса `GoalBar` — вторая самостоятельная карточка в стеке composer-контекста `conversation.input.dock` (order 10, после Todo и перед Queue). Живая цель приходит через `useProjection('goal')` — вычисляемое на Host целостное значение, засеянное страницей хвоста истории и обновляемое кадрами `session/projection`, — поэтому плагин не владеет ни доменным store, ни цепочкой обновления, ни слушателем событий. Inject-грань slot несёт только четыре глагола мутации (edit / pause / resume / clear через `ctx.remote.goals` — активная цель предлагает действие pause, приостановленная — resume); каждый читает CAS-ref из текущего спроецированного значения сессии в момент вызова и показывает отвергнутую ошибку Remote инлайн. Полоса выполняет мутации в режиме single-flight синхронно, потому что ожидающий рендер React не способен отгородить клики одного кадра; после успешного clear она немедленно подавляет именно этот id цели, пока авторитетная null-проекция не догонит. Создание цели остаётся на host-команде `/goal`; загружающаяся, отсутствующая, завершённая и успешно очищенная цели не рендерят ничего.

Отдельно плагин проецирует каждое долговечное `command/run` команды `/goal` через собственный Conversation Definition. Он строит Chat Node `command-input` перед универсальным Node результата команды и регистрирует key-renderer этого Node как выровненный вправо моноширинный пузырь пользовательского стиля 14px/22px с локализованным именем группы `Command input` / `命令输入` и без действий timestamp, copy или branch. Видимый не-командный Node активирует свежий Chat; перезагрузка реконструирует его из run, тогда как окно истории, содержащее только `command/done`, сохраняет лишь универсальную строку результата. Эта проекция никогда не создаёт `user/message` или ход модели.

Экспорты `/client` — тело плагина (`apply`/`inject`), компоненты `GoalBar`/`GoalDock` и типы inject-грани глаголов.

## Влияние на модель

Косвенно — через вызываемые полосой Remote-методы `goals/edit`, `goals/pause`, `goals/resume` и `goals/clear`: каждая принятая мутация коммитится долговечной вставкой `agent/inbox/spliced`, которую проекция цели немедленно сворачивает, и ставит в очередь контекстное сообщение `goal/change`. Модель видит этот контекст, только если более поздний pre-step его допустит; отбрасывание стоящего в очереди сообщения не откатывает спроецированное состояние. Сама полоса не добавляет содержимого промпта.

#### Влияние на KV-кэш

Никакого, пока стоящий в очереди контекст цели не допущен. Допущенный контекст удлиняет хвост истории, как любое другое сообщение; вставка, отброшенная до допуска, на кэш не влияет.

## Известные ограничения и отложенная работа

- **Только долговечная фаза** — проекция опускает локальный для процесса признак активности, поэтому полоса не может отличить активную, но невзведённую цель от взведённой; resume снова взводит через сторону RPC. Живого host-канала активации нет.
