# @deepseek-ai/dsh-client-ui-jobs

[English](README.md) | [中文](README.zh.md) | Русский

Владелец функции фоновых задач веб-интерфейса: добавляет один элемент в `conversation.session.header.actions`, перечисляющий записи `ctx.jobs`, которые эта сессия может видеть. Данные приходят целиком через зеркальный список `jobsBySession`, который [`dsh-client-runtime`](../runtime/README.ru.md) сворачивает из кадров `session/jobs`, поэтому пакет не отправляет ни одного RPC и не хранит состояния за пределами видимости popover.

Триггер рендерится только тогда, когда у сессии есть хотя бы одна задача, поэтому обычный разговор никогда не обрастает органом управления для возможности, которой он не пользуется. Бейдж считает `running` вместе с `stopping` и опускается при нуле, оставляя сессии, где остались лишь завершённые задачи, тихую точку входа в их историю, а не объявление о количестве, равном нулю. Popover — плоский список: сначала живые строки по возрастанию `startedAt`, затем завершённые по убыванию `finishedAt`, причём ничья в одну миллисекунду разрешается по порядку старта, чтобы порядок итерации map на хосте никогда её не решал. Строка показывает тип производителя, метку, маркер статуса, `detail` производителя вместо общего слова о статусе, как только тот появляется, и прошедшую длительность. Эта длительность сдвигается раз в секунду, пока строка жива, и замирает на `finishedAt`; часы тикают только пока открытый список держит что-то движущееся. Завершённая строка без `finishedAt` читается как ноль, а не как отрицательное число, а длительность сверх часа остаётся в часах и не обрастает словарём суток, которого ещё не достиг ни один производитель.

Завершённые строки остаются видимыми и приглушёнными, пока реестр не выбросит их при освобождении ресурсов владельца. Они попадают в снапшот, `detail` проваленной задачи — единственное место, где её провал читаем, а фильтрация их здесь — работа, которую фазы вывода и отмены пришлось бы отменять. Запущенный одноразовый фоновый сабагент поэтому появляется и здесь, и в [каталоге сабагентов](../ui-subagent/README.ru.md): каталог ведёт в транскрипт потомка, а этот список — единственный дескриптор, за который будущая отмена может ухватиться.

Escape закрывает список и возвращает фокус триггеру, как и нажатие указателем вне его. Исчезновение последней задачи закрывает список до размонтирования органа управления, так что фокус никогда не пропадает вместе с удалённым узлом. Оформление использует только токены; текст проходит через собственное пространство локали `job` этого пакета. Поведение специфицировано в [Agent Note о показе фоновых задач веб-интерфейса](../../../.agents/notes/implemented/feature/2026-08-08-web-background-job-display.md).

## Влияние на модель

Отсутствует: этот пакет рендерит вычисленное хостом состояние реестра для человека и не касается ни промпта, ни сообщения, ни схемы, ни потока, ни результата инструмента. Собственный взгляд модели на те же задачи остаётся за [`dsh-tool-jobs`](../../jobs/tool-jobs/README.ru.md).

#### Влияние на KV-кэш

Отсутствует; пакет никогда не собирает и не отправляет запросы к провайдеру.

## Известные ограничения и отложенная работа

- **Строки доступны только для чтения** — потоковый вывод задачи и инициированная человеком отмена являются раздельными фазами. Отмена дополнительно требует ориентированного на модель решения, которого seam сегодня не даёт: `kill()` помечает терминальную доставку как сообщённую, поэтому прерывание, написанное против текущего контракта, оставило бы модель в уверенности, что её задача всё ещё работает.
- **Список — не собственное множество реестра** — он показывает то, что одна сессия может видеть через протокольное представление, поэтому задача, принадлежащая другой сессии, здесь никогда не появится, а перезапуск процесса опустошает список, пока транскрипт сохраняет карточки `run_in_background`, запустившие эти задачи. Задача без владельца (запущенная без живого `Agent`) — противоположный случай: она попадает в список каждой сессии, согласуясь с тем, что `list(caller)` сообщает каждому вызывающему.
