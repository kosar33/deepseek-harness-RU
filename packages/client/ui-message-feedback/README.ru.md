# @deepseek-ai/dsh-client-ui-message-feedback

[English](README.md) | [中文](README.zh.md) | Русский

Плагин обратной связи по каждому сообщению, браузерная половина: пара Like/Dislike плюс опциональная заметка, вносимые как entry `feedback` (порядок 10) полосы `conversation.chat.assistant-actions`. Полоса объявляется пакетом ui-conversation и отрисовывается внутри строки IconActions финализированного сообщения ассистента, между копированием и ветвлением, поэтому элементы управления наследуют обвязку и поведение при наведении этой строки. Сам редактор заметки не сидит в этой строке: это всплывающая панель с `role="dialog"`, вынесенная порталом в `document.body` и закреплённая под своей кнопкой, поэтому строка хранит единственную линию, открыт редактор или закрыт, а панель не обрезается колонкой беседы. Сбой выставления оценки или загрузки списка показывается прямо в строке; сбой сохранения заметки показывается внутри всплывающей панели, которая остаётся открытой, чтобы черновик можно было исправить. До slot'а доходят только финализированные сообщения — частичное сообщение, замороженное прерыванием, не несёт `messageId`, а значит, и элементов управления обратной связью. Полоса отрисовывается один раз за ход, на закрывающем сообщении ассистента, которому принадлежит строка IconActions этого хода: более ранние шаги многошагового хода дают строки инструментов, а не оцениваемое тело, поэтому они не представляют элементов управления, хотя Host принял бы их как цели.

Один `MessageFeedbackController` на сессию обслуживает каждый элемент управления сообщениями в этой сессии, поэтому единственное чтение `messageFeedback.list` засеивает весь транскрипт. Чтение откладывается до первого наведения или фокуса, а не срабатывает на монтировании, потому что элементы управления монтируются один раз на каждое завершённое сообщение в видимой истории.

Мутации идут через `ctx.remote.messageFeedback`; Host владеет сравнением-с-записью по каждому элементу. Каждый `put` и `delete` несёт `version`, которую этот контроллер наблюдал последним, а ответ `version-conflict` несёт авторитетный элемент, поэтому проигранная гонка сверяется из самого ответа вместо повторного чтения сессии. Мутации сериализуются на сессию, поэтому операция в очереди всегда сверяется с закоммиченной версией. Повторный щелчок по записанной оценке отзывает обратную связь; смена стороны переносит существующую заметку дальше.

Экспорты `/client` — тело плагина (`apply`/`inject`), компонент `MessageFeedbackActions`, класс `MessageFeedbackController` и типы inject-интерфейсов.

## Model Experience

Нет: обратная связь — сопутствующий слой, который никогда не входит в append-only журнал сессии, контекст модели или телеметрию; ни оценка, ни заметка никогда не видимы модели.

#### KV Cache effect

Нет; ни одна мутация обратной связи не касается хвоста истории.

## Известные ограничения и отложенная работа

- **Размер заметки — политика Host** — развёртывание конфигурирует `maxNoteBytes` (8192 в веб-бандле), и Host отклоняет чрезмерную заметку с `note-too-large`. Редактор не проверяет лимит заранее, поэтому чрезмерная заметка падает при сохранении, а не во время набора.
- **Нет push между вкладками** — оценка второй вкладки становится видимой при переподключении или в следующем ответе о конфликте, а не сразу; сопутствующий слой не публикует живых кадров.
- **Только представление чата** — представления trajectory и каскада не отрисовывают элементов управления обратной связью, хотя их узлы ассистента теперь несут тот же `messageId`.
