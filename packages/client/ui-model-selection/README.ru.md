# @deepseek-ai/dsh-client-ui-model-selection

[English](README.md) | [中文](README.zh.md) | Русский

Плагин выбора модели, браузерная половина: ДВА входа над ОДНИМ каталогом на сессию, владение которым несёт `ModelDirectoryResolver` (`ctx.modelDirectories`). Для обычных сессий вклад `/model` в popupSelect (регистрируемая через `ctx.commandUi`) и именованное место `conversation.input.model` композера оба загружают рекомендательный каталог сессии через `session.models` и подают выбор через `session.selectModel`, пользуясь одним и тем же экземпляром `ModelDirectory`. Компактный триггер композера открывает двухуровневое меню Модель/Усилие: модели остаются сгруппированными по провайдерам, а выбранная точная модель поставляет принадлежащие её адаптеру имена усилий, описания и значение по умолчанию. `/model` применяет усилие по умолчанию выбранной модели, после чего композер может выбрать любое из объявленных усилий.

Сообщаемая хостом `ModelSelection` с провайдером/моделью/рассуждением — единственный факт выбора, но она отражается, только когда точная пара провайдер/модель остаётся в объявленных группах; отсутствие строки каталога оставляет маршрутизуемый выбор нетронутым, пока триггер предлагает `Select model`, устаревшая строка не синтезируется, а строка Усилие не показывается, пока пользователь не выберет объявленную модель. Загрузки каталога и выборы делят счётчик поколений, поэтому более старый ответ никогда не затирает более новый; сброс соединения стирает каждую резидентную проекцию и заново вытягивает восстановленный хостом выбор перед показом. Локальные для провайдера неудачи получения метаданных значатся строкой внутри списка, тогда как пригодные группы остаются выбираемыми, а неудачи выбора сохраняют прежний выбор и каталог.

Когда хост сообщает, что ни один адаптер не обслуживает маршрут сессии (`session.models.routable`), этот плагин поднимает блок композера через `ctx.conversation.blocks`, и ввод становится инертным с собственной копией этого плагина; восстановление снимает блок без перезагрузки. Он следует за `routable` и ничем больше: `null` — до первой загрузки или после одной неудачи — никогда не блокирует, иначе медленный хост запер бы работающий композер, и членство в каталоге тоже никогда не блокирует, потому что маршрут, обслуживающий модель, которую он перестал объявлять, отсутствует в группах, но вполне пригоден. Собственный запасной путь триггера `Select model` всё равно покрывает этот случай — это вопрос показа, а не запрет.

Каталоги существуют на сессию, разрешаются лениво через `ctx.modelDirectories.directoryFor(sessionId)` и освобождаются вместе со scope сессии. Адресуемые сессии субагентов не открывают ни один из входов, а их каталог отвергает загрузки, выборы и обновления при переподключении, потому что обычные привязанные к Agent модельные RPC активировали бы сохранённую историю ребёнка вне пути продолжения прямого родителя.

Каждый резидентный каталог перезапрашивается напрямую на пересланных событиях-владельцах `llm/adapters-updated` и `settings/document-updated`. Топология провайдеров, их каталоги и выбор по умолчанию сходятся поэтому без того, чтобы хост или клиентский рантайм выводили отдельный псевдоним изменения моделей.

Экспорты `/client` — это тело плагина (`apply`/`inject`), `ModelDirectoryResolver`, `ModelDirectory` со своими полями состояния и тип inject-грани места.

## Опыт модели

Косвенно, через RPC `session.selectModel`, доступный обычным сессиям, оба входа подают полную `ModelSelection`, которую хост снимает в снапшот на следующей границе сборки промпта, поэтому следующий запрос использует выбранного провайдера, модель и усилие, пока идущий шаг удерживает свою уже собранную выборку; выбор становится долговечным, только когда существующий заголовок запроса записывает запрос, потребивший его, а взаимодействие с меню не добавляет никакого содержимого промпта.

#### Влияние на KV-кэш

Смена маршрута может сократить или обнулить переиспользование кэша на стороне провайдера для последующих запросов; сам префикс промпта не затрагивается.

## Известные ограничения и отложенная работа

- **Нет выбора при создании и для адресуемых субагентов** — обоим входам нужен Agent существующей обычной сессии; выбора модели в фазе черновика, который можно было бы включить в создание сессии, нет, а продолжение субагента нарочно не открывает независимого контракта выбора модели.
- **Имена каталогов существуют только для показа** — выбор и персистентность используют id провайдера/модели/усилия; провайдер, у которого поиск каталога или метаданных точной модели падает, значится невыбираемой строкой отказа до перезагрузки.
- **Нет произвольного ввода усилия** — композер предлагает только уровни точной модели, объявленные её адаптером; адаптер без метаданных рассуждений оставляет строку Усилие отсутствующей.
