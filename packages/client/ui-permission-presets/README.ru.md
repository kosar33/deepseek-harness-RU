# @deepseek-ai/dsh-client-ui-permission-presets

[English](README.md) | [中文](README.zh.md) | Русский

Браузерные поверхности разрешений для двух разных времён жизни. Строка общих настроек читает явно предоставляемый дескриптор настроек `permission`, выводит свои варианты из динамического перечисления `defaultPreset` хоста и записывает одну путевую операцию `settings.mutate` с ревизией дескриптора. Её observable едет в отсеке `hooks` slot-системы, поэтому привязку React-хуков держит рендерер; пуш-инвалидация перезапрашивает дескриптор. Это значение применяется только при создании последующей сессии; его изменение не переключает текущую сессию. Выбор Full access требует явного подтверждения риска, прежде чем строка его запишет.

Поверхность текущей сессии остаётся DECORATION-элементом popupSelect, подвешенным на хостовую команду `/permission` (`ctx.commandUi.decorate`). Декорация — не вторая команда: хостовая команда сохраняет свою строку в slash-меню, путь с аргументом (`/permission <preset>` переключает напрямую) и долговечное журналирование жизненного цикла; декорация заменяет лишь голый вызов пикером — одним плоским списком пресетов, где текущее значение помечено активным, а имена пресетов в kebab-case отображаются как метки в Title Case (`workspace-write` → `Workspace Write`, близнец преобразования отображения чипа композера), и выбор отправляет командную строку `/permission <preset>`. Варианты и активная метка читают проекцию `permissions` сессии (тот же вычисляемый хостом select, который рендерит чип композера), поэтому обе поверхности текущей сессии делят один источник чтения и один путь записи, а доставленный кадр проекции — единственное подтверждение, которому следуют обе. Декорация доступна ровно пока существует ключ проекции; композиция без разрешений не показывает ни пикера, ни строки настроек.

Экспорты `/client` — тело плагина (`apply`/`inject`).

## Model Experience

Опосредованно — через факты разрешений, записываемые её двумя поверхностями: строка настроек заставляет будущую сессию стартовать с цельнозначных knob-событий (`permission/preset`, `sandbox/mode`, `approval/policy`), а пикер `/permission` дописывает те же факты, когда переключает текущую сессию; эти события задают режим песочницы и политику одобрения, по которым разрешаются последующие вызовы инструментов, а взаимодействие с пикером не добавляет в промпт никакого содержимого.

#### KV Cache effect

Прямой инвалидации нет; за любые изменения префикса запроса отвечают потребители knob-событий.

## Известные ограничения и отложенная работа

- **Строка настроек существует только в Web** — не-Web клиенты по-прежнему могут переключать текущую сессию через `/permission`, но не получают этот браузерный вклад.
