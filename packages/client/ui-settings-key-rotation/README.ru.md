# @deepseek-ai/dsh-client-ui-settings-key-rotation

English | [中文](README.zh.md) | Русский

Редактор ротируемых ключей внутри каждой карточки провайдера на странице «Модели»: когда Host монтирует [`@deepseek-ai/dsh-llm-key-rotation`](../../llm/llm-key-rotation/README.ru.md), этот плагин вносит слот `settings.models.credential`, и каждая карточка рисует его вместо одиночного поля API-ключа — владельцу больше не нужно править `cordis.yml`, чтобы ротировать ключи маршрута. Слот редактирует маршрут своей карточки (owner-проп `provider`) против пространства имён `llm-key-rotation` и сводит два wire-чтения в один общий снапшот: `llm.keyRotation` (живой статус пулов плагина по каждому маршруту) и `settings.describe` (это пространство имён). Развёртывание, чей Host не отвечает лицом ротации, слота никогда не увидит — проба не проходит, регистрация не случается, и все карточки остаются с родным полем.

Над строками — чипы живого здоровья пула: липкий ключ выделен как **активен**, остальные **доступен** или **отложен**, а отложенный выводит обратный отсчёт («лимит откатится через N ч M мин»), вычисляемый локально из `resetAt` снапшота и идущий вместе с настенными часами. Строки упорядочены — ключи пробуются сверху вниз; стрелки меняют порядок, не перемещая сохранённую ссылку строки. Цикл сохранения повторяет модель доверия страницы «Модели»: введённые значения проходят только на запись через `credentials.set` под производными ссылками `<ROUTE>_KEYROTATION_<n>` (на единицу больше крупнейшего занятого индекса, поэтому перестановка никогда не перенаправляет ссылку на другой секрет), а одна целостная операция `keys` записывает лишь имена этих ссылок — документ настроек никогда не содержит секрета. Удаление всех строк снимает пользовательский элемент маршрута; выброшенные ссылки снимают свои учётные данные. Пустая новая строка блокирует сохранение сообщением с именем поля до любого wire-вызова; как и две строки с одинаковым значением — один секрет не должен сохраняться под двумя ссылками. Капсула «Сбросить таймауты» рядом с кнопкой сохранения снимает все живые парковки маршрута через `llm.keyRotationResetParks` и перезагружает снапшот; пока отложенных нет, она неактивна. Необслуживаемая запись отвергается там же, где записывается (плагин проверяет при `settings.mutate`), поэтому слот показывает сообщение Host, а не молча отключает маршруты.

Push-уведомления об инвалидации (`settings/document-updated`, `credentials/reference-updated`, `llm/adapters-updated`, переподключение) обновляют общий снапшот без опроса; открытые карточки хранят локальные черновики сквозь обновления и стирают потреблённые значения при сохранении.

## Model Experience

None: слот настраивает учётные данные провайдера в настройках браузера; сюда не попадает ничего от запроса к модели.

#### KV Cache effect

None; этот пакет ни собирает, ни отправляет запрос провайдеру.

## Known Limitations and Deferred Work

- **Редактируются только ключи** — поля идентичности (эндпоинт, протокол, модели) остаются в родных полях карточки под своими домашними секциями; слот пишет исключительно пространство `llm-key-rotation`.
- **Дев-литеральные ключи без редактора** — интерфейс создаёт только ссылки; композиция может объявить `value:`-ключи, они видны как чипы `literal` в строке статуса.
- **Свежесть статуса — по запросу** — изменения откладываний не приходят пушем; чипы обновляются общими инвалидациями и перезагрузками после сохранения, а обратные отсчёты идут локально между обновлениями.
