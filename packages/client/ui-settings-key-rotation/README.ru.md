# @deepseek-ai/dsh-client-ui-settings-key-rotation

[English](README.md) | [中文](README.zh.md) | Русский

Страница редактирования плагина [`@deepseek-ai/dsh-llm-key-rotation`](../../llm/llm-key-rotation/README.ru.md) в веб-настройках: владельцу больше не нужно править `cordis.yml` вручную, чтобы ротировать API-ключи маршрута провайдера с лимитами. Браузерный плагин регистрирует одну локализованную запись `settings.section` (`key-rotation`, сразу после «Моделей»); страница сводит три wire-чтения в один снапшот: `llm.keyRotation` (живой статус пулов плагина по каждому маршруту), `settings.describe` (пространство имён `llm-key-rotation`, которое устанавливает плагин) и `credentials.describe` (бейджи configured/source/writable без значений для видимых ссылок).

Верхняя карточка показывает живой статус ключей: по строке на настроенный маршрут, у каждого ключа своя метка — **активен** на липкой позиции, **доступен** или **отложен** — а отложенный ключ выводит обратный отсчёт («лимит откатится через N ч M мин»), вычисляемый локально из `resetAt` снапшота и идущий вместе с настенными часами, не затрагивая состояние пула. Сохранённые маршруты перечислены ниже карточками; каждая раскрывает не более одного редактора с полями профиля (отображаемое название, базовый URL, API-протокол, упорядоченные модели) и упорядоченными строками ключей. Ключи пробуются сверху вниз; кнопки-стрелки меняют порядок строк, не перемещая их сохранённые ссылки.

Цикл сохранения повторяет модель доверия страницы «Модели»: введённые значения ключей проходят только на запись через `credentials.set` под производными ссылками `<ROUTE>_KEYROTATION_<n>` (на единицу больше крупнейшего занятого индекса, поэтому перестановка никогда не перенаправляет ссылку на другой секрет), а path-операции `settings.mutate` записывают лишь имена этих ссылок — документ настроек никогда не содержит секрета. Удаление строки снимает её ссылку на учётные данные; удаление целого пользовательского маршрута снимает все сохранённые им ссылки. Проверка полей выполняется до любого wire-вызова: пустая новая строка ключа, пустой или дублирующийся ID модели и неположительное окно контекста получают сообщения, называющие поле. Необслуживаемый раздел отвергается там же, где записывается (плагин проверяет его при `settings.mutate`), поэтому редактор показывает сообщение Host, а не молча отключает маршруты.

Развёртывание без плагина показывает уведомление о его отсутствии; подключённый, но пустой — приглашение спящего состояния с карточкой добавления маршрута. Добавление работает как «открыть или создать»: допустимое незанятое имя открывает пустой редактор под зарезервированным именем, занятое — редактор этого маршрута. Маршруты, принадлежащие базовому слою композиции, прячут кнопку удаления — удаление означает возврат к базовому слою, пользовательский слой его не выполняет. Push-уведомления об инвалидации (`settings/document-updated`, `credentials/reference-updated`, `llm/adapters-updated`, переподключение) обновляют открытую страницу без опроса.

## Model Experience

Нет: раздел настраивает учётные данные и маршруты провайдера в браузерных настройках; ничто из здесь написанного не попадает в запрос к модели.

#### Влияние на KV Cache

Нет; этот пакет не собирает и не отправляет запросы к провайдеру.

## Известные ограничения и отложенная работа

- **Здесь редактируются только профили ротации** — раздел пишет только пространство имён `llm-key-rotation`; политика повторов и другие расширенные поля профиля остаются там, где их объявляет композиция, а маршруты базового слоя нельзя удалить со страницы.
- **Литеральные dev-ключи не редактируются** — интерфейс создаёт только ключи по ссылкам; композиция может объявлять ключи `value:`, они отображаются в статусной карточке строками `literal`.
- **Актуальность статуса основана на pull-модели** — изменения парковок не публикуют событий; панель обновляется общими инвалидациями, кнопкой обновления и перезагрузкой после сохранения, а отсчёты идут локально между обновлениями.
