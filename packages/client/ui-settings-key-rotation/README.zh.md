# @deepseek-ai/dsh-client-ui-settings-key-rotation

[English](README.md) | 中文 | [Русский](README.ru.md)

Web 设置中 [`@deepseek-ai/dsh-llm-key-rotation`](../../llm/llm-key-rotation/README.zh.md) 插件的编辑页，让拥有者无需再手改 `cordis.yml` 即可为受限流提供方路由配置多把轮换 API 密钥。浏览器插件注册一个本地化的 `settings.section` 条目（`key-rotation`，紧跟“模型”之后），页面将三路 wire 读取合并为一份快照：`llm.keyRotation`（插件实时的逐路由密钥池状态）、`settings.describe`（插件安装的 `llm-key-rotation` 命名空间），以及 `credentials.describe`（可见引用的无值 configured/source/writable 徽标）。

上方卡片渲染实时密钥状态：每个已配置路由一行，每把密钥带一枚状态标签——粘滞位置为**使用中**，其余为**可用**或**已停用**——已停用的密钥会根据快照中的 `resetAt` 本地计算倒计时（«限额将在 N 小时 M 分后重置»），随墙钟推进，而不触碰密钥池状态。已存储的路由在下方以卡片列出；每张卡片一次只展开一个编辑器，覆盖 profile 字段（显示名称、基础 URL、API 协议、有序模型）与有序的密钥行。密钥按自上而下的顺序尝试；方向按钮调整行序时不会移动行已绑定的存储引用。

保存回路沿用“模型”页的信任模型：输入的密钥值经 `credentials.set` 只写不读，存放在派生的 `<ROUTE>_KEYROTATION_<n>` 引用下（取现有最大索引加一，因此调序绝不会让引用改指另一把密钥）；`settings.mutate` 路径操作只记录这些引用名——设置文档永不携带机密。删除一行会 unset 它的凭据；删除整个用户层拥有的路由会 unset 它存储的每一条引用。字段校验先于任何 wire 调用：新增密钥行留空、模型 ID 为空或重复、上下文窗口非正数，都会得到指名字段的提示。不可服务的配置在写入处即被拒绝（插件在 `settings.mutate` 时校验），因此编辑器展示 Host 的报错，而不是静默停用路由。

未挂载该插件的部署显示“未挂载”提示；已挂载但配置为空时显示休眠引导与添加路由卡片。添加流程即“打开或创建”：合法且未占用的名称会在保留名下打开空白编辑器，已有名称则打开该路由的编辑器。组合基础层拥有的路由隐藏删除入口——删除意味着恢复组合基础，用户层无权执行。推送的失效通知（`settings/document-updated`、`credentials/reference-updated`、`llm/adapters-updated`、重连）会让已打开的页面免轮询刷新。

## 模型体验

无，因为本分区只在浏览器设置中配置提供方凭据与路由；没有任何内容进入模型请求。

#### KV Cache 影响

无；本包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **这里只能编辑轮换 profile** —— 本分区只写入 `llm-key-rotation` 命名空间；重试策略与其他高级档案字段仍留在声明它们的组合里，且基础层路由无法从页面删除。
- **字面量开发用密钥没有编辑入口** —— UI 只创建引用型密钥；组合仍可声明 `value:` 密钥，它们在状态卡片中显示为 `literal` 行。
- **状态新鲜度依赖拉取** —— 停用变化没有推送事件；面板通过共享失效通知、刷新按钮与保存后的重载来更新，倒计时则在两次刷新之间本地推进。
