# @deepseek-ai/dsh-client-ui-settings-models

[English](README.md) | [中文](README.zh.md) | Русский

Плагин настроек моделей и продуктового онбординга. Тот же клиентский Cordis-плагин регистрирует страницу Models плюс два упорядоченных диалога первого запуска: версионированное уведомление о внутреннем тестировании и условный шаг credential официального DeepSeek. Оба шага разделяют одну modal-обёртку и остаются упорядоченными через `settings.onboarding`. Плоскость Models соединяет три протокольных домена в один общий снапшот — `llm.providers` (каталог конфигурируемых провайдеров с состоянием live/dormant каждого маршрута), `settings.describe` (сериализованные схемы, послойные redacted-значения, secret slots) и `credentials.describe` (не содержащие значений бейджи configured/source/writable) — и рендерит строки провайдеров с одной карточкой редактора за раз, не выдавая живость маршрута за статус провайдера.

Строки — это *настроенные* провайдеры (их профиль разрешается во владеющем пространстве имён); провайдер целого раздела, чей ключ не настроен нигде, рендерится своей открытой карточкой настройки вместо строки, но только в состоянии первого запуска — пока ни один провайдер не зарегистрирован с credential, на который указывает его профиль, — и только до тех пор, пока пользователь не закроет эту карточку, после чего это обычная строка с точкой отсутствующего ключа. Каждый вид карточки владеет собственным состоянием открытости, поэтому закрытие одной никогда не отбрасывает черновик в другой. Поток добавления — карточка с select'ом провайдера из спящего каталога: голый смонтированный `llm-pi-ai` предлагает весь установленный каталог, пока маршрутов нет. Карточка pi-ai дополнительно редактирует **список моделей** этого маршрута и может спросить провайдера, что он обслуживает. Строка помечает состояние API-ключа зелёной сплошной точкой только когда указанный credential подтверждён как настроенный, и красной сплошной точкой только когда именованная ссылка подтверждена как отсутствующая; свободная от ссылок провайдер-нативная аутентификация и недоступное credential-обогащение остаются без пометок. Редактор — рукописная карточка на семейство адаптеров: главное поле — единственный ввод **API key**, страница никогда не спрашивает имя переменной окружения; введённый ключ сохраняется **write-only** через `credentials.set` под ссылкой профиля, выводя `<ROUTE>_API_KEY`, когда у профиля её нет, а профиль pi-ai записывает этот вывод как `apiKeyEnv`, поэтому `settings.yaml` никогда не несёт значения ключа. Оставленный пустым ключ нового pi-ai-провайдера сохраняет профиль без ссылок и потому сохраняет провайдер-нативную аутентификацию вроде цепочки credential Bedrock или Vertex ADC. Успешный Apply выдаёт локальное доступное сообщение статуса, не раскрывая секретный материал. Свёрнутая секция 自定义设置 несёт курируемые дополнительные поля — `baseURL` обоих семейств (placeholder deepseek показывает публичный эндпоинт), каталог моделей каждого адаптера, а также **display name** и **API protocol** маршрута pi-ai, которого адаптер не поставляет. Эти два поля — то, что маршрут, объявленный вручную, называет сам: карточка создания спрашивает оба, потому что ничто не может подставить их по умолчанию, поэтому редактор охватывает оба, а не оставляет их `settings.yaml`. Очистка имени делает unset, и маршрут возвращается к своему id, что и показывает placeholder; у протокола такого возврата нет. Маршрут каталога не получает ни того, ни другого: имя по умолчанию берётся из записи каталога, а его модели каждая несёт собственный протокол, поэтому маршрутный мог бы только перекрывать каждую из них. Provider ID остаётся фиксированным: это ключ настроек, имя, на которое ссылается каждое другое пространство имён и каждая залогированная сессия, и основа ссылки credential, которую страница не может прочитать обратно, чтобы перенести. Reasoning effort намеренно НЕ среди них: это возможность отдельной модели, и модели одного провайдера расходятся в том, какие уровни они принимают, поэтому управление на уровне провайдера можно было бы установить лишь в значение, которое некоторые отвергнут, — а это скрыло бы даже поддерживающие уровень модели. Пикер моделей композера предлагает каждой модели её собственные уровни, а переключение там записывает провайдера, модель и effort вместе как значение по умолчанию следующей сессии. Поле профиля остаётся в `settings.yaml` для развёртывания, знающего свой маршрут. Каждая строка DeepSeek редактирует `id`, необязательный display `name` и необязательные `contextWindow`/`maxTokens`; существующие поля вне этого курируемого набора переживают правки, а всякое иное поле профиля остаётся во владении `settings.yaml`. Строка удаляема, только когда она присутствует лишь в пользовательском слое (удаление возвращает базу композиции), а её локализованный диалог подтверждения называет провайдера в заголовке, описании и финальном действии. Строка помечена **Custom**, когда запись каталога говорит, что владеющий адаптер не поставляет ничего под этим ключом. Пометка следует одному этому ответу: наличие сохранённого профиля не делает маршрут custom — сужение моделей поставленного провайдера тоже сохраняет профиль, — а адаптер, не сообщающий ничего, оставляет свои строки без пометок — из этого нельзя заключить, что он их поставляет.

Шаг уведомления владеет своим точным текстом и версией в `src/onboarding-copy.ts`. На loopback он сравнивает и записывает `ui-onboarding.welcomeNoticeVersion` через существующий API настроек; только явный Continue записывает текущую версию. Браузер не на loopback не может использовать этот namespace, доступный только Host, поэтому подтверждение живёт в пределах процесса, и уведомление возвращается после перезагрузки.

После завершения этого уведомления шаг DeepSeek проецирует готовность первого запуска из того же соединённого снапшота Models. ЛЮБОЙ провайдер, которым пользователь уже может воспользоваться, завершает его без рендеринга — зарегистрированный маршрут, чья именованная ссылка credential сохранена, включая read-only credential из среды запуска, или маршрут, чей профиль не называет ссылки и потому аутентифицируется нативно. Только пользователю, у которого нет ни одного, предлагают официальный ключ DeepSeek. Смонтированный активный адаптер с отсутствующей writable-ссылкой рендерит существующий `ProviderEditor` в режиме только-credential внутри общей onboarding-модали; `credentials.set` остаётся единственной записью секрета, и никакие настройки провайдера не меняются. «Настроить позже» завершает только этот проход координатора. Отсутствующий адаптер, неактивный маршрут, неудавшийся join, read-only развёртывание или непригодная возможность settings или credentials завершают шаг без рендеринга; Models остаётся диагностической поверхностью.

Каждая правка отправляется как операции путей `settings.mutate` над сохранённым разделом — set на каждое изменённое поле, unset на каждое очищенное и один unset на удалённую строку провайдера. Страница всегда держит только дескриптор REDACTED, поэтому изменяет видимые ей поля, а не пересобирает раздел. `models` DeepSeek — один массив с заменой по значению: редактор показывает унаследованные эффективные строки, пока первая правка модели не материализует полный массив в пользовательском слое, а reset снимает это переопределение. Строка несёт id модели и display name; её контекстное окно и лимит вывода сидят за собственным раскрытием строки, с теми же полями, что использует форма провайдера pi-ai. Любая ёмкость вводится как число с необязательным десятичным суффиксом `K` или `M` (`256K`, `1M`; `1M` — это 1000K) и сохраняется как простое число, а читается обратно в кратчайшей форме, которая преобразуется без потерь. Пустые id, дубликаты id, пустые явные имена и нечитаемые, неположительные или дробные ёмкости отвергаются до любой записи. Введённый API-ключ проверяется по собственному полю так же: после обрезки пробелов он должен быть непустым, и каждый символ должен быть печатаемым ASCII (`[\x21-\x7E]`) — ровно то, что может нести значение HTTP-заголовка; это близнец `normalizeApiKey` из `@deepseek-ai/dsh-llm`, отражённый здесь, потому что разделение source-плоскости запрещает импортировать его. Значение, совпадающее с вставленной строкой окружения `NAME=value` или обёрнутое в парные кавычки, отвергается как та же ошибка формата; эта проверка вставленной строки выполняется только в браузере, поскольку ложное срабатывание в резолвере заставило бы среду тоже отказаться от ключа. Поле из одних пробелов отвергается с ошибкой, а не молча отбрасывается, тогда как пустое поле вовсе не ошибка: на карточке редактора оно означает «оставить сохранённый ключ», на карточке создания — «аутентифицируйся иначе». Отвергнутый ключ блокирует и запись, и опрос эндпоинта, поэтому страница никогда не тратит round trip, чтобы узнать то, что и так говорит поле. Каждая запись настроек несёт текущую `revision` карточки, поэтому параллельная запись из другой вкладки или внешняя правка `settings.yaml` отвергается как `settings-conflict`; после коммита настроек карточка принимает возвращённое redacted-поддерево пользователя и ревизию до сохранения credential, так что после неудавшегося этапа credential повторяется только этот этап. Удаление убирает настроенный writable-credential, только когда профиль называет выводимый страницей целевой `<ROUTE>_API_KEY`, затем делает unset профиля; обе операции идемпотентны, а частичный сбой остаётся в определённом диалоге подтверждения для повтора. Credential из окружения, кастомные ссылки и credential с неопознаваемой целью остаются нетронутыми. После загрузки страница подписывается напрямую на перенаправляемые owner-события `settings/document-updated`, `credentials/reference-updated` и `llm/adapters-updated` плюс локальный `connection/reset`, поэтому внешняя правка `settings.yaml`, вторая вкладка или родившийся из настроек маршрут сходятся без опроса.

## Список моделей и опрос эндпоинта

Список `models` профиля pi-ai редактируется на карточке: одна строка на модель с её id и display name, контекстное окно и лимит вывода — за построчным раскрытием, и два действия без подписей — развернуть и удалить — справа. Пустой список означает «обслуживай встроенный каталог этого маршрута», поэтому строку добавляют только намеренно; очистка ёмкости убирает её, а не сохраняет значение, которое схема отвергла бы, а маршрутные запасные значения адаптера задают размер всему, что конфигурация оставила неуказанным: пустая ёмкость показывает порядок величины этих запасных значений как placeholder, намёк, а не зеркало, ведь поле считает `K` равной 1000, а развёртывание может их переопределить. Ёмкость, не являющаяся положительным целым, просто не сохраняется.

**Fetch available models** спрашивает `llm.discoverModels` об эндпоинте, который форма показывает **прямо сейчас**, включая отредактированный, но ещё не сохранённый base URL и введённый, но ещё не сохранённый ключ, поэтому добавление провайдера — один проход вместо «сохрани и вернись». Ответ открывает пикер, а не записывается: уже настроенные кандидаты стартуют неотмеченными, поэтому принятие выбора никогда не перезапишет исправленную пользователем ёмкость. **Выбрать все** / **Снять все** меняют только текущие галочки пикера; ничто не записывается до **Добавить выбранное**. Провайдер, который нельзя опросить, — это обходной путь, а не тупик: собственное сообщение адаптера появляется рядом со строками, которые остаются редактируемыми вручную.

**Добавить кастомного провайдера** объявляет маршрут, которого pi-ai не поставляет. Это собственная карточка, а не редактор с дополнительными полями, потому что здесь выбирается id маршрута, а адрес настроек не существует, пока его не создадут: один `settings.mutate` устанавливает весь профиль по адресу `providers.<route>`, а ключ передаётся отдельно через `credentials.set` под тем же выводом `<ROUTE>_API_KEY`, что использует существующий провайдер. То, чего маршрут, объявленный вручную, не может взять по умолчанию, гейтит кнопку создания — уникальный **Provider ID**, эндпоинт, протокол и хотя бы одна однозначно идентифицированная модель, — поэтому сбой называет поле, пока пользователь ещё смотрит на него. Id обязан начинаться со строчной буквы, потому что это также основа выводимой ссылки credential, а ссылка — идентификатор POSIX shell: id, начинающийся с цифры, иначе пройдёт каждую проверку этой карточки и завершится ошибкой на seam'е credential с сырым регулярным выражением. Ёмкости её не гейтят: запасные значения адаптера задают размер модели, которую эндпоинт описал одним id, — именно это возвращают большинство листингов. Варианты протокола читаются из схемы самого пространства имён, а не из поля протокола и не из константы, поэтому они не могут разойтись с теми, что принимает адаптер. Карточка записывает стандартную ссылку `apiKeyEnv` только когда введён ключ — то же правило, что применяет редактор, — поэтому маршрут, объявленный ради провайдер-нативной аутентификации, не рождается указывающим на ссылку, которую никто никогда не установит. Когда запись профиля прошла, а запись ключа не удалась, провайдер уже существует: карточка фиксирует описывающие его поля, повторяет один credential — повторный запуск записи профиля передал бы ревизию, которую та запись только что вытеснила, поэтому Host ответил бы `settings-conflict`, и ключ никогда не был бы сохранён отсюда, — и сообщает о созданном провайдере, даже если пользователь затем отменяет.

Отсутствует: раздел рендерит браузерный UI конфигурации; ничто отсюда не достигает запроса к модели.

## Known Limitations and Deferred Work

- **На карточке редактируются только ключ API и поля курируемой секции** — рукописный редактор обменял схемно-общее покрытие полей на макетный вид ([Agent Note](../../../.agents/notes/implemented/architecture/2026-07-30-web-config-plane.md)). Оба семейства предоставляют `baseURL` и модельные `id`/`name`/`contextWindow`/`maxTokens`; объявленный вручную маршрут pi-ai также предоставляет `displayName` и `api`. Политика retry, таймауты, описания моделей DeepSeek и прочие продвинутые поля остаются в `settings.yaml`; существующие модельные поля, которых редактор не показывает, сохраняются. Схема профиля без обычных полей рендерит одну лишь подсказку, а два курируемых макета ключуются по именам пространств `llm-deepseek`/`llm-pi-ai`.
- **Очистка credential намеренно узка** — удаление строки убирает настроенный writable-credential, только когда его ссылка — точная цель `<ROUTE>_API_KEY`, которую выводит эта страница. Кастомные ссылки, credential из окружения и неопознаваемые цели сохраняются, потому что строка не может доказать владение ими.
- **Вручную объявлять можно только маршруты pi-ai** — карточка кастомного провайдера пишет в `llm-pi-ai`, единственное пространство имён, чьи профили описывают целого провайдера. Маршрут `llm-deepseek` — факт композиции, а не то, что эта страница может создать.
- **Опрос покрывает OpenAI-совместимые эндпоинты** — адаптер читает только этот формат ответа списка моделей, поэтому шлюз с другим протоколом сообщает, что спросить его нельзя, а его модели вводятся вручную.
- **Незаявленные live-маршруты нигде не рендерятся** — маршрут, зарегистрированный без объявления конфигурируемого провайдера, не имеет адреса настроек; он остаётся видимым в пикерах, но не в строках этой страницы.
