# @deepseek-ai/dsh-client-ui-skill

[English](README.md) | [中文](README.zh.md) | Русский

Источник вызова скиллов, браузерная половина: регистрирует источник `skill` триггера `/` в `ctx.inputTriggers`. Кандидаты обычной сессии приходят из RPC `skill.list`, адресуемого `{sessionId}` из проекции `ClientSessionContext` каждого вызова, причём хост разрешает `cwd` из заголовка сессии. Хост выдаёт каждый скилл, вызываемый пользователем; запись с `modelInvocable: false` (скилл с `disable-model-invocation`, чья единственная точка входа — этот путь) носит маркер «только для пользователя» как префикс описания на активном языке. Продолжаемые дочерние агенты, адресованные каталогом, не разрешают кандидатов скиллов локально, потому что существующий RPC скиллов требует присоединённой сессии; просмотр их персистентной истории НЕ ДОЛЖЕН их активировать. Каталоги кэшируются на обычную сессию с единственным параллельным запросом (single-flight); перехватчик `warm`, срабатывающий при рождении области, прогревает запись сессии, пересылаемое событие владельца `agent-preset/selected` сбрасывает запись этой одной сессии (каталог принадлежит пресету, а пустая сессия может переключить его после прогрева), а `connection/reset` очищает всё. Результаты фильтруются по `startsWith(query)`.

Выбор вставляет литеральный текст `/name `, и промпт отправляет тот же литерал ([Agent Note о слэш-конвейере](../../../.agents/notes/implemented/architecture/2026-07-25-web-input-machine-and-slash-pipeline.md)) — этот источник не реализует перехватчиков арбитража и кодека ссылок. Детерминизм живёт на стороне хоста: предшаговая граница жестов (`dsh-tool-skill`) распознаёт ограниченные пробелами токены `/name`, называющие вызываемые пользователем скиллы где угодно в пользовательском сообщении, и инъецирует отрендеренный `<skill_content>` для каждой точки входа, поэтому выбор в меню, набранный вручную токен и промпт TUI/ACP загружают скилл одинаково. Имя, разделяемое с командой хоста, всё же разрешается в команду: арбитраж захватывает строку на клиенте прежде, чем она станет промптом, — намеренный приоритет, совпадающий с однопорядковыми продуктами. RPC списка идёт по соединению корневого контекста плагина, захваченному при регистрации, — источник никогда не читает сервисы из аргумента отдельного вызова; визуальность чипов черновика выводится из сканирования `lexicon`.

Неудачный `skill.list` бросает исключение из `candidates`; слэш-оболочка журналирует его и молча убирает группу меню — меню показывает только состояния ожидания/готовности.

Экспорты `/client` — только тело плагина (`apply`/`inject`); объект источника внутренний для эффекта регистрации.

## Строка инструмента скиллов

Браузерный плагин также регистрирует протокольное имя `skill` в ключёванном slot'е `tool.call.toolview` пакета `ui-tool`. Свёрнутая строка рендерит 14-пиксельный глиф «документ и искра» скилла, заголовок `Skill`, разделитель и имя запрошенного скилла с той же нейтральной иерархией, что строка Bash; исполняющиеся вызовы несут мерцание транскрипта, отказы заменяют имя первой строкой ошибки, а прерванные вызовы используют предупреждающее состояние. Завершённая строка раскрывается одним раскрытием всей строки в ограниченную карточку `Instructions`, содержащую точный долговечный вывод инструмента, со стандартным аффордансом `Inspect` траектории, когда он доступен. Строка выводит своё имя, жизненный цикл и тело только из замороженного среза вызова/результата, поставляемого `ui-tool`, и никогда из текущего каталога, поэтому воспроизведение остаётся стабильным при смене установленных скиллов или их описаний.

## Model Experience

### Вызов скилла, инициированный пользователем

#### Что видит модель

Сообщение пользователя доходит до модели дословно, включая литерал `/name`. Затем предшаговая граница хоста (`dsh-tool-skill`) добавляет канонический блок `<skill_content>` — тот же вывод `renderSkillContent`, который возвращает инструмент `skill`, — как инъецированный контекст наставлений в конце инъекций этого шага, ближе всего к ответу модели. Загрузка детерминирована: модель получает полное тело без просьбы вызвать инструмент `skill`, а каталог велит ей не перезагружать встроенно инъецированный скилл.

#### Эффект на токены

Один вызов добавляет отрендеренное тело скилла в тот ход как инъецированный контекст — та же стоимость, что у загрузки скилла моделью через инструмент, но оплачиваемая безусловно, а не по усмотрению модели. Просмотр меню и выборка кандидатов не добавляют ни одного модельного токена.

#### KV Cache effect

Append-only: инъецированное сообщение встаёт после переиспользуемого префикса истории. Этот пакет никогда не правит более ранние токены запроса.

## Known Limitations and Deferred Work

- **Страницы истории с одним лишь результатом используют общую строку** — ключёванная диспетчеризация требует парного вызова в окне рантайма; пагинация, оставляющая вызов за пределами, не имеет идентичности инструмента. Эта клиентская презентационная функция не расширяет протокольный контракт истории ради её восстановления.
- **Текст — истина** — ссылка есть простой текст черновика; набранный вручную идентичный токен — та же ссылка, а граница жестов хоста судит отправленный текст, а не взаимодействие с меню. Визуальность чипов выводится из сканирования лексикона; никакой идентичности вхождения, отслеживания позиции или структурированной полезной нагрузки ссылки при передаче промпта нет (и то и другое — записи реестра задач).
- **Меню, открытое до завершения прогрева**, не показывает кандидатов скиллов на то нажатие клавиши; следующее нажатие переспрашивает устоявшийся кэш.
