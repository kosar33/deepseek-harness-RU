# @deepseek-ai/dsh-client-ui-slots

[English](README.md) | [中文](README.zh.md) | Русский

Чистое ядро реестра slot'ов, терминальный дизайн slot'ов: слияние объявлений SlotMap, единственный композиционный API `register` на SlotCore, семейство типов пропсов компонентов из четырёх долей, семейство типов места хранилища и контракт установки рендерера. От React — только типы: пакет свободен от React и cordis.

Один вызов `register({ name, children?, store?, inject?, ...kind }, Component)` вносит компонент в объявленный slot и тем же вздохом объявляет дочерние slot'ы (объявление = авторизация рендера = спецификация времени выполнения, одна таблица), место хранилища и бизнес-грань регистранта. Компонент проверяется в месте вызова против `ComposedProps` — пересечения четырёх долей, каждая из которых выведена из своего единственного источника истины:

| доля | тип | источник |
|---|---|---|
| рантайм | `PropsRuntime<K>` | запись SlotMap: `owner` (место вызова renderSlot родителя) + стандартный набор сессии + глобальное место |
| дочерний рендер | `PropsRenderSlots<S>` | множество ключей `children` вызова register (статически сужаемый `renderSlot`) |
| хранилище | `PropsStore<H>` | объявленный дескриптор: селекторный хук `useStore` + `actions` без черновика |
| бизнес-грань | `I` | выводится из возвращаемого значения фабрики `inject` |

Slot'ы цепочечного вида обращают маршрутизацию по ключу — записи выдвигают себя сами, вместо того чтобы место диспетчеризации выбирало `entryKey`: каждая регистрация несёт чистый селектор `ChainSelect` (плюс необязательный возрастающий `priority`, при равенстве решает порядок регистрации), первый ненулевой возврат избирает свою запись и становится пропсом `matched` компонента, а сплошные null падают в запасной вариант владельца `renderSlotChain` (`ChainRenderOpts`).

Интерфейсы стандартного набора (`SessionStandardProps`, `GlobalStandardProps`) объявлены здесь пустыми и сливаются пакетом рантайма (тот же шаблон declare-merge, что у ключей SlotMap). Рендерер связывает наблюдаемые источники сессии и workspace рантайма в селекторные хуки. Параметры фабрики inject выводятся из объявления (`InjectParams`): session-slot'ы получают `sessionId`, объявленное хранилище добавляет очищенные от черновика `actions`, и больше ничего — доступ к данным живёт в ctx замыкания apply.

Семейство хранилища (спецификация `defineStore` на входе / `StoreHandle<T, A>` на выходе) типизирует место хранилища: `init` выводит схему состояния, `actions` — полный набор записывающих преобразований черновика, а `BakedActions` снимает параметр черновика, оставляя колбэки, которые получают компоненты и фабрики inject. Реализация значения `defineStore` живёт в пакете рантайма (дом движка) и удовлетворяет экспортируемому здесь контракту `DefineStore`. Продукты движка и контракт хоста рендерера несут голые snapshot-источники (`getSnapshot`/`subscribe`), но никогда хуки React — привязка хуков принадлежит механике рендера; здесь живёт лишь тип хука из контракта пропсов (`SnapshotSelectorHook`).

`SlotCore` засеивает априорный slot `'root'` при построении и принуждает валидацию времени загрузки (регистрация в необъявленный slot, дублирующее объявление ребёнка, один разделяемый дескриптор под двумя scope, цепочечная регистрация без `select` — всё это бросает исключение на register). Disposer записи рекурсивно схлопывает объявленные ею дочерние slot'ы: строки гроссбуха, вклады и монтирования хранилищ умирают на одной оси жизненного цикла. Каждый ключ несёт также эпоху объявления, которая продвигается только при объявлении и схлопывании; рантайм использует её для [`ctx.slots.inject`](../runtime/README.ru.md#инъекция-объявления-slotа) независимо от обычных версий записей. `renderer.ts` несёт контракт установки (`SlotRenderer`, `SlotRendererHost`) плюс `StaleAuthorizationError`/`SlotOwnershipError`; ui-renderer владеет и реализацией, и её установкой на жизненном цикле плагина.

## Опыт модели

Отсутствует: реестр slot'ов — браузерная UI-обвязка; ничто здесь не достигает запроса к модели.

#### Влияние на KV-кэш

Отсутствует; этот пакет ни собирает, ни отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **`isLive` сканирует все записи линейно** — приемлемо при счёте регистраций UI-плагинов (десятки); вернуться к этому вопросу с обратной ссылкой запись→запись, если гроссбухи когда-нибудь разгорячатся.
- **Фантомный якорь `__renders` виден на `PropsRenderSlots`** — тот же принятый шум, что `__accepts` в дизайне цепочки типов: обобщённые сигнатуры методов сравниваются свободно по объединениям ключей, поэтому именно контравариантный маркер принуждает «множество ключей компонента ⊆ объявлению детей».
