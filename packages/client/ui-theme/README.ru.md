# @deepseek-ai/dsh-client-ui-theme

[English](README.md) | [中文](README.zh.md) | Русский

Плагин темы: ThemeRuntime поверх базовых таблиц стилей токенов `--dsw-*` (статический масштаб + семантический слой псевдонимов). Сервис владеет актуальным предпочтением темы (`light`/`dark`/`system`), разрешает `system` через `prefers-color-scheme` и публикует неизменяемые `ThemeSnapshot` в событии `theme/change`; сам он DOM не касается — презентер ui-layout применяет разрешённый снапшот (`html { color-scheme }`, `body[data-ds-dark-theme]` и строчные псевдонимные токены). Браузер, подключающийся по loopback, получает сервис сразу со значением `system`, затем в фоне загружает `ui-theme.preference` и записывает каждый выбор встроенной темы через Host settings API, чей локальный провайдер по умолчанию хранит его в `$DSH_HOME/settings.yaml`; Push-изменения настроек и переподключения перечитывают значение, быстрые выборы сериализуются в порядке жестов с ревизиями пространств имён, а отклонённая последняя запись возвращает перечитанное долговечное значение. Удалённый браузер не имеет доступа к привилегированному settings API, поэтому его выбор остаётся локальным для процесса. Сторонние зарегистрированные id тем остаются внутрипроцессным расширением и не пересекают схему встроенных настроек; удаление такой темы никогда не перезаписывает последнее долговечное встроенное предпочтение. Границу персистентности задаёт [решение о предпочтениях на стороне Host](../../../.agents/notes/implemented/bug-fix/2026-08-06-host-backed-web-preferences.md).

Когда композиция хоста включает HTTP-сервер, хостовая половина внедряет синхронный бутстрап непосредственно после открывающего тега `<body>`. Каждый ответ index встраивает зарегистрированную настройку Host для `ui-theme.preference`, а при отсутствии провайдера настроек — `system`; браузер разрешает `system` по схеме ОС и затем устанавливает `color-scheme` и `body[data-ds-dark-theme]` до того, как отрисуется загрузочная страница оболочки. Композиции без HTTP-сервера остаются незатронутыми, а ThemeRuntime и ui-layout остаются авторитетными за клиентское состояние и последующие обновления DOM и после активации дерева плагинов.

В `src/styles/` лежат пять таблиц стилей, которые динамический клиентский вход ui-theme импортирует по порядку: `base.css`, `design-platform.css`, `scrollbar.css`, `gradient-shadow-text.css` и `shiki.css`. Клиентский бандл компилирует и внедряет их как глобальные стили, принадлежащие плагину, поэтому выгрузка и HMR удаляют их вместе с ui-theme, а не оставляют CSS темы в статической веб-оболочке. `scrollbar.css` — единственный потребитель токенов `--dsw-alias-scrollbar-*` и обязан следовать за `design-platform.css`, которая их объявляет.

Контракт перепривязки скроллбара: `scrollbar.css` привязывает `--dsh-scrollbar-thumb` и `--dsh-scrollbar-thumb-hover` на `body` к токенам l1 (базовой поверхности), и оба пути рендеринга читают эту пару. Приподнятая поверхность (меню, поповер, диалог) устанавливает `--dsh-scrollbar-thumb: var(--dsw-alias-scrollbar-bg-l2)` и `--dsh-scrollbar-thumb-hover: var(--dsw-alias-scrollbar-hover-l2)` на собственном контейнере; одна перепривязка перекрашивает любой из путей, каким бы ни пошёл движок. Вторая законная цель этой пары — `transparent`, который вообще не рисует ползунок, — так [ui-sidebar](../ui-sidebar/README.md) перепривязывает свою колонку, пока указатель находится в другом месте. Перепривязка к паре l1 перепривязкой не является: она заново утверждает умолчание базовой поверхности. `--dsh-scrollbar-width` зеркалирует ширину WebKit-полосы в раскладке для поверхностей, выстраивающихся вплотную к занимающей место полосе, — [ui-conversation](../ui-conversation/README.ru.md) читает её для смещения `right` места оверлейного композера, — и спецификация стилей скроллбаров связывает её с зеркалящим правилом и этим потребителем.

Эти два пути взаимоисключающие по построению. `scrollbar-width`/`scrollbar-color` находятся внутри `@supports not selector(::-webkit-scrollbar)`, потому что любое значение, отличное от `auto`, у любого из них заставляет Chromium и Safari отбросить все правила `::-webkit-scrollbar*` для этого элемента, включая `::-webkit-scrollbar-thumb:hover`, — безусловное объявление обоих оставляет `--dsh-scrollbar-thumb-hover` без рендеринга где бы то ни было. Поэтому Firefox берёт стандартные свойства, а движки на базе WebKit — псевдоэлементы, так что hover-токен отрисовывается только через путь псевдоэлементов. Рассуждение и измеренные computed-значения: [Agent Note о тематизированных скроллбарах](../../../.agents/notes/implemented/bug-fix/2026-07-28-themed-scrollbars-and-reserved-gutter.md).

## Model Experience

Нет: сервис темы управляет предпочтением браузера, и ничто отсюда не попадает в запрос к модели.

#### KV Cache effect

Нет; этот пакет не собирает и не отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Сторонние темы — точка расширения, а не продукт** — регистрация такой темы означает переопределение одноимённых псевдонимных переменных; проверки полноты набора переопределений не существует.
- **Токенные таблицы — единственный авторитет в цвете** — значения, отсутствующие в cssdesign (например, синий цвет вкладки #4176E6 из дизайна), намеренно не дописываются; побеждает ближайший семантический токен. Добавления, одобренные владельцем дизайна, — исключение: они входят статическим шагом плюс семантическим псевдонимом в одном изменении (`--dsw-static-blue-900` / `--dsw-alias-label-primary-bluish`).
