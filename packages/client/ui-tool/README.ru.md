# @deepseek-ai/dsh-client-ui-tool

[English](README.md) | [中文](README.zh.md) | Русский

Клиентский плагин представления инструментов. `ui-conversation` направляет каждый упорядоченный узел диалога `tool-call` по совпадающему ключу `conversation.chat.node`; этот пакет рендерит его корень и дочерние элементы Code Dispatch, а каждый атомарный вызов направляет через ключевой slot `tool.call.toolview`. Незарегистрированные имена инструментов получают универсальную карточку.

Бизнес-пакеты UI регистрируют только имена своих инструментов из протокола и атомарные представления. Они не сопоставляют события сессии, не пересобирают транскрипт и не владеют топологией корень/подвызов. Рантайм остаётся авторитетным в сопоставлении вызова с результатом, жизненном цикле и рекурсивной проекции `subCalls`; представление диалога остаётся авторитетным в размещении ChatFlow.

## Контракт рендеринга

`ToolCallTree` получает один корневой `ToolCallBlock`, который уже содержит рекурсивные `subCalls`, состояние выделения, `cwd` сессии и колбэки Host для открытия файлов и инспекции вызовов. Он рекурсивно обходит стандартные блоки вызовов и проводит корень и потомков на каждой глубине через один и тот же путь атомарной диспетчеризации, не подписываясь на отдельную карту «родитель — потомки».

Каждая обёртка корня и потомка сохраняет DOM-контракт `data-chat-anchor-key="call:<id>"` и `data-chat-call-id`, используемый для постраничной навигации и выделения.

Пакет также заполняет `conversation.details.tool` значением `ToolDetails`. Рендереры строки и деталей разделяют одни и те же чистые модели карточек для намерений рендера `terminal`, `read`, `diff`, `search` и `web`. Неизвестные теги намерений и искажённые данные карточек в протоколе откатываются к плоскому тексту результата инструмента.

Универсальные строки классифицируют известные имена инструментов в варианты search, read, shell, write, edit, code или generic. Состояния жизненного цикла running, successful, failed и interrupted приходят только из замороженного среза пары вызов/результат. Пути файлов разрешаются относительно `cwd` сессии только тогда, когда пользователь вызывает колбэк Host на открытие файла; код представления не читает сервисы Session.

## Атомарные представления инструментов

Владеющий бизнес-пакет регистрирует имя своего инструмента из протокола в `tool.call.toolview`:

```ts ignore-check
ctx.slots.inject('tool.call.toolview', () =>
  ctx.slots.register({
    name: 'tool.call.toolview',
    key: '<wire tool name>',
  }, BusinessToolRow))
```

Полезная нагрузка владельца — `ToolCallOwnerProps`: `callId`, `toolName`, замороженный `block`, необязательные `cwd` и `home` и простые колбэки `openFile`/`inspect`. Сводки путей сначала делаются относительными к cwd сессии, затем заменяют остаточную POSIX-домашнюю папку хоста на `~`; `filePath` и открытие через Host сохраняют авторский путь файловой системы. Регистрация получает обычную долю рантайма session slot'а. Она не получает ни React-узлов, ни сервисов рантайма, ни знания о корне и подвызовах.

Этот пакет сейчас владеет универсальным запасным вариантом и встроенными представлениями shell/pwsh, read, write/edit, grep/glob, web, todo, question и Code Dispatch. `ui-skill` демонстрирует бизнес-регистрацию для `skill`.

Специфичные для карточек лимиты и правила отката остаются в владеющих заметках: [terminal](../../../.agents/notes/implemented/feature/2026-07-28-web-terminal-card.md), [diff](../../../.agents/notes/implemented/feature/2026-07-30-web-diff-card.md), [read](../../../.agents/notes/implemented/feature/2026-07-30-web-read-card-frontend.md), [search](../../../.agents/notes/implemented/feature/2026-07-30-web-search-card.md) и [web](../../../.agents/notes/implemented/feature/2026-07-30-web-result-card-frontend.md).

## Опыт модели

Отсутствует: этот пакет рендерит уже записанные вызовы инструментов и их результаты, не меняя запросы к модели, выполнение инструментов и события сессии.

#### Влияние на KV-кэш

Отсутствует. Пакет — чистое клиентское представление.

## Известные ограничения и отложенная работа

- Host исключает `run_code` из привязок программы Code Mode, поэтому производственные события дают один уровень диспетчеризации; рекурсивный контракт рантайма и UI поддерживает вложенность.
- Представления инструментов первой стороны расположены здесь и могут независимо переезжать в свои владеющие бизнес-пакеты через ключевой slot.
- Тексты инструментов повторно используют namespace локали `ui-conversation`.
