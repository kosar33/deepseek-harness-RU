# @deepseek-ai/dsh-client-ui-workflow-run

[English](README.md) | [中文](README.zh.md) | Русский

Браузерный плагин, восстанавливающий долговечные запуски воркфлоу верхнего уровня как независимые Chat-узлы. Он потребляет четыре события сессии `tool-workflow/*`, принадлежащие [`dsh-tool-workflow`](../../workflow/tool-workflow/README.ru.md), регистрирует одно `ConversationNodeDefinition` и выполняет рендеринг через ключевой slot `conversation.chat.node`, не трогая существующую карточку инструмента воркфлоу.

## Долговечное состояние и воспроизведение

`tool-workflow/run-start` создаёт один Context с ключом `runId`; старты участников, завершения участников и завершение запуска обновляют этот Context в порядке журнала. Хвост истории, содержащий одни лишь обновления, остаётся в ожидании, пока более старая страница не доставит единственный старт; после этого prepend, полное воспроизведение и живое дописывание дают одно и то же состояние. Закрытый Turn или Step с отсутствующими терминальными событиями показывает затронутый запуск или участников как прерванные, не меняя результат инструмента.

Группы фаз образуют только участники, которые действительно стартовали. Одинаковые строки фаз попадают в одну группу, опущенная фаза отличается от пустой строки, а завершение меняет статус, не удаляя и не переставляя участников.

## Представление и навигация

Запуск и каждая фаза представляют собой управляемые раскрывающиеся разделы при любом статусе. При монтаже уровни running, failed, cancelled и interrupted раскрываются, а полностью завершённые уровни сворачиваются; далее пользователь может переключать любой уровень щелчком по всей строке, Enter или Space. Обычные обновления работающего запуска сохраняют текущий выбор, первый ненормальный переход раскрывает уровень один раз, нормальное завершение сворачивает его один раз, а завершённая фаза вместе с внешним запуском раскрываются вновь, когда под тем же ключом фазы стартует новый работающий участник. Если целый новый чистый цикл приходит за один рендер, пока запуск ещё активен, фаза остаётся свёрнутой, но внешний запуск раскрывается один раз, показывая обновлённую сводку. Завершение сразу обновляет видимый статус, но откладывает автоматическое сворачивание, пока фокус остаётся внутри содержимого. Выборами фаз владеет `WorkflowRunPanel`, поэтому закрытие и повторное открытие внешнего запуска их не сбрасывает; перемонтирование рендерера восстанавливает каждый исходный выбор из долговечных фактов. Запуск использует строку высотой 32 пикселя с фоном `--dsw-alias-bg-module-platform`, постоянными шевронами вправо/вниз и строчной точкой состояния с текстом статуса, без бейджа. Фазы используют раскрывающиеся строки высотой 32 пикселя с заголовком и числом участников в гибкой основной области и фиксированным точным хвостом агрегированного статуса, без дополнительной точки. Участники используют позицию точки размером 16 пикселей, обрезаемую область имени и фиксированную колонку статуса шириной 64 пикселя.

Участник открывает дочернюю сессию только тогда, когда сходятся все текущие факты: участник работает, идентификатор потомка присутствует в обычном списке сессий, у строки указано `origin: 'subagent'`, её `parentId` — текущая сессия, а строка списка всё ещё работает. Подчёркнутый текст участника — единственный видимый признак возможности навигации; клавиатурный фокус рисует кольцо цвета business-primary толщиной два пикселя вокруг области имени, тогда как текст статуса остаётся `Running`. Компонент вызывает только внедрённое обычное действие `sessions.open(id)`; удалённые, только адресованные, с чужим родителем и терминальные строки остаются неинтерактивными.

## Композиция

Пакет регистрирует свой Definition, словарь локализации и рендерер `workflow-run` как эффекты Cordis. Удаление клиентской записи отзывает все три вклада. Поставляемый веб-бандл включает плагин после `ui-conversation` и `ui-tool`.

## Опыт модели

Отсутствует: этот пакет отображает человеку долговечные факты сессии и не добавляет ни промпта, ни схемы инструмента, ни содержимого запроса, ни видимого модели результата.

#### Влияние на KV-кэш

Отсутствует.

## Известные ограничения и отложенная работа

- Эти записи создают только вызовы верхнего уровня через `dsh-tool-workflow`; вложенные вызовы Code Mode и прямые потребители `WorkflowEngine` — нет.
- Навигация намеренно доступна только в живой сессии. Завершённые участники остаются видимыми для обзора, но этот узел никогда не предлагает открыть их холодную сессию.
- Узел показывает только запуск, фазу, идентификацию участников и статус; скрипты, выводы, ошибки, журналы, расход токенов, статическая топология и элементы управления остаются вне этой поверхности.
