# @deepseek-ai/dsh-code-runtime-python

[English](README.md) | [中文](README.zh.md) | Русский

Реализация seam'а [`@deepseek-ai/dsh-code-runtime`](../code-runtime/README.ru.md) на субпроцессах CPython. Спутник [`@deepseek-ai/dsh-code-runtime-worker-thread`](../code-runtime-worker-thread/README.ru.md); меняет воркер-тред Node на свежий субпроцесс `python3`, чтобы код модели был на Python, а не на TypeScript.

Пакет владеет форматом протокола этого seam'а: кодеком кадров на стороне хоста и питоновским зеркалом того же словаря сообщений.

## Формат протокола

Хост и субпроцесс CPython обмениваются неверсионируемым протоколом JSON-lines по fd 3 дочернего процесса — один JSON-объект на строку, оставляя stdout/stderr свободными для собственного вывода программы. `src/protocol.ts` — сторона хоста; `py/protocol.py` зеркалит формы его сообщений и общий текст маркера усечения на стороне Python.

- **fd 3, а не stdout** — Node закрепляет канал позиционно через `stdio: ['pipe','pipe','pipe','pipe']`; питоновский bootstrap читает ту же константу `PROTOCOL_FD`. Обрамление JSON-lines.
- **Хост считает каждый входящий кадр враждебным** — код модели имеет полный доступ к fd 3 и может прислать через него что угодно, поэтому `validateChildFrame` проверяет форму и ПЕРЕСОБИРАЕТ каждый кадр прежде, чем хост его прочитает: поддельные лишние поля никогда не проезжают, call id не-числом не может отразиться эхом в ответе, а мусор оседает в `undefined` вместо броска в обработчике сообщений хоста. Сторона Python доверяет ответам хоста (хост не контролируется моделью).
- **Переход lossless-JSON** — значения завершения и аргументы биндингов переходят как точный JSON. `encodeJsonPlain` сериализует значение, порождённое `JSON.parse`, без рекурсии, поэтому глубокое значение в пределах байтового бюджета переходит целым, а не гибнет на пределе стека `JSON.stringify`; `checkDoneValue` одним обходом меряет у поддельного значения завершения байтовую длину И losslessness чисел и отбрасывает перерасходованную полезную нагрузку до той инкрементальной работы, которую она добавила бы (постановку детей в очередь; строки и ключи меряются невыделяющим память сканом экранированного размера, поэтому экранированная копия никогда не материализуется) — собственная ширина кадра уже разобрана и ограничена выше по течению приёмным буфером fd-3 хоста и здесь повторно не ограничивается; `hasUnsafeIntegerToken` читает сырой текст кадра, ловя целый литерал, который `JSON.parse` молча округлил бы; `hasNonLosslessNumber` отвергает не-конечное или отрицательно-нулевое число в неограниченных `call.args`. Интегральные double вне safe-диапазона сериализуются цифрами `BigInt`, поэтому переходит точное целое, а не округлённая форма `String()`.
- **Общий маркер усечения** — `logTruncationMarker(maxBytes)` выдаёт побайтово идентичный текст на обеих сторонах, поэтому усечённый прогон лога читается одинаково, каким бы образом предел ни был достигнут. Флаг `truncated` кадра `log` отличает собственный маркер детского ledger от вывода программы.

## Влияние на модель

Опосредованно — через Code Mode в [`dsh-tools`](../../core/tools/README.ru.md), который рендерит в удерживаемый результат `run_code` точное значение завершения этого бэкенда, когда оно помещается (или явный отказ `invalid-output` / `output-limit`), плюс точный маркер лога `[dsh-code-runtime-python] log capture truncated at <maxLogBytes> bytes`.

#### Влияние на KV-кэш

Прямой инвалидации нет; за изменения префикса запроса отвечает названный потребитель.

## Известные ограничения и отложенная работа

- **Межъязыковая защита покрывает исполняемые рантаймом поверхности и формы полей кадров** — `tests/protocol-mirror.e2e.ts` спавнит настоящий `python3` и против `src/protocol.ts` проверяет одновременно `PROTOCOL_FD` / текст маркера усечения лога И требуемый/необязательный набор проводных полей каждого `TypedDict` в `py/protocol.py`. Чего он не сравнивает, так это *типы* полей (например, что `cpuSeconds` — `int` на обеих сторонах): сравнение объявлений типов между TypeScript и Python не имеет здесь механического эквивалента, поэтому дрейф на уровне типов по-прежнему ловят ревью плюс набор тестов бэкенда на настоящих субпроцессах, а не тесты этого пакета.
- **`src/index.ts` экспортирует только словарь протокола** — в пакете нет пути исполнения субпроцессов и питоновского кодека JSON, поэтому ничто здесь не спавнит `python3` вне зеркального теста.
