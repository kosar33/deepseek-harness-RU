# @deepseek-ai/dsh-code-runtime-worker-thread

[English](README.md) | [中文](README.zh.md) | Русский

Реализация seam'а [`@deepseek-ai/dsh-code-runtime`](../code-runtime/README.md) на воркер-тредах: `WorkerThreadCodeRuntime` гоняет каждую программу в ОДИН свежий Node `worker_threads.Worker` — на входе TypeScript, типы стираются на стороне хоста, биндинги наводятся мостом через message port, на выходе `{ value, logs, error? }`. **Сдерживание, а не граница безопасности**: позиция доверия равноценна bash по дизайну ([Agent Note о Code Mode](../../../.agents/notes/implemented/feature/2026-06-15-code-mode.md), раздел «Trust posture»), но с сдерживанием, которого у bash нет, — отдельный изолят, пустое окружение, предел кучи, жёсткое завершение.

## Конфигурация

```yaml
- id: code-runtime
  name: '@deepseek-ai/dsh-code-runtime-worker-thread'
  config:
    computeMs: 60000              # busy-time budget (measured event-loop active time)
    maxWallMs: 600000             # wall-clock ceiling; never pauses for anything
    maxOutputBytes: 67108864      # combined serialized outer-output cap (64 MiB)
    maxOldGenerationSizeMb: 512   # worker heap cap (resourceLimits)
```

Каждое поле валидируется и получает значение по умолчанию; `maxOutputBytes` — safe integer минимум четырёх байт, остальные поля — положительные конечные числа, `maxWallMs` вдобавок не больше `2147483647` (максимальная задержка `setTimeout` в Node), других настроечных величин нет.

## Устройство

- **Один свежий воркер на запуск, без пула** — мир программы умирает вместе с воркером: межзапускного состояния для журнала нет, протечку состояния невозможно даже выразить, запуски восстанавливаются из одного лишь журнала сессии.
- **Стирание типов на стороне хоста, в контексте исполнения** — программа заворачивается в оболочку async-функции, стирается через `stripTypeScriptTypes` из `node:module` (только erasable-синтаксис — `enum`/неймспейсы отвергаются как `exception` программы, и воркер не спавнится), а затем вырезается обратно по байтовым позициям; исполняется она как тело `AsyncFunction`, поэтому top-level `await`/`return` работают.
- **Порт считает пир враждебным** — код модели может достать `parentPort` и подделывать трафик, поэтому каждое входящее сообщение проходит проверку формы и ПЕРЕСОБИРАЕТСЯ до того, как его прочитает кто угодно (`null`, примитивы, мусорные типы и искажённые полезные нагрузки отбрасываются без броска; поддельные лишние поля никогда не проезжают), хост отвечает на каждый call id максимум однажды, разрешает имена биндингов только как СОБСТВЕННЫЕ свойства (поддельный `constructor` не сможет пройтись по цепочке прототипов), отбрасывает ответы после settlement и валидирует каждое разрешение биндинга и каждое завершение как lossless JSON. Поддельные сообщения `log`/`done` внешний лимит не обходят: хост повторяет валидацию и учитывает каждый пропущенный лог плюс завершение или диагностику. Воркерские неймспейсы создаются с null-прототипом через `defineProperty`, поэтому имена биндингов вида `__proto__` остаются обычными ключами.
- **Классы отвержения биндингов — данные запроса** — необязательный дескриптор неймспейса называет конструктор-глобал и собственное свойство, принимающее имя неудачного члена. Воркер материализует и внедряет тот настоящий класс, поэтому `instanceof` работает без хардкода `tools` или `ToolCallError`; объявления с неверными или коллидирующими глобалами падают до спавна воркера. Отказы используют захваченные модулем интринсики ошибок и определения свойств плюс дескрипторы с null-прототипом, поэтому позднейшие мутации модели не могут превратить отвергнутый биндинг в краш воркера.
- **Два независимых бюджета, потому что пир враждебен** — `computeMs` меряет ИЗМЕРЕННОЕ занятое время воркера (опрос `worker.performance.eventLoopUtilization()`): горячий цикл не может спрятаться за висящей приманкой-диспетчем, а программа, ждущая медленный инструмент, ничего не накапливает. `maxWallMs` подстилает то, чего занятое время не видит (ожидание промиса, которого никто не разрешит). Оба бюджета стекаются в `worker.terminate()`, добивающий и горячие синхронные циклы; переполнение кучи проявляется как OOM-выход воркера (`kind: 'worker-exit'`). `maxWallMs` при загрузке проверяется на диапазон против `MAX_TIMER_DELAY_MS`: `setTimeout` зажимает большую задержку до 1 мс, поэтому одна проверка положительности приняла бы потолок, истекающий на первом же тике. `computeMs` такой границы не требует — он сравнивается с измеренной утилизацией, а не скармливается таймеру.
- **Промежуточные значения биндингов — полный JSON** — аргументы и результаты биндингов проходят итеративную lossless-JSON валидацию. До исполнения программы воркер захватывает идентичности прототипов plain-container собственного realm плюс проверку исходника нативных функций, применяемую только к чужим realm'ам, поэтому мутация слота конструктора и самодельные самозванцы не могут изменить классификацию контейнера. Он также захватывает каждую структурную и учётную интринсику этого JSON-рубежа, создаёт дескрипторы свойств без прототипа и обходит мутабельные прототипы коллекций для приватного состояния обхода; поэтому мутации глобалов, методов прототипов или полей `Object.prototype` вида дескрипторов не могут изменить ни валидацию, ни проводный транспорт, ни байтовый учёт. Значения сплющиваются в wire value ограниченной глубины в pre-order для structured clone и итеративно пересобираются на другой стороне. Байтового предела, предела стека вызовов JavaScript или глубины вложенного structured clone у них нет. Во внешний ledger вывода и в контекст модели они не попадают; пределами остаются границы получения провайдера/исполнителя и память процесса/воркера.
- **Логи eagerly текут в один внешний ledger** — текст console/stdout/stderr переходит порт в порядке эмиссии, поэтому программа, вышедшая по таймауту или убитая, всё равно показывает напечатанное. Воркер начисляет точные байты JSON-строк и прогоняет preflight значений завершения и диагностик исключений против оставшегося комбинированного бюджета до их отправки; поэтому выброшенный миллионбайтовый стек превращается в фиксированную диагностику `output-limit` на рубеже воркера. Нативные записи, минующие пропатченные слоты потоков, приходят по пайпам, независимым от порта завершения, поэтому хост повторяет ledger для этих байтов и враждебного поддельного трафика; settlement продолжает ограниченный захват пайпов до полного завершения termination воркера, прежде чем материализовать результат. `maxOutputBytes` учитывает JSON-сериализацию внешнего массива `logs` плюс значение завершения или payload сообщения об отказе; фиксированные имена полей `CodeRunResult`, фигурные скобки, ограниченный тег вида ошибки и позднейшие презентационные пробелы находятся вне этого ledger переменной полезной нагрузки. На пределе или ниже возвращается точное значение; потеряющее данные завершение — это `invalid-output`, а комбинированное переполнение — `output-limit`, а не подменённая инспектированная строка. Отказ удерживает подходящий захваченный префикс и позже следует нормальной внешней политике spill `run_code`.
- **Пустое окружение** — воркер получает `env: {}` и `execArgv: []`: никаких фоновых учётных данных (сильнее правила вычищенного окружения для спавненных команд) и никаких унаследованных loader-флагов.
- **Освобождение ресурсов до quiescence** — teardown топит незавершённые запуски как `abort` и ОЖИДАЕТ выход каждого воркера, прежде чем разрешиться.

## Воркерная точка входа: исходная и собранная

Исходный режим загружает только-erasable `src/worker.ts` через нативное стирание типов Node. Его транзитивное рантаймное замыкание содержит только встроенные модули Node и относительные исходники, поэтому свежий checkout никогда не требует несобранного экспорта `lib/` соседнего пакетa workspace. Воркер-локальный и принадлежащий сессии JSON-рубежи одинаково сплющивают и пересобирают валидированные значения вокруг message port, чтобы вложенность приложения никогда не доставала до structured clone. Собранный режим передаёт соседний `lib/worker.cjs` путём файловой системы, потому что VFS Worker hook pkg ожидает CommonJS; тот же путь работает и под обычным Node. Требование репозитория упражнять этот опубликованный путь входа принадлежит [политике тестирования](../../../docs/testing.ru.md).

API SDK — класс `WorkerThreadCodeRuntime` (дефолтный и именованный экспорт) плюс `Config`. Рабочий субпуть `./worker` существует только как упакованная точка спавна; проводной протокол и bootstrap-хелперы — приватные для исходников детали реализации.

## Влияние на модель

Опосредованно — через Code Mode в [`dsh-tools`](../../core/tools/README.ru.md), который рендерит точное внешнее значение, когда оно помещается, либо явный отказ `invalid-output` / `output-limit`. В контекст модели попадает только внешний результат `run_code` со своей обычной политикой spill; биндинговый трафик и промежуточные значения остаются локальными для исполнения.

#### Влияние на KV-кэш

Прямой инвалидации нет; за изменения префикса запроса отвечает названный потребитель.

## Известные ограничения и отложенная работа

- **ОС-процессы, заспавненные программой, переживают завершение** — `worker.terminate()` гасит только тред, что слабее убийства группы процессов в bash-local; уборка сирот — забота развёртывания, пока не появился контейнерный бэкенд.
- **Стирание типов едет на экспериментальном API Node `stripTypeScriptTypes`** — amaro и sucrase названы заменами прямой подстановкой, если полагающееся поведение сдвинется.
- **Истечение `computeMs` может промахнуться вверх до одного интервала опроса** — занятое время семплируется каждые 25 мс (внутренняя константа, нарочно не конфиг).
- **Программы получают пяти-методную shim `console`** (`log`/`info`/`warn`/`error`/`debug`) — нарочно не полный console API Node.
- **У промежуточных значений биндингов нет байтового предела** — программа способна исчерпать память процесса или воркера значением, которое внешним выводом так и не станет.
- **Дефолтные 64 МиБ — рубеж отвержения, а не восстанавливаемое хранилище** — внешний spill способен сохранить только ограниченные логи и диагностику, возвращаемые после `output-limit`; байты, отвергнутые за рантаймным пределом, до слоя spill не доходят.
