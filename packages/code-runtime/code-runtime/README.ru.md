# @deepseek-ai/dsh-code-runtime

[English](README.md) | [中文](README.zh.md) | Русский

**`CodeRuntime`** (`ctx.codeRuntime`) определяет, ЧТО делает рантайм кода, — исполнить одну написанную моделью программу против набора предоставленных хостом асинхронных привязок и отчитаться `{ value, logs, error? }` — не говоря КАК.

Этот пакет владеет ролью Service Definition данной возможности (трио bash — шаблон; см. [capability seams](../../../.agents/notes/implemented/architecture/2026-06-13-capability-seams.md)): провайдеры наследуют `CodeRuntime` и регистрируют сервис; Consumer — это Code Mode реестра инструментов, который генерирует обращённый к модели SDK и мостит диспетчеризацию инструментов, — и то и другое определено в [Agent Note о Code Mode](../../../.agents/notes/implemented/feature/2026-06-15-code-mode.md), чьим первым провайдером стал бэкенд на воркер-потоках Node. Рантайм ничего не знает ни об инструментах, ни о сессиях: ему передают именованные асинхронные функции и строку программы, а всё инструментообразное остаётся за Consumer.

## Сервисный API (`ctx.codeRuntime`)

| Член | Семантика |
|---|---|
| `run(request)` | Исполняет одну программу против привязок запроса. **Разрешается полем ошибки для любого исхода программы** — отказ разбора/трансформации, брошенное исключение, недопустимое завершение, переполнение вывода, истечение бюджета, отмена или смерть субстрата (ортогональная таксономия `kind` у `CodeRunFailure`); reject происходит только при нарушении вызывающим контракта Service Definition (например, запуск, отправленный после освобождения ресурсов). Программа выполняется как тело async-функции: верхнеуровневые `await`/`return` работают, а завершение в форме lossless JSON становится `result.value`. |
| `language` | Readonly-дескриптор: исходный язык, который ожидает `run`. `'typescript'` и `'python'` — общеизвестные значения, которые подаёт `dsh-tools`; опубликованный бэкенд есть только у `'typescript'`. Информационное поле, не ограничитель — потребитель, генерирующий зависящее от языка представление, переключается по нему и громко падает на языке, который не может представить. |
| `isolation` | Readonly-дескриптор: субстрат исполнения (`'worker-thread'`, `'process'`, `'container'`). Метка для развёртываний и диагностики, **а не заявление о безопасности**. |

Семантика, которую каждая реализация ДОЛЖНА чтить (детали контракта в JSDoc класса): вызовы привязок переносят полные аргументы и результаты lossless JSON без seam-ограничения на байты; программа трактуется как враждебная сторона (произвольные имена привязок — собственные свойства объекта, искажённый трафик никогда не роняет хост); никакое состояние не переживает между запусками; освобождение ресурсов терминирует выполняющиеся запуски И дожидается их выхода прежде чем завершиться.

## Словарь

`CodeRunRequest` (`program`, `bindings`, `signal?`) несёт всё, на чём действует рантайм, — назначение дефолтов (временные бюджеты и внешний лимит вывода) является валидированной конфигурацией провайдера, но никогда скрытым `??` внутри `run()`. `bindings` — список `CodeBindingNamespace` (`global` + `functions` + опциональный `errorClass`), каждый из которых выставлен программе как один глобальный объект асинхронных вызываемых, возвращающих `CodeJsonValue` — локальный для сервиса структурный эквивалент канонического `JsonValue`, сохраняющий независимость этого пакета Service Definition от сессий. Дескриптор `errorClass` называет настоящий глобальный для программы конструктор и own property, принимающий отвергнутое имя члена; рантаймы остаются независимыми от терминов Consumer вроде `ToolCallError`. `CodeRunResult` сообщает завершение в форме lossless JSON `value?`, упорядоченные `logs: string[]` и `error?` (`CodeRunFailure`: `kind` + пригодное для подачи модели `message`). Полные контракты см. в `src/types.ts`.

Имена глобальных привязок и классов ошибок **переносимы между языками**: они ДОЛЖНЫ соответствовать подмножеству идентификаторов `[A-Za-z_][A-Za-z0-9_]*` (без JS-only `$`) и проходить мимо экспортируемых seam множеств исключений, поэтому один список `bindings` остаётся действительным против каждого бэкенда независимо от его `language`. Пакет экспортирует контракт, который обеспечивает каждый бэкенд, — `PORTABLE_RESERVED_WORDS` (зарезервированные слова ECMAScript ∪ Python), `RESERVED_BINDING_GLOBALS` (принадлежащие бэкендам глобальные объекты вроде `console`), `RESERVED_ERROR_MEMBERS` и `DUNDER_MEMBER` (исключения имён членов ошибок), — поэтому имя вроде `$tools`, `lambda` или `__dsh_main__` заставляет `run()` отвергнуть запуск как злоупотребление seam на любом бэкенде, а не только на некоторых. Точные множества и обоснование см. в `src/index.ts`.

## Влияние на модель

Косвенно, через Code Mode в `dsh-tools`, который выставляет `run_code` и возвращает журналы программы, значения или отказы как удерживаемые токены результата инструмента.

#### Влияние на KV-кэш

Прямой инвалидации нет; любые изменения префикса запроса — забота именованного потребителя.

## Известные ограничения и отложенная работа

- **`run()` одноразовый** — `logs` прибывают только вместе с разрешённым `CodeRunResult`; seam не выставляет потокового журнала или API прогресса для вывода работающей программы.
- **Постоянное REPL-подобное ядро записано как будущая работа** — контракт отсутствия состояния между запусками стоит, пока бэкенд постоянного ядра не принесёт собственную историю журналирования ([Agent Note о Code Mode](../../../.agents/notes/implemented/feature/2026-06-15-code-mode.md)).
- **Поставляется только worker-thread бэкенд** — `'process'`/`'container'` объявлены общеизвестными значениями `isolation` без реализации; жёсткая граница безопасности появится с контейнерным бэкендом.
- **Промежуточные значения привязок свободны от байтового лимита** — реализации по-прежнему ограничены стоимостью structured clone и памятью процесса, хотя провайдер или исполнитель могли уже наложить собственную границу добывания данных.
