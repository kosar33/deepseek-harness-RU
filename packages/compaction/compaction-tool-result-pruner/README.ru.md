# @deepseek-ai/dsh-compaction-tool-result-pruner

[English](README.md) | [中文](README.zh.md) | Русский

Безопасный при воспроизведении сервис прореживания без обращения к модели (`ctx.toolResultPruner`). Он переписывает вышедшие за бюджет узлы поверхности `tool/result` в ограниченную голову, фиксированный маркер пропуска и ограниченный хвост, сохраняя полное исходное событие в append-only журнале сессии.

Это конкретный спутник [`dsh-compaction-basic`](../compaction-basic/README.ru.md), а не бэкенд компакции и не инструмент, видимый модели. Compact-basic читает его через необязательный `ctx.get('toolResultPruner')`, поэтому каждый из двух пакетов остаётся независимо собираемым.

## API сервиса

`pruneSession(session)` сканирует один стабильный снапшот текущей поверхности. Каждый вышедший за бюджет результат инструмента заменяется одним заново добавленным `tool/result`, несущим `{ surfaceOp: { op: 'replace', start: originalSeq, end: originalSeq }, sourceEventSeqs: [originalSeq] }`. Замена переносит полные исходные данные и меняет только `content`, сохраняя `turn`, `step`, `callId`, поля ошибок, `meta` и позднейшие добавления данных. Исходное событие остаётся доступным для персистентности, воспроизведения и точной инспекции журнала.

Метод выбрасывает исключение синхронно, когда сессия отклоняет замену. Замены, зафиксированные ранее в проходе, остаются долговечными.

`measureContent(blocks)` считает кодовые точки Unicode в блоках `text`. `pruneContent(blocks)` возвращает ограниченную замену либо `null`, когда содержимое уже в пределах порога. Нетекстовые блоки сохраняются на исходных относительных позициях; нарезка текста никогда не разрезает суррогатную пару UTF-16, хотя может разрезать графемный кластер из нескольких кодовых точек.

Каждый выданный результат точно соответствует настроенным бюджету головы, фиксированному маркеру и бюджету хвоста в текстовых кодовых точках, не превосходит `thresholdChars` и строго меньше вызвавшего его входа. Поэтому второй проход не выдаёт замен.

## Конфигурация

Нераспознанные ключи приводят к неудаче при конструировании плагина. Разрешённая конфигурация отсоединена и глубоко неизменяема.

| Ключ | Обязателен | Значение |
|---|---|---|
| `thresholdChars` | нет (умолчание `8192`) | Прореживать, когда суммарный текст превышает это число кодовых точек Unicode. |
| `headChars` | нет (умолчание `4096`) | Удерживаемые начальные кодовые точки Unicode. |
| `tailChars` | нет (умолчание `1024`) | Удерживаемые конечные кодовые точки Unicode. |

Все значения — целые; порог положителен, голова/хвост неотрицательны. Сумма `headChars + marker + tailChars` **ДОЛЖНА** помещаться в `thresholdChars`, поэтому валидная конфигурация способна проредить любой вышедший за бюджет результат без роста и повторного переписывания.

## Использование

```ts
import type { Context } from '@deepseek-ai/cordis'
import ToolResultPruner from '@deepseek-ai/dsh-compaction-tool-result-pruner'

export function apply(ctx: Context): void {
  ctx.plugin(ToolResultPruner)
}
```

## Влияние на модель

### Прореженный результат инструмента

#### Что видит модель

Как только триггер компакции срабатывает, будущие запросы видят вместо удалённого текста удержанную голову, `\n\n[... tool result middle pruned ...]\n\n` и удержанный хвост. Богатые блоки сохраняют свой порядок. Второй копии оригинала модель не видит.

#### Влияние на токены

Каждый переписанный результат инструмента содержит не больше `thresholdChars` текстовых кодовых точек. Само прореживание не делает вызовов модели; compaction-basic пропускает суммаризацию, когда перемеренный запрос опускается ниже порога давления, иначе суммаризатор читает прореженную поверхность.

#### Влияние на KV-кэш

Замена раннего результата инвалидирует повторное использование с первого изменившегося токена. Прореженный префикс пригоден для повторного использования, пока его маршрут, конверт и предшествующая история остаются идентичными.

## Известные ограничения и отложенная работа

- **Символьные бюджеты — не токенные бюджеты** — плотность токенов у провайдеров различается, поэтому `ctx.tokenMeter` остаётся авторитетом в решении, сняло ли прореживание давление на запрос.
- **Прореживание синтаксично** — оно удерживает начало и конец, не разбирая, какие из средних строк семантически важны.
- **Графемные кластеры могут разрезаться** — нарезка по кодовым точкам защищает суррогатные пары, но не выполняет сегментацию графем с учётом локали.
