# @deepseek-ai/dsh-time-context

[English](README.md) | [中文](README.zh.md) | Русский

Включаемый явно долговечный контекст с текущим зональным временем, зоной браузера, приложенной к открытому запросу, и прошедшим временем, считываемым при подготовке запроса к модели. Композиции по умолчанию оставляют его отключённым; веб-оверлей Schedule монтирует его, чтобы модель могла истолковывать неопределённые даты и времена в зоне браузера пользователя. Запись решения: [Agent Note о долговечном time-context](../../../.agents/notes/implemented/feature/2026-07-16-durable-per-step-time-context.md).

## Конфигурация

```yaml
- id: time-context
  name: '@deepseek-ai/dsh-time-context'
  config:
    timeZone: Asia/Shanghai  # optional fallback when the request has no unique browser zone
    refreshIntervalMs: 60000 # optional; omit or set to 0 for every eligible attempt
```

Когда открытый ход содержит одну валидированную Host'ом зону браузера, эта локальная для запроса зона форматирует отметку времени. При отсутствующем или смешанном браузерном происхождении `timeZone` поставляет запасное значение для показа; его пропуск разрешает зону процесса Node один раз при загрузке плагина. Node соблюдает `TZ`, а каждая явная запасная зона валидируется через `Intl.DateTimeFormat`.

Значение `refreshIntervalMs` ДОЛЖНО быть неотрицательным безопасным целым числом. Пропуск или `0` добавляет контекст каждому подходящему входящему пре-шагу, чей сигнал ещё не прерван. Положительное значение добавляет его, только когда у Session нет более ранней инъекции time-context, wall time сдвинулся назад или прошло не меньше указанного числа миллисекунд с последней инъекции.

## Владение зоной запроса

Браузер считывает `Intl.DateTimeFormat().resolvedOptions().timeZone` для каждого промпта. Host валидирует и канонизирует это значение прежде, чем привязать его к точному источнику долговечного сообщения `user-rpc`. Time-context рассматривает только эти источники в открытом ходе: одна уникальная зона определяет запрос, несколько зон дают `mixed`, ни одной — `unavailable`. Он не читает и не мутирует заголовки Session, состояние соединения или записи Schedule.

Разрешённая инструкция предписывает модели истолковывать неопределённые даты и времена в той зоне браузера. Смешанное или недоступное происхождение предписывает модели попросить пользователя уточнить. Это контекст на естественном языке, а не вводимое по умолчанию значение на другой пакетной границе: инструмент, принимающий локальные календарные поля, по-прежнему владеет своим явным требованием зоны.

## Семантика тайминга

Плагин добавляет слушатель `agent/pre-step` в начало цепочки и сначала делегирует дальше. Когда инъекция назрела и нижестоящее решение допускает вход, он дописывает один снабжённый источником `UserMessage` в возвращаемый набор. AgentLoop записывает финальный набор после `step/start` и до формирования запроса. Отклонение, сбой слушателя или уже прерванный сигнал ничего не записывают.

Каждое считывание использует точный источник снапшота `{ kind: 'plugin', plugin: 'time-context', form: 'snapshot', sections: [{ name: 'time-context', text: <same text> }] }`. Сопутствующий `./invariant` валидирует эту форму, заново выводит политику браузера текущего хода из исходных сообщений `user-rpc` и проверяет зону отметки времени и базовую линию прошедшего времени.

Планирование с положительным интервалом сканирует сырые долговечные события Session в поисках последнего сообщения с атрибуцией плагина, включая считывание, затенённое компакцией. Поэтому оно переживает возобновление без процессно-локального кэша. Положительный интервал может намеренно позволить более позднему запросу переиспользовать существующую историю без свежего считывания; веб-оверлей Schedule опускает интервал.

Шаг 1 отмеряет от последнего предшествующего долговечного сообщения пользователя, ассистента или результата инструмента. Промпт, предложенный для этого шага, ещё не дописан. Последующие шаги отмеряют от предшествующего события time-context в том же ходе. Отсутствующая базовая линия сообщает `unavailable`, а движение wall time назад сводит прошедшее время к нулю.

Считывание записывает вошедший шаг, а не завершившийся или переданный запрос. Последующий отказ подготовки может оставить его в истории. Сообщение остаётся в выведенной истории диалога, пока его не затенит компакция; `request/header` не содержит состояния time-context, а реконструкция запроса использует полный префикс долговечной поверхности после каждого `step/start`.

## Model Experience

### Временной контекст в момент подготовки

#### What the model sees

Каждое внедрённое сообщение содержит три строки. `<timestamp>` — отметка времени ISO-формы с числовым смещением и зоной IANA; длительности используют компактные целосекундные единицы.

##### Первый шаг

```markdown
Time sampled while preparing turn <turn>, step 1: <timestamp>
Browser time zone for this request: <iana-zone-or-mixed-or-unavailable-policy>.
Elapsed since the preceding model-visible message: <duration-or-unavailable>.
```

##### Последующие шаги

```markdown
Time sampled while preparing turn <turn>, step <step>: <timestamp>
Browser time zone for this request: <iana-zone-or-mixed-or-unavailable-policy>.
Elapsed since the preceding step context: <duration-or-unavailable>.
```

#### Token effect

Каждое считывание накапливается, пока его не затенит компакция. Положительный интервал сокращает добавления; пропуск или `0` добавляет по одному при каждой подходящей попытке подготовки.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Только происхождение промпта** — контекст зоны браузера направляет истолкование на естественном языке, но сам не подставляет обязательное поле зоны, требуемое другим инструментом.
- **Смешанные ходы спрашивают** — если один открытый ход содержит промпты из разных зон браузера, модели предписано уточнить, а не угадывать, какая зона относится к времени без явного указания.
- **Запасная зона не считается зоной пользователя** — настроенная или процессная зона форматирует часы, когда браузерное происхождение отсутствует или смешано, но обращённая к модели политика всё равно предписывает уточнять.
- **Целосекундный показ** — отметки времени и длительности опускают подсекундную точность, хотя долговечные события хранят время с точностью до миллисекунд.
- **Стоимость истории между компакциями** — пропуск или `0` удерживает одно считывание на каждую подходящую попытку; положительный интервал сокращает, но не устраняет эту стоимость и может оставить более поздний запрос без свежего руководства по зоне браузера.
