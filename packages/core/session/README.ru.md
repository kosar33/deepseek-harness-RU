# dsh-session

[English](README.md) | [中文](README.zh.md) | Русский

Event-sourced журнал сессии и хранилище в памяти. `Session` — append-only источник истины для всей истории взаимодействия агента; история сообщений LLM *выводится* из неё. Поверх сырого журнала поддерживается слой **поверхности** (упорядоченная проекция порождающих сообщения событий) ради эффективного вывода и компакции.

Необязательный спутник `@deepseek-ai/dsh-session/invariant` регистрирует реляционные проверки этого пакета в `ctx.invariants`: монотонные номера последовательностей, вложенность ходов и шагов, парность вызовов инструментов и результатов внутри одного шага. При загрузке или перезагрузке он воспроизводит существующие сессии; валидация хранилища, снапшоты, заморозка, проверка цитируемых исходных событий и приём поверхности остаются постоянно включёнными обязанностями корневого пакета сессий.

## Сервис: `SessionStore` (ключ контекста: `sessions`)

Создаёт и хранит event-sourced экземпляры `Session`. Персистентность нарочно не реализована здесь: плагины подписываются на `session/event`, сбрасывают накопленное на `session/flush` и могут зеркалить парный жизненный цикл `session/created`/`session/disposed`.

### Публичный API

- `ctx.sessions.create(id?, { seed?, meta? }?)` валидирует и отсоединяет долговечные данные затравки и заголовка, заполняет версию и идентификатор, устанавливает `createdAt` по умолчанию в текущий момент, публикует сессию и привязывает её к fiber вызывающего. Восстановление из персистентности подставляет исходные `createdAt`, `seedLength` и `delegationDepth`.
- `ctx.sessions.flush(session)` диспетчеризует дожидаемый параллельный чекпоинт долговечности через захваченный скоуп сессии. Каждый слушатель стартует, а вызов ждёт урегулирования всех перед сообщением о сбое; неопубликованные, отсоединённые и устаревшие объекты отклоняются.
- `ctx.sessions.fork(source, boundary?, childSessionId?): Session` — разрешает живой объект сессии или идентификатор, выбирает затравку через включительное значение seq события `boundary` (по умолчанию — текущее последнее событие), требует, чтобы этот префикс заканчивался вне открытого хода, и создаёт живую дочернюю сессию с метаданными родословной.
- `ctx.sessions.get(id: SessionId): Session | undefined`
- `ctx.sessions.list(): Session[]`

#### Расширенное: примитивы жизненного цикла упорядоченной разборки

Пользуйтесь разделённым жизненным циклом только тогда, когда разборка ДОЛЖНА быть упорядочена с другим ресурсом:

- `prepare(id?, options?)` валидирует и конструирует без публикации.
- `enter(session)` выполняет проверку коллизии, публикует без объявления и возвращает привязанное к записи идемпотентное отсоединение. Параллельные подготовки с одним идентификатором допустимы, но вход удаётся лишь одной из них; устаревшее отсоединение не может удалить свою замену.
- `announce(session)` испускает единственное ребро создания и отвергает повторные или реентерабельные объявления. Отсоединение во время этой диспетчеризации откладывается и позже испускает парное ребро освобождения ресурсов; необъявленный вход не испускает ни одного ребра жизненного цикла.

Этим разделением пользуется `dsh-agent-loop`, чтобы финальный flush цикла предшествовал отсоединению сессии; см. [Agent Note о владении](../../../.agents/notes/implemented/architecture/2026-06-18-agent-lifecycle-and-ownership-contracts.md).

### Живые события сервиса

Хранилище ставит объявленное создание в пару с освобождением ресурсов, публикует пост-коммитные уведомления о дополнениях с изоляцией сбоев по слушателю и предоставляет дожидаемый чекпоинт долговечности. Точные сигнатуры и поведение скоупов содержатся в генерируемой области [session.ru.md](../../../docs/subsystems/session.ru.md#cordis-surface); полезные нагрузки содержатся в [каталоге персистентности](../../../docs/persistence-catalog.md).

### Класс: `Session`

Обычный класс (не Cordis Service). Живые сессии создавайте через `ctx.sessions.create()`, а отсоединённые сессии для воспроизведения или инспекции — через `Session.create()`; отсоединённая фабрика не публикует события жизненного цикла и не привязывает сессию к fiber.

- `session.append(type, data, opts?)` снимает в снапшот и замораживает долговечные данные и метаданные поверхности, валидирует форму маркера, цитируемые seq исходных событий, полноту покрытия замены и content-only перезаписи `tool/result` с единственным результатом, коммитит синхронно, затем уведомляет наблюдателей с независимой изоляцией сбоев. Реентерабельные дополнения в присоединённую сессию отклоняются, а проверки времени исполнения покрывают расширенные объединения и загруженные журналы.
- `session.deriveMessages()` инкрементально проецирует каждую новую запись поверхности ровно один раз и возвращает свежий массив над полными опознанными замороженными сообщениями, которые хранят эти записи. Сообщения ассистента сохраняют породивших их провайдера и модель плюс приватное для адаптера состояние воспроизведения в своём источнике модели. Перезапись поверхности перестраивает проекцию; отката к сырому журналу нет.
- `session.deriveEventMessage(event)` — каноническая по-событийная проекция, которую используют реконструкция и проверки запросов.
- `session.surface` предоставляет readonly-представление `SessionSurface`, которым владеет единственный инкрементальный менеджер поверхности сессии; `replaceGeneration` меняется при каждой закоммиченной перезаписи.
- `session.events` — кешированный замороженный снапшот, теряющий актуальность при дополнении; принятые события остаются глубоко замороженными.
- `session.seq`, `session.id` — текущая последовательность и readonly типизированная идентичность.
- `session.header: SessionHeader` — отсоединённые глубоко замороженные метаданные создания (`version`, `id`, `createdAt`, необязательные `cwd`/`parentSession`/`seedLength`/`delegationDepth`). Конструкция валидирует долговечную запись и требует совпадения её идентификатора с `session.id`.

### Утилиты JSON без потерь

Долговечным значениям нужна одна принимаемая репрезентация, а не проверка, за которой следует повторное чтение. `isJsonValue(value)` — булев предикат; `snapshotJsonValue(value)` итеративно валидирует и копирует простое значение за один проход, возвращая `undefined` для невалидного ввода и пробрасывая бросающий геттер. Хелпер снапшота принимает финитные JSON-числа кроме `-0` (JSON переписывает его в `0`), плотные обычные массивы и plain-объекты либо объекты с прототипом null; циклы, неподдерживаемые скаляры и экзотические прототипы он отвергает до нормализации, не навязывая предела глубины стека вызовов.

Импорт событий сессии разделяет владение и валидацию сообщений. `snapshotSessionEvent(event)` клонирует заимствованное событие до валидации и заморозки его опознанного сообщения. `adoptSessionEvent(event)` делает ту же работу с сообщением на месте и возвращает исходное событие; пользоваться им можно только при передаче графа объектов в исключительном владении, ни один изменяемый потомок которого не разделён с другим событием.

### Кодек хранения чанк-строк (`chunk-rows.ts`)

Общий [кодек хранения](src/chunk-rows.ts) без потерь преобразует последовательности событий в компактные строки и обратно. Он дословно сохраняет неопознанные события и отвергает искажённые закодированные строки; бэкенды персистентности сами решают, включать ли упакованную запись.

### Типы поверхности

Этот пакет владеет упорядоченной проекцией поверхности, валидацией замен, воспроизведением и тайпгардами, отличающими события append-происхождения от событий-замен. Точные формы и семантику полей описывает [каталог типов поверхности](../../../docs/subsystems/session.ru.md#типы-поверхности). Человеческий транскрипт ДОЛЖЕН проецировать события append-происхождения, а не `session.surface`: вступившие замены затеняют историю, которую читатель уже видел; потребители, обращённые к модели, продолжают читать `session.surface`.

### Реконструкция заголовка запроса (`request-header.ts`)

`request/header` записывает полный канонический снапшот конверта запроса вне истории с причиной `initial`, `resume` или `change`. Его необязательная карта `adapterDefaults` помечает действующие значения `reasoningEffort` или `maxTokens`, материализованные разрешением точной модели, позволяя следующему предложению запроса отличить их от явных настроек диалога. `foldRequestHeader()` выбирает новейший снапшот; легаси-события-дельты и удалённая причина `fallback` отвергаются. См. [Agent Note о воспроизводимых запросах](../../../.agents/notes/implemented/architecture/2026-07-05-reconstructable-requests.md).

`user/message` хранит полный `UserMessage` напрямую, включая идентичность, созданную до маршрутизации инбокса или входа в шаг. Свой `content` он рендерит дословно — будь то прямой человеческий промпт, синтетическая инъекция или вошедший goal round; типизированный `source` — единственный канал, их различающий, и носитель любых доменно-специфичных долговечных фактов. `assistant/message` и `tool/result` также хранят полные значения сообщений. Исполнение хода остаётся заключённым между `turn/start` и `turn/end`; `agent.inject()` ставит ввод в очередь, пока более поздний pre-step его не захватит и не вернёт в enter-решении.

`tool/result` сохраняет одно опознанное сообщение результата инструмента роли user, необязательную внутреннюю идентичность сбоя и необязательные метаданные презентации. Успешное каноническое значение `value` инструмента и человекочитаемое каноническое сообщение сбоя остаются локальными для исполнения; отрендеренное содержимое ошибки — сообщение, авторитетное для воспроизведения.

### Словарь событий сессии (`types.ts`)

Генерируемый [каталог событий журнала персистентности](../../../docs/persistence-catalog.md) перечисляет каждый append-only тип события с его полезной нагрузкой, поверхностным бейджем и местом объявления. Учёт токенов читает пошаговые записи `assistant/chunk { type: 'usage' }` и считает `assistant/message.usage` резервом закоммиченного шага, когда чанка usage нет; неудавшиеся попытки запроса к модели сообщения ассистента не имеют. Каждое `assistant/message` записывает провайдера, модель и необязательное состояние воспроизведения.

Расширение слиянием через `SessionEventMap` — плагин добавляет собственные типы декларативным слиянием (`compaction/*` seam компакции, не попадающее на поверхность `llm/retry` ограниченного восстановления, `hook/*` хук-мостов); слитые члены появляются в том же каталоге. Плагин владеет реляционным инвариантом своих слитых событий, включая то, может ли событие только-для-журнала появляться между ходами. Производитель, которому нужна долговечность, дополняет через `Session` и затем дожидается `ctx.sessions.flush(session)`, не фабрикуя исполнительский ход.

Здесь же определён `TurnEndReasonMap` — расширяемый слиянием суммарный тип причин завершения хода с тегом `kind`. `turn/start` несёт только номер хода; следующая вошедшая партия `user/message` записывает его ввод, а `llm/retry` — восстановление запроса.

Прерванный живой ход завершается как `{ kind: 'aborted', reason: AgentCancelCause }`, сохраняя типизированную причину отмены в долговечном транскрипте. Персистентность импортирует грубый исход aborted из поддерживаемого старого формата как `{ kind: 'aborted', reason: { kind: 'legacy' } }`, ведь та запись не сохранила своего инициатора. Сбой хода несёт `{ kind: 'error', error }`; один лишь механизм восстановления после сбоя синтезирует `{ kind: 'interrupted' }`.

Каждое `SessionEvent` несёт три необязательных поля верхнего уровня (структурные метаданные):

- `sourceEventSeqs?: number[]` — номера seq более ранних событий, процитированных как источники (например, seq `assistant/chunk` позади `assistant/message` или затенённые записи позади записи замены компакции). На `assistant/message` присутствующий `[]` фиксирует известный пустой поток провайдера, а отсутствие поля означает, что легаси- или стороннее событие поток-источник не зафиксировало; прочие события поверхности при наличии поля требуют непустого списка.
- `surfaceOp?: SurfaceOp` — как это событие попало на поверхность. Отсутствует у событий вне поверхности (границы, чанки, usage, ошибки).
- `ignorable?: true` — помечает событие, которое читатель вправе безопасно пропустить, не узнав его типа; отсутствие поля означает обязательность, поэтому событие неизвестного типа отказывает в реконструкции сессии ([механизм](../../../.agents/notes/implemented/architecture/2026-08-10-session-log-version-mechanism.md)).

### Типы метаданных (`types.ts`)

- `SessionHeader` — метаданные сессии, записываемые однократно при публикации как `Session.header`, где отсоединение и глубокая заморозка обеспечивают неизменяемость во время исполнения: `{ version, id, createdAt, cwd?, parentSession?, seedLength?, delegationDepth? }`. Загрузчики персистентности могут возвращать изменяемые отсоединённые копии того же типа данных. Владеет ими этот пакет (рядом с `SessionId`), потому что типизирован именно `Session.header`; бэкенды персистентности реэкспортируют тип, а не владеют им — иначе возник бы цикл пакетов.

### Точки расширения

- Плагины персистентности: подписывайтесь на `session/event` (write-behind) и разбирайте скопившееся на `session/flush` (с ожиданием) и при освобождении ресурсов fiber. Долговечный бэкенд читает журнал и перезагружает его в живую сессию; контракт метаданных (`SessionHeader`, `session.header`) — то, что такой бэкенд хранит рядом с журналом.
- Воспроизведение/fork: `create(id, { seed })` валидирует и замораживает непрерывный журнал текущего формата и перестраивает его поверхность; заголовки запросов требуют провайдера/модель, а сообщения ассистента — происхождение провайдер/модель. За совместимость чтения до конструирования такой затравки текущего формата отвечает персистентность. `fork(source, boundary?, childSessionId?)` выбирает префикс завершённых ходов и записывает родословную.
- Компакция: `dsh-compaction-basic` дополняет журнал заменой `user/message` ради чекпоинтов-итогов, а `dsh-compaction-tool-result-pruner` — content-only заменой `tool/result`. Политика границы парности инструментов и её кеш принадлежат [seam'у `dsh-compaction`](../../compaction/compaction/readme.ru.md), тогда как этот пакет владеет членством упорядоченной поверхности, валидацией замен и `replaceGeneration`.

## Model Experience

### Производная история сообщений

#### What the model sees

Модель получает полные сообщения из записей поверхности `user/message`, `assistant/message` и `tool/result` дословно. Их идентичности, роли, источники и блоки содержимого — те же значения, что установлены при создании; проекции идентичности не отчеканивают. Прямые промпты и внедрённый контекст остаются отдельными событиями `user/message`, чьи источники сохраняют их происхождение. Конверт промпта меняет только человеческое представление; его префиксный контекст и разделитель запроса уже присутствуют в содержимом события. Вызовы инструментов живут внутри сообщений ассистента. Чанки, границы, usage, записи хуков, записи todo и прочие события только-для-журнала не добавляют сообщений.

#### Token effect

Дополненные записи поверхности пересылаются повторно на последующих шагах. Поверхностная операция `replace` убирает затенённые записи из будущих вводов, не удаляя их сырых записей журнала.

#### KV Cache effect

Дополненные записи поверхности сохраняют переиспользуемые префиксы. Операция `replace` делает переиспользование недействительным начиная с первого затенённого сообщения, хотя нижележащий журнал событий остаётся append-only.

### Результат восстановления после сбоя

#### What the model sees

Если восстановление находит запрос инструмента ассистента без долговечного `tool/call`, его синтетический результат `TOOL_NOT_STARTED` говорит `The tool call was interrupted before the Harness recorded it as started. Retry it if it is still needed.` Если у долговечного `tool/call` нет результата, его результат `TOOL_OUTCOME_UNKNOWN` говорит `The tool call was interrupted after it was recorded, but no result was durably recorded. Its outcome is unknown. Decide whether to retry from the tool semantics: retry only if the operation is read-only or idempotent; if it may have side effects, first verify external state or ask the user. Do not retry blindly.`

#### Token effect

Ноль токенов в неповреждённой сессии. При возобновлении каждый починенный вызов добавляет свой сохранённый специфичный для риска текст ошибки.

#### KV Cache effect

Append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-cache.

### Залогированный заголовок запроса

#### What the model sees

Сессия реконструирует системный промпт, схемы инструментов, конфигурацию вызова и префикс сессии, которые цикл реально отправил. События заголовка не добавляют вторую копию в историю сообщений; префикс подставляется перед историей вне `deriveMessages()`.

#### Token effect

Ноль дублирующих токенов от логирования. Реконструированные префикс, системный текст и схемы по-прежнему несут обычную стоимость на каждый запрос.

#### KV Cache effect

Логирование не вызывает инвалидации, а точная реконструкция сохраняет идентичность префикса запроса. Более поздний заголовок с изменившимся префиксом, промптом или схемами может сделать переиспользование недействительным начиная с первого различия.

## Известные ограничения и отложенная работа

- **Ветвление/дерево сессии** (дерево записей в стиле pi) — отложено, пока не понадобится сверх основанного на границах `fork()`.
- **`fork()` режет только на стабильных границах живых сессий** — избранная затравка ДОЛЖНА заканчиваться вне открытого хода, а источник ДОЛЖЕН находиться в хранилище; fork персистентной, но незагруженной сессии исключён из [Fork-API](../../../.agents/notes/implemented/feature/2026-06-30-session-store-fork-api.md).
- **`SESSION_FORMAT_VERSION` закреплён на `0`** — препрелиз, широкой совместимости не подразумевается: `Session` принимает только текущие формы затравки, а бэкенд отказывает любой другой версии, называя направление (новее: "written by a newer harness — upgrade"; старее: пути обновления пока нет). Неизвестные типы событий отказывают так же, если только конверт не пометил их `ignorable`; механизм версионирования описывает [заметку о механизме версии журнала сессии](../../../.agents/notes/implemented/architecture/2026-08-10-session-log-version-mechanism.md). Узкие обновления импорта хранилища принадлежат границе персистентности ([политика](../../../AGENTS.md), [восстановление сообщений до появления идентичностей](../../../.agents/notes/implemented/bug-fix/2026-07-28-load-pre-identity-session-messages.md)).
- **`TurnEndReasonMap` не содержит названных ACP вариантов `refusal` / `max_turn_requests`** — решает производитель: они появятся, когда адаптер или цикл впервые начнут их испускать.
