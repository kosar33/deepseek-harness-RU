# dsh-system-prompt

[English](README.md) | [中文](README.zh.md) | Русский

Реестр сборки системного промпта. Плагины вносят упорядоченные секции, схемы инструментов и именованные переменные. Цикл собирает промпт один раз за шаг и отрисовывает результат как полный промпт модели. Этот плагин владеет статической идентичностью harness и глобальной персоной развёртывания; персона в области агента затеняет глобальный дефолт.

## Конфигурация

| Ключ | Дефолт | Значение |
|---|---|---|
| `includeHarnessIdentity` | `true` | Включать фиксированное открытие `You are an AI agent powered by DeepSeek Harness.` порядка −100. Ставьте false, только когда развёртывание для совместимости владеет полным системным промптом. |
| `includeRuntimeContext` | `true` | Включать упорядоченные динамические контексты в сборку. При false провайдеры контекста не вычисляются, а контексты, добавленные слушателями `system-prompt/assemble`, отбрасываются после каскада; остальные сервисы и их принуждение остаются активными. |
| `persona` | `''` | Глобальный дефолт персоны развёртывания: ЕДИНСТВЕННЫЙ заданный конфигурацией фрагмент промпта, отрисовываемый секцией `deployment:persona` порядка 0, пока его не затенит вклад в области агента. Шаблон — полные группы `{{…}}` интерпретируются строго по зарегистрированным переменным (поставляемый цикл регистрирует `{{model}}`/`{{cwd}}`), синтаксиса экранирования литеральных фигурных скобок пока нет. Пусто ⇒ секция отбрасывается при отрисовке. |
| `toolOrder` | — | Явный обращённый к модели порядок инструментов: список `ToolSchema.name` с одним остаточным входом `'<unlisted-tools>'` (`TOOL_ORDER_REST`); перечисленные инструменты занимают перечисленные позиции, неперечисленные попадают в остаточный вход в лексикографическом порядке имён. Отсутствует ⇒ простой лексикографический порядок имён. Применяется к собранным инструментам ДО каскада `system-prompt/assemble` — как и сортировка секций по `order`, канонизирует вклад реестра (порядок регистрации — артефакт загрузки плагинов), а слушатель каскада, меняющий список, сам владеет детерминизмом того, что выдаёт. Неверная конфигурация отказывает громко: список без ровно одного остаточного входа или с дубликатами бросает исключение при загрузке; перечисленное имя без зарегистрированного инструмента отвергает каждый `assemble()`; провайдер инструментов, вернувший зарезервированное имя остаточного входа, тоже отвергает. Под поставляемым циклом ход падает до любого запроса к модели. Почему центральный список, а не веса по плагинам: [Explicit model-facing tool order](../../../.agents/notes/implemented/feature/2026-07-06-explicit-tool-order.md). |

## Сервис: `SystemPrompt` (ключ ctx: `systemPrompt`)

### Публичный API

- `ctx.systemPrompt.section(section: PromptSection): () => void` Добавить секцию. Слой — скоуп вызывающего контекста: `agent.ctx` вносит секцию одному этому агенту, затеняя там одноимённую глобальную. Секция с `complete: true` становится точным полным промптом после каскада сборки; больше одной действующей complete-секции отвергает сборку. Дубликаты имён в одном слое и неконечные значения порядка бросают исключение. Освобождается вместе с fiber вызывающего.
- `ctx.systemPrompt.context(context: PromptContext): () => void` Добавить упорядоченный динамический контекст для скоупа вызывающего. Провайдеры вычисляются для каждой подходящей сборки и под поставляемым циклом становятся снабжённым источником снапшотом контекста рантайма в истории модели.
- `ctx.systemPrompt.suppressRuntimeContext(): () => void` Подавить все вклады динамического контекста для скоупа вызывающего. Несколько регистраций компонуются независимо; освобождение возвращённого эффекта возвращает контекст, когда подавителей не остаётся.
- `ctx.systemPrompt.tools(provider: (context: AssembleContext) => ToolProviderResult): () => void` Добавить схемы инструментов, вычисляемые на каждой сборке с контекстом той сборки. `ToolProviderResult` = `{ schemas, knownNames? }`: `schemas` — видимое множество после ограничений; `knownNames` — доограничительная вселенная, которую использует `toolOrder`. Провайдер не должен возвращать схему с именем `TOOL_ORDER_REST`. Скоупированные провайдеры опрашиваются только для сборок своего скоупа. Освобождается вместе с fiber вызывающего.
- `ctx.systemPrompt.variable(name: string, provider: (context) => string | undefined): () => void` Добавить переменную промпта, на которую текст секции ссылается как `{{name}}`. Скоупированные переменные затеняют одноимённую глобальную для этого агента. Дубликат в слое или имя, на которое невозможно сослаться, бросают исключение; `undefined` значит «для этой сборки значения нет». Освобождается вместе с fiber вызывающего.
- `ctx.systemPrompt.assemble(context?: AssembleContext): Promise<PromptAssembly>` Собрать промпт для одного вызывающего: глобальный слой, слитый со слоем `context.scope`, со схемами инструментов, отсоединёнными до каскада преобразований. Проходит через скоуп-фильтрованный каскад `system-prompt/assemble`, затем восстанавливает действующую complete-секцию единственной секцией промпта и приводит в действие активный подавитель контекста рантайма. Необязательный `context.signal` явно управляет этим запросом сборки; провайдеры и слушатели могут с ним сотрудничать, но не должны удерживать его до другого хода. Отвергает при нескольких complete-секциях, когда настроенный `toolOrder` называет инструмент вне вселенной `knownNames` провайдеров или когда провайдер возвращает зарезервированное имя остаточного входа.

### События

Каскад `system-prompt/assemble` авторитетен для обычных секций; complete-секция — финальное ограничение промпта, применяемое после каскада. Слушатели, заменяющие записи, должны сохранять любой активный протокол Code Mode или структурированного вывода. Когда фильтрация должна оставаться согласованной между представлением, поиском и исполнением, используйте [`ToolRuntime.restrict()`](../tools/README.ru.md). Уведомления об изменениях реестра не фильтруются. Порождаемая область [system-prompt.md](../../../docs/subsystems/system-prompt.ru.md#cordis-surface) владеет подписями и контрактами диспетчеризации.

### Ключевые типы

- `AssembleContext` — для чего существует один вызов `assemble()`. Расширяется слиянием объявлений; здесь объявляет `scope?: ScopeKey` (селектор слоя) и `signal?: AbortSignal` (явная возможность управления запросом), а `dsh-agent` объявляет `agent?: Agent` (типизированное поле DX — никогда не задавать без `scope`; используйте `assembleContextFor(agent, signal)`). Провайдеры должны терпеть отсутствие полей, поскольку голый `assemble()` несёт пустой контекст без скоупа и без сигнала. `signal` — значение запроса, а не часть окружающего исполнительного фрейма Agent.
- `PromptSection` — `{ name, order, text, complete? }`. Секции склеиваются по возрастанию `order`. Диапазоны порядка: `-100` — идентичность harness, `0` — персона развёртывания, руководства инструментов используют `100–199`. Одна действующая `complete`-секция подавляет все прочие после кооперативной сборки.
- `PromptAssembly` — `{ sections: AssembledSection[], tools: ToolSchema[], variables: Record<string, string | undefined> }`. Тексты секций приходят разрешёнными, но ещё не интерполированными; `variables` держит каждую зарегистрированную переменную, разрешённую по контексту. Схемы инструментов — часть сборки по замыслу: «что модели сказано, что она может» — одна связная вещь, даже если адаптеры передают схемы отдельным полем протокола.
- `renderPrompt(assembly)` — интерполирует ссылки `{{variable}}` в каждой секции, отбрасывает пустые секции, склеивает пустыми строками. СТРОГО: неизвестная ссылка (поиск через `Object.hasOwn` — имена прототипа вроде `{{constructor}}` неизвестны), зарегистрированная, но не имеющая значения ссылка, искажённая полная группа `{{…}}` или `{{`, открывающее незавершённую группу, за которой всё же следует `}}` (`{{{model}}}`), бросает исключение — громкий отказ лучше отгрузки искажённого промпта. Одинокий `{{`, после которого нигде нет `}}`, проходит дословно; подставленные значения заново не сканируются.

Расширяется слиянием: плагины могут объявлять дополнительные поля на `PromptAssembly` и `AssembleContext` через declaration merging.

### Точки расширения

- Провайдеры секций: пакеты инструментов владеют своими межвызовными руководствами (`tool:bash`, `tool:read`, …); этот плагин владеет `harness:identity` и `deployment:persona`.
- Провайдеры переменных: агентный цикл регистрирует `model` и `cwd`; любой плагин может зарегистрировать принадлежащие ему факты (будущие `date`, состояние git, …).
- Провайдеры схем инструментов: `ToolRuntime` регистрирует себя провайдером инструментов автоматически.
- [Каскад `system-prompt/assemble`](#события): кооперативно меняет или заменяет сборку для каждого вызывающего до приведения в действие любого ограничения complete-секции.

Обоснование замысла: [Agent Note о переменных промпта](../../../.agents/notes/implemented/architecture/2026-07-05-prompt-variables-and-tool-guidance-ownership.md).

## Model Experience

### Системный промпт

#### What the model sees

По умолчанию каждая сборка начинается с приведённой ниже идентичности harness, затем идут настроенная персона и упорядоченные секции плагинов после строгой интерполяции переменных. `includeHarnessIdentity: false` опускает только это фиксированное открытие. Пустые секции исчезают; скоупированные секции и переменные могут затенять глобальные для одного агента. Каскад `system-prompt/assemble` определяет доставляемый промпт и схемы инструментов, пока одна действующая секция не объявит себя complete; тогда именно она становится всем системным промптом, а контексты, инструменты и переменные каскада остаются. Упорядоченные динамические контексты отделены от секций системного промпта и становятся снабжёнными источником снапшотами роли пользователя, только когда присутствуют. `includeRuntimeContext: false` или скоупированный подавитель убирает все такие контексты, включая добавления слушателей, не отключая сервисы, владеющие лежащей в основе политикой или состоянием.

##### Идентичность harness

```markdown
You are an AI agent powered by DeepSeek Harness.
```

#### Token effect

Идентичность — фиксированная стоимость каждого запроса, когда включена. Персона и текст плагинов повторяются в каждом запросе и растут вместе со своим отрисованным содержимым.

#### KV Cache effect

Стабилен по префиксу, пока идентичность, персона, переменные, текст секций и порядок отрисовываются одинаково. Любое изменение может инвалидировать переиспользование с первого изменившегося токена системного промпта.

### Схемы инструментов

#### What the model sees

Для поставляемых инструментов модель получает видимое каждому агенту подмножество [порождаемых схем инструментов](../../../docs/tool-catalog.md#tool-package-map), упорядоченное конфигурацией или лексикографически после ограничений и перехвата сборки. Расширения могут вносить дополнительные определения через тот же реестр. Секции и провайдеры схем — отдельные входы сборки, поэтому ограничение инструмента не убирает независимо зарегистрированное руководство.

#### Token effect

Токены схем повторяются в каждом запросе. Ограничение инструмента убирает всю стоимость его схемы для этого агента, но не отдельную секцию промпта; переупорядочивание меняет форму кэша, но не смысловое содержимое.

#### KV Cache effect

Стабилен по префиксу, пока видимое множество схем, отрисовка и порядок не меняются. Регистрация, ограничение или переупорядочивание могут инвалидировать переиспользование с первого изменившегося токена схемы.

## Известные ограничения и отложенная работа

- **Текст промпта, задаваемый развёртыванием, — только конфигурация/композиция** — этот плагин владеет глобальным дефолтом персоны, плагины-создатели могут регистрировать тени в области агента, а остальные секции приходят от плагина, владеющего фактом; API правки промпта конечным пользователем отсутствует.
- **Нет синтаксиса экранирования литеральных скобок `{{…}}`** — каждая полная группа интерполируется по зарегистрированным переменным; экранирование отложено, пока реальный промпт в нём не нуждается.
- **Неверный `toolOrder` обнаруживается при сборке промпта (первый ход), а не при загрузке** — при загрузке конфигурации бросают исключение только нарушения формы.
- **Секции с одинаковым значением `order` разбираются по порядку регистрации** — артефакт загрузки плагинов; детерминизм держится на соглашении о непересекающихся диапазонах порядка, в отличие от канонизированного порядка инструментов.
