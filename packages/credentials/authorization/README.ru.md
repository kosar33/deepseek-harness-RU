# dsh-authorization

[English](README.md) | [中文](README.zh.md) | Русский

Service Definition авторизации (`ctx.authorization`). Некоторые учётные данные нельзя настроить — их можно только получить: получение означает разговор с человеком — откройте такую-то страницу, вставьте такой-то код, выберите аккаунт. Этот seam владеет тем разговором и жизненным циклом вокруг него и никогда — протоколом.

**Флоу — это знание плагина о том, как добыть его собственный credential.** Он регистрируется под тем [`CredentialKey`](../credentials/README.md#two-key-spaces-two-questions), куда пишет, поэтому флоу говорит, какую запись производит, а через скоуп этого ключа — какой плагин отвечает за формат внутри неё. Второй протокол авторизации приходит как ещё один флоу, а не как ещё один seam.

**Флоу владеет записью.** Успешно завершившийся `run()` означает, что запись уже зафиксирована через `ctx.credentials`; seam подтверждает фиксацию, наблюдённую во время попытки, — одной лишь проверки наличия хватило бы, чтобы повторная авторизация выдала устаревшую запись за свежую, — и отвергает флоу, завершившийся без фиксации. Фиксация внутри флоу как раз и позволяет библиотеке, сохраняющей через собственный store-адаптер, оставаться единственным писателем, а не копироваться наружу и записываться дважды.

**Взаимодействие передаётся вместе с запросом, а не хранится в реестре.** Тот, кто начинает авторизацию, и есть тот, кто может говорить с человеком о ней, поэтому промпты достигают ровно той поверхности, что спросила, а headless-вызывающий поставляет взаимодействие, которое отвечает отказом. Нет окружающего провайдера, который мог бы отсутствовать, и не возникает вопроса, к какой из двух открытых страниц относится промпт.

## Поверхность

```ts
import type { Context } from '@deepseek-ai/cordis'
import { AuthorizationDeclinedError, type AuthorizationSession } from '@deepseek-ai/dsh-authorization'
import { credentialKey } from '@deepseek-ai/dsh-credentials'

declare const ctx: Context
declare const exchange: (signal: AbortSignal) => Promise<void>

const key = credentialKey('llm-pi-ai', 'openai-codex')

const dispose = ctx.authorization.registerFlow({
  key,
  label: 'ChatGPT (Codex)',
  methods: [{ id: 'oauth', label: 'Sign in with ChatGPT' }],
  async run(session: AuthorizationSession) {
    session.notify({ message: 'Continue in your browser', url: 'https://auth.example/start' })
    const code = await session.prompt({ kind: 'text', message: 'Paste the code' })
    // Commits the record through ctx.credentials before resolving.
    await exchange(session.signal)
    void code
  },
})

ctx.authorization.list()                    // [{ key, label, methods, inFlight }]
ctx.authorization.describe(key)             // the same entry, or undefined
await ctx.authorization.begin({             // { status: 'authorized' | 'cancelled' }
  key,
  interaction: { notify: () => {}, prompt: () => Promise.reject(new AuthorizationDeclinedError()) },
})
ctx.authorization.cancel(key)               // withdraw whatever is running for the key
dispose()
```

Одна попытка на ключ одновременно. Второму вызывающему отказывают с `ALREADY_IN_FLIGHT`, а не присоединяют его, потому что двое задавали бы вопросы разным людям через один флоу, и второй отвечал бы на вопросы, заданные первому. `inFlight` лежит в самой записи, чтобы поверхность рисовала кнопку неактивной, а не узнавала об этом из ошибки.

`cancel(key)` существует рядом с собственным сигналом запроса, потому что транспорт «запрос–ответ» отвечает кнопке Cancel вторым вызовом, не удерживая дескриптора сигнала первого. Флоу, чья регистрация освобождается посреди попытки, отзывается тем же способом: его исполнитель принадлежит плагину, который уходит.

Попытка, чей вызывающий уже отозвался, никогда не захватывает ключ и никогда не запускает флоу — надежда на то, что каждый флоу проверит свой сигнал до первого await, позволила бы тому, кто не проверяет, висеть с захваченным ключом. Валидация всё же выполняется первой, поэтому вызывающий, назвавший несуществующий ключ или метод, услышит об этом независимо от того, отозвался ли он к тому моменту.

Человеческое «нет» — это исход, а не поломка. Взаимодействие, которое отказывает, отвергает свой промпт с `AuthorizationDeclinedError`, и попытка, потерпевшая неудачу после отказа на промпте, завершается как `cancelled` — точно так же, как при отозванном сигнале; любое иное отвержение промпта остаётся сбоем флоу, который добирается до вызывающего. Извещение — fire-and-forget по тому же принципу, и это гарантирует seam: поверхность, которая не может отрисовать извещение, теряет извещение, но не попытку.

`authorization/settled (key, settlement)` срабатывает после освобождения ключа для каждого терминального исхода. `settlement` добавляет `failed` к двум статусам, которые умеет возвращать `begin()`: сбой добирается до собственного вызывающего брошенной ошибкой, поэтому поток событий — единственное место, где наблюдатель, не запускавший попытку, отличит отказ от поломки. Неудачи слушателей локализованы: выполняется каждый слушатель, throw или rejection логируется без изменения исхода завершённой попытки, и лишь неудача с кодом `INVARIANT` перебрасывается дальше после того, как остальные выполнились.

## Словарь взаимодействия

Извещение однонаправленно и никогда не несёт секрета: сообщение, опционально страница, которую человек должен открыть, и код, который он должен там ввести. Промпт — вопрос, на который флоу не может ответить сам: `text`, `secret` или `select`; `secret` отличается от `text` только подачей. Промпт несёт собственный `signal`, поэтому флоу, у которого введённый вручную код соревнуется с колбэком браузера, может отозвать проигравший вопрос, пока попытка продолжается; сигнал запроса вместо этого отзывает всю попытку.

Словарь намеренно меньше любого отдельного провайдерского: он описывает, что поверхность должна уметь отрисовать, поэтому поверхность, отрисовывающая один флоу, отрисовывает их все.

## Влияние на модель

Отсутствует: авторизация — разговор с человеком во время настройки, и ни один флоу, извещение или промпт не достигает запроса к модели.

#### Влияние на KV-кэш

Инвалидации нет; никакое состояние авторизации не входит в префикс запроса.

## Известные ограничения и отложенная работа

- **Ни один флоу не возобновляем** — попытка живёт в процессе, который её начал, поэтому перезагрузка браузера посреди входа оставляет её незавершённой, и человек начинает заново. Долговечные попытки требуют хранилища, которого у этого seam нет.
- **Ничего не отзывает выданного** — выход из системы — это `ctx.credentials.deleteRecord(key)`, который забывает локальную запись, не сообщая эмитенту. Провайдеру, которому нужен серверный revoke, пока негде его объявить.
- **Ключ без флоу инертен** — seam сообщает о зарегистрированном, поэтому запись, оставленную неустановленным плагином, можно удалить, но не переавторизовать. Распознавание такой записи-сироты — ответственность вызывающего, как и для [`listRecords()`](../credentials/README.md#surface).
