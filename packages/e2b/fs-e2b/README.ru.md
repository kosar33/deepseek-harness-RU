# @deepseek-ai/dsh-fs-e2b

[English](README.md) | [中文](README.zh.md) | Русский

E2B-реализация провайдерского контракта [`@deepseek-ai/dsh-fs`](../../fs/fs/README.ru.md). Собственной конфигурации у него нет: сначала загрузите [`@deepseek-ai/dsh-e2b`](../e2b/README.md), затем этот сервис вместо `dsh-fs-local`. Провайдер пользуется удалённым cwd и дескриптором SDK своего владельца, поэтому файловые инструменты наблюдают тот же мир, что и Bash-процессы на базе E2B.

## Поведение

- **Удалённая идентичность и метаданные** — относительные пути разрешаются как POSIX-пути от cwd вызывающего или `ctx.e2b.cwd`; GNU `realpath -mz` предоставляет каноническую идентичность цели, не требуя существования конечного файла, а ASCII/base64 со строгим NUL-кадрированием сохраняет переводы строк и многобайтовые пути через декодированный транспорт SDK. `stat`, no-follow `lstat` и стабильные одноуровневые перечни каталогов проецируют метаданные E2B в seam файловой системы; перечни переиспользуют возвращённые метаданные и последовательно разрешают записи символических ссылок. Версии — непрозрачные хэши метаданных E2B плюс расширенный атрибут на каждую запись.
- **Пути мира исполнения** — канонические цели предоставляют абсолютные POSIX-пути процессов, percent-кодированные URI `file:` и принадлежащие провайдеру проверки границ песочницы, поэтому универсальные потребители subprocess никогда не разбирают id целей E2B и не применяют хостовых правил путей.
- **Чтения UTF-8** — чтения целиком и потоковые чтения сохраняют декодирование между чанками, отвергают неверный UTF-8 и используют 8192-байтовый NUL-образец seam для обнаружения бинарности. Инструмент, видимый модели, по-прежнему владеет выбором размера и оконной нарезкой строк.
- **Ограниченные чтения сырых байтов** — `readBytes` завершается досрочно по размеру stat до всякого переноса содержимого, затем передаёт удалённый объект потоком и отменяет поток на первом чанке сверх `maxBytes` (`FS_TOO_LARGE`), поэтому ни уже превышающий лимит файл, ни разрастающийся после stat не буферизуются в памяти хоста целиком. Особенность пустых файлов у зафиксированного SDK (content-length 0 возвращает `''` в потоковом формате) даёт пустой результат.
- **Атомарные мутации** — записи создают случайный соседний промежуточный каталог, переводят его в режим `0700` до загрузки содержимого и сохраняют POSIX-режим существующего файла. Замены публикуются через атомарный rename E2B в той же файловой системе. Охраняемый `createIfAbsent` вместо этого публикует удалённым `ln -T`, делая фиксацию атомарной операцией без замены, даже когда в точке назначения появляется каталог; метаданные, прочитанные с промежуточного файла до той фиксации, проецируются на целевой путь для возвращаемой версии, поэтому за любой из точек фиксации не следует запрос метаданных, который может завершиться неудачей. E2B создаёт недостающие родительские каталоги. Литеральные правки нормализуют LF для сопоставления, восстанавливают преобладающее CRLF-хранилище и сериализуют мутации по канонической цели внутри хостового процесса.
- **Отказы и отмена** — not-found, permission, abort и прочие отказы контроллера E2B сопоставляются с существующим словарём `FsError`. Отмена действует по возможности на более ранних границах запросов SDK и проверяется непосредственно перед публикацией. Сигнал не пробрасывается в фиксацию rename или охраняемой ссылки, поэтому отмена не может прервать атомарную публикацию или превратить уже зафиксированную запись в сообщённую неудачу.

Провайдер не копирует, не монтирует и не сверяет хостовую рабочую область. Хостовый путь, данный ему как `cwd`, лишь создаёт удалённый каталог с тем же написанием.

## Model Experience

Косвенно — через [`dsh-tool-fs`](../../fs/tool-fs/README.ru.md), который отрисовывает удалённое содержимое UTF-8, результаты каталогов, подтверждения мутаций и ошибки провайдера, тогда как идентичность и транспорт E2B остаются внутренними.

#### KV Cache effect

Прямой инвалидации нет; названный потребитель владеет любыми изменениями префикса запроса.

## Известные ограничения и отложенная работа

- **Нет синхронизации с хостом** — пустой E2B cwd остаётся пустым, пока его не наполнит инструмент, команда или внешний процесс; локальные файлы ни загружаются, ни отражаются обратно.
- **Координация мутаций локальна для хостового процесса** — `createIfAbsent` защищает удалённого создателя, состязающегося с публикацией, но другое подключение harness или команда всё ещё могут вступить в гонку с заменой; версионные проверки обнаруживают только те изменения метаданных, которые может представить E2B.
- **Чтения заново открывают канонические цели по пути** — конкурентная удалённая подмена пути между разрешением и открытием потока не ограждена стабильным файловым дескриптором; ни один наблюдавшийся продуктовый дефект не оправдывает специфичный для провайдера протокол ограниченных чтений в этом POC.
- **Расходы на мутации целого файла остаются** — диффы перезаписи и литеральные правки читают полные файлы в память хоста, и каждая операция несёт задержку контроллера E2B.
- **POC нацелен на Linux-образ E2B по умолчанию** — он опирается на GNU `realpath`/`base64`/`chmod`, rename в той же файловой системе, потоковые чтения и расширенные атрибуты метаданных; пользовательские шаблоны вне этого POC.
