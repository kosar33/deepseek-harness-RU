# @deepseek-ai/dsh-message-feedback

[English](README.md) | [中文](README.zh.md) | Русский

Редактируемая обратная связь во владении Host для одного финализированного сообщения ассистента. Пакет регистрирует `ctx.messageFeedback`, сохраняет одну привязанную к жизненному циклу сопутствующую строку на сессию в storage-domain и публикует унарный Remote-контракт Host: `messageFeedback.list`, `messageFeedback.put` и `messageFeedback.delete`. Он отделён от неизменяемого события уровня сессии `feedback/record` и не выполняет телеметрической передачи. Проектную границу описывает [Agent Note о сопутствующем хранилище message-feedback](../../../.agents/notes/implemented/architecture/2026-08-10-message-feedback-sidecar.md).

Публичные типы запросов, значений, версий и отказов экспортируются из корня пакета и `@deepseek-ai/dsh-message-feedback/types`; их источник — [`src/types.ts`](src/types.ts).

## Конфигурация

| ключ | значение |
|---|---|
| `maxNoteBytes` | Обязательное положительное безопасное целое: максимальная длина одной необязательной заметки в байтах UTF-8. |

Заметки должны содержать хотя бы один непробельный символ, однако принятый текст хранится дословно, без обрезки. Отсутствие `note` означает, что желаемое значение не имеет заметки, поэтому согласованный по версии материальный `put` стирает существующую заметку. Проверка заметки предшествует поиску сессии и потому может вернуть `note-blank` или `note-too-large` для отсутствующей сессии, не касаясь персистентности.

```yaml
- id: message-feedback
  name: '@deepseek-ai/dsh-message-feedback'
  config:
    maxNoteBytes: 8192
```

Сервис внедряет `storageDomain`, `sessionPersistence` и `sessions`. Его домен долговечности — `message_feedback` с одной строкой таблицы `sessions` на каждый `SessionId`.

## Данные, жизненный цикл и долговечность

`MessageFeedbackItem` содержит `messageId`, `rating: 'positive' | 'negative'`, необязательную `note`, непрозрачную версию `version`, сравнимую только на равенство, и назначенные Host метки времени `createdAt`/`updatedAt` в миллисекундах эпохи Unix. Материальное обновление сохраняет `createdAt`, заменяет `version` и не даёт `updatedAt` сдвинуться назад. `list` возвращает свежие неизменяемые снимки в порядке первого создания; обновление элемента удерживает его место, а удаление с последующим повторным созданием добавляет новый элемент.

Каждая сохранённая строка несёт проверенную идентичность заголовка сессии `{createdAt, cwd}`. Несовпадение трактуется как отсутствие: `list` возвращает пустой массив `items`, `delete` возвращает постусловие отсутствия, а `put` вправе заменить устаревшую строку строкой, привязанной к текущей идентичности. Это ограждает от повторно использованного `SessionId` в случае, когда его заголовочная идентичность отличается. Fork обладают отличающейся идентичностью сессии и копии строки обратной связи не получают.

`SessionPersistence.inspect()` даёт безопасное при холодном состоянии наблюдение без публикации или возобновления агента и без фиксации холодного ремонта. Для сессии без живого владельца `listSnapshots()` сначала выносит решение об определённом отсутствии; сбой `inspect()` для занесённой в каталог сессии остаётся инфраструктурной ошибкой, а не превращается догадкой в `session-not-found`. `put` принимает только непустое сообщение `assistant/message` происхождения дописывания с затребованным `MessageId`; сообщения происхождения замены, пустые ассистентские записи только о расходе токенов и неассистентские записи возвращают `target-not-found`.

После начальной проверки `put` возводит барьер долговечности перед записью сопутствующего хранилища. Совпадающая живая сессия фиксируется через канонический чекпоинт `ctx.sessions.flush`, затем оба пути — живой и холодный — физически перечитываются с нулевой последовательности через `SessionPersistence.readFrom`. Идентичность заголовка и цель полученного наблюдения проверяются снова. Отсутствующий участник flush, изменившаяся идентичность, исчезнувшая цель или сбой физического чтения предотвращают фиксацию сопутствующего хранилища, поэтому долговечная обратная связь никогда не опережает долговечное целевое сообщение.

Обратная связь сообщений — ни содержимое журнала сессии, ни проекция сессии. Она не излучает событие `feedback/record`, не попадает в историю модели и не запускает телеметрическое высвобождение `FEEDBACK_ONLY`.

## Сервис и Remote-контракт Host

Одни и те же три метода `MessageFeedbackService` публикуются `TypertRemoteService` и `@Remote`; имена конечных точек Host — `messageFeedback.list`, `messageFeedback.put` и `messageFeedback.delete`. Каждый метод возвращает размеченное бизнес-объединение: `{ ok: true, value }` либо `{ ok: false, error }`. Операционные сбои хранилища, повреждения или отсутствующего слушателя долговечности отклоняются вместо того, чтобы ошибочно именоваться бизнес-ошибками.

| Метод | Запрос | Успешный `value` | Отвергнутый `error.code` |
|---|---|---|---|
| `list` | `MessageFeedbackListRequest { sessionId }` | `MessageFeedbackListValue { items }` | `session-not-found` |
| `put` | `MessageFeedbackPutRequest { sessionId, messageId, rating, note?, ifVersion }` | зафиксированный `MessageFeedbackItem` | `session-not-found`, `target-not-found`, `version-conflict`, `note-blank`, `note-too-large` |
| `delete` | `MessageFeedbackDeleteRequest { sessionId, messageId, ifVersion }` | `MessageFeedbackDeleteValue { absent: true }` | `session-not-found`, `version-conflict` |

`MessageFeedbackVersionConflict` возвращает авторитетный текущий элемент либо `null`, когда элемента нет. Это позволяет вызывающему согласовать текущие оценку, заметку и версию без второго запроса `list`. `MessageFeedbackNoteTooLarge` возвращает и `maxBytes`, и `actualBytes`. Клиентский Remote-агрегат пока не монтирует сгенерированный клиентский вклад; вызывающие на стороне Host могут пользоваться сервисным и Remote-контрактом без этой клиентской сборки.

## Compare-and-set и идемпотентность

`ifVersion: null` запрашивает только создание; каждый запрос к существующему элементу требует его точной текущей версии, включая холостую операцию, чьё желаемое значение уже совпадает. Проверка ведётся на сообщение, а не на сессию, поэтому изменение одного элемента не конфликтует с другим. Каждое материальное создание или обновление назначает свежий непрозрачный UUID-токен, не позволяя устаревшим записям пересечь цикл значений ABA.

Холостая операция при совпавшей версии возвращает уже сохранённый элемент с неизменными версией и метками времени. После потерянного успешного ответа повтор с прежним токеном получает `version-conflict.current`; вызывающий может сверить этот авторитетный элемент со своим желаемым значением без дополнительного чтения. `delete` игнорирует `ifVersion`, когда элемент уже отсутствует, и после успеха всегда возвращает устойчивое постусловие `{ absent: true }`.

Очередь обещаний на каждую сессию охватывает наблюдение, проверку долговечности, чтение сопутствующего хранилища, сравнение и запись всей строки. Эти семантики сериализуют параллельные мутации сквозь один экземпляр сервиса; сам storage-domain не имеет условной записи между процессами.

Освобождение ресурсов плагина закрывает приём мутаций, выкачивает каждую уже принятую в очереди сессий операцию и лишь затем закрывает домен хранилища. Мутация, поданная после начала освобождения, отклоняется как сбой жизненного цикла вместо входа в закрывающийся домен.

## Опыт модели

### Локальное состояние message-feedback

#### Что видит модель

Ничего. `ctx.messageFeedback` не регистрирует ни инструмента, ни раздела промпта, ни адресованного модели контекста, ни события сессии; обратная связь остаётся в сопутствующем хранилище под владением Host, пока отдельно документированный Consumer явным образом её не выставит наружу.

#### Влияние на токены

Ноль. Ни один запрос, результат, оценка, заметка, метка времени или отказ этого пакета не входит в запрос к модели.

#### Влияние на KV-кэш

Независимо. Чтение списка или изменение обратной связи сообщений не касается префикса запроса к модели и не способно инвалидировать пригодную для переиспользования запись кэша провайдера.

## Известные ограничения и отложенная работа

- **Клиентский агрегат и UI отсутствуют** — Remote-контракт Host поставляется, но вклад клиентского Remote-агрегата и любые UI-потребители находятся в отдельном владении и отложены.
- **Compare-and-set работает в пределах одного процесса** — очередь на сессию сериализует только один экземпляр сервиса; несколько процессов Host, пишущих в один корень хранилища, всё ещё способны терять обновления, поскольку storage-domain не выставляет условной записи между процессами.
- **Нет каскада долговечного удаления сессии** — персистентность сессии не имеет API удаления, а `session/disposed`/`host/session-removed` означают отсоединение, а не долговечное удаление. Поэтому сервис удерживает пустые строки и может оставлять осиротевшие строки после внешнего удаления журнала, вместо того чтобы удалять действительную обратную связь при отсоединении.
- **Окно отсоединения и вывода каталога из эксплуатации** — запрос в узком интервале после живого отсоединения, но до того, как каталог персистентности овеществит заголовок, может получить `session-not-found`; вызывающие повторяют попытку после того, как вывод из эксплуатации овеществлён.
- **Идентичность заголовка — не отпечаток содержимого** — `{createdAt, cwd}` обнаруживает повторное использование, только когда эти поля различаются; клонированный журнал, сохранивший ту же идентичность заголовка, неотличим.
- **Граница доверенного вызывающего** — `list`/`put`/`delete` не несут аутентифицированного деятеля или аудиторской идентичности. Развёртывание обязано выставлять шлюз Host только через свой доверенный или отдельно аутентифицированный рубеж, пока не добавлены авторизация и атрибуция.
- **Границы каталога и строки** — холодный запрос просматривает полный каталог снапшотов сессии, потому что персистентность не имеет операции поиска метаданных по id. `maxNoteBytes` ограничивает одну заметку, но число элементов и суммарные удерживаемые байты строки одной сессии ничем не ограничены; индексированное чтение метаданных и принадлежащая развёртыванию граница строки остаются отложенными, пока конкретный потребитель не определит их политику.
