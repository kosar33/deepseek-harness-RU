# fs/ - семейство возможности файловой системы

[English](README.md) | [中文](README.zh.md) | Русский

Стек файловой системы: контракт провайдера (пути исполнительного мира, ограниченный текстовый ввод-вывод и атомарная мутация с необязательной защитой по версии), локальная реализация, плагин-гейт политики (наблюдённое состояние + чтение перед правкой + запись/правка с защитой по версии), ориентированные на модель файловые инструменты + исполнитель и инструменты поиска на основе ripgrep. Все пакеты — **продуктовые**.

| Пакет | Роль | Ключ ctx |
|---|---|---|
| `fs/` | Service Definition: канонические пути процессов/файловые URI/вхождение, текстовый ввод-вывод и примитивы атомарной мутации; владеет событиями политики `fs/*` | `ctx.fs` |
| `fs-local/` | Реализация `FileSystem` над локальной файловой системой | (регистрирует `ctx.fs`) |
| [`e2b/fs-e2b`](../e2b/fs-e2b/README.ru.md) | Реализация `FileSystem` на базе E2B, разделяющая удалённый рантайм, которым владеет `ctx.e2b` | (регистрирует `ctx.fs`) |
| `fs-sandbox/` | Реализация `FileSystem` с принудительной песочницей: расширяет `fs-local` и отгораживает write/edit политикой «режим на вызов + корень workspace» (read-only запрещает, workspace-write удерживает в workspace сессии и временных корнях), чтения проходят сквозь без ограничений | (регистрирует `ctx.fs`) |
| `fs-observation-policy/` | Плагин-гейт политики: наблюдённое состояние + чтение перед правкой + запись/правка с защитой по версии, через событийный гейт `fs/*` | (нет сервиса — слушатели `fs/*`) | |
| `tool-fs/` | Ориентированные на модель инструменты `read`/`write`/`edit` И исполнитель (читает через `ctx.fs`, владеет оконным чтением, диспетчеризует `fs/*`); сохраняет семантику файловой системы для путей относительно cwd сессии и объявляет поля эскалации песочницы, когда смонтированный `ctx.fs` ставит ограничения | (регистрируется на `ctx.tools`) |
| `tool-fs-search/` | Ориентированные на модель инструменты поиска `glob`/`grep` на базе упакованного бинарника `@vscode/ripgrep`, запускаемого через `ctx.subprocess`, а НЕ через методы провайдера `ctx.fs` | (регистрируется на `ctx.tools`) |

Service Definition живёт в `fs/fs/`. Песочничный, удалённый или ограниченный проектом бэкенд файловой системы может заменить `fs-local`, не трогая Service Definition, гейт политики или схемы инструментов для модели: `fs-sandbox` предоставляет внутрипроцессное ограничение путей поверх общего режима песочницы ([решение](../../.agents/notes/implemented/feature/2026-07-14-cross-family-fs-sandbox.md)), а `fs-e2b` помещает состояние файлов в удалённый исполнительный мир, общий с провайдером подпроцессов E2B ([решение](../../.agents/notes/implemented/architecture/2026-07-28-portable-execution-world-consumers.md)). Политика (`fs-observation-policy/`) — плагин, участвующий только через событийный гейт `fs/*`, а не сервис, который внедряет инструмент, — поэтому её исключение безболезненно теряет политику и оставляет ничем не ограниченного базового провайдера, не ломая инструмент. Ожидается, что развёртывание, загружающее `tool-fs/`, загрузит и её. Ограничение по режиму и гейт чтения перед правкой ортогональны и компонуются вместе. Поиск (`tool-fs-search/`) намеренно НЕ расширяет контракт провайдера: поиск — это выполнение `rg` как отдельного процесса (упакованный бинарник `@vscode/ripgrep`, запускаемый через `ctx.subprocess`), поэтому бэкенды файловой системы остаются свободными от универсального контракта поиска; его инструменты регистрируются безусловно, а его результаты можно дочитать последующим `read`, когда рабочий каталог поиска и корень `read` лежат в одном workspace (совмещённое развёртывание, задокументированное в его README).

## Никаких таймаутов на файловом вводе-выводе

`read`/`write`/`edit` не принимают `timeoutMs`, и контракт провайдера не устанавливает дедлайна: файловый ввод-вывод здесь выполняется без учёта времени, потому что дедлайн убил бы работу, которую ОС всё равно завершит, — см. [страницу подсистемы файловой системы](../../docs/subsystems/filesystem.ru.md). Отмена по-прежнему распространяется через сигнал выполнения инструмента ради прерывания best-effort на границах системных вызовов.

Справочник подсистемы — цели, результаты, защиты, события политики, таксономия ошибок и почему файловый ввод-вывод не берёт таймаут — это [docs/subsystems/filesystem.ru.md](../../docs/subsystems/filesystem.ru.md); ограничение песочницы — в [Agent Note о межсемейной песочнице fs](../../.agents/notes/implemented/feature/2026-07-14-cross-family-fs-sandbox.md).
