# @deepseek-ai/dsh-fs-local

[English](README.md) | [中文](README.zh.md) | Русский

**Реализация локальной файловой системы** контракта провайдера `ctx.fs` ([`@deepseek-ai/dsh-fs`](../fs)). Реализует двенадцать примитивов `FileSystem` поверх хостовой файловой системы; загрузка плагином наполняет `ctx.fs`.

```ts ignore-check
import { LocalFileSystem } from '@deepseek-ai/dsh-fs-local'

await ctx.plugin(LocalFileSystem, { cwd: process.cwd() })
// ctx.fs uses the local backend; load @deepseek-ai/dsh-fs-observation-policy for the
// freshness policy gate and @deepseek-ai/dsh-tool-fs to expose read/write/edit.
```

## Поведение

- **`resolve(path, opts?)`** — относительный `path` разрешается относительно `opts.cwd`, когда вызывающий его передаёт (обращённые к модели инструменты передают cwd сессии вызывающего агента — см. [Agent Note о cwd на сессию](../../../.agents/notes/implemented/architecture/2026-07-02-fs-per-session-cwd.md)), иначе `config.cwd` (по умолчанию `process.cwd()`); абсолютный `path` игнорирует и то, и другое. `opts.signal` проверяется до и после локального разрешения, а удалённый соседний бэкенд может использовать его для прерывания своего обмена. `targetKey` — это `realpath` файла, поэтому два входных пути, доходящие до одного файла через symlink, получают общую идентичность, а записи/правки попадают в цель ссылки (сохраняя ссылку). Ещё не существующий путь использует приведённый к realpath родительский каталог плюс basename, когда родитель существует; лишь неразрешимый родитель откатывается к абсолютному пути. `displayPath` — абсолютный (не разрешённый) путь.
- **Координаты исполнительного мира** — `processPath` выдаёт канонический хостовый путь цели, `fileUrl` кодирует тот путь через учитывающее платформу преобразование URL в Node, а `contains` проверяет идентичность или вхождение потомка семантикой путей платформы, не заставляя потребителей разбирать `targetKey`.
- **`stat` / `lstat`** — возвращают метаданные цели либо `undefined`, когда её нет. `stat` сообщает `FsInfo` уже разрешённой цели (`version` = непрозрачный токен из bigint `dev:ino:size:mtimeNs:ctimeNs`, `type` из `file`/`directory`/`other`, размер в байтах); путевая форма `lstat` сообщает `FsPathInfo`, не переходя по последней symlink, и потому может вернуть `symlink`. Обе проверяют отмену до и после своей асинхронной пробы метаданных, поэтому прерывание, произошедшее во время пробы, сообщает `FS_ABORTED`, а не устаревшее отсутствие.
- **`readText` / `streamText`** — только UTF-8. `readText` читает файл целиком; `streamText` декодирует чанки, так что огромный файл не нужно целиком держать в памяти, а потребители могут соблюдать собственные лимиты удержания. Оба отвергают недопустимый UTF-8 и бинарные образцы с NUL-байтами (`FS_NOT_TEXT`) и цели, не являющиеся обычными файлами. Окнами строк владеет инструмент `read` (`@deepseek-ai/dsh-tool-fs`).
- **`readBytes`** — сырые байты всего файла без декодирования и отвержения бинарных данных (содержимое проверяет инструмент `read_image` через сервис вложений). Обязательный лимит байтов досрочно завершает операцию по размеру из stat ещё до любого содержимого I/O; последующее потоковое чтение заходит не более чем на один байт за этот лимит, поэтому файл, выросший после stat, всё равно отклоняется с `FS_TOO_LARGE` без неограниченной буферизации.
- **`listDir`** — перечисляет один уровень каталога в стабильном порядке `name.localeCompare()`. Каждая запись несёт имя дочернего элемента, его тип, разрешённую цель дочернего элемента (`displayPath` под перечисляемым каталогом, `targetKey` как realpath-идентичность) и дешёвые stat-метаданные (`version`, плюс `size` для обычных файлов). Содержимое файлов она никогда не открывает и не декодирует. Отсутствующие цели сообщают `FS_NOT_FOUND`, цели-файлы/спецфайлы — `FS_NOT_DIRECTORY`, прерванные вызовы — `FS_ABORTED`, отказы в разрешении — `FS_PERMISSION_DENIED`, прочие сбои перечисления или метаданных дочерних элементов — `FS_IO_ERROR`. Битые/исчезнувшие дочерние записи возвращаются как `other` без метаданных, но отказы разрешения/ввода-вывода при разрешении дочернего элемента приводят к сбою всего перечисления со структурированной `FsError`.
- **`writeText`** — атомарна: пишет во временный файл, открытый монопольно (`wx`, `0o600`), внутри приватного staging-каталога со случайным именем (`0o700`) рядом с целью, затем делает fsync и публикует. Режим существующего файла сохраняется, новые файлы по умолчанию получают `0o600`; на Windows новый файл наследует DACL каталога назначения, а замещение копирует DACL цели на пустой временный файл до записи и публикует через `ReplaceFileW`, чтобы исходная политика доступа пережила замену ([Agent Note о сохранении DACL на Windows](../../../.agents/notes/implemented/bug-fix/2026-07-19-windows-atomic-write-dacl-preservation.md)). Guard `expected` ОПЦИОНАЛЕН: если его опустить — безусловное создание или перезапись; `createIfAbsent` жёстко линкует подготовленный файл на место как атомарную публикацию без вытеснения, поэтому созданный после первичной пробы обычный файл сохраняется, а запись отклоняется с `FS_NOT_OBSERVED`; путь, не являющийся обычным файлом, тоже сохраняется, а запись отклоняется с `FS_NOT_REGULAR_FILE`; `replaceIfVersion` заменяет только при наблюдённой версии (отсутствующая цель или несовпадение — `FS_STALE_VERSION`). Перезапись возвращает прежний текст как основу контекстного diff только когда и открытый прежний файл, и UTF-8-замена строго ниже `config.diffBasisMaxBytes` (по умолчанию 10 МиБ). Чтение через дескриптор соблюдает этот лимит, даже если внешний писатель заменит файл или изменит его размер после первичной пробы. Иначе провайдер возвращает `before: null`, и презентация пользуется своим запасным вариантом целого файла.
- **`editText`** — атомарная литеральная последовательность «чтение—правка—запись» поверх того же примитива, сериализуемая по цели мутационной блокировкой. Guard `expected` ОПЦИОНАЛЕН: если он передан, версия проверяется ДО литерального сопоставления (устаревшая правка сообщает `FS_STALE_VERSION`, но никогда `FS_EDIT_NOT_FOUND`/`FS_AMBIGUOUS_EDIT` против более нового содержимого); если же guard опущен, правка выполняется над текущим содержимым безусловно. Отсутствующая цель в обоих случаях сообщает `FS_STALE_VERSION`. Нормализует LF для сопоставления, восстанавливает доминирующий стиль CRLF/LF файла и отвергает пустой `oldString` / ноль совпадений (`FS_EDIT_NOT_FOUND`) либо неоднозначные множественные совпадения без `replace_all` (`FS_AMBIGUOUS_EDIT`).

SDK API корня пакета — класс `LocalFileSystem` (и по умолчанию, и именованно) плюс `Config`. Сырой ввод-вывод живёт в `src/fsio.ts` (без Cordis, независимо покрыт юнит-тестами); `src/index.ts` — тонкая сервисная компоновка.

## Model Experience

Опосредованно — через [`dsh-tool-fs`](../tool-fs/README.ru.md), который рендерит построчно-оконный UTF-8-контент этого провайдера, подтверждения мутаций и точные сообщения провайдера в ограниченных удерживаемых результатах, пока версии, механика атомарной записи и метаданные каталогов остаются внутренними.

#### KV Cache effect

Прямой инвалидации нет; любые изменения префикса запроса находятся в ведении соответствующего потребителя.

## Известные ограничения и отложенная работа

- **`config.cwd` — не песочница** — это умолчание для разрешения путей, а не изоляция: абсолютные пути и `..` его покидают. Изоляцию обеспечивайте более строгим бэкендом `ctx.fs` или плагином разрешений на каскаде `tools/execute` ([Agent Note о capability seam](../../../.agents/notes/implemented/architecture/2026-06-17-filesystem-capability-seam.md#consequences)).
- **Токены версий зависят от метаданных файловой системы** — они сочетают устройство, inode, размер, наносекундные mtime и ctime; слой хранения, который не способен обновить ни один из этих фактов при переписывании, всё ещё может обмануть guard устаревания.
- **`editText` держит весь файл (плюс правленую копию) в памяти** — потоковая обработка есть только на пути чтения.
- **Перезапись ниже лимита всё равно буферизует контекстную основу** — `writeText` может удерживать почти до `config.diffBasisMaxBytes` прежнего текста сверх принадлежащей вызывающему замены; граница не ограничивает возвращаемое значение `after` и запасной вариант презентации с целым файлом.
- **Обнаружение бинарных данных асимметрично** — чтение берёт NUL-образец только из первых 8192 байтов, тогда как правки сканируют весь буфер, поэтому файл с поздним NUL читается без проблем, но отвергает правки.
- **Мутационная блокировка на цель действует только внутри процесса** — защищённое создание всё равно использует атомарную публикацию без вытеснения между процессами, но замещающих писателей в другом процессе ловит лишь необязательный guard версии, наблюдающий изменение их метаданных; сериализации между ними нет.
- **Защищённое создание требует поддержки жёстких ссылок** — файловые системы или монтирования, отвергающие публикацию жёсткой ссылкой, не могут обслужить `createIfAbsent`; провайдер сохраняет отсутствующую цель и сообщает `FS_IO_ERROR`.
- **Очистка после фиксации делается по возможности** — успешная публикация остаётся успешной, даже если удаление её приватного staging-каталога потерпит неудачу, оставляя приватные остатки для последующей очистки оператором.
