# @deepseek-ai/dsh-fs-observation-policy

[English](README.md) | [中文](README.zh.md) | Русский

**Плагин fs-observation-policy**: он записывает наблюдённое наличие или отсутствие и добавляет поверх провайдерского контракта `ctx.fs` ([`@deepseek-ai/dsh-fs`](../fs/README.ru.md)) правило read-before-edit плюс охраняемые write/edit — через событийный гейт `fs/*`, а **НЕ** через методный сервис. Этот плагин **не** регистрирует сервис `ctx.fsPolicy` и не имеет публичных методов `read`/`write`/`edit`/`resolve`. Он — третий слой файлового стека, политика: не сменяемый seam, а та политика, что не принадлежит базовому классу провайдера `FileSystem`.

```ts
import type { Context } from '@deepseek-ai/cordis'
import * as FsPolicy from '@deepseek-ai/dsh-fs-observation-policy'

declare const ctx: Context

// No service to inject — this plugin only registers the three fs/* listeners.
// Load it alongside a ctx.fs provider (e.g. @deepseek-ai/dsh-fs-local) and the
// @deepseek-ai/dsh-tool-fs tools; the tools dispatch the fs/* events this plugin
// decides. Order does not matter for resolution (no inject), but the policy
// listener should be the first decider registered for the fs/*-intent slots.
await ctx.plugin(FsPolicy)
```

## Разделение на четыре слоя

| Слой | Пакет | Роль |
|---|---|---|
| tool / executor | `@deepseek-ai/dsh-tool-fs` | видимые модели схемы + оконное чтение + текстовый рендеринг; читает/пишет/правит через `ctx.fs`, диспетчирует события `fs/*` |
| policy | `@deepseek-ai/dsh-fs-observation-policy` (этот) | наблюдённое состояние + read-before-edit + write/edit с проверкой версии, вносится через событийный гейт `fs/*` (без сервиса) |
| provider contract | `@deepseek-ai/dsh-fs` | `ctx.fs`: текстовый IO + примитивы атомарной мутации (опциональная защита по версии); владеет словарём событий `fs/*` |
| provider | `@deepseek-ai/dsh-fs-local` | локальная реализация `ctx.fs` |

## Как гейт участвует

Три события `fs/*` (объявлены в `@deepseek-ai/dsh-fs`, диспетчируются `@deepseek-ai/dsh-tool-fs`):

| Событие | Слушатель этого плагина |
|---|---|
| `fs/write-intent` | Не наблюдалось или наблюдено отсутствие → `{ kind: 'createIfAbsent' }`; наблюдено наличие → `{ kind: 'replaceIfVersion', version: vObserved }`. Решение принимается в одном slot; **НЕ** вызывает `next()`. |
| `fs/edit-intent` | Не наблюдалось → `FS_NOT_OBSERVED`; наблюдено отсутствие → `FS_NOT_FOUND`; наблюдено наличие → `{ version: vObserved }` как основа CAS. Решение принимается в одном slot; **НЕ** вызывает `next()`. |
| `fs/observed` | Записывает `{ kind: 'present', version }` или `{ kind: 'absent' }` для этой пары owner+target. Синхронный `WeakMap.set` — единственный побочный эффект. |

## Наблюдённое состояние — запись прежних наблюдений; актуальность — CAS провайдера

Наблюдённое состояние — слабая карта owner→target с тремя логическими состояниями: не наблюдалось, подтверждённое отсутствие или наличие на определённой версии. Успешное чтение файла или мутация записывают наличие; промах по метаданным в `read` либо в командах `view`, `str_replace` или `insert` редактора `str_replace_editor` записывает отсутствие перед возвратом `FS_NOT_FOUND`. Плагин не выполняет файлового ввода-вывода: он превращает это состояние в охрану провайдера. Наличие поставляет наблюдённую версию, а отсутствие пропускает только запись `createIfAbsent`; у edit нет версионной основы, и он возвращает `FS_NOT_FOUND`. Оконное чтение наблюдает версию всего файла, поэтому последующее точечное edit допускается лишь пока файл остаётся неизменным. Состояние отбрасывается при освобождении ресурсов плагина и не персистируется между сессиями.

## Один slot, побеждает первый

Slot'и `fs/write-intent`/`fs/edit-intent` держат ровно одного решающего — этот плагин решает полностью и не вызывает `next()`. Slot отдаётся первому по порядку регистрации; владение этим плагином — соглашение развёртывания по умолчанию, а не инвариант, обеспеченный событиями (решающий, зарегистрированный раньше или добавленный через `prepend`, выиграл бы вместо него). Это не композируемая цепочка авторизации — многослойные перехваты разрешений, аудита и песочницы принадлежат `tools/execute`.

## Без привязки к методам

Поскольку плагин влияет на мир только через события, его удаление не ломает `@deepseek-ai/dsh-tool-fs` на границе внедрения сервиса: инструмент откатывается к базовому провайдеру `ctx.fs` (безусловные write/edit, без наблюдённого состояния). Повторная загрузка снова надстраивает политику. Именно эта безболезненность добавления и удаления — весь смысл событийного гейта вместо обязательного методного сервиса.

## Влияние на модель

### Исход инструментов файловой системы

#### Что видит модель

Плагин не добавляет ни промпта, ни схемы. Он отвергает edit без предшествующего наблюдения с кодом `FS_NOT_OBSERVED` и точным сообщением `edit requires reading "<path>" first`; редактирование цели, у которой только что зафиксировано отсутствие, возвращает `FS_NOT_FOUND`. Охраняемые мутации с устаревшим подтверждением наличия пробрасывают принадлежащую провайдеру ошибку `FS_STALE_VERSION`. [`dsh-tool-fs`](../tool-fs/README.ru.md) владеет видимой модели обёрткой ошибок, которая добавляет инструкцию по восстановлению к сообщениям `FS_STALE_VERSION` (`— re-read the file, then retry`) и `FS_NOT_OBSERVED` (`— read the file, then retry`), сохраняя код. Выполнение совета из stale-ошибки на цели, удалённой извне, теперь записывает отсутствие: следующий охраняемый write может воссоздать файл через `createIfAbsent`, при этом провайдер атомарно сохраняет любое параллельное создание.

#### Влияние на токены

Ноль токенов на разрешённых операциях сверх обычного результата инструмента. Отказ добавляет небольшой удержанный результат с ошибкой и не содержит payload успеха.

#### Влияние на KV-кэш

Append-only; новое видимое содержимое следует за повторно используемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Наблюдённое состояние не переживает возобновление сессии** — персистентность записи `WeakMap` отложена, поэтому возобновлённая сессия **ДОЛЖНА** перечитать файлы перед охраняемыми write/edit.
- **Действующие лица без агентской сессии никогда не удовлетворяют политике** — их edit бросают `FS_NOT_OBSERVED`, а их write всегда сводятся к `createIfAbsent`, так что не-агентный вызывающий не может перезаписать существующий файл через гейт.
- **Прямые чтения `ctx.fs` не порождают `fs/observed`** — файл, прочитанный вне инструмента `read`, остаётся ненаблюдённым, и более поздний охраняемый edit отвергается с `FS_NOT_OBSERVED`, пока инструмент его не прочитает.
- **Авторизация — это актуальность версии, а не полнота просмотра** — любое оконное чтение авторизует полную перезапись неизменённого файла, сознательно слабее правила полного просмотра ([Agent Note о разделении seam](../../../.agents/notes/implemented/simplification/2026-06-26-fsspec-style-fs-seam.md)).
