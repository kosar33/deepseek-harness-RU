# dsh-fs-sandbox — бэкенд файловой системы с принудительной песочницей

[English](README.md) | [中文](README.zh.md) | Русский

`SandboxedFileSystem` расширяет [`LocalFileSystem`](../fs-local/README.ru.md) и регистрируется как `ctx.fs`. Он дословно наследует всю механику текстового хранилища (resolve, stat, read/stream, list, атомарную запись, критическую секцию правки read-match-write) и добавляет только ограждение РЕЖИМА на каждый вызов для `writeText`/`editText`. Чтения всегда проходят — чтение разрешено в каждом режиме.

Конфигурация его плагина совпадает с конфигурацией локального бэкенда без изменений: `cwd` остаётся умолчанием разрешения относительных путей, а `diffBasisMaxBytes` ограничивает необязательную основу контекстного диффа для перезаписи.

Загрузка его ВМЕСТО `dsh-fs-local`, вместе с [`ctx.sandboxPolicy`](../../sandbox/sandbox-policy/README.ru.md), — вся подмена; обращённые к модели инструменты (`dsh-tool-fs`) не затронуты. Слой инструментов разрешает режим и cwd вызывающей сессии в ТА ЖЕ политику на каждый вызов, какую получает bash, поэтому два семейства никогда не оказываются ограниченными разными корнями.

## Ограждение

Политика на каждый вызов несёт действующий режим (переопределение сессии или выданная эскалация) вместе с неизменяемым корнем cwd вызывающей сессии и возвращается к политике развёртывания только для вызовов без неё:

- `read-only` — отклоняет любую мутацию структурированным `FS_SANDBOX_DENIED`.
- `workspace-write` — разрешает мутацию, только когда цель канонизируется под перезаписываемым корнем: корень рабочей области плюс временные каталоги платформы (`/tmp`, `os.tmpdir()`), ТОТ ЖЕ набор, который выдаёт профиль Seatbelt, — выведенный из единственной функции [`writableRoots`](../../sandbox/README.md), чтобы fs-ограждение и bash-раннер не могли разойтись. Канонические написания идут по лексическому быстрому пути; основанный на идентичности предковый фолбэк распознаёт эквивалентные написания-псевдонимы одного корня, такие как длинные имена Windows и имена 8.3, не считая посторонние префиксы вложенными. Цель канонизируется заново непосредственно перед делегированием, поэтому симлинк-предок, подменённый после того, как инструмент её разрешил, будет пойман.
- `danger-full-access` — делегирует без ограждения.

## Модель угроз: политическое ограждение, а не граница ядра

Ограждение — это проверка в ДОВЕРЕННОМ коде над УПРАВЛЯЕМЫМ МОДЕЛЬЮ путём: операции принадлежат самому seam (open, rename), недоверен только целевой путь, поэтому «сначала канонизируй, затем удерживай» — исчерпывающее решение для этой поверхности. Это зеркально отражает позицию `code-runtime`: удержание, а не граница безопасности. Изоляция недоверенного КОДА уровня ядра остаётся работой `ctx.shell` ([`dsh-bash-sandbox`](../../shell/bash-sandbox/README.ru.md)). Остаточный TOCTOU (симлинк-предок, подменённый между повторной проверкой удержания и системным вызовом) сужается повторной канонизацией непосредственно перед записью и принимается в этой модели угроз; граница на уровне ядра потребовала бы примитивов класса `openat2`, чья цена переносимости здесь не оправдана.

Отказ — это структурированный `FsError` (`FS_SANDBOX_DENIED`, несущий действующий режим) — без выводов из текста stderr (в отличие от ядерных отказов bash), потому что внутрипроцессное ограждение точно знает, что именно оно отклонило. Обращённый к модели маркер `[sandbox: file access denied under <mode> mode]` и повтор с однократным одобренным расширением прав живут в слое инструментов (`dsh-tool-fs`) — в точности как у bash. См. [Agent Note о межсемейной fs-песочнице](../../../.agents/notes/implemented/feature/2026-07-14-cross-family-fs-sandbox.md).

## Model Experience

### Политика файловой системы и отказы

#### What the model sees

Владелец политики добавляет независимый от возможностей контекст `sandbox:policy`. Косвенно `dsh-tool-fs` отрисовывает отказы `FS_SANDBOX_DENIED` этого бэкенда как маркер `[sandbox: file access denied under <mode> mode]` плюс подсказку об эскалации в том же ходе.

#### Token effect

Оговорка о текущей политике добавляет небольшое сообщение рантайм-контекста, пока смонтирован этот бэкенд; отказ добавляет в историю диалога ограниченный маркер и подсказку об эскалации.

#### KV Cache effect

Изменение постоянной политики добавляет после удержанной истории заменяющий рантайм-контекстный снапшот, отрисованный владельцем; результаты операций остаются append-only.

## Известные ограничения и отложенная работа

- **Ограждение политикой, а не граница ядра** — проверка является доверенным кодом над управляемым моделью путём, поэтому остаточный TOCTOU от resolve до syscall сужается (повторной канонизацией на месте), но не устраняется; враждебные хостовые процессы вне охвата. Изоляция недоверенного кода уровня ядра остаётся за `ctx.shell`.
- **Паритет ограждения и раннера обеспечивает один владелец** — перезаписываемый набор берётся из `writableRoots`, общего с профилем Seatbelt; профиль раннера, определяющий свой перезаписываемый набор в другом месте, разошёлся бы с ограждением.
- **Требует `ctx.sandboxPolicy`** — инструменты используют её для разрешения политики каждой сессии, а бэкенд — для фолбэков вызовов без агента; без неё в композиции бэкенд ничего не ограничивает.
