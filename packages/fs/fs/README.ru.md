# @deepseek-ai/dsh-fs

[English](README.md) | [中文](README.zh.md) | Русский

**`FileSystem`** (`ctx.fs`) определяет примитивы хранения одного исполнительного мира — разрешение путей, выдачу канонических путей процесса и file-URI, проверку вхождения, чтение текста целиком или потоком, чтение ограниченных сырых байтов, инспекцию/перечисление метаданных, атомарную запись и литеральную правку — не говоря КАК. Обе мутации принимают свой guard версии **опционально**, поэтому сам по себе `ctx.fs` — полный, свободный от ограничений storage seam. Этот пакет также владеет словарём событий политики `fs/*`, которые диспетчеризует инструмент и слушает плагин политики.

Этот пакет владеет слоем Service Definition и контракта провайдера четырёхслойного стека файловой системы, разделённого так, чтобы каждый аспект мог развиваться (и подменяться) независимо (см. [Agent Note о capability seams](../../../.agents/notes/implemented/architecture/2026-06-13-capability-seams.md), [Agent Note о capability seam файловой системы](../../../.agents/notes/implemented/architecture/2026-06-17-filesystem-capability-seam.md), [Agent Note о разделении seam файловой системы](../../../.agents/notes/implemented/simplification/2026-06-26-fsspec-style-fs-seam.md) и [Agent Note о файловом контексте как событийном гейте](../../../.agents/notes/implemented/architecture/2026-06-26-file-context-as-event-gate.md)):

| Слой | Пакет | Роль |
|---|---|---|
| инструмент / исполнитель | `@deepseek-ai/dsh-tool-fs` | обращённые к модели схемы `read`/`write`/`edit` + окна чтения + рендеринг текста; читает/пишет/правит через `ctx.fs`, диспетчеризует события `fs/*` |
| политика | `@deepseek-ai/dsh-fs-observation-policy` | наблюдённое состояние + чтение перед правкой + запись/правка под guard'ом версии, добавляемые через событийный гейт `fs/*` (без сервиса) |
| контракт провайдера | `@deepseek-ai/dsh-fs` (этот пакет) | `ctx.fs`: пути исполнительного мира, текстовый IO и примитивы атомарной мутации (опциональный guard версии); владеет словарём событий `fs/*` |
| провайдер | `@deepseek-ai/dsh-fs-local` | реализация хостовой файловой системы |

`fs-sandbox` и `fs-e2b` реализуют этот интерфейс, не затрагивая слои политики и инструментов.

## Сервисный API (`ctx.fs`)

Бэкенд наследует `FileSystem` и реализует двенадцать примитивов.

| Член | Семантика |
|---|---|
| `resolve(path, opts?)` | Разрешает путь в стабильную цель `FsTarget` (непрозрачные `targetKey`, `displayPath`). `opts.cwd` — база, относительно которой разрешается относительный `path` (вызывающий подставляет рабочую область своей сессии; абсолютные пути её игнорируют; отсутствие ⇒ умолчание бэкенда), а `opts.signal` прерывает обмен с бэкендом. Асинхронно — удалённому бэкенду может понадобиться I/O. Один и тот же файл через разные пути ДОЛЖЕН давать один и тот же `targetKey`. |
| `processPath(target)` | Возвращает канонический абсолютный путь, который дочерний процесс в исполнительном мире этого провайдера способен открыть. Намеренно отлично от непрозрачного `targetKey`. |
| `fileUrl(target)` | Возвращает канонический `file:`-URI в платформенном синтаксисе исполнительного мира. Кодированием владеет бэкенд, а не хостовый процесс. |
| `contains(parent, child)` | Проверяет каноническую идентичность либо вхождение потомка, не выдавая наружу и не разбирая ключи целей. Обе цели получены от этого провайдера. |
| `stat(target, signal?)` | Возвращает метаданные `FsInfo` (`version`, `type`, необязательный `size`) либо `undefined`, когда цель отсутствует. Никогда не содержимое. |
| `lstat(path, opts?, signal?)` | Возвращает метаданные `FsPathInfo`, не переходя по последнему компоненту пути, когда тот — symlink. Форма принимает путь (а не цель), чтобы потребители могли отвергнуть принадлежащие репозиторию symlink до того, как `resolve` перейдёт по ним в цель. |
| `readText(target, signal?)` | Читает весь обычный текстовый файл одной декодированной строкой. Владеет проверками обычного файла, декодированием UTF-8 и отвержением бинарных данных/NUL (`FS_NOT_TEXT`). |
| `streamText(target, signal?)` | Отдаёт тот же текст потоком декодированных чанков для больших файлов (межчанковое декодирование UTF-8 остаётся здесь); потребители, которым нужен лимит байтов, соблюдают его при чтении потока. |
| `readBytes(target, signal, maxBytes)` | Читает полный обычный файл сырыми байтами без декодирования и без отвержения бинарных данных. `maxBytes` обязателен и ограничивает полное содержимое прямо на этом seam: известное или обнаруженное переполнение завершается ошибкой `FS_TOO_LARGE`, а не усечением или буферизацией без границы. |
| `listDir(target, signal?)` | Перечисляет дочерние записи каталога первого уровня в стабильном порядке имён. Возвращает имена записей, типы записей, разрешённые цели дочерних записей и дешёвые метаданные (`version`/файловый `size`, когда доступно); содержимое файлов никогда не читает. Отсутствующая цель бросает `FS_NOT_FOUND`, не-каталоги — `FS_NOT_DIRECTORY`, отказы в разрешении — `FS_PERMISSION_DENIED`, прочие ошибки ввода-вывода бэкенда — `FS_IO_ERROR`. Битые/исчезнувшие дочерние записи могут вернуться как `other` без метаданных; отказ разрешения/ввода-вывода у дочерней записи приводит к сбою всего перечисления с теми же структурными кодами. |
| `writeText(target, content, expected?, signal?)` | Атомарное создание/замена. `expected` ОПЦИОНАЛЕН: опустить ⇒ безусловное создание-или-перезапись; передайте `FsWriteIntent` (`createIfAbsent`/`replaceIfVersion`) для guard'а. `createIfAbsent` ДОЛЖЕН выполнять публикацию без вытеснения, чтобы создатель, соревнующийся с первичной проверкой, сохранился. |
| `editText(target, edit, expected?, signal?)` | Литеральная правка. `expected` ОПЦИОНАЛЕН: опустить ⇒ безусловная правка текущего содержимого; передайте `{ version }` для guard'а (проверяется ДО сопоставления). Отсутствующая цель в обоих случаях сообщает `FS_STALE_VERSION`. Применяется и записывается атомарно — одна критическая секция мутации. |

Мутация в любом случае исполняется внутри блокировки бэкенда на отдельную цель, поэтому безусловная запись/правка всё равно атомарна — «безусловность» снимает предварительное условие *версии*, но не атомарность.

## События политики `fs/*`

Этот пакет объявляет три события (см. генерируемую область [filesystem.ru.md](../../../docs/subsystems/filesystem.ru.md#cordis-surface)), чтобы эмиттер (`@deepseek-ai/dsh-tool-fs`) и слушатель политики (`@deepseek-ai/dsh-fs-observation-policy`) разделяли словарь без зависимости эмиттера от плагина политики. `fs/write-intent` и `fs/edit-intent` — решающие каскады с одним slot'ом (слушатель решает всё целиком, ни разу не вызывая `next()`); `fs/observed` — событие фиксации fire-and-forget, несущее дискриминированное объединение `FsObservation`: присутствует с версией либо подтверждённо отсутствует. Они несут только словарь `dsh-fs` плюс непрозрачного актёра `object` — никаких обращённых к модели понятий и никакой структуры владельца агент/сессия.

## Контракт провайдера, а не слой политики

`ctx.fs` нарочно близок к примитивам хранения в духе fsspec — на пол-уровня выше байтовых `cat`/`open`, потому что он декодирует текст и отвергает бинарные данные, так что слой политики никогда не касается сырых байтов. Он владеет декодированием UTF-8, отвержением бинарных данных, атомарными записями и критической секцией литеральной правки. Окнами строк, нумерованными строками, отрендеренными колонтитулами или наблюдённым состоянием он **НЕ** владеет. Наблюдённое состояние, чтение перед правкой и запись/правка под guard'ом версии — та политика, которую плагин (`@deepseek-ai/dsh-fs-observation-policy`) ДОБАВЛЯЕТ, поставляя опциональный guard, — а не поведение провайдера, поэтому песочничный/удалённый бэкенд не наследует никакой обращённой к модели политики наблюдения.

`editText` остаётся на этом seam (не собирается в слое политики из чтения и записи), потому что guard версии + литеральное сопоставление + атомарная перезапись ДОЛЖНЫ оставаться внутри одной критической секции ради корректной атрибуции ошибок и конкурентности «один побеждает / один получает stale», а удалённый бэкенд может реализовать её нативным сравнением с правкой.

## Словарь

`FsTargetKey` / `FsVersion` — брендированные непрозрачные идентификаторы ([Agent Note о брендированных идентификаторах](../../../.agents/notes/implemented/architecture/2026-06-20-branded-ids.md)); потребители НЕ ДОЛЖНЫ разбирать `targetKey` или интерпретировать `version`; для вывода модели/UI предназначен только `displayPath`. `FsObservation` отличает `{ kind: 'present', version }` от `{ kind: 'absent' }`, поэтому политика способна отделить невиденную цель от подтверждённого отсутствия, не выполняя I/O. `FsWriteIntent` — явное ЗАЩИЩЁННОЕ намерение записи (`createIfAbsent` создаёт отсутствующую цель и отвергает существующую с `FS_NOT_OBSERVED`; `replaceIfVersion` заменяет только по наблюдаемой версии, иначе `FS_STALE_VERSION`); его пропуск в `writeText` — третье, безусловное состояние. `FsPathInfo` — форма метаданных без перехода по symlink, умеющая сообщать `symlink`, в отличие от целевой `FsInfo`. Сбои бросают `FsError` (расширяет `HarnessError`, [Agent Note о таксономии структурированных ошибок](../../../.agents/notes/implemented/architecture/2026-06-11-structured-error-taxonomy.md)), несущий стабильный `FsErrorCode` (`FS_NOT_FOUND`, `FS_NOT_DIRECTORY`, `FS_NOT_TEXT`, `FS_NOT_REGULAR_FILE`, `FS_TOO_LARGE`, `FS_PERMISSION_DENIED`, `FS_IO_ERROR`, `FS_STALE_VERSION`, `FS_NOT_OBSERVED`, `FS_AMBIGUOUS_EDIT`, `FS_EDIT_NOT_FOUND`, `FS_ABORTED`); реестр инструментов предоставляет `{ name, code }` в результатах `isError`. Полные контракты — в `src/types.ts`.

## Model Experience

Опосредованно — через `dsh-tool-fs`, который рендерит текст и ошибки провайдера как ограниченные, удерживаемые результаты инструментов файловой системы.

#### KV Cache effect

Прямой инвалидации нет; любые изменения префикса запроса находятся в ведении соответствующего потребителя.

## Известные ограничения и отложенная работа

- **Мутации — только текстовые по контракту** — текстовые чтения и обе мутации отвергают бинарный/не-UTF-8 контент с `FS_NOT_TEXT`; `readBytes` — единственный примитив сырых байтов, а безопасные к бинарным данным мутации остаются намеренной отсрочкой [Agent Note о схемах инструментов](../../../.agents/notes/implemented/feature/2026-06-17-filesystem-tool-schemas.md).
- **Ровно двенадцать примитивов** — нет delete, rename/move, copy или watch; `listDir` одноуровневый, а рекурсия, globbing, пагинация и поиск вне охвата согласно [Agent Note о перечислении каталогов](../../../.agents/notes/archived/architecture/2026-07-03-filesystem-directory-listing-seam.md).
- **Нет дедлайна ввода-вывода** — seam не задаёт таймаут; отмена — необязательный `AbortSignal` по принципу best-effort у каждого примитива (намеренная [позиция семейства fs](../README.md)).
- **«Сначала разреши, потом действуй» стоит удалённому бэкенду двух обменов на вызов инструмента** — сворачивание или кеширование разрешения оставлено такому бэкенду.
