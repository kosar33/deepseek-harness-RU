# @deepseek-ai/dsh-tool-fs-search

[English](README.md) | [中文](README.zh.md) | Русский

**Обращённые к модели инструменты обнаружения в файловой системе** — `glob` и `grep` — основаны на упакованном бинарнике ripgrep, а не на методах провайдера `ctx.fs` и не на системной установке `rg`. Обычные Node-развёртывания разрешают платформенный бинарник из `@vscode/ripgrep`; однофайловый рантайм pkg разрешает лежащий рядом с исполняемым файлом сопутствующий файл `-rg` и возвращается к бинарнику зависимости, когда его нет. Регистрация безусловна, потому что оба носителя упаковывают ripgrep, поэтому проверки доступности при загрузке нет. Каждый вызов порождает разрешённый бинарник через seam `ctx.subprocess` с фиксированным argv-вектором (`--no-config` добавляется в начало, чтобы хостовый `RIPGREP_CONFIG_PATH` не мог внедрить preprocessor `--pre` в неограниченный spawn; управляемые моделью значения — обычные элементы argv, слоя оболочки нет, поэтому экранирование кавычками неприменимо), разбирает сырой вывод `rg` и возвращает каноническое значение относительно рабочего каталога. Пакет внедряет `tools`, `systemPrompt` и `subprocess` — сознательно **не** `fs`; `ctx.spillStore` читается оппортунистически через `ctx.get()`, потому что spill форматированного результата необязателен.

```ts ignore-check
// A deployment chooses how over-cap glob pages are selected.
await ctx.plugin(LocalSubprocessRuntime)                     // @deepseek-ai/dsh-subprocess-local
await ctx.plugin(ToolFsSearch, { sampleOverCapGlobResults: false })
// Optional: a spill backend makes capped results fully recoverable.
await ctx.plugin(LocalSpillStore)                           // @deepseek-ai/dsh-spill-local
```

Почему выбран запуск процесса: локальное обнаружение в рабочей области по своей природе — работа утилиты `rg` через запускаемый процесс, и перенос поиска на `ctx.fs` заставил бы каждый файловый бэкенд реализовать собственный поисковый API. Subprocess seam владеет исполнением spawn, завершением дерева процессов, очисткой окружения и ограниченным захватом вывода; этот пакет владеет схемами, валидацией аргументов, построением argv, разбором, удержанием, spill форматированного результата и объявлением тайм-аута. Инструменты никогда не порождают фоновое задание — вызов возвращается только после того, как `rg` выйдет сам, будет завершён кооперативным тайм-аутом, прерван или упадёт.

## Требование развёртывания: никакого хостового rg, совмещённые рабочий каталог и файловая система

Node-развёртывания получают платформенный пакет `@vscode/ripgrep` на поддерживаемых целях macOS, Linux и Windows x64/arm64. Wheel-пакеты Python SDK под Linux и macOS копируют целевой нативный бинарник рядом с однофайловым рантаймом как `<runtime>-rg`; `deepseek_harness_runtime.bundled_runtime_path()` отвергает неполный wheel до запуска. Ни одному носителю не требуется установленная в системе программа `rg`. Возвращённые пути показываются относительно разрешённого рабочего каталога (cwd сессии вызывающего агента, когда он есть, иначе `process.cwd()`) и доступны для последующего чтения через `read` только тогда, когда этот рабочий каталог и корень файловой системы — одна и та же рабочая область. Это требование совмещённости не предусматривает межсервисной проверки во время исполнения; поиск по удалённым или виртуальным файловым системам ждёт общего контракта рабочих областей или специфичного для провайдера поискового бэкенда.

## Конфигурация

Ключ `sampleOverCapGlobResults` обязателен и не имеет запасного значения; развёртывания явно выбирают контракт порядка сверх лимита. Остальные ключи — необязательные ограничения поиска со значениями по умолчанию ниже.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `sampleOverCapGlobResults` | нет (обязателен) | `true` делает выборку страницы `glob` сверх лимита по записям верхнего уровня; `false` сохраняет начало, упорядоченное по времени изменения. Когда spill форматированного результата удаётся, оба режима сохраняют полный отсортированный список в этом артефакте. |
| `globMaxResults` | `100` | Максимум путей, которые один вызов `glob` показывает инлайн (совпадает с лимитом `GlobTool` Claude Code). Результат в пределах лимита остаётся полным и упорядоченным по времени изменения. |
| `grepMaxMatches` | `250` | Максимум плоских совпадений, которые один вызов `grep` удерживает инлайн (соответствует `head_limit` из `GrepTool` Claude Code); последующие совпадения уходят в артефакт spill форматированного результата. |
| `grepMaxLineBytes` | `2000` | Байтовый предел на превью совпавшей строки; срез сохраняет границы UTF-8 и помечается `(line truncated)`. |
| `rawOutputMaxBytes` | `20000000` | Максимум полного сырого stdout `rg`, который разберёт поиск (соответствует сырому буферу ripgrep в Claude Code); больший сырой вывод падает с `SEARCH_RAW_OUTPUT_OVERFLOW`. |
| `timeoutMs` | `30000` | Кооперативный бюджет вызова инструмента, прикреплённый к обоим определениям инструментов и применяемый `@deepseek-ai/dsh-tool-call-timeout-policy` через `exec.signal`; эскалация завершения в subprocess seam — жёсткий kill. |
| `graceMs` | `3000` | Положительный льготный интервал эскалации завершения, который subprocess seam даёт сверх `timeoutMs`, прежде чем поиск упадёт с `SEARCH_ABORTED`; он не может превышать [`MAX_TIMER_DELAY_MS`](../../util/timeout/README.md). |
| `stderrMaxBytes` | `65536` | Бюджет диагностического хвоста stderr `rg`, захватываемого через collect-диспозицию subprocess seam; чтение с потерями сохраняет только хвост (с пометкой `[stderr truncated]`). |

## Инструменты

| Инструмент | Аргументы | Поведение |
|---|---|---|
| `glob` | `pattern`, `path?` | `rg --files --glob <pattern> --sort=modified --no-ignore --hidden` плюс исключения метаданных VCS (`.git`, `.svn`, `.hg`, `.bzr`, `.jj`, `.sl`). `path` — необязательный корень поиска: **каталог**; пропуск означает разрешённый рабочий каталог. Возвращает один путь FILE на строку; `rg --files` никогда не выдаёт записи каталогов. Шаблон сохраняет семантику ripgrep: без `/` он соответствует базовому имени на любой глубине, поэтому `*` соответствует всему дереву. Полные результаты остаются упорядоченными по времени изменения; представление сверх лимита следует `sampleOverCapGlobResults`. |
| `grep` | `pattern`, `path?`, `include?` | Построчный разбор `rg --json` (без двусмысленности разделения по двоеточию). `pattern` — регулярное выражение ripgrep; `path` — необязательная цель: **файл или каталог**; `include` — ОДИН позитивный glob-фильтр; список через запятую или значение с отрицанием (`!…`) отвергается сразу (альтернатива фигурных скобок вроде `*.{ts,tsx}` допустима). Возвращает совпадения, сгруппированные по файлам, в виде `Line N: <preview>`. |

Рутинные бюджеты остаются вне обращённой к модели схемы (нет `head_limit`/`offset`/`case_insensitive`/режимов вывода): модели, которой нужен окружающий контекст, следует читать совпавший файл через `read`; той, которой нужны последующие результаты, — следовать подсказке извлечения у возвращённого spill-локатора.

## Два бюджета, два артефакта

Сырые stdout и stderr `rg` — внутренние транспортные детали. Каждый поиск запрашивает у subprocess seam бюджеты режима collect — полный stdout в пределах `rawOutputMaxBytes` и диагностический хвост `stderrMaxBytes` — без spill-файлов ни на одном из потоков (инструмент никогда не читает сырой spill-путь). Если seam всё же сообщает о чтении stdout с потерями, поиск падает с `SEARCH_RAW_OUTPUT_OVERFLOW` и предлагает модели сузить запрос; чтение stderr с потерями лишь помечает диагностическую выдержку `[stderr truncated]`. Успешный `glob` сохраняет показанный корень поиска и все полученные пути в `{ root, paths }`; когда выборка включена, `root` позволяет нативному рендереру группировать явный относительный или абсолютный путь поиска по записям непосредственно под этим корнем, а не по префиксу рабочего каталога. `grep` сохраняет каждое полученное `{ path, lineNumber, line }` в `{ matches }`. Лимиты инлайн-элементов и превью на строку действуют только в нативном рендерере. Для прямого вызова поверхности с большим числом логических результатов, чем инлайн-лимит, best-effort после политики сохраняет полное форматированное превью через `ctx.spillStore.saveText()` и заменяет только представление настроенной страницей плюс локатором. Вложенные диспетчеризации Code пропускают этот spill, потому что их полное каноническое значение не входит в контекст модели. Отсутствующий или неудавшийся spill сохраняет инлайн-страницу и сообщает, что полный результат сохранить не удалось, — но никогда не даёт `isError`.

## Ошибки

Поисковые отказы несут принадлежащий пакету `SearchError` (подкласс `HarnessError`), доступный вызывающей стороне как `{ name, code }` в результатах `isError`: `SEARCH_INVALID_PATTERN` (ripgrep отверг регулярное выражение/glob), `SEARCH_FAILED` (неудавшийся запуск `rg`, недоступная цель, принудительное завершение сигналом, некорректный `--json`-вывод), `SEARCH_RAW_OUTPUT_OVERFLOW` (сырой вывод сверх `rawOutputMaxBytes` или всё ещё с потерями после запрошенного бюджета захвата stdout) и `SEARCH_ABORTED` (кооперативный тайм-аут инструмента или отмена вызывающим). Семантика кодов выхода ripgrep принадлежит инструменту: выход 0 — успех с результатами, выход 1 — успешный пустой поиск (`No files found` / `No matches found`), и только прочие выходы считаются отказами. Ошибки аргументов со стороны модели (пустой шаблон, списочное значение `include`) остаются обычными ошибками аргументов инструмента.

## Model Experience

### Системный промпт

#### What the model sees

Каждый запрос в скоупе регистрации этого плагина содержит приведённое ниже независимо зарегистрированное руководство для glob и grep. Ограничения инструментов на уровне агента могут скрыть любую из схем, не убирая её секцию промпта.

##### Руководство для glob с `sampleOverCapGlobResults: true`

```markdown
Use the glob tool — not shell find — to discover files by path pattern. A pattern with no "/" matches basenames at any depth, so "*" matches every file in the tree rather than its top level. Results are files only, never directories, and include hidden and ignored files: a result that fits comes back in modification-time order, while a larger one is sampled across top-level entries, so it spans the tree instead of one subtree.
```

##### Руководство для glob с `sampleOverCapGlobResults: false`

```markdown
Use the glob tool — not shell find — to discover files by path pattern. A pattern with no "/" matches basenames at any depth, so "*" matches every file in the tree rather than its top level. Results are files only, never directories, and include hidden and ignored files: a result that fits comes back in modification-time order, while a larger one keeps the modification-time-ordered head.
```

##### Руководство для grep

```markdown
Use the grep tool — not shell grep or rg — to search file contents. Use read on a matched file when you need surrounding context.
```

#### Token effect

Фиксированная цена руководства на каждый запрос, пока инструменты зарегистрированы; обязательный выбор режима выборки выбирает один из вариантов glob.

#### KV Cache effect

Префиксно-стабильно, пока скоуп плагина, выбор режима выборки и текст руководства неизменны. Активация, освобождение ресурсов или изменение выбора могут инвалидировать переиспользование начиная с этой секции промпта.

### Схемы инструментов

#### What the model sees

Описание glob сообщает настроенный порядок сверх лимита. Сгенерированные [схемы `glob` и `grep`](../../../docs/tool-catalog.md#deepseek-aidsh-tool-fs-search) используют `sampleOverCapGlobResults: true`; инструменты регистрируются безусловно.

#### Token effect

Фиксированная цена схемы на каждом запросе, где инструменты видимы.

#### KV Cache effect

Префиксно-стабильно, пока видимость и определения инструментов неизменны. Жизненный цикл регистрации или скоупные ограничения могут инвалидировать переиспользование с первого изменившегося токена схемы.

### Результаты и spill-уведомления

#### What the model sees

`glob` возвращает один путь на строку; `grep` группирует совпадения вида `Line <line>: <preview>` под каждым путём. Пустые поиски возвращают `No files found` или `No matches found`. Ограниченный результат оканчивается числом пропущенных элементов, за которым следуют spill-локатор и подсказка извлечения бэкенда, либо сообщает, что полный результат сохранить не удалось. С `sampleOverCapGlobResults: true` страница `glob` сверх лимита берёт пути по кругу (round-robin) по записям, находящимся непосредственно под фактическим корнем поиска, а нижний колонтитул называет основание выборки и то, скольких записей верхнего уровня она достигла; когда достичь их всех нельзя, колонтитул указывает модели сузить `path`. С `false` страница — это начало, упорядоченное по времени изменения, и она сохраняет простой колонтитул ограниченного результата. Уместившийся в инлайне результат остаётся нетронутым, а плоский результат с выборкой тоже сохраняет простой колонтитул, потому что его выборка совпадает с началом по времени изменения. Spill-артефакт всегда содержит полный список в порядке времени изменения.

#### Token effect

Инлайн-пути и совпадения ограничены `globMaxResults`, `grepMaxMatches` и `grepMaxLineBytes`; вызов и удержанный результат остаются в истории до компакции.

#### KV Cache effect

Append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Ошибки инструментов

#### What the model sees

Отказы нормализуются как `Error: <message>` со структурными метаданными `SEARCH_INVALID_PATTERN`, `SEARCH_FAILED`, `SEARCH_RAW_OUTPUT_OVERFLOW` или `SEARCH_ABORTED` для вызывающих сторон.

#### Token effect

Только неудавшийся вызов добавляет эти удержанные токены.

#### KV Cache effect

Append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Known Limitations and Deferred Work

- **У поиска и доступа к файлам нет доказательства общей рабочей области** — возвращённые пути доступны для последующего чтения, только когда рабочий каталог и корень файловой системы обозначают одну рабочую область; пакет не выполняет межсервисной проверки во время исполнения.
- **Упакованный бинарник зафиксирован версией зависимости** — Node-развёртывания используют версию, выбранную `@vscode/ripgrep`; однофайловые рантаймы Python копируют эту целевую нативную версию в обязательный сопутствующий файл `-rg`. Неподдерживаемая платформа или повреждённая установка падают с `SEARCH_FAILED`, а пакет рантайма Python отвергает отсутствующий сопутствующий файл ещё до запуска. Удалённым или виртуальным файловым системам нужна совмещённая рабочая область либо другой поисковый потребитель.
- **Схемы предоставляют одну ограниченную страницу** — пагинация смещениями, переключатели режима регистра, альтернативные режимы вывода и обнаружение с поддержкой провайдеров остаются вне этого пакета; ограниченный полный вывод требует spill-бэкенда.
- **Выборка, когда включена, группирует только по первому сегменту пути под корнем поиска** — страница `glob` сверх лимита балансируется по этим записям верхнего уровня, поэтому результат, сосредоточенный глубже (один занятой каталог внутри в целом равномерного дерева), всё равно оказывается показанным неравномерно ниже этого уровня; рекурсивное балансирование отложено.
