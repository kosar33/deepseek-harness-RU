# @deepseek-ai/dsh-command-goal

[English](README.md) | [中文](README.zh.md) | Русский

Управление `/goal`, обращённое к человеку, поверх [`ctx.goals`](../goal/README.ru.md). Плагин регистрирует одну глобальную команду через [`ctx.commands`](../../interaction/commands/README.ru.md), поэтому каждый собранный командный адаптер обнаруживает и исполняет её без модельного хода. Решения по UX и композиции принадлежат [Agent Note о человеческой команде goal](../../../.agents/notes/implemented/feature/2026-07-19-human-goal-command.md).

## Контракт команды

| Ввод | Результат |
|---|---|
| `/goal` | Показывает текущую формулировку цели, долговечную фазу, счётчик/предел Round, активацию в пределах процесса и допустимые следующие команды; заблокированная цель дополнительно показывает код своей политики и объяснение, а отсутствие цели показывает справку. |
| `/goal <objective>` | Создаёт и взводит цель либо заменяет завершённую цель с новой идентичностью. Незавершённая цель никогда не заменяется без явного clear. |
| `/goal edit <objective>` | Правит текущую формулировку, не меняя её фазу или активацию. Правка завершённой цели создаёт новую активную цель. |
| `/goal pause` | Приостанавливает активную цель и разоружает продолжение. |
| `/goal resume` | Возобновляет остановленную цель или перевзводит активную цель после возобновления/fork сессии, в пределах оставшегося лимита Round. |
| `/goal clear` | Очищает текущий указатель, сохраняя его долговечную историю и tombstone. |

Служебные слова нечувствительны к регистру только когда занимают весь ввод. Любой иной непустой суффикс — формулировка цели, поэтому `/goal pause after verification` создаёт именно такую литеральную цель. Домен целей обрезает и валидирует формулировки. Поскольку общая командная плоскость не имеет модального редактора или примитива подтверждения, `edit` принимает замену инлайн, а незавершённая замена возвращает прямую ошибку, предлагающую пользователю отредактировать цель или очистить её.

Команда декларирует `input.images`, поэтому вложенные изображения композера могут сопровождать вызов. Вложения сопровождают только формулировку: при удачном создании или правке продюсер отправляет один пользовательский followup, несущий принятые блоки изображений плюс фиксированный текст `Reference images for the goal objective.`, поэтому последующие Round читают их из обычной истории сессии, а домен целей не хранит состояние вложений. Любая другая подкоманда, равно как любой отклонённый create или edit, возвращает прямую ошибку и ничего не отправляет, поэтому диспетчеризующий композер сохраняет изображения.

Ожидаемые отказы домена становятся стабильными прямыми ошибками команды без раскрытия брендированных id или ревизий. Неожиданные сбои реализации по-прежнему отклоняют диспетчеризацию, чтобы адаптеры могли сообщить о них как о сбоях команды. Общий текст и вывод команды остаются живым состоянием UI; `dsh-goal` персистирует каждую принятую мутацию через собственное долговечное событие `goal/change`.

## Композиция

Продюсер внедряет `commands` и `goals`. Собственное приложение монтирует их владельцев плюс этот плагин; автоматическое продолжение остаётся самостоятельным выбором:

```yaml
- id: commands
  name: '@deepseek-ai/dsh-commands'
- id: goal
  name: '@deepseek-ai/dsh-goal'
- id: command-goal
  name: '@deepseek-ai/dsh-command-goal'
```

Поставляемая база `dsh` включает стек персистентных целей и эту команду; веб-клиент предоставляет её интерактивный адаптер. Автоматизационное приложение ACP включает домен и модельные инструменты без командного адаптера; `goals: false` удаляет этот стек. Свободный от UI `agent-spine-demo` требует явного `goals: {}`, чтобы headless-вызывающие «одного выстрела» не переключались молча от одного физического хода к многоходовой операции.

## Model Experience

### Человеческое управление `/goal`

#### Что видит модель

Слэш-ввод, мутация и прямой вывод статуса/ошибки отсутствуют в модельных запросах. Домен целей записывает мутацию как `goal/change`; включённый same-session драйвер может раскрыть получившееся состояние в более позднем промпте продолжения. Презентационный текст никогда не журналируется. Когда create или edit несёт вложенные изображения, модель видит одно обычное пользовательское сообщение: блоки изображений, за которыми следует текст `Reference images for the goal objective.`; оно предшествует следующему Round цели в истории сессии.

#### Эффект на токены

Чтение статуса, мутация цели или получение прямой ошибки команды не добавляют модельных токенов. Включённый same-session драйвер может добавить поздние промпты Round. Вложенные изображения формулировки добавляют одно пользовательское сообщение, тарифицируемое как любой промпт с изображением.

#### KV Cache effect

Обнаружение команды, мутации и прямой вывод не затрагивают кэш. Поздние промпты продолжения следуют обычной истории запросов драйвера.

## Known Limitations and Deferred Work

- **Только текстовое взаимодействие** — общий реестр команд не имеет модальной формы правки или колбэка подтверждения замены; инлайн-правка и явный clear удерживают деструктивное намерение детерминированным у всех адаптеров.
- **Нет аргумента лимита Round на команду** — `defaultMaxGoalRounds` остаётся конфигурацией развёртывания, тогда как прямой запрос человека может поручить модели править `max_goal_rounds` через отдельно авторизованный инструмент целей.
- **Нет постоянного виджета статуса** — голый `/goal` и есть переносимый API наблюдения; адаптерно-специфичные бейджи и переподключаемый вывод команды остаются будущей работой по UI.
- **Веб-командный адаптер — только в поставляемых приложениях** — headless-, ACP-автоматизация и JSON-RPC адаптеры не потребляют `ctx.commands`. Обычные промпты тем не менее могут авторизовать обращённые к модели инструменты целей, когда те собраны в композицию.
