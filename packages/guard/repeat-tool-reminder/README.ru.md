# @deepseek-ai/dsh-repeat-tool-reminder

[English](README.md) | [中文](README.zh.md) | Русский

Консультативный прерыватель циклов, а не обращённый к модели инструмент: он никогда не появляется в списке инструментов, никогда не накладывает вето и не переписывает вызов и добавляет ровно одно поведение — следит за потоком вызовов инструментов каждого агента, считает серии подряд идущих вызовов одного инструмента с идентичными канонизированными аргументами и на сконфигурированных длинах серий внедряет эскалирующее консультативное напоминание, призывающее модель перестать повторяться, перечитать последний результат и либо сменить подход, либо завершиться. Решение (повторить иначе, собрать больше свидетельств или закончить) остаётся целиком за моделью: законно повторяющийся вызов ничем не задерживается и не блокируется. Запись решения: [Agent Note о repeat-tool-reminder](../../../.agents/notes/archived/feature/2026-07-08-repeat-tool-guard.md).

## Конфигурация

```yaml
- id: repeat-tool-reminder
  name: '@deepseek-ai/dsh-repeat-tool-reminder'
  config:
    thresholds: [3, 5, 8]        # default; consecutive counts that trigger a reminder
    include: []                  # tool-name patterns to track; empty ⇒ all tools
    exclude: [todo_write]        # tool-name patterns transparent to the chain
    argumentsPreviewChars: 500   # default; cap on arguments quoted in the detailed reminder
```

`thresholds` громко отказывает при загрузке плагина: пустой список, нецелое значение, значение ниже 2 или дубликат бросает исключение — никогда тихого отката к значениям по умолчанию; `argumentsPreviewChars` равным образом отвергает всё, кроме целого >= 1. Список нормализуется в восходящий порядок; ПЕРВЫЙ порог доставляет короткое общее подталкивание, каждый последующий — подробную форму, называющую инструмент, длину серии и канонические аргументы, — обрезанную с головы на `argumentsPreviewChars` с маркером числа опущенных символов, чтобы зациклившийся payload `write`/`edit` не мог уехать в следующий запрос без границ (ключ цепочки всегда сравнивает ПОЛНУЮ каноническую строку; потолок ограничивает напоминание, никогда само распознавание).

Записи `include`/`exclude` поддерживают подстановочные `*` и являются предикатами над тем, какие инструменты существуют в момент вызова, а не ссылками на записи реестра — шаблон, не совпадающий ни с одним из зарегистрированных сейчас инструментов, НЕ является ошибкой (`exclude: [mcp_*]` остаётся валидным в развёртывании, не загружающем MCP-инструментов), в отличие от проверки референта `toolOrder`.

## Семантика цепочки

Ключ цепочки — `(tool name, canonical arguments)`; канонизация — глубокая сортировка ключей плюс `JSON.stringify`, поэтому объекты аргументов, различающиеся только порядком свойств, считаются идентичными. Вызов, идентичный предыдущему отслеженному, наращивает счётчик подряд идущих вызовов агента; иной отслеженный вызов сбрасывает его в 1.

- **Неотслеженные вызовы прозрачны для цепочки.** Вызов, исключённый `include`/`exclude`, ни наращивает, ни сбрасывает счётчик, поэтому `grep X → todo_write → grep X` всё ещё считается двумя подряд `grep X`, когда `todo_write` исключён. Именно это делает исключение полезным: служебные инструменты, вклиненные в цикл, не должны его обеливать.
- **Отклонённые вызовы считаются.** Распознавание сидит на `tools/post-execute`, который выполняется и для вызовов, отклонённых слушателем `tools/pre-execute`, — модель, долбящая отклонённый вызов, ровно тот цикл, который стоит разорвать.
- **Вызовы без агента игнорируются.** У прямого вызывающего `ctx.tools.execute()` нет модели, которой стоит напоминать, и нет живого объекта агента, на котором можно ключовать.
- **Ключование по агенту.** Реестр инструментов живёт на уровне контекста, и субагенты вклиниваются через тот же каскад, поэтому `WeakMap<Agent, Chain>` ключует каждую цепочку по живому объекту агента; повторение одного агента никогда не взводит напоминание другого. Пользовательский промпт (`agent/pre-step`) сбрасывает цепочку подающего агента, а время жизни объекта ограничивает слабую запись без слушателя освобождения.
- **Только в памяти.** Сессия, возобновлённая из персистентности, начинает со свежей цепочки — guard — эвристическое подталкивание, а не залогированный инвариант, и поздние напоминания — принятая цена.

## Доставка напоминаний

Напоминания едут в `additionalContexts` решения post-execute (источник `{kind: 'plugin', plugin: 'repeat-tool-reminder'}`), никогда не подменой `content`: событие `tool/result` остаётся собственным выводом инструмента ради аудита. Цикл буферизует контекст и дописывает его как внедрённый `user/message` после результатов инструментов шага, и сессия рендерит его как обычное синтетическое пользовательское сообщение — так напоминание видимо модели, атрибутировано по источнику и воспроизводимо из журнала сессии без нового события сессии. Guard всегда делегирует через `next()` и ставит своё напоминание в начало массива контекстов нижестоящего решения (оба варианта — заблокированный вызов тоже получает подталкивание); каждая запись сохраняет свой источник и метаданные.

## Model Experience

### Контекстное сообщение первого порога

#### What the model sees

На первом сконфигурированном пороге подряд идущих повторов этот агент получает приведённое ниже напоминание. Ни схема инструмента, ни текст обычного вызова не добавляются.

##### Напоминание первого порога

```markdown
You are repeating the exact same tool call with identical arguments. Carefully analyze the previous result before calling again: if the task is not complete, try a different approach or different arguments instead of repeating the call.
```

#### Token effect

Ноль токенов до порога. Напоминание — удерживаемая история этого агента.

#### KV Cache effect

Append-only; новый видимый контент следует за повторно используемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Контекстное сообщение последующих порогов

#### What the model sees

Последующий порог получает приведённый ниже шаблон подробного напоминания. Ограниченный предпросмотр аргументов заканчивается ровно `… (+<omitted> more chars)`.

##### Напоминание последующих порогов

```markdown
Repeated tool call detected:
- tool: <toolName>
- consecutive_calls: <count>
- arguments: <canonicalArguments>
The repeated calls are not making progress. Do not call this tool with these exact arguments again. Inspect the latest result and choose a different action, different arguments, or finish the task if enough evidence has been gathered.
```

#### Token effect

Каждое напоминание — удерживаемая история; `argumentsPreviewChars` ограничивает его зависящий от данных текст аргументов, при этом агенты держат независимые счётчики.

#### KV Cache effect

Append-only; новый видимый контент следует за повторно используемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Только распознавание точных совпадений** — канонизация это глубокая сортировка ключей, поэтому почти идентичные варианты (подправленный путь, лишние пробелы внутри значения) ускользают от цепочки; нечёткое сопоставление отвергнуто до свидетельств потребности.
- **Компакция не сбрасывает цепочки** — цепочка, пересекающая чекпоинт компакции, продолжает считать.
- **Только консультативно** — эскалация до `block` на высоком пороге не реализована, хотя `PostToolDecision` уже поддерживает блокировку.
- **Нет разделения цепочек между субагентами** — цепочки остаются изолированными по агенту; повторяющие один и тот же вызов родитель и его субагент никогда не суммируются.
- **Законный идемпотентный поллинг всё же получает подталкивания** сверх порогов — предохранительные клапаны это конфигурация `thresholds`/`exclude`.
- **Высочайшего порога цепочка замолкает** — напоминания срабатывают только на точных сконфигурированных счётах и никогда за их пределами.
