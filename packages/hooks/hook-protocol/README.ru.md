# @deepseek-ai/dsh-hook-protocol

[English](README.md) | [中文](README.zh.md) | Русский

**Общее ядро** формата протокола хуков Claude Code / Codex. НЕ плагин cordis — он ничего не регистрирует и ничего не внедряет. Это **библиотека** диалектно-нейтральных примитивов, которую импортируют два плагина-моста (`@deepseek-ai/dsh-hooks-claude-code`, `@deepseek-ai/dsh-hooks-codex`), чтобы ни один из них не реализовывал заново одинаковые половины протокола.

Codex сознательно переimplementирует *подмножество* протокола хуков Claude Code — ту же форму групп матчеров в `hooks.json`, тот же контракт вывода через код выхода/stdout, ту же модель исполнения command-хуков. Подлинно общие части живут здесь; каждый мост владеет только тем, что различается.

## Общее (здесь) и диалектное (мосты)

| Аспект | Здесь (`dsh-hook-protocol`) | Мост (`dsh-hooks-claude-code` / `-codex`) |
|---|---|---|
| Валидация и проверка матчера | `matcherDiagnostic(pattern, mode)` для диагностик во время разбора; `matchesMatcher(pattern, query, mode)` для содержательного сопоставления во время выполнения | выбирает свой `mode` (`claude` = литерал или regex, `codex` = всегда regex) и отвергает группу конфигурации, несущую диагностику |
| Запуск хука | `runHook(bash, hook, opts, now)` — полезная нагрузка stdin + env через `ctx.shell`, декодирование | строит пособытийную **полезную нагрузку** stdin + **env** диалекта |
| Декодирование вывода | `parseHookOutput(exit, stdout, stderr)` → нейтральный `HookOutput` | проецирует нейтральный `HookOutput` на типизированное решение конкретной точки расширения |
| Слияние N хуков | `mergeHookOutputs(outputs)` → максимально ограничивающий `MergedHookOutcome` | — |
| Долговечная запись | `appendHookInvoked` / `appendHookResult` (события сессии `hook/*`; `decision`/`stderrSummary` результата выводятся здесь из `HookOutput`) | вызывает их вокруг каждого вызова |
| Quiescence отсоединённых запусков | `createDetachedRuns()` — отслеживает цепочки запусков fire-and-forget; `drain()` прерывает их, затем ожидает | передаёт `signal` каждому отсоединённому `runHook`, регистрирует `drain` как disposer своего эффекта |

## Примитивы

- **`matcherDiagnostic(matcher, mode)` / `matchesMatcher(matcher, query, mode)`** — соответствие всему при отсутствии/`''`/`'*'`; режим `claude` считает чистый шаблон `[A-Za-z0-9_|]+` литералом (pipe = перечисление точных совпадений), а всё прочее — regex'ом; режим `codex` — всегда незаякоренный regex. Разборщики мостов отбрасывают поля матчера у событий без субъектов-матчеров, затем используют `matcherDiagnostic`, чтобы отвергнуть недействительный употреблённый regex со стабильной диагностикой до регистрации каких-либо хуков. Предикат времени выполнения по-прежнему содержит недействительный шаблон как несовпадение, поэтому прямой вызывающий библиотеки не может бросить исключение в цикл агента.
- **`runHook(bash, hook, options, now)`** — требует и пробрасывает принадлежащий вызывающему `options.signal`, сериализует `options.payload` в stdin хука (с завершающим переводом строки тогда и только тогда, когда задан `options.trailingNewline`), сливает `options.env` после очистки credential исполнителем (API доверенного плагина `dsh-shell`), соблюдает `timeoutSec` хука (иначе `options.defaultTimeoutMs` — умолчание принадлежит мосту, а его конфигурация опирается на справочные десять минут библиотечного `DEFAULT_HOOK_TIMEOUT_MS`) и декодирует результат (пробрасывая `options.expectedEventName` в кодек). Отмена поэтому доходит до завершения группы процессов исполнителя и его join-границы. Никогда не бросает: отказ исполнителя (инфраструктурная неисправность) становится `HookOutput` с `exitCode: undefined` (неблокирующая ошибка). `now` внедряется ради проверяемых длительностей.
- **`parseHookOutput(exitCode, stdout, stderr, expectedEventName?)`** декодирует статус выхода и структурированный stdout. Код выхода 2 блокирует с stderr; другие отказы неблокирующие. Совпадающее специфичное для хука решение о разрешении переопределяет устаревшее решение верхнего уровня; несовпадающие или отсутствующие различители событий подавляют только специфичные для события поля. Поля верхнего уровня остаются не зависящими от события, а успешный не-JSON вывод остаётся на усмотрение моста.
- **`mergeHookOutputs(outputs)`** — свёртка результатов всех хуков, совпавших в одной точке: приоритет разрешений **deny > ask > allow**, залипание halt на первом `continue:false`, причины блокировки соединяются `\n\n`, `additionalContext`/`systemMessages` накапливаются по порядку.
- **`createDetachedRuns()`** — отслеживание quiescence для точек формы emit, которые выполняются отсоединённо (ни одна точка расширения их не ожидает). Мост отслеживает каждую цепочку выполнения — запуск хука ПЛЮС его продолжение — и регистрирует `drain()` как disposer своего эффекта: drain подаёт abort `signal` трекера (так что всё ещё выполняющийся процесс хука завершается через `runHook`, а не дожидается своего таймаута), затем разрешается, когда урегулирована каждая отслеженная цепочка. Разрешение `fiber.dispose()` поэтому означает, что не осталось отсоединённой работы хука, способной выстрелить в уже освобождённый контекст ([защитные паттерны](../../../docs/defensive-patterns.ru.md): dispose обязан достигать quiescence).

## События сессии `hook/*`

Слиянием деклараций входят в `SessionEventMap` (только журнал, как `compaction/*` — НЕ `SurfaceEventType`, без `surfaceOp`): `hook/invoked` (выполнилась команда хука) и `hook/result` (её исход, сопоставленный по `handlerId`, где правилом решений владеет `appendHookResult`). Полезные нагрузки и JSDoc каждого события — в сгенерированном [каталоге событий журнала персистентности](../../../docs/persistence-catalog.md); `stderrSummary` усекается до `stderrSummaryMaxChars` записи (конфигурация моста, справочное значение по умолчанию `DEFAULT_STDERR_SUMMARY_MAX_CHARS` = 500; опускается, когда пусто).

Записи вызова/результата хука **ДОЛЖНЫ** находиться внутри открытого хода. `UserPromptSubmit`, `PreToolUse`, `PostToolUse` и `Stop` удовлетворяют это определённое владельцем отношение по построению. `SessionStart` выполняется до хода 1 и не получает записи `hook/*`; его разрешённый контекст остаётся ожидающим в inbox, пока пробуждающая доставка не откроет ход — см. Agent Note о хуках.

## Model Experience

Косвенно, через `dsh-hooks-claude-code` и `dsh-hooks-codex`, которые способны превращать разобранный вывод хука в контекст промпта, блокирующие исходы или обратную связь для продолжения.

#### KV Cache effect

Прямой инвалидации нет; изменения префикса запроса находятся во владении названного потребителя.

## Известные ограничения и отложенная работа

- **`HookOutput.updatedInput` разбирается, но не применяется** — переписывание входа — отложенная задача согласования дизайна ([Agent Note о переписывании входа перед инструментом](../../../.agents/notes/proposed/feature/2026-06-30-pre-tool-input-rewrite.md)); мост логирует и предупреждает, когда хук выставляет это поле. Полные контракты — в `src/types.ts`.
