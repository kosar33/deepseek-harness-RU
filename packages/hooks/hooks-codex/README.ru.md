# @deepseek-ai/dsh-hooks-codex

[English](README.md) | [中文](README.zh.md) | Русский

Плагин cordis, запускающий поддерживаемое подмножество существующей конфигурации хуков **Codex** пользователя на канонических точках перехвата harness. Половина подсистемы хуков, реализующая «диалект Codex». Не зависящие от диалекта примитивы приходят из [`@deepseek-ai/dsh-hook-protocol`](../hook-protocol/README.md); этот мост владеет payload'ами в форме Codex, режимом матчеров и отображением решений.

Этот мост реализует сознательно выбранное подмножество нынешнего протокола хуков Codex:

- **Пять из десяти точек хуков:** `PreToolUse`, `PostToolUse`, `SessionStart`, `UserPromptSubmit` и `Stop`.
- **Матчеры только на регулярных выражениях** (без быстрого пути по литеральной строке; матчер — всегда незаякоренное регулярное выражение).
- **Payload'ы stdin в snake_case** с дополнительными полями `turn_id`/`model`, записываемые **без** завершающего перевода строки.
- **Нет инъекции окружения плагинов Codex и нет подстановки placeholder'ов при разборе конфигурации** (команда всё равно получает окружение исполнителя и запускается через его оболочку).
- **Нет одобрения перед вызовом и нет перезаписи входа инструмента** — хук может заблокировать, но мост не одобряет заранее и не заменяет вход инструмента.

Собственный плагин cordis мог бы делать всё, что делает этот мост, и мощнее; мост существует только как путь совместимости для отображённого подмножества Codex (см. [Agent Note о точках расширения перехвата](../../../.agents/notes/implemented/feature/2026-06-30-interception-extension-points.md)).

## Конфигурация

```ts
import type { Config } from '@deepseek-ai/dsh-hooks-codex'
const config: Config = {
  configPath: '/path/to/.codex/hooks.json', // required
  model: 'deepseek-v4',                      // optional: stamped on every payload (Codex includes `model`)
  defaultTimeoutMs: 600_000,                 // optional: per-hook timeout when a hook sets none
  stderrSummaryMaxChars: 500,                // optional: char cap on the hook/result event's persisted stderr summary
}
```

В `cordis.yml`:

```yaml
- dsh-hooks-codex:
    configPath: ./.codex/hooks.json
    model: deepseek-v4
```

Конфигурация разбирается **один раз** при загрузке. `configPath` — **на уровне процесса**: относительный путь разрешается от cwd запуска процесса во время загрузки, а не посессионно (`TODO(per-session-hook-config)`). Отказ чтения/разбора локализуется (пишется в журнал и ничего не регистрирует); неверный regex-матчер на событии, использующем матчеры, — один из таких отказов и сообщает свой шаблон и событие. Запускаются только синхронные хуки `type: 'command'` — не-command или `async: true` хук разбирается и пропускается с предупреждением. Хук принимает `timeout` или алиас `timeoutSec`; не задавший ни того ни другого работает с референсным дефолтом протокола (`DEFAULT_HOOK_TIMEOUT_MS` из `dsh-hook-protocol`, 10 минут). События вне пяти поддерживаемых мостом точек отбрасываются при разборе.

Сами хуки работают в воркспейсе сессии агента: для точек в области агента мост передаёт `cwd` сессии как рабочий каталог процесса хука, поэтому хук действует в дереве проекта пользователя, а не в каталоге запуска сервера.

## Точки хуков → типизированные решения

| Хук Codex | Точка Harness | Отображение |
|---|---|---|
| `SessionStart` | `agent/session-start` (emit) | вывод хука с простым stdout → additionalContext → `agent.inject()` |
| `UserPromptSubmit` | `agent/pre-step` (waterfall) | `block` (выход 2) → `PreStepDecision.reject`; только additionalContext → делегировать через `next()`, затем добавить к последующему решению `enter` сообщение с отдельной атрибуцией источника |
| `PreToolUse` | `tools/pre-execute` (waterfall) | `block` → `PreToolDecision.deny` (без `allow`/`ask`) |
| `PostToolUse` | `tools/post-execute` (waterfall) | `block` → `block` с обратной связью; только additionalContext → делегировать через `next()`, затем добавить в начало последующего решения контекст с отдельной атрибуцией источника; Code Mode откладывает контексты под-вызовов до результата внешнего `run_code` |
| `Stop` | `agent/turn-stopping` (serial) | блокирующий Stop-хук подаёт свою причину через `steer()`, принуждая ещё один шаг |

Payload вызова инструмента несёт реальное `tool_name` (то же значение, которое проверяет матчер) и форму Codex `tool_input: { command }` (аргумент `command`, когда есть, иначе `''`). Субъект матчера — имя инструмента (`PreToolUse`/`PostToolUse`) или источник сессии (`SessionStart`); `UserPromptSubmit`/`Stop` игнорируют матчеры.

Каждый stdin-payload в области агента несёт `session_id` и `transcript_path`. Мост разрешает последний через `ctx.sessionPersistence.locate(session.header)`, когда тот доступен, иначе шлёт `null`, сохраняя форму Codex `string | null`. Поиск не создаёт и не сбрасывает артефакт, поэтому путь может отсутствовать до первого чекпоинта конца хода или не включать текущий открытый ход.

`SessionStart` — единственная точка emit — работает отсоединённо; каждая цепочка запусков отслеживается, а освобождение ресурсов моста прерывает ещё работающий процесс хука, затем осушает продолжение до разрешения освобождения (`createDetachedRuns` в `dsh-hook-protocol`).

## Источник контекста

Внедряемый контекст несёт явный источник `{ kind: 'plugin', plugin: 'hooks-codex' }`, чтобы долговечное сообщение никогда не приняли за промпт пользователя.

## Model Experience

### Контекст, предоставленный хуками

#### What the model sees

`SessionStart`, хук принятого промпта и пост-инструментальные хуки могут добавлять сообщения контекста с атрибуцией источника; блокирующий хук `Stop` добавляет свою причину как steering следующего шага.

#### Token effect

Без затрат, когда хуки не возвращают контекст. Текст хука зависит от данных, пишется в журнал и пересылается до компакции.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Заблокированный промпт или исход инструмента

#### What the model sees

Заданные провайдером причины передаются дословно. Когда их нет, заблокированный промпт использует в точности `blocked by UserPromptSubmit hook`, отвергнутый инструмент становится `Error: blocked by PreToolUse hook`, обратная связь заблокированного пост-инструментального хука — в точности `blocked by PostToolUse hook`, а блокирующая остановка добавляет steering ровно в виде `continue: blocked by Stop hook`. `systemMessage` Codex не показывается.

#### Token effect

Блокировка промпта убирает его токены запроса; отказ или обратная связь добавляют сохранённый запасной либо провайдерский текст; принудительное продолжение стоит ещё одного полного запроса.

#### KV Cache effect

Заблокированный промпт не шлёт запроса и ничего не инвалидирует. Отказ, обратная связь и контекст принудительного продолжения добавляются после переиспользуемого префикса, не переписывая его.

## Известные ограничения и отложенная работа

- **Неподдерживаемые события хуков (5 из нынешних 10 у Codex):** `PermissionRequest`, `PreCompact`, `PostCompact`, `SubagentStart` и `SubagentStop`. Конфигурация этих событий при разборе молча отбрасывается. База сравнения — [официальный справочник хуков Codex](https://learn.chatgpt.com/docs/hooks).
- **`SessionStart` частичен:** простой stdout и JSON `additionalContext` работают, но хук работает отсоединённо, поэтому контекст может не успеть к первому запросу (`TODO(session-start-gating)`).
- **`UserPromptSubmit` частичен:** блокировка плюс простой stdout или JSON-контекст работают, но обычные механизмы управления `systemMessage` и `{"continue": false}` не применяются.
- **`PreToolUse` частичен:** блокировка работает, но `additionalContext`, `permissionDecision: "allow"` и `updatedInput` игнорируются. Всякий инструмент представлен как `tool_input: { command }`, поэтому аргументы не-shell инструментов недоступны хуку в достоверном виде.
- **`PostToolUse` частичен:** обратная связь при блокировке и JSON `additionalContext` работают, но `{"continue": false}` не применяется, аргументы не-shell инструментов сводятся к `{ command }`, а структурированный вывод инструмента сводится к тексту в `tool_response`.
- **`Stop` частичен:** блокировка принуждает ещё один ход модели, но `stop_hook_active` всегда `false`, `last_assistant_message` всегда `null`, а `{"continue": false}` не применяется. Поэтому безусловно блокирующий хук принудительно продолжит каждый шаг, если сам себя не ограничит (`TODO(stop-loop-guard)`).
- **Общие поля payload'ов и вывода частичны:** каждое отображённое событие сообщает статически настроенный `model` и `permission_mode: "default"` вместо текущих значений рантайма Codex. `systemMessage` пишется в журнал и сопровождается предупреждением, но не показывается, а `{"continue": false}` записывается, но не применяет характерное для события Codex поведение остановки (`TODO(hook-continue-false)`).
- **Загрузка конфигурации и исполнение частичны:** при загрузке разбирается один `configPath` уровня процесса; активные слои Codex (пользовательский, проектный, сессионный, system/managed и плагинов), элементы управления доверием и форма хуков, встроенная в `config.toml`, не реализованы (`TODO(per-session-hook-config)`). Запускаются только синхронные обработчики `command`, текущие метаданные вроде `statusMessage` и `commandWindows` игнорируются, а совпавшие обработчики работают последовательно, а не с конкурентной семантикой запуска Codex.
