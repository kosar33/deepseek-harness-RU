# @deepseek-ai/dsh-host-directory-picker-auto

[English](README.md) | [中文](README.zh.md) | Русский

**Адаптивный механизм выбора** [seam'а выбора каталога](../directory-picker/README.ru.md): плагин только для node-половины, который один раз при загрузке оценивает ситуацию хоста и монтирует подходящий двухгранный бэкенд — [`-native`](../directory-picker-native/README.ru.md) или [`-browse`](../directory-picker-browse/README.ru.md) — как настоящую запись Loader в находящемся в памяти корневом дереве (в конфигурационный файл не сохраняется никогда; `write()` дерева корня — no-op). Поскольку бэкенд приходит обычной записью, его браузерную половину обнаруживает таблица клиентских модулей — точно так же, как пришедшую из строки конфигурации, поэтому инвариант seam «одна строка меняет обе грани» выполняется и для результата разрешения. Выгрузка механизма выбора снова удаляет запись, выгружая вместе с ней обе грани.

Разрешение — одна чистая выборка на этапе загрузки (`resolveDirectoryPickerBackend`), экспортируемая для повторного использования. `native` требует одновременно всех сигналов, что оператор может видеть дисплей хоста и нативный бэкенд может его обслужить: привязку только на loopback (читается из внедрённого `webServer`; привязка на все интерфейсы допускает удалённые браузеры, до которых ни один системный диалог не доберётся), запуск вне SSH (`SSH_CONNECTION`/`SSH_TTY` не установлены или пусты — при переносе портов через SSH диалог открылся бы на безнадзорном сервере) и обслуживаемую дисплейную сессию — на darwin/win32 предполагается; на linux нужны `DISPLAY`/`WAYLAND_DISPLAY` плюс бинарник zenity или kdialog на `PATH` (проверка — ещё один факт времени загрузки); никогда — на любых прочих платформах, ведь нативный бэкенд поддерживает ровно darwin/win32/linux. Всё неоднозначное разрешается в `browse`, работающий везде. Выборка происходит ровно один раз за загрузку, чтобы смонтированная возможность оставалась стабильной в течение жизни сервиса, как того требует seam. Закрепить взаимодействие конфигурационным полем здесь нельзя — вместо этого пакета компонуйте напрямую строку `-native` или `-browse`, это документированная точка замены seam; монтаж механизма выбора **и** строки бэкенда вместе падает с явной ошибкой (дубликат сервиса `directoryPicker`, дубликат клиентского потока в `single`-hole'ах).

## Model Experience

Отсутствует: механизм выбора лишь компонует выбор каталога GUI-хоста; ничто из этого пакета не попадает в запрос к модели.

#### Влияние на KV-кэш

Отсутствует; пакет ни собирает, ни отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Определение выводит местоположение оператора из контекста запуска, чего никакой сигнал запуска доказать не может** — tmux-сессия, отсоединённая от своего SSH-запуска, теряет маркеры `SSH_*`; процесс Darwin вне Aqua-сессии всё равно считается имеющим дисплей; а локальный запуск рабочей станции, позже достигнутый через `ssh -L`, приходит с `127.0.0.1`, разрешается в `native` и открывает диалог на безнадзорной станции. Ошибочный выбор `native` деградирует до существующего повторяемого диалога сбоя бэкенда, а прямая композиция `-browse` выбирает безопасное взаимодействие для таких развёртываний.
- **Linux-проверка выбора читает только `PATH`** — zenity/kdialog, доступный иным путём (shell-алиас, установка вне `PATH`), всё равно даёт `browse`; установка любого из этих бинарников на `PATH` вернёт пригодность к `native` при следующей загрузке.
- **Только на этапе загрузки** — одно разрешение обслуживает всех клиентов данной загрузки; адаптивность по соединению (native для локального браузера, browse для удалённого, тот же сервер) потребовала бы возможности уровня клиента и объявления её по протоколу, которое seam сознательно удалил, — и ждёт развёртывания, обслуживающего обоих сразу.
