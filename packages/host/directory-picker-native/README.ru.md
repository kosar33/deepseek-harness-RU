# @deepseek-ai/dsh-host-directory-picker-native

[English](README.md) | [中文](README.zh.md) | Русский

**Бэкенд нативного системного диалога выбора** [seam'а выбора каталога](../directory-picker/README.ru.md): `NativeDirectoryPicker` регистрирует `ctx.directoryPicker` с возможностью `native`, чей `pick(signal)` открывает один нативный диалог на вызов и разрешается выбранным абсолютным путём (`null` при отмене). Платформенные инструменты запускаются без оболочки: `osascript` на macOS и Zenity с откатом к KDialog на Linux; прерывание вызывающим завершает нативный процесс. Windows открывает современный `IFileOpenDialog` в порождённом дочернем процессе — COM-разговор под управлением koffi на главном потоке потомка с максимальной DPI-осведомлённостью потока, какую примет хост (сначала per-monitor-v2), — с прерыванием отправкой `WM_CLOSE` потоку диалога. Работоспособно лишь когда оператор сидит за дисплеем хоста — удалённые развёртывания вместо этого компонуют [`-browse`](../directory-picker-browse/README.ru.md). Командная граница (`DirectoryPickerRunner`) и платформенные факты допускают внедрение. Общий исполнитель дочерних процессов без оболочки находится в [`dsh-native-command`](../../util/native-command/README.md).

**Двухгранный пакет**: браузерная половина (`./client`) без рендера занимает оба directory-flow hole'а [ui-workspace](../../client/ui-workspace/README.ru.md) — каждый запрос `open` приводит в действие `host.pickDirectory` и сообщает единственный исход (выбранный путь / отмена / сбой) через разговор, владеющий данным hole'ом. Обе декларации directory-flow **ДОЛЖНЫ** стать живыми до установки любого из вкладов. Поэтому одна строка cordis.yml компонует обе стороны нативного взаимодействия; клиентская сторона не несёт ветвления по kind возможности, а монтаж второго пакета потока отказывает при загрузке (hole'ы имеют kind `single`).

## Model Experience

Отсутствует: бэкенд обслуживает выбор каталога GUI-хоста; ничто из этого пакета не попадает в запрос к модели.

#### Влияние на KV-кэш

Отсутствует; пакет ни собирает, ни отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Linux требует настольных утилит** — без установленного Zenity или KDialog `pick` отклоняется с ошибкой, подсказывающей действие; подсказки ручного ввода пути нет (откатом на уровне композиции служит browse-бэкенд).
- **У Windows нет резервного механизма** — выбор в дочернем процессе через упакованный koffi — единственный нативный уровень, поэтому отказ COM или крах диалога проявляются как сбой. Browse-бэкенд остаётся откатом на уровне композиции.
