# @deepseek-ai/dsh-host-directory-picker

[English](README.md) | [中文](README.zh.md) | Русский

Выбор каталога рабочей области в хосте веб-GUI — это capability seam. Абстрактный сервис `DirectoryPicker` (`ctx.directoryPicker`) — его Service Definition. Единственный метод, `capability()`, возвращает дискриминируемое объединение, описывающее, как оператор выбирает каталог. Бэкенды различаются взаимодействием с пользователем, а не только реализацией: `{ kind: 'native', pick(signal) }` открывает один нативный выбор ОС на дисплее хоста ([`-native`](../directory-picker-native/README.ru.md)); `{ kind: 'browse', list(path?), createDirectory(path, name) }` даёт операции перечисления и создания для встроенного в приложение обозревателя, что подходит удалённым клиентам без доступа к системному диалогу выбора ([`-browse`](../directory-picker-browse/README.ru.md)). Потребители переключаются по `capability().kind`; объединение выводится из merge-extensible-отображения `DirectoryPickerCapabilities`, и новый бэкенд добавляет свой вариант туда через declaration merging. При неизвестном kind потребители скрывают выбор каталога вместо того, чтобы падать. Объект capability **ДОЛЖЕН** оставаться стабильным в течение жизни сервиса. Каждый пакет-бэкенд имеет также браузерную точку входа, регистрирующую соответствующее взаимодействие в slot'ах потока каталогов ui-workspace, так что одна строка композиции выбирает сразу и хостовую возможность, и клиентский поток. Композиция, которая должна выбирать во время выполнения, монтирует [`-auto`](../directory-picker-auto/README.ru.md): тот один раз осматривает хост при загрузке и монтирует подходящую строку бэкенда.

Примитивы обзора завершаются типизированной ошибкой `DirectoryPickerError` (`directory-unreadable` / `directory-exists` / `directory-create-failed`, каждая несёт затронутый `path`), которую потребляющий шлюз отображает один к одному на коды ошибок протокола. Строки `DirectoryEntry` несут принадлежащий хосту флаг `hidden` (POSIX-соглашение о точке), поэтому политика показа остаётся на стороне клиента; `DirectoryListing.crumbs` — цепочка предков от корня файловой системы, где каждый crumb — цель перехода. Проектное обоснование, отделение `ctx.fs` и решения политики находятся в [Agent Note о capability seam выбора каталога](../../../.agents/notes/implemented/architecture/2026-07-28-directory-picker-capability-seam.md).

## Model Experience

Отсутствует: seam обслуживает выбор каталога GUI-хоста; ничто из этого пакета не попадает в запрос к модели.

#### Влияние на KV-кэш

Отсутствует; пакет ни собирает, ни отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Поддержки нескольких корней нет** — контракт обзора открывает одну цепочку предков на каждый список; ограничение корней по развёртыванию (и перечисление корней дисков Windows над диском) ждёт потребителя, которому это понадобится, согласно Agent Note о DirectoryPicker.
