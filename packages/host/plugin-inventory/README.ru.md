# @deepseek-ai/dsh-host-plugin-inventory

[English](README.md) | [中文](README.zh.md) | Русский

Проекция хоста только для чтения над текущим деревом Cordis Loader. `PluginInventoryGateway` регистрирует сервис `pluginInventory` и публикует один сгенерированный прямой Remote, `pluginInventory/list`. Каждый вызов читает `ctx.loader.entries()` напрямую, пропускает структурные строки групп и возвращает остальные записи в порядке Loader только с id записи Loader, спецификатором модуля, действующим состоянием включённости и текущей фазой корневого fiber.

Фаза — это `pending`, `loading`, `active`, `failed` или `unloading`; она равна `null`, когда у записи нет живого корневого fiber. Снапшот намеренно фиксирует момент времени: Loader остаётся единственным распорядителем жизненного цикла, а этот пакет не владеет ни кэшем, ни историей, ни моделью происхождения, ни потоком событий, ни путём изменения. Его публичные типы полезной нагрузки живут под `./types`, а Typert генерирует артефакты Remote для Host и Client, открываемые через `./typert` и `./remote`.

Сервис доступен только через Remote и сознательно не объявляет слияния с внутрипроцессным `Context` Cordis. Клиентские пакеты используют его через явную сборку [`api-remotes`](../../api/remotes/README.ru.md), а не импортируя реализацию хоста.

## Model Experience

Отсутствует: эта проекция описи только для хоста не регистрирует ни промпта, ни инструмента, ни сообщения, ни запроса к провайдеру.

#### Влияние на KV-кэш

Отсутствует; пакет никогда не собирает вход для модели.

## Известные ограничения и отложенная работа

- **Только состояние на момент времени** — результат не содержит долговечной истории отказов или подписки; отсутствие живого корневого fiber передаётся как `null` независимо от того, почему живого корня нет.
- **Ни происхождения, ни мутаций** — сервис не сообщает, какой бандл, профиль или переопределение ввели запись, и не может включать, отключать, добавлять или удалять плагины.
