# @deepseek-ai/dsh-permission-presets

[English](README.md) | [中文](README.zh.md) | Русский

Пользовательские пресеты разрешений через `ctx.permissionPresets` ([`PermissionPresetService`](src/index.ts)). Каждое настроенное имя объединяет `sandbox/mode` с `approval/policy`; значения по умолчанию — `workspace-write` (`workspace-write` + `ask`) и `danger-full-access` (`danger-full-access` + `never`). UI-адаптеры могут показывать таблицу одним селектором, тогда как исполнение в песочнице и одобрение продолжают использовать собственные регуляторы.

`set(session, name)` записывает изменившийся выбор в событие `permissionPresets/preset`, существующее только в журнале, затем вызывает сеттер каждого регулятора лишь когда его эффективное значение меняется. Событие выбора предшествует событиям регуляторов и сохраняет намерение пользователя, когда пресеты делят один бандл; выбор с нулевым итогом ничего не дописывает. `current(events)` предпочитает всё ещё совпадающий записанный выбор, затем первую совпадающую запись таблицы, а иначе возвращает `custom`. Клиенты могут показывать `custom` как текущее значение, но не могут его выбрать.

Сервис владеет namespace'ом Settings `permissionPresets`. Его `defaultPreset` — умолчание для будущих сессий: запись композиции использует `Config.defaultPreset`, а если он опущен — выводит пресет, соответствующий заданным композицией умолчаниям песочницы и одобрения. Зафиксированное изменение Settings читается при создании следующей сессии; создание закрепляет `permissionPresets/preset`, `sandbox/mode` и `approval/policy` в той сессии, так что последующие изменения никогда не трогают существующую сессию. Возобновляемый засев (seed), включая явно пустой с пометкой `session/end-seed`, сохраняет свои эффективные разрешения и получает только недостающие долговременные факты, а не последние пользовательские умолчания. Монтирование сервиса заодно охватывает уже живые сессии, поэтому замена по HMR закрепляет любую сессию, созданную в отсутствие плагина.

Сервис требует сдерживающего исполнителя `ctx.shell` и `ctx.approval`. Запись таблицы с именем `custom` бросает исключение при загрузке. Когда умолчания композиции не совпадают ни с одним пресетом, плагин требует явный `defaultPreset`; независимо построенная сессия без событий всё же может вывести `custom`. См. [дизайн переключения песочницы](../../../.agents/notes/implemented/feature/2026-07-06-sandbox.md).

Два необязательных дочерних плагина предоставляют продуктовые поверхности на основе того же сервиса: единица проекции сессии `permissions` (`src/types.ts` объявляет ключ; единица сворачивает три события регуляторов с полными значениями и показывает селектор — варианты таблицы плюс `custom`, доступный только для показа как текущее значение, — поверх умолчаний композиции) и команда `/permissionPresets` (вызов без аргументов сообщает текущий пресет и таблицу; аргумент-пресет переключает через `set`). Каждый дочерний плагин активируется, только когда его реестр (`ctx.sessionProjections` / `ctx.commands`) включён в композицию.

## Опыт модели

Косвенно, через `dsh-user-approval` и `dsh-tool-bash`, которые отображают промпт политики одобрения, уведомление о переключении и исходы инструментов в песочнице, выбранные событиями регуляторов этого сервиса; само `permissionPresets/preset` живёт только в журнале.

#### Влияние на KV-кэш

Прямой инвалидации нет; изменения префикса запроса остаются во владении названных выше потребителей.

## Известные ограничения и отложенная работа

- **Объединены только два регулятора механизмов** — пресеты выбирают режим песочницы и политику одобрения; выбор агента/профиля пока не входит в `PresetSpec`.
- **`custom` существует только как вывод** — вызывающие могут переключиться с несовпадающей комбинации регуляторов, но не могут выбрать или сохранить именованный пользовательский пресет через этот сервис.
- **Таблица пресетов живёт на уровне процесса** — конфигурация зафиксирована на время жизни плагина; изменение доступных пресетов требует перезагрузки плагина.
- **Сохранённые умолчания должны оставаться в таблице пресетов** — удаление упомянутого пресета ломает регистрацию настроек Permission, пока раздел `permissionPresets` в `settings.yaml` не будет обновлён или сброшен.
