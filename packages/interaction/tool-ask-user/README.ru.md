# @deepseek-ai/dsh-tool-ask-user

[English](README.md) | [中文](README.zh.md) | Русский

Инструмент `ask_user_question` для модели поверх `ctx.userQuestions`. Он позволяет модели задать человеку краткий вопрос, когда перед продолжением ей нужно подтверждение, выбор или недостающая информация.

## Инструмент

`ask_user_question` принимает:

- `questions` — обязательный непустой массив объектов-вопросов.
- `id` — обязательный стабильный id каждого вопроса, который эхом возвращается в ответе.
- `question` — обязательный текст каждого вопроса.
- `header` — необязательный короткий заголовок.
- `options` — необязательные варианты выбора с `label` и `description`. Рекомендуя вариант, ставьте его первым и добавляйте к его метке `(Recommended)`.
- `multi_select` — может ли этот вопрос вернуть более одного выбранного варианта.

Инструмент вызывает `ctx.userQuestions.ask()` и возвращает каноническое `{ answers: [{ id, selected, custom? }] }`. `selected` содержит метки вариантов; `custom` несёт ответ в свободной форме, дополняя `selected` для вопроса с множественным выбором и перекрывая его для вопроса с единственным выбором. Нативный рендерер сохраняет компактную текстовую форму JSON `{ "answers": [{ "id": "...", "selected": ["..."], "custom": "..." }] }`.

## Роль

Это пакет-Consumer для seam'а вопросов пользователю. Он не рендерит интерфейс и не знает, как собирается ввод; он лишь переводит аргументы модели в `AskUserQuestionRequest` и возвращает ответ человека в агентский цикл.

## Model Experience

### Схема инструмента

#### What the model sees

Модель видит сгенерированную [`схему ask_user_question`](../../../docs/tool-catalog.md#deepseek-aidsh-tool-ask-user), включая id вопросов, тексты, заголовки, варианты и флаги множественного выбора.

#### Token effect

Фиксированная стоимость схемы в каждом запросе, где инструмент виден.

#### KV Cache effect

Префикс стабилен, пока определение и видимость не меняются. Жизненный цикл плагина или ограничения скоупа могут инвалидировать переиспользование начиная с этой схемы.

### История вызовов инструментов и результаты

#### What the model sees

Полные вопросы модели остаются в аргументах вызова инструмента ассистента. После ответа человека следующий шаг видит компактный JSON в точной форме `{"answers":[{"id":"<id>","selected":["<label>"],"custom":"<text>"}]}`; `custom` опускается, когда не используется, а `selected` может содержать ноль, одну или несколько меток. Взаимодействие с интерфейсом, пока вызов в ожидании, контекстом модели не является.

#### Token effect

Аргументы и ответный JSON — удерживаемые токены, зависящие от данных; пока идёт ожидание человека, стоимости в токенах нет.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Known Limitations and Deferred Work

- **Ожидающий вопрос блокирует вызов инструмента, пока человек не ответит** — инструмент не объявляет бюджета `timeout-policy`; отмена возможна только через `exec.signal` хода.
- **Субагенты, принадлежащие рантайму, не могут спрашивать пользователя** — `ask_user_question` отклоняет живого дочернего агента, принадлежащего другому агенту, с ошибкой `DELEGATED_CALLER`; дочерний агент обязан включить нерешённый вопрос или решение в свой итоговый результат. Долговременная родословная эту границу не определяет, поэтому сессия с родословной, возобновлённая как корень рантайма, может спрашивать как обычно.
- **Нативные ответы рендерятся как текст JSON** — каноническое значение остаётся структурированным, но видимый модели результат использует компактный JSON вместо более богатого набора блоков содержимого.
