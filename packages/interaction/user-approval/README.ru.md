# @deepseek-ai/dsh-user-approval

[English](README.md) | [中文](README.zh.md) | Русский

Нейтральный к каналам seam однократных одобрений. `ctx.approval.request(req)` возвращает `allowed-once`, `rejected`, `cancelled` или `unavailable`; отсутствующие или падающие отвечающие действуют по fail closed, а выданное разрешение применяется только к запрошенному действию. Точные сигнатуры событий живут в сгенерированной области [одобрений пользователей](../../../docs/subsystems/approval.ru.md#cordis-api).

Каждый запрос обязан принадлежать открытому ходу агента. Сервис добавляет парную аудиторскую запись `approval/asked` и `approval/decided`, тогда как модель видит только итоговый записанный в журнал результат инструмента. Прерванный запрос резолвится в `cancelled`; добавление аудита, упавшее до фиксации, приводит к отказу, а не к возврату незаписанного решения.

Отвечающие — слушатели каскада `approval/request`. Верните исход, чтобы ответить за своего агента, или вызовите `next()` для делегирования. Слушатели со скоупом агента получают только запросы этого агента; компонуйте одного терминального отвечающего на развёртывание, поскольку порядок соседних слушателей — не механизм приоритетов политики. Мост автоматизации ACP поставляет однократные машинные решения для принадлежащих ему сессий.

`ApprovalPolicy` — это `'ask'` или `'never'`. Действующее значение — последнее событие `approval/policy` с откатом к конфигурации; путь записи — `setApprovalPolicy()`. `'never'` отвергает до интерактивной диспетчеризации. Обе политики вносят свой полный текущий смысл в безопасный для кэша снапшот рантайм-контекста.

Пайплайн инструментов маршрутизирует решения `ask` через этот seam и действует по fail closed при его отсутствии; изолированный bash-инструмент тоже использует его для эскалированных повторных попыток. Мост автоматизации ACP отвечает на вызовы своих агентов через машинную политику клиента. Аудиторские события остаются только в журнале, поэтому модель видит лишь результат запрашивающего потребителя. См. [Agent Note о seam'е одобрений](../../../.agents/notes/implemented/feature/2026-07-06-approval-seam.md) и [Agent Note о песочнице](../../../.agents/notes/implemented/feature/2026-07-06-sandbox.md).

## Влияние на модель

### Контекст текущей политики одобрений

#### Что видит модель

Первый запрос и каждое действующее изменение политики добавляют полный снапшот рантайм-контекста после удерживаемой истории. При `ask` вклад одобрений сообщает, что настроенные отвечающие могут быть опрошены, а их отсутствие действует по fail closed. При `never` он сообщает о детерминированном отказе без запроса эскалации. Неизменившиеся запросы удерживают прежний снапшот без добавления ещё одного сообщения.

##### Вклад политики ask

```markdown
Approval policy: ask. Operations that require approval may ask through the configured answerers; without an available answerer, the request fails closed.
```

##### Вклад политики never

```markdown
Approval prompts are disabled in this session: actions that require approval are rejected automatically — do not request sandbox escalation (do not set `sandbox_permissions`).
```

#### Влияние на токены

Одно лаконичное сообщение контекста при первом запросе и при действующем изменении; неизменившиеся запросы не добавляют дублирующих токенов политики.

#### Влияние на KV-кэш

append-only после удерживаемой истории. Переключение `ask`/`never` сохраняет стабильный системный и разговорный префикс вместо перезаписи первого сообщения запроса.

### Результат инструмента

#### Что видит модель

`approval/asked` и `approval/decided` существуют только в журнале. Модель видит только итоговый результат инструмента запрашивающего потребителя — allowed, rejected, cancelled или unavailable; человеческий UI разрешений не является контекстом.

#### Влияние на токены

Ноль дублирующих аудиторских токенов. Отказ может заменить обычный результат инструмента малой удерживаемой ошибкой, тогда как разрешение оставляет обычный результат потребителя.

#### Влияние на KV-кэш

append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Запросы валидны только внутри открытого хода** — простаивающий или вызывающий между ходами бросает исключение до аудита; долговременный сценарий одобрений вне хода отложен.
- **Существуют только однократные разрешения** — словарь исходов имеет `allowed-once`, но не `allow-always`, запомненное правило, отзыв или хранилище разрешений; политика сессии — только `ask` / `never`.
- **Запрос не несёт аргументов инструмента** — отвечающий видит имя инструмента, причину и необязательный id вызова; машинный канал ACP требует id вызова и делегирует запросы без него.
- **Нет встроенного отвечающего** — headless или неполно скомпонованные развёртывания резолвят `unavailable` и действуют по fail closed; сервис сам никогда не спрашивает человека.
