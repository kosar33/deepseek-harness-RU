# @deepseek-ai/dsh-user-questions

[English](README.md) | [中文](README.zh.md) | Русский

Service Definition пользовательского взаимодействия: он владеет сервисом `ctx.userQuestions`, которым пользуется обращённый к модели инструмент или плагин разрешений, когда ему нужно приостановить работу и спросить у человека решение.

## Сервис: `UserQuestionService` (ключ ctx: `userQuestions`)

### Публичный API

- `ctx.userQuestions.registerProvider(provider): () => void` Регистрирует провайдера на стороне UI. В контексте активным может быть только один провайдер; освобождение ресурсов отменяет регистрацию.
- `ctx.userQuestions.ask(request): Promise<AskUserQuestionAnswer>` Спрашивает активного провайдера и дожидается ответа.

### Основные типы

- `AskUserQuestionRequest` — `{ questions: [{ id, question, detail?, header?, options?, multiSelect?, intent? }], agent?, signal? }`; `detail` задаёт поясняющий текст, который провайдеры показывают вместе с вопросом, не превращая его в подпись варианта. Если `agent` присутствует, он **ДОЛЖЕН** быть точным живым корнем рантайма из реестра.
- `AskUserQuestionOption` — `{ label, description? }`.
- `AskUserQuestionIntent` — `{ kind: 'plan-review', approve }`; тегированное намерение представления, описанное ниже.
- `AskUserQuestionAnswer` — `{ answers: [{ id, selected, custom? }] }`.
- `UserQuestionProvider` — реализация UI с методом `ask(request)`.
- `UserQuestionError` — подкласс `HarnessError` с такими кодами, как `EMPTY_QUESTIONS`, `BAD_INTENT`, `NO_PROVIDER`, `DUPLICATE_PROVIDER`, `ASK_ABORTED`, `CALLER_NOT_LIVE` и `DELEGATED_CALLER`.

Для вопроса с одиночным выбором `custom` заменяет выбранный вариант, а `selected` пуст. Для вопроса с множественным выбором `custom` может дополнять метки в `selected`. UI может сохранить пропущенный пункт как `{ id, selected: [] }`, удерживая существующий формат ответа и остальные ответы батча.

Если в запросе указан агент, `ask()` аутентифицирует его точную идентичность через живой `AgentRegistry` и допускает только корень рантайма. Долговременная родословная не даёт полномочий: сессия с исторической глубиной делегирования может спрашивать после возобновления в качестве нового корня рантайма, тогда как живой дочерний агент, принадлежащий другому агенту, отклоняется, даже если его долговременная глубина равна нулю. Программные запросы без агента сохраняют существующий путь через провайдера.

### Намерение представления

`intent` объявляет, что вопрос является заведомо известным видом решения, поэтому UI, узнающий тег, может показать его соответствующим образом: `plan-review` говорит, что `detail` — план на рассмотрении, а `dsh-plan-mode` ставит его на вопросе `exit_plan_mode`. Намерение меняет только представление: UI, учитывающий его, отвечает теми же метками вариантов, какие отправил бы универсальный UI, а UI, не знающий тега, рисует универсальный список вариантов, так что вызывающий читает одни и те же поля ответа в обоих случаях. `approve` называет метку, означающую одобрение, вместо опоры на порядок вариантов. `ask()` отклоняет с кодом `BAD_INTENT` два утверждения, которые не способен выразить ни один тип: `approve`, не называющий ни одного из вариантов самого вопроса, и намерение на вопросе без `detail` — того самого, чем вопрос объявляет себя предметом рассмотрения.

## Роль

Это пакет Service Definition. Потребители вроде `@deepseek-ai/dsh-tool-ask-user` зависят от этого сервиса; рантайм веб-хоста предоставляет поставляемый Service Provider. Цикл остаётся неизменным: вызов инструмента ждёт промис, а результат инструмента возобновляет обычный цикл агента.

## Опыт модели

Косвенно, через `dsh-tool-ask-user`, который сохраняет успешный ответ провайдера как компактный JSON либо одну из этих ошибок: `Error: ask_user_question was aborted before the user answered`, `Error: ask_user_question requires at least one question`, `Error: human interaction requires the exact live calling agent when an agent is supplied`, `Error: human interaction is unavailable while the calling agent is owned by another live agent; include the unresolved question or decision in the child agent's final result`, `Error: no user-questions provider is registered` или `Error: <message>`. Ожидание человека не добавляет токенов.

#### Влияние на KV-кэш

Прямой инвалидации нет; за любые изменения префикса запроса отвечает названный выше потребитель.

## Известные ограничения и отложенная работа

- **Один провайдер на контекст** — маршрутизации или рассылки на несколько UI нет; повторная регистрация бросает `DUPLICATE_PROVIDER`, а когда провайдер не зарегистрирован, `ask()` бросает `NO_PROVIDER`, а не деградирует.
- **Словарь покрывает только форму «вопрос с вариантами»** — выбираемые варианты плюс необязательный произвольный текст; более богатые формы взаимодействия (выбор файлов, подтверждения с предпросмотром diff) пока не имеют словаря в seam.
