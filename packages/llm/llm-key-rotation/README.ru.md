# `@deepseek-ai/dsh-llm-key-rotation`

Функциональный плагин, позволяющий одному маршруту провайдера переживать по-ключевые ограничения 429 ротацией нескольких API-ключей. Он владеет перечисленными в его конфигурации маршрутами, обслуживает учётные данные каждого запроса из упорядоченного пула ключей и восстанавливает ограниченный запрос на каскаде `agent/request-error` агентного цикла раньше любой политики повторов.

Каждая запись под `providers` несёт те же поля, что и профиль провайдера dsh-llm-pi-ai, кроме `apiKeyEnv`, который заменён упорядоченным списком `keys`. Каждый ключ называет ровно один источник: ссылку на учётные данные (`apiKeyEnv`), разрешаемую на каждом запросе через seam учётных данных, или литеральное `value`, которое попадает в файл композиции дословно и предназначено только для разработки. Необязательный `label` называет ключ в журналах; по умолчанию это имя ссылки или порядковая позиция с единицы. Маршрут, зарегистрированный здесь, не должен также объявляться в обычной секции dsh-llm-pi-ai, поскольку две регистрации не могут владеть одним маршрутом. Разрешение валидирует каждый маршрут при загрузке плагина: отсутствующие или удвоенные источники ключей, дубликаты меток, искажённые ссылки, пустые литералы и необслуживаемые протоколы приводят монтирование к отказу.

Запросы аутентифицируются одной липкой позицией на процесс. При сбое `RATE_LIMIT` на маршруте с несколькими ключами слушатель паркует обслуженный ключ до его момента сброса — `providerRetryAfterMs` из отказа, когда адаптер его выставляет, иначе ближайшая полночь UTC, ограничивающая суточные квоты, — переходит на первый незапаркованный ключ и возвращает `{ kind: 'retry' }`, так что цикл немедленно перевыпускает идентичный запрос со следующим ключом без назначенного ожидания. Каждое переключение журналирует оба ключа и момент сброса через стандартный логгер; в журнал сессии ничего не дописывается. Когда запаркован каждый участник, брошенная ошибка несёт код `KEY_POOL_EXHAUSTED` и перечисляет каждый ключ с его таймштампом сброса. Парковки истекают лениво при чтении, поэтому таймеры не запускаются, а запаркованный ключ возвращается в строй ровно в свой сброс.

Парковки переживают рестарт. Каждая парковка сохраняется в `.llm-key-rotation-parks.json` рядом с `.credentials.yaml` в домашнем каталоге харнесса — переназначьте расположение через `parkFile`, а домашний каталог по умолчанию — через `dshHome`. Документ хранит только метки и таймштампы, никогда значения ключей; он атомарно перезаписывается в режиме «только владельцу» при каждом изменении парковки или истечения. При монтировании истекшие строки выбрасываются, строки, называющие маршруты или ключи, которых больше нет в конфигурации, вычищаются, живые парковки присоединяются заново по маршруту и метке, а пул, чья липкая позиция запаркована, стартует с первого пригодного ключа. Отсутствующий документ — пустое состояние; искажённый документ или документ неверной версии приводит монтирование к явному отказу с указанием пути. Неудавшаяся запись сохранения журналируется громко, и ротация продолжается на состоянии в памяти для этого запуска.

Слушатель регистрируется с `prepend`, поэтому ротация предшествует обычным политикам восстановления независимо от порядка монтирования: запаркованный ключ обходится прежде, чем dsh-llm-retry успеет назначить ожидание отката на том же ключе, а повторная попытка приходит в dsh-llm-retry свежей, если снова сорвётся. Пулы из одного ключа делегируют любой сбой нетронутым, поэтому ведут себя в точности как простой адаптер, включая политику повторов и откат. Сбои, не являющиеся `RATE_LIMIT`, и сбои маршрутов, которыми этот плагин не владеет, делегируются без изменений.

```yaml
- id: credentials
  name: '@deepseek-ai/dsh-credentials-local'

- id: llm-openrouter
  name: '@deepseek-ai/dsh-llm-key-rotation'
  config:
    providers:
      openrouter:
        displayName: OpenRouter
        api: openai-completions
        baseURL: https://openrouter.ai/api/v1
        models:
          - id: anthropic/claude-sonnet-4.5
            name: Claude Sonnet 4.5
            contextWindow: 200000
        keys:
          - apiKeyEnv: OPENROUTER_KEY_1
          - apiKeyEnv: OPENROUTER_KEY_2
          - apiKeyEnv: OPENROUTER_KEY_3
            label: spare
```

Храните упомянутые значения в `$DSH_HOME/.credentials.yaml` под `refs:` (этот документ пишет страница Models веб-интерфейса) или экспортируйте их в окружении запуска; композиция без seam учётных данных полагается только на окружение. Ссылка, разрешившаяся в ничто, приводит запрос к отказу `MISSING_CREDENTIAL` с названием ключа пула вместо тихого пропуска участника.

## Лик состояния

Пока настроен хотя бы один маршрут, плагин предоставляет лик состояния, который другие плагины читают через `ctx.get('llmKeyRotation')`. Его единственный метод, `snapshot()`, отображает каждый настроенный маршрут; пригодность в снимке — view-only, поэтому чтение никогда не мутирует состояние пула или сохранённый файл. Значения ключей не появляются никогда.

```json
[
  {
    "provider": "openrouter",
    "activeLabel": "OPENROUTER_KEY_2",
    "keys": [
      {
        "provider": "openrouter",
        "label": "OPENROUTER_KEY_1",
        "source": "reference",
        "reference": "OPENROUTER_KEY_1",
        "status": {
          "state": "parked",
          "parkedAt": "2026-08-24T12:00:00.000Z",
          "resetAt": "2026-08-25T00:00:00.000Z"
        }
      },
      {
        "provider": "openrouter",
        "label": "OPENROUTER_KEY_2",
        "source": "reference",
        "reference": "OPENROUTER_KEY_2",
        "status": { "state": "usable" }
      }
    ]
  }
]
```

Каждая запись под `keys` несёт `provider`, `label`, `source` — `reference` с именем `reference` либо `literal` для значения только для разработки, которое не несёт поля reference вовсе, — и `status`: `{ state: 'usable' }` или `{ state: 'parked', parkedAt, resetAt }` с моментами ISO 8601 UTC. Виджет страницы настроек отображает «лимит откатится через Nч Mм», сравнивая `status.resetAt` с текущим временем — внутренности плагина не нужны. `activeLabel` называет позицию, с которой аутентифицируется следующий запрос; когда запаркован каждый ключ, он называет застрявшую позицию, с которой запрос упал бы. Лик отсутствует, пока плагин спит (ни одного настроенного провайдера).

## Model Experience

### Восстановление запроса к модели

#### Что видит модель

Никакая ротация, парковка, таймштамп сброса или личность ключа не видны модели. Повторный запрос несёт идентичную историю сообщений, инструменты и конфигурацию вызова; меняется только значение заголовка `Authorization`.

#### Эффект на токены

Каждое переключение ключей повторяет один запрос к провайдеру, с его тарификацией входных токенов, прежде чем появится хоть какой-то вывод; само переключение — восстановительное действие `{ kind: 'retry' }` и не дописывает ничего в журнал сессии. Парковка прекращает тарификацию исчерпанных ключей до их сброса вместо траты повторов на них.

#### Эффект KV Cache

Повторный запрос сохраняет прежний префикс и пригоден для переиспользования кэша провайдера по правилам каждого провайдера. Разные ключи обычно держат раздельные кэши у провайдеров, метрящих кэш на аккаунт.

## Известные ограничения и отложенная работа

- **Точность сброса зависит от адаптера** — через путь pi-ai проводные ошибки приходят сплющенными до текста сообщения, поэтому сбросы суточного лимита паркуются до ближайшей полуночи UTC; `providerRetryAfterMs` учитывается, когда адаптер его выставляет.
- **Парковка следит за липкой позицией, а не за запросом** — конкурентные запросы делят один липкий индекс на процесс, поэтому сбой может запарковать позицию, с которой обслуживался другой находящийся в полёте запрос; одноагентные сессии не затронуты.
- **Владение маршрутом переходит к этому плагину** — ротируемый маршрут не может одновременно появляться в обычной секции dsh-llm-pi-ai, и записи настраиваемого каталога провайдеров для него не предлагаются.
- **Сохранение однописательне на документ** — у документа парковок нет межпроцессной блокировки писателя, поэтому два процесса харнесса с общим `parkFile` затирают парковки друг друга; дайте каждому развёртыванию собственное расположение, когда оно нужно.
