# lsp/ — семейство возможности LSP

[English](README.md) | [中文](README.zh.md) | Русский

Seam возможности языковых серверов: Service Definition LSP, универсальный stdio-провайдер и обращённый к модели инструмент `lsp`. Все пакеты — **продуктовые**.

| Пакет | Роль | ctx-ключ |
|---|---|---|
| `lsp/` | Service Definition (реестр провайдеров по брендированным id + отображение расширений, выбор на каждый запрос, словарь, `LspError`) | `ctx.lsp` |
| `lsp-stdio/` | Универсальный мульти-серверный stdio-бэкенд поверх `ctx.fs` и `ctx.subprocess` (JSON-RPC, документы открываются только на время запроса) | (регистрирует провайдеров на `ctx.lsp`) |
| `tool-lsp/` | Обращённый к модели инструмент `lsp` (четыре операции, координаты курсора UTF-16 с единицей в качестве начала) | (регистрируется на `ctx.tools`) |

Service Definition живёт в `lsp/lsp/`. Seam открывает ровно четыре семантические операции — `goToDefinition`, `findReferences`, `goToImplementation`, `hover` — и не предоставляет универсального обходного пути через JSON-RPC, поэтому смена провайдера не меняет того, как модель запрашивает навигацию, и ни одна полезная нагрузка протокола или непросмотренная мутация не достигает контракта модели. Провайдеры регистрируют **возможности**, а не инструменты; `tool-lsp` — единственный владелец обращённого к модели имени, схемы, руководства в промпте и представления.

Обоснование дизайна — включая то, почему документы открываются только на время каждого запроса, почему stdio-хост использует общую среду исполнения файловой системы и субпроцессов и почему владение расширением эксклюзивно в пределах одного рантайма — находится в [Agent Note о capability seam LSP](../../.agents/notes/implemented/architecture/2026-07-15-lsp-capability-seam.md).

Справочник подсистемы — операции, координаты, запросы/результаты, `LspError` — это [docs/subsystems/lsp.md](../../docs/subsystems/lsp.ru.md); обоснование дизайна — в [Agent Note о capability seam LSP](../../.agents/notes/implemented/architecture/2026-07-15-lsp-capability-seam.md).
