# @deepseek-ai/dsh-lsp-stdio

[English](README.md) | [中文](README.zh.md) | Русский

**Универсальный stdio-бэкенд языковых серверов** для `ctx.lsp`. Один экземпляр плагина принимает именованную таблицу серверов и регистрирует по одному изолированному провайдеру на запись. Он читает через `ctx.fs` и запускает через `ctx.subprocess`, поэтому сервер и источник всегда находятся в смонтированном мире исполнения. Это универсальный хост, а не каталог и не установщик языковых серверов — развёртывания явно настраивают команды и соответствия; пресеты принадлежат оверлеям `cordis.yml`.

Плагин в форме namespace-экспорта (`name` / `inject` / `Config` / `apply`, без экспорта по умолчанию).

## Что он делает

- Разрешает все локальные для сервера настройки до регистрации; неверное соответствие или конфликт регистраций откатывает предыдущие записи, поэтому неудавшаяся загрузка не оставляет ни одного маршрута провайдеров.
- Лениво порождает ровно один процесс сервера на пару `(server id, каноническая цель рабочего пространства)` по схеме single-flight. Ошибка живого сервера не повторяется; если выбранный транспорт из пула падает до или во время запроса только для чтения, провайдер дожидается освобождения его ресурсов и повторяет этот запрос один раз на свежем процессе.
- Использует ориентированную на совместимость последовательность **transient-open** на каждый запрос: разрешить источник и ограничить его байтами, потоково прогоняя через `ctx.fs`; `textDocument/didOpen` (версия 1, полный текст); запрошенный запрос; затем `textDocument/didClose` в `finally`. Неудавшаяся или отменённая запись `didOpen` завершает экземпляр прежде, чем пул сможет его переиспользовать. Документы закрываются после каждого вызова, поэтому первой версии не нужны ни `didChange`, ни кэш содержимого, ни LRU документов.
- Сериализует каждый жизненный цикл «чтение источника/open/запрос/close» через одну отменяемую очередь на рабочее пространство, поэтому стоящие в очереди вызовы читают актуальный источник только тогда, когда начинается их черёд; разные рабочие пространства работают параллельно. Освобождение ресурсов провайдера прерывает файловую и протокольную работу, дожидается обращений к рабочим пространствам, ещё не вошедших в очередь, затем опустошает каждую очередь и сервер.
- Когда протокольный shutdown не удался, уничтожает дерево потомков сервера через subprocess seam (POSIX: сигнал группе процессов; Windows: `taskkill /T /F`). Доставка tree-kill локализована, как у всякого группового сигнала, — она соревнуется с выходом сервера, — а quiescence подтверждается ожиданием живости дерева у дескриптора, а не исходом самой посылки kill.
- Разрешает исполняемый файл сервера, cwd, процесс и протокольные потоки через `ctx.subprocess`; `initialize.processId` равен `null`, потому что другая машина или пространство PID не должны наблюдать за процессом harness.
- Использует каноническое ограничение `ctx.fs`, file-URI и валидацию потокового текста, но не испускает `fs/observed`: модель видит только результат LSP, поэтому запрос не удовлетворяет политике обязательного чтения перед записью.

## Конфигурация

Ключ записи в `servers` — стабильный идентификатор провайдера, резервируемый на `ctx.lsp`; каждое значение имеет такую форму:

| Ключ сервера | По умолчанию | Значение |
|---|---|---|
| `command` | (обязателен) | Исполняемый файл для запуска — абсолютный путь либо имя, разрешаемое по PATH потомка при загрузке. Запуск идёт без оболочки. |
| `args` | `[]` | Аргументы, передаваемые исполняемому файлу. |
| `env` | `{}` | Дополнительное окружение, сливаемое поверх очищенного от учётных данных внешнего окружения (переменные, чьи имена содержат `KEY`/`PASSWORD`/`SECRET`/`TOKEN`, не пересылаются); явная запись `DSH_*` сливается после того, как seam вычистит внешние переменные. |
| `extensionToLanguage` | (обязателен) | Расширение в нижнем регистре с ведущей точкой → идентификатор языка LSP (например `{ '.ts': 'typescript' }`). |
| `initializationOptions` | `null` | Статические опции `initialize`, пересылаемые серверу. |
| `configuration` | `null` | Статический ответ на каждый элемент `workspace/configuration`. |
| `maxMessageBytes` | `16000000` | Наибольшее одиночное фреймированное сообщение, принимаемое от сервера. |
| `maxStderrBytes` | `1000000` | Наибольший хвост stderr, сохраняемый для диагностики. |
| `maxDocumentBytes` | `4000000` | Наибольший исходный файл, который откроет этот хост. |
| `shutdownTimeoutMs` | `5000` | Бюджет времени на корректные `shutdown`/`exit` до эскалации. |
| `killGraceMs` | `2000` | Льготное время на отмену запроса и на эскалацию SIGTERM→SIGKILL. |

`servers` должен содержать минимум одну запись, и каждый идентификатор обязан быть непустым. Таймерные бюджеты — положительные целые числа не больше таймерного предела Node в `2_147_483_647` мс. Все исполняемые файлы разрешаются при загрузке после очистки учётных данных; плохая поздняя запись мешает регистрации всех провайдеров. Процессы запускаются лениво по первому подходящему запросу.

## Протокольное поведение

Инициализация объявляет `general.positionEncodings: ['utf-16']`, `workspace: { workspaceFolders: true, configuration: true }`, `textDocument.hover.contentFormat: ['markdown', 'plaintext']` и `linkSupport: true` для definition и implementation, без динамической регистрации. Авторитетны возвращённые сервером возможности: неподдерживаемая операция или синхронизация без transient open/close приводит запрос к ошибке. Пропущенный серверный `positionEncoding` считается `utf-16`; любое другое значение — протокольная ошибка. Клиент отвечает на `workspace/configuration` из статической конфигурации, принимает служебные запросы жизненного цикла и отвергает `workspace/applyEdit` — он никогда не применяет правки и не выполняет команды. Навигация отображает `Location` напрямую, а `LocationLink` — по `targetUri` + `targetSelectionRange`; нормализация hover берёт валидное `MarkupContent.value`, сохраняет строковые `MarkedString`, рисует значения с языковым тегом как блок кода в fence и соединяет массивы одной пустой строкой. Отсутствующие результаты, искажённые диапазоны и позиции и искажённые кодировки hover дают структурные ошибки `LSP_MALFORMED_RESPONSE`.

## Граница безопасности

Провайдер доверяет своему сконфигурированному серверу и не заявляет изоляции в песочнице. Каноническую идентификацию, ограничение, потоковое чтение обычных файлов, проверку UTF-8 и кодирование file-URI он делегирует `ctx.fs`; до старта сервера он отвергает отсутствующие, не являющиеся обычными файлами, не-UTF-8, чрезмерно большие или канонически лежащие вне рабочего пространства источники запроса. Ограничение вычисляется до открытия потока и не обещает стабильной идентичности дескриптора при конкурентной подмене пути. Найденные расположения могут быть внешними, но внешний путь не может стать источником запроса. Развёртывание должно смонтировать провайдеров файловой системы и подпроцессов для одного и того же мира исполнения; композиция из разных миров недопустима.

## Опыт модели

Косвенно, через `dsh-tool-lsp`, который предъявляет нормализованные результаты этого провайдера; сам хост не добавляет ни промпта, ни схемы.

#### Влияние на KV-кэш

Прямой инвалидации нет; изменениями префикса запроса владеет `dsh-tool-lsp`.

## Известные ограничения и отложенная работа

- **Нет политики изоляции** — пакет доверяет сконфигурированному серверу и не помещает его процесс в песочницу; ограниченное развёртывание должно предоставить подходящих провайдеров процессов/файловой системы либо обёртку same-world-песочницы.
- **Нижняя граница совместимости transient-open** — серверы, чья синхронизация обходится без open/close (или объявляет `None`), не поддерживаются, даже если запросы к закрытым документам могли бы работать; закреплённый TypeScript e2e устанавливает один уровень совместимости, а не межъязыковое утверждение.
- **Задержка сериализации на пару сервер/рабочее пространство** — параллельные агенты, делящие один сервер и одно рабочее пространство, стоят в очереди к одному процессу; долгоживущие процессы рабочих пространств потребляют память до освобождения ресурсов.
- **Жёстко убитый harness осиротяет языковые серверы** — `initialize.processId: null` убирает серверный мониторинг PID клиента, поэтому серверы вычищаются только корректным освобождением ресурсов сервиса; harness, убитый сигналом SIGKILL, оставляет их работать, пока они не выйдут сами.
