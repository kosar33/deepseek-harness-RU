# @deepseek-ai/dsh-lsp

[English](README.md) | [中文](README.zh.md) | Русский

**LSP capability seam**: абстрактный `LspService` (`ctx.lsp`), определяющий, КАКАЯ семантическая навигация по коду есть у harness — переход к определению, поиск ссылок, поиск реализаций, hover — поверх провайдеров языковых серверов, не привязывая модельный контракт к локальным дочерним процессам.

Этот пакет владеет ролью Service Definition LSP-возможности:

| Пакет | Роль |
|---|---|
| `@deepseek-ai/dsh-lsp` (этот пакет) | Service Definition: сервис, реестр провайдеров с ключом по брендированному id + отображению расширений, выбор на каждый запрос, словарь запросов/результатов, таксономия `LspError` |
| `@deepseek-ai/dsh-lsp-stdio` | Service Provider: универсальный локальный бэкенд, регистрирующий настроенных провайдеров stdio-языковых серверов |
| `@deepseek-ai/dsh-tool-lsp` | Consumer: обращённый к модели инструмент `lsp` поверх `ctx.lsp` |

Seam открывает ровно четыре семантические операции — `goToDefinition`, `findReferences`, `goToImplementation`, `hover` — и не имеет универсального аварийного выхода в JSON-RPC, поэтому ни полезная нагрузка протокола, ни нерассмотренная команда/мутация не достигают провайдера через `ctx.lsp`.

## Сервисный API (`ctx.lsp`)

| Член | Семантика |
|---|---|
| `registerProvider(provider)` | Регистрирует бэкенд, атомарно резервируя его брендированный `id` и каждое нормализованное расширение файлов. Любой некорректный вход или конфликт ничего не публикует и бросает `LspError` (`LSP_INVALID_PROVIDER` / `LSP_CONFLICT`). Возвращает disposer, освобождающий все резервации. Освобождается вместе с вызывающим fiber'ом. |
| `query(request, signal?)` | Выбирает провайдера по итоговому расширению файла, выводит `languageId` из отображения этого провайдера и выполняет один запрос. Без совпадения бросается `LspError` `LSP_UNAVAILABLE`. |

Выбор выполняется на каждый запрос и не зависит от порядка: провайдер владеет набором расширений эксклюзивно, поэтому порядок регистрации и HMR никогда не меняет маршрутизацию. Ключи расширений нормализуются к нижнему регистру с ведущей точкой; `languageId` только синхронизирует преходящий документ и никогда не участвует в выборе. У первой версии нет селектора по glob, language-id или явному маршруту.

Провайдеры регистрируют **возможности**, а не инструменты. `dsh-tool-lsp` — единственный владелец обращённых к модели имени, описания, руководства для промпта, схемы и представления.

## Словарь

`LspQueryRequest` (`operation`, `filePath`, `position`, `workspaceRoot`) — каждое поле обязательно, поэтому ни одному полю не нужны дефолты реализации, а шага `resolve()` нет. Позиции и диапазоны отсчитываются от нуля в UTF-16, как в протоколе; конвенцию курсора с единичной базой владеет инструмент. `findReferences` всегда включает объявления — провайдеры обеспечивают это внутри себя, поэтому вызывающие не получают флага. `LspQueryResult` — ЗАКРЫТЫЙ discriminated union: `{ kind: 'locations'; locations; resolvedWorkspaceUri }` для навигации, `{ kind: 'hover'; hover }` для hover (содержимое или `null`) — потребители пишут `switch` до исчерпывающести, так что новая ветвь ломает компиляцию, пока не обработана. `resolvedWorkspaceUri` — канонический workspace `file:` URI провайдера; вызывающие строят относительные URI мест от него, вместо того чтобы применять правила путей платформы хоста к возможно symlink-корню запроса. Полные контракты см. в `src/types.ts`, а коды `LspError`, включая `LSP_DISPOSED` и `LSP_MALFORMED_RESPONSE`, — в `src/index.ts`.

## Влияние на модель

Косвенно, через `dsh-tool-lsp`, который владеет обращённой к модели схемой `lsp`, промптом и отрисованными результатами, тогда как этот реестр сам не добавляет ни промпта, ни схемы.

#### Влияние на KV-кэш

Прямой инвалидации нет; изменениями префикса запроса владеет `dsh-tool-lsp`.

## Известные ограничения и отложенная работа

- **Эксклюзивное владение расширениями внутри одного рантайма** — два провайдера не могут оба заявить `.ts`, даже с разными language id; пересечения роняют регистрацию. Задуманное расширение — настраиваемый развёртыванием селектор над регистрациями, способный ослабить эксклюзивную резервацию без добавления выбора провайдера в модельный ввод ([Agent Note о seam'е](../../../.agents/notes/implemented/architecture/2026-07-15-lsp-capability-seam.md)).
- **Только четыре операции** — символы и иерархия вызовов отложены (им нужны другие схемы); диагностике нужны отдельные правила актуальности/накопления; мутациям (переименование, кодовые действия, форматирование) требуются отдельные инструменты с интеграцией предпросмотра, разрешений и политики записи.
- **Нет API наблюдения** — доступность наблюдается только исполнением `query()` и маршрутизацией брошенных кодов `LspError`; ни события смены провайдера, ни запроса статуса возможности нет.
