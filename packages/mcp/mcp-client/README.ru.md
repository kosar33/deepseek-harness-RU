# @deepseek-ai/dsh-mcp-client

[English](README.md) | [中文](README.zh.md) | Русский

Плагин-мост клиента MCP: соединяется с внешними серверами [Model Context Protocol](https://modelcontextprotocol.io/) и регистрирует их инструменты на `ctx.tools`, делая их доступными модели как нативные инструменты под именами, квалифицированными сервером (`mcp__<serverName>__<rawName>`).

## Использование

Один экземпляр плагина на сервер MCP в `cordis.yml`:

```yaml
- id: mcp-github
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: github
    transport: stdio
    command: npx
    args: ['-y', '@modelcontextprotocol/server-github']
    env:
      GITHUB_TOKEN: !!js process.env.GITHUB_TOKEN

- id: mcp-web
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: web
    transport: streamable-http
    url: http://localhost:3000/mcp
    headers:
      Authorization: !!js '`Bearer ${process.env.MCP_TOKEN}`'
```

Модель видит `mcp__github__create_issue`, `mcp__web__search`, … — ту же форму с квалификацией сервером, что используют Claude Code и Codex. HMR подменяет на горячую: правка записи вызывает отключение + переподключение без перезапуска процесса; неизменный `serverName` воспроизводит идентичные имена инструментов.

## Конфигурация

| Поле | Транспорт | Обязательное | Описание |
|---|---|---|---|
| `transport` | оба | да | `"stdio"` или `"streamable-http"` |
| `serverName` | оба | да | Пространство имён для обращённых к модели имён инструментов этого сервера; `[A-Za-z0-9_-]{1,32}`, уникально среди живых экземпляров |
| `command` | stdio | да | Исполняемый файл для порождения |
| `args` | stdio | нет | Аргументы, передаваемые команде |
| `env` | stdio | нет | Дополнительные переменные окружения, накладываемые поверх вычищенной окружающей среды |
| `cwd` | stdio | нет | Рабочий каталог дочернего процесса |
| `url` | http | да | URL сервера MCP |
| `headers` | http | нет | Дополнительные заголовки (например, токены аутентификации) |
| `toolCallTimeoutMs` | оба | нет | Тайм-аут на вызов `callTool` (по умолчанию 60000) |
| `failOnStartupError` | оба | нет | Отклонять активацию плагина, когда первичное соединение или синхронизация инструментов не удались (по умолчанию `false`) |
| `reconnect.enabled` | оба | нет | Переподключаться автоматически после потери соединения (по умолчанию `true`) |
| `reconnect.initialDelayMs` | оба | нет | Первая задержка переподключения в мс; удваивается с каждой подряд идущей неудачной попыткой (по умолчанию 500) |
| `reconnect.maxDelayMs` | оба | нет | Потолок отсрочки в мс; также бесперебойное время, после которого бюджет попыток сбрасывается (по умолчанию 30000) |
| `reconnect.maxAttempts` | оба | нет | Подряд идущие неудачные попытки на сбой, прежде чем сдаться окончательно (по умолчанию 10) |

## Именование инструментов

У каждого MCP-инструмента два имени: сырое имя MCP (уходящее на провод в `tools/call`) и публичное имя `mcp__<serverName>__<rawName>`, регистрируемое на `ctx.tools`. Публичные имена нормализуются под контракт имён функций DeepSeek (64 символа, `[A-Za-z0-9_-]`); когда замена или усечение меняют имя, к нему добавляется детерминированный 12-значный шестнадцатеричный хэш `(serverName, rawName)`, поэтому различные инструменты никогда не схлопываются в одно имя. Имена — чистые функции от `(serverName, rawName)`: порядок соединения, ресинхронизации и другие серверы никогда не переименовывают инструмент.

- Два сервера, публикующих одно сырое имя (например, `search`), сосуществуют под своими пространствами имён.
- Дублирующийся `serverName` среди живых экземпляров валит более поздний экземпляр плагина при загрузке.
- Сервер, перечисляющий одно имя инструмента дважды, отвергается как недопустимый список инструментов.
- Чужая регистрация, самовольно занявшая пространство имён этого сервера, откатывает всё поколение целиком (никогда не частичный набор) с громкой ошибкой.

## Поведение

- При соединении: активация плагина дожидается `listTools()` и регистрирует каждый инструмент через `ctx.tools.register()` под его публичным именем до того, как композиция начнёт первый ход. Неудача первичного соединения, обнаружения или регистрации всегда журналируется; она отклоняет активацию при истинном `failOnStartupError` и иначе активирует плагин без инструментов.
- Слушает `notifications/tools/list_changed` → ресинхронизируется; неудача фазы получения сохраняет зарегистрированным предыдущее поколение, тогда как конфликт регистрации откатывает попытанное поколение и не оставляет ни одного инструмента этого сервера.
- Исполнение инструмента: `client.callTool({ name: rawName, arguments }, { signal })` с поддержкой тайм-аута и отмены — публичное имя никогда не отправляется серверу.
- Канонический успех — `{ content: JsonValue[], structuredContent? }`; полные JSON-блоки MCP сохраняются для программных вызывающих. Поддерживаемый объявленный `outputSchema` валидирует `structuredContent`; неподдерживаемый словарь схем откатывается к неограниченному `JsonValue`.
- Нативный/модельный рендер сохраняет порядок блоков MCP. Похожие на текст серии соединяются переводами строк; ссылки на ресурсы сохраняют своё имя и URI текстом; поддерживаемые изображения становятся долговечными базовыми блоками изображений, только когда смонтирован `ctx.attachments` и точный маршрут вызывающей модели явно объявляет вход изображений. Вся партия изображений декодируется и допускается до сохранения любого её члена. Искривлённая/отвергнутая партия изображений, аудио, встроенные ресурсы и неподдерживаемые блоки становятся явным диагностическим текстом, а не исчезают.
- При отключении/сбое: супервизор перезапускает исходную конфигурацию сервера с экспоненциальной отсрочкой (`reconnect.initialDelayMs` удваивается до `reconnect.maxDelayMs`) и при успехе заново проводит обнаружение — восстановленное поколение заменяет предыдущее, поэтому инструменты ни дублируются, ни утекают. Во время сбоя последнее исправное поколение остаётся зарегистрированным; вызовы против него терпят неудачу до восстановления.
- Переподключение имеет бюджет на сбой: после `reconnect.maxAttempts` подряд идущих неудач инструменты сервера снимаются с регистрации, а переподключение останавливается до HMR-перезагрузки или рестарта Host. Соединение, пережившее `maxDelayMs`, сбрасывает бюджет, поэтому сервер, падающий изредка, восстанавливается бесконечно, а зацикленный на сбоях — даже с краткими удачными соединениями — всё же исчерпывает потолок вместо вечного перезапуска.
- Состояния переподключения видны пользователю в журналах: переподключение (warn, с числом попыток и задержкой), восстановление (info), финальная неудача и потеря при отключённом режиме (error). Освобождение ресурсов отменяет любое ожидающее переподключение. С `reconnect.enabled: false` потерянное соединение держит инструменты зарегистрированными, но отказными до перезагрузки — поведение ручного восстановления.

## Потребляемые сервисы

| Сервис | Использование |
|---|---|
| `ctx.tools` | Регистрация/снятие с регистрации MCP-инструментов |
| `ctx.attachments` | Опциональная валидация и персистенция партий результатов-изображений до проекции на модель |

## Model Experience

### Обнаруженные MCP-инструменты

#### What the model sees

После успешного первичного обнаружения каждый объявленный MCP-инструмент появляется как нативный инструмент с именем `mcp__<serverName>__<rawName>` (или его детерминированной нормализованной формой), с предоставленными сервером описанием и схемой входа. Удачная ресинхронизация — включая ту, что следует за автоматическим переподключением, — заменяет поколение; освобождение ресурсов плагина или исчерпанный бюджет переподключения удаляет его.

#### Token effect

Зависимая от данных цена схем платится в каждом запросе, пока инструменты зарегистрированы. Ресинхронизация заменяет, а не накапливает схемы, а имя с квалификацией сервером добавляет токены к каждому определению инструмента и каждому вызову.

#### KV Cache effect

Префиксная стабильность, пока набор обнаруженных инструментов и схемы неизменны. Ресинхронизация, добавляющая, удаляющая, переименовывающая или меняющая инструмент, заменяет определения и может инвалидировать переиспользование с первого изменившегося токена схемы; переподключение, восстановившее неизменённый список, воспроизводит идентичные определения и остаётся префиксно-стабильным.

### История вызовов инструментов и результаты

#### What the model sees

Публичное имя инструмента и JSON-аргументы остаются в истории ассистента. Локальное для исполнения каноническое значение всегда удерживает полные JSON-блоки MCP и опциональное структурное содержимое для программных вызывающих и Code Mode. В нативном контексте поддерживаемые блоки изображений долговечно проецируются рядом с текстом в исходном порядке после точного доказательства возможностей маршрута; Code Mode дополнительно перевозит устоявшуюся богатую проекцию через внешний результат `run_code`, не меняя канонического значения привязки. Отвергнутые изображения, аудио, встроенные ресурсы, ссылки на ресурсы и неизвестные блоки остаются видимыми как ограниченные текстовые диагностики, а MCP `isError` отвергает вызов до персистенции изображений.

#### Token effect

Аргументы, отображённый текст и долговечные ссылки на изображения удерживаются до компакции. Инлайновый base64 MCP остаётся только в локальном для исполнения каноническом значении и никогда не копируется в событие сессии; провайдер читает проверенные байты из хранилища вложений. Payload аудио и встроенных ресурсов не попадают в контекст модели.

#### KV Cache effect

Append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Known Limitations and Deferred Work

- **Инструменты — единственная наведённая мостом возможность MCP** — у Resources и Prompts нет потребителя в harness, они отложены.
- **Тайм-аут старта унаследован от MCP SDK** — DSH пока не выставляет тайм-аут соединения/обнаружения. Каждый запрос `initialize` или постраничный `tools/list` пользуется дефолтом SDK в 60 секунд, поэтому неотзывчивый сервер или цепочка курсоров могут задержать и активацию, и teardown, пока первичная синхронизация не завершится.
- **Переподключение срабатывает на закрытии транспорта** — его зажигает упавший stdio-ребёнок; неудачи Streamable HTTP проявляются на каждый запрос и через собственное восстановление SSE-потока транспорта SDK, поэтому недостижимый HTTP-сервер повторяется на вызов, а не перезапускается супервизором.
- **Изображение — единственный долговечный мост богатых результатов** — PNG, JPEG, WebP и GIF могут войти в нативный контекст после точного доказательства возможностей. Payload аудио и встроенных ресурсов остаются локальными для исполнения с явными диагностиками, тогда как ссылки на ресурсы сохраняют только своё имя и URI текстом.
- **Неподдерживаемые выходные схемы MCP не принуждаются** — `structuredContent` откатывается к `JsonValue`, когда объявленная схема пользуется словарём вне подмножества harness.
