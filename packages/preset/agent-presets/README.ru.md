# dsh-agent-presets

[English](README.md) | [中文](README.zh.md) | Русский

Композиция агентов по пресетам. **Пресет** — каталог с одним файлом `agent.cordis.yml`; ростер монтирует его ОДИН раз на процесс под постоянным скоупом, и каждая сессия, называющая его, присоединяется тем, что ключ скоупа её агента становится потомком ключа монтирования (цепочка родителей `dsh-scope`). Инструменты, разделы промпта и единицы проекции монтирования существуют ровно один раз и покрывают каждого присоединившегося агента — их плагины ключуют своё состояние по Session/Agent, поэтому сессии остаются разделёнными внутри одного общего экземпляра, — а читающий хост вовсе без агента (холодное чтение транскрипта) разрешает те же постоянные регистрации по id пресета.

Механизм состоит из двух seam'ов. Контексты записей наследуются от контекста, в который подключено поддерево, и [`dsh-tools`](../../core/tools/README.ru.md), и [`dsh-system-prompt`](../../core/system-prompt/README.md) записывают регистрации в слой скоупа вызывающего контекста — поэтому вклады постоянного монтирования попадают в слой ПРЕСЕТА. Доставляет их каждой сессии цепочка родителей `dsh-scope`: представления агента разрешаются по цепочке `agent → preset → global` (ближайшее затеняет дальнее), слушатели монтирования допускаются для каждого агента, дочернего под ним, а слушатели соседнего пресета остаются глухими.

## Сервис: `AgentPresets` (ключ ctx: `agentPresets`)

Обнаружение не мемоизируется: `list()` и `resolve()` перечитывают корни при каждом вызове, поэтому пресет, созданный во время работы процесса, виден немедленно, а удалённый исчезает при следующем чтении. Обнаружение владеет и «здоровьем» пресетов: каталог, чья композиция отсутствует или не загружается (непарсящийся YAML — проверяется диалектом самого загрузчика, включая `!!js`, — либо не список именованных строк плагинов), попадает в перечень с причиной `broken`, а не пропускается, потому что пропущенный каталог продолжал бы занимать свой id на диске, тогда как ни одна поверхность не показала бы, что удалять. Каталог, чьё имя не годится в id пресета (`[a-z0-9][a-z0-9-]*`), пропускается полностью: никакая копия не смогла бы его заявить.

- `ctx.agentPresets.defaultId: string` Id пресета, монтируемого, когда вызывающий не называет никакого.
- `ctx.agentPresets.list(): Promise<AgentPreset[]>` Все пресеты, которые настроенные корни поставляют сейчас; при дублирующемся id побеждает более ранний корень; сломанные пресеты включены, каждый со своей причиной.
- `ctx.agentPresets.resolve(id?): Promise<AgentPreset>` Один пресет по id, по умолчанию `defaultId`. Бросает исключение с перечнем доступных id, когда ни один корень его не поставляет. Сломанный пресет разрешается — для удаления, чтения и отчёта о нём всем нужна эта строка.
- `ctx.agentPresets.mount(agentCtx, id?): Promise<AgentPreset>` Собирает одного агента из пресета — обеспечивает его постоянное монтирование (single-flight) и делает ключ скоупа агента потомком ключа монтирования — возвращая пресет, чтобы вызывающий его записал. Заранее отвергает сломанный пресет с причиной из обнаружения, поэтому любая незагружаемая форма отказывает одинаково ещё до участия загрузчика.
- `ctx.agentPresets.composeFrom(agentCtx, parentCtx): string | undefined` Присоединяет агента к постоянной композиции, на которой уже работает другой, возвращая присоединённый id пресета — `undefined`, когда родитель не присоединился ни к чему, что является развёртыванием без ростера, а не ошибкой. Это привязка, а не монтирование, поэтому она синхронна и не имеет сценария сбоя композиции; ошибку вызывающего она всё же отвергает (контекст без скоупа или уже присоединившийся агент).
- `ctx.agentPresets.composedPreset(agentCtx): string | undefined` Пресет, на котором работает данный ЖИВОЙ агент, читаемый из его цепочки скоупов, а не из сессии, — единственный доступный ответ для агента, чей долговременный заголовок ещё строится.
- `ctx.agentPresets.recompose(agentCtx, id): Promise<AgentPreset>` Перепривязывает агента к постоянной композиции другого пресета. Действительно только пока агент не произвёл ничего — **эта проверка принадлежит вызывающему**; новое монтирование обеспечивается до переноса привязки, поэтому сбой оставляет агента как был. Отвергает сломанный пресет, как `mount()`.
- `ctx.agentPresets.standingKeyFor(id?): Promise<ScopeKey>` Постоянный ключ скоупа, в котором читающий хост вовсе без агента (холодное чтение транскрипта) разрешает регистрации пресета; обеспечивает монтирование, не запуская ни агента, ни сессии, ни хода. Отвергает сломанный пресет, как `mount()`.
- `ctx.agentPresets.roots: readonly PresetRoot[]` Корни, которые сканирует этот ростер, — каждый настроенный корень по порядку, затем производный корень home-каталога харнесса. Не `config.roots`: читайте это, чтобы ответить, собран ли ростер вообще, — одно вычисление решает вопрос.
- `ctx.agentPresets.authorable: boolean` Есть ли у какого-нибудь из этих корней доверие `user`, а значит, можно ли вообще создать пресет.
- `ctx.agentPresets.read(id): Promise<string>` Текст композиции одного пресета, ровно как он сохранён.
- `ctx.agentPresets.copy(from, id, name?): Promise<void>` Создаёт локальный пресет копированием целого каталога существующего — единственная запись при создании. Через этот seam не проходит ни один текст композиции, поэтому копия загружается ровно так же, как её источник; скопированные метаданные сохраняют описание источника, но никогда его имя или порядок ростера, а различают строки `name` (или запасной id).
- `ctx.agentPresets.remove(id): Promise<void>` Удаляет локальный пресет; присоединившиеся сессии сохраняют своё постоянное монтирование. Сбрасывает пользовательское умолчание, если оно называло только что удалённый пресет: сохранить умолчание, которого ещё нет, — намеренное решение, но удалённое этим вызовом больше никогда не будет поставляться и ломало бы каждую сессию, созданную без явного выбора.

`AgentPreset` несёт `id` (имя каталога), `trust` (`system` или `user`, от корня, под которым найден), `path` (абсолютный файл композиции) и — только когда пресет не может собрать сессию — `broken` (одна человекочитаемая причина, показываемая дословно на поверхностях ростера).

### Где вызывать `mount()`

Хук `setup(agentCtx)` фабрики агентов — единственное поддерживаемое место вызова. Только там присоединение устанавливается, пока агент ещё не опубликован, поэтому отвергнутая композиция откатывает создание целиком, не оставляя полусобранной сессии. Постоянным поддеревом владеет собственный fiber сервиса ростера — намеренно его НЕТРАССИРУЕМЫЙ контекст, потому что поддерево, порождённое от трассируемого `this.ctx`, разрешало бы каждый сервис через теневой fiber вызывающего вместо собственного хранилища инъекций каждой записи, — поэтому оно переживает любого агента и демонтируется только вместе со всем деревом. Каждое поколение записывает отметку своего файла композиции (mtime и размер): сессия, нашедшая отметку устаревшей, начинает следующее поколение, тогда как каждая уже присоединившаяся сессия сохраняет ту, на которой работает, — композиция, к которой работающая сессия присоединилась, переживает изменение или исчезновение своего файла под ней, а файлы — единственный редактор композиции, поэтому именно отметка доносит правку до позднейших сессий.

### Сборка дочернего агента

Ребёнок субагента присоединяется к постоянной композиции родителя через `composeFrom()`, никогда через `mount()`. Каждая строка, обращённая к модели, живёт на плоскости агента, поэтому глобальный слой реестра инструментов пуст, и ребёнок, не присоединившийся ни к чему, достигает модели вовсе без инструментов и без разделов промпта родителя.

Повторное монтирование пресета родителя по id отличалось бы от привязки двумя способами, оба из которых важны. Файл композиции, отредактированный после старта родителя, вручил бы ребёнку ДРУГОЕ поколение, чем то, под которым была произведена история его родителя, а пресет, удалённый после, сломал бы ребёнка наглухо, пока его родитель продолжает работать. Привязка к тому же синхронна — именно это вообще позволяет внутрипроцессным драйверам субагентов ею пользоваться: они собирают детей внутри синхронного окна создания.

Ребёнок записывает присоединённый id в собственный долговременный заголовок ([`dsh-subagent`](../../subagent/subagent/README.ru.md)), поэтому холодное чтение истории ребёнка перестраивает композицию, под которой он реально работал, а не умолчание развёртывания.

### Какой пресет запускает сессия

Заголовок создания называет пресет, с которым сессия СТАРТОВАЛА; `resolveSessionPreset(session)` называет тот, на котором она РАБОТАЕТ. Они различаются всякий раз, когда пустая сессия переключилась, поэтому каждый путь реконструкции — сводка, которую читает селектор, возобновление, fork — разрешает, а не читает заголовок.

Заголовок остаётся замороженным, потому что это факт создания. Переключение — событие сессии `agent-preset/selected`, дописываемое после фиксации подмены, чего требует правило «видимое модели ⟺ залогировано»: пресет решает, какие схемы инструментов и разделы промпта видит модель, поэтому он должен быть восстановим из журнала. Сервис переиздаёт этот зафиксированный факт как событие cordis без скоупа `agent-preset/selected(sessionId, agentPreset)`, объявленное безопасным для клиента экспортом `./types`, позволяя удалённым потребителям инвалидировать производное от сессии состояние без импорта рантаймных типов Host. Чтение одного лишь заголовка перестроило бы переключённую сессию под композицией, с которой она создавалась, воспроизводя историю, на которую новый набор инструментов неспособен воздействовать, — именно та опасность, для предотвращения которой существует блокировка только для пустых.

### Переключение пустого агента

`recompose()` размонтирует установленное поддерево и монтирует новое, потому что две композиции не могут сосуществовать — обе регистрировали бы одни и те же имена инструментов в один слой. Неудавшееся монтирование восстанавливает предыдущую композицию, не оставляя агента ни с чем, а неизвестный id отвергается до того, как что-то разобрано.

Ограничение агентом, не произведшим ничего, — продуктовое правило, а не механическое: подмена инструментов посреди беседы оставила бы залогированные вызовы инструментов, которых новая композиция сделать не может. Шлюз принуждает его на уровне протокола ([`dsh-apiproxy`](../../host/apiproxy/README.ru.md) отвечает `agent-preset-locked`) — там, где история сессии уже в руках.

## Создание

Создание — только копирование. Новый пресет — копия целого каталога существующего — композиция, метаданные, каталоги скиллов, ресурсы, — размещаемая под первым корнем `user`; входы — два id, разрешаемых сервисом по его собственным корням, плюс необязательное отображаемое имя, поэтому вызывающий никогда не поставляет текст композиции, и копия не даёт ничего, чего ростер уже не нёс. Всё после создания происходит в собственных файлах пресета. `copy()` отвергает три вещи, прежде чем что-либо разместится:

- **Id, не являющийся `[a-z0-9][a-z0-9-]*`.** Id становится именем каталога, поэтому вложенность — свойство самого id, а не проверка пути задним числом: `../escape`, `a/b` и абсолютный путь отвергаются как id.
- **Уже занятый id.** Копия никогда не перезаписывает: любой корень, поставляющий этот id, отвергает его (пользовательский каталог, названный как штатный пресет, был бы им затенён), и каталог, занимающий имя на диске, тоже отвергает. Обнаружение перечисляет такой каталог как сломанный пресет, поэтому выход из отказа — удалить его — лежит на той же странице, которая об этом сообщила.
- **Неизвестный источник.** Источник может быть любого доверия — копирование штатного пресета и есть главный случай, — но он должен существовать; неудавшаяся копия откатывает свой полуготовый каталог, а не оставляет его невидимым для обнаружения.

Скопированное дерево заново ужимается до доступа только владельцу (файлы `0o600` с сохранением бита исполнения владельцем, каталоги `0o700`), симлинки разыменовываются, чтобы копия была самодостаточной, а корень создаётся при первой копии — развёртывание, настраивающее ещё не существующий пользовательский корень, есть нормальное состояние первого запуска. Скопированный `preset.yml` переписывается: описание источника сохраняется, чтобы автор правил его на месте, но имя и порядок ростера `order` отбрасываются — копия, представляющаяся тождественно своему источнику или сортируемая в заявленный порядок штатного набора, заставила бы ростер перестать их различать. `remove()` отвергает пресет, поставляемый с развёртыванием; штатный набор — заведомо рабочие композиции, с которых начинают копии.

### Как разрешаются строки пресета

**Имя пакета** строки разрешается из хостовой композиции, а не из каталога пресета. Загрузчик обычно разрешает запись относительно `baseUrl` собственного дерева, что для пресета означает место, где лежит файл композиции; локально созданный пресет живёт в домашнем каталоге пользователя, откуда восходящий обход `node_modules` Node никогда не дойдёт до харнесса, поэтому каждая строка `@deepseek-ai/dsh-*` не смогла бы импортироваться. Монтирование записывает базу хоста до подключения поддерева и отправляет туда голые спецификаторы.

**Относительный** путь по-прежнему разрешается от каталога самого пресета, поэтому собственные файлы плагинов и каталоги скиллов пресета передаются вместе с ним.

**Абсолютный** путь файловой системы сохраняет своё расположение. Монтирование преобразует его в URL `file:` перед импортом ESM, чтобы пути POSIX и Windows (буква диска или UNC) использовали спецификатор, который принимает Node.

### Отображаемые метаданные

Пресет может публиковать отображаемый текст в необязательном `preset.yml` рядом со своей композицией:

```yaml
name: 极简模式
description: 仅提供持久 bash 与 str_replace_editor 的双工具编码 Agent。
```

Он несёт ТОЛЬКО отображаемый текст. `id` — имя каталога, а `trust` приходит от корня, под которым обнаружен пресет, поэтому ни одно из них здесь не записывается — иначе локально созданный пресет мог бы вписать себя в штатный набор. Это отдельный файл, потому что композиция — список строк плагинов верхнего уровня: YAML не может нести соседние ключи рядом с ним, а поддельная строка метаданных дала бы загрузчику что-то для загрузки.

Любой сбой чтения вырождается в отсутствие метаданных — отсутствующий, искажённый, неверного типа или пустой файл означают одно и то же, а селектор возвращается к id. Представление — не возможность: пресет со сломанным именем всё равно монтируется.

## Конфигурация

| Поле | По умолчанию | Значение |
|---|---|---|
| `default` | обязателен | Id пресета, монтируемого, когда вызывающий не называет никакого |
| `roots` | `[]` | Сканируемые каталоги в порядке приоритета; каждый поставляет `path` (ведущая `~` раскрывается) и `trust` (по умолчанию `user`) |
| `includeUserRoot` | `true` | Добавлять `<dshHome>/.agent-presets` как корень `user` после каждого настроенного корня |

Отсутствующий корень не поставляет пресетов вместо отказа: пользовательского корня нет до первого локально созданного пресета, а умолчание, которое ни один корень не поставляет, и так отказывает с явной ошибкой при разрешении.

### Перезаписываемый корень принадлежит этому пакету, штатный — приложению

`<dshHome>/.agent-presets` — место собственных пресетов человека, как `<dshHome>/skills` — место его собственных скиллов ([`dsh-skill-filesystem`](../../skill/skill-filesystem/README.md)), поэтому ростер вычисляет его сам, не дожидаясь, пока развёртывание вспомнит, — лаунчер, не настраивающий ничего, всё равно находит и создаёт пресеты. Он добавляется ПОСЛЕ каждого настроенного корня, что сохраняет приоритет более раннего корня при дублирующемся id: штатный `standard` по-прежнему затеняет домашний каталог, присвоивший это имя, а `copy()` отвергает такой id, не размещая пресет, который ничто не разрешило бы.

Корни разрешаются однократно, при конструировании сервиса. Если набор корней изменился между `list()` и действующей по её ответу `copy()`, создание попало бы в каталог, которого вызывающий никогда не видел.

`includeUserRoot: false` монтирует ростер только поверх `roots`. Это нужно развёртыванию, замыкающему пресеты в собственных каталогах, и любому тесту, закрепляющему точный состав ростера, — иначе реальный `<dshHome>` машины решает, что содержит ростер.

ШТАТНЫЙ корень остаётся фактом сборки: он лежит рядом с собственной конфигурацией установленного приложения, по пути, который способно разрешить только оно.

### Пресет по умолчанию — пользовательская настройка

Когда в композиции есть провайдер настроек, этот плагин регистрирует пространство имён `agent-presets` с `config.default` в качестве базы композиции, поэтому пользовательский документ наслаивается поверх инженерного умолчания развёртывания:

```yaml
agent-presets:
  default: minimal
```

Значение читается при каждом разрешении, а не фиксируется снапшотом, поэтому горячо перезагруженный документ вступает в силу на следующей созданной сессии, а каждая работающая сессия остаётся на пресете, из которого была собрана. Очистка пользовательского поля возвращает наследование умолчания композиции. Умолчание, называющее пресет, который ни один корень не поставляет, сохраняется без возражений и отказывает при следующем `resolve()` — ростер живой каталог, поэтому имя, отсутствующее сейчас, может появиться к моменту, когда сессия спросит.

## Что отвергает монтирование

Напрямую подключённое поддерево отсутствует в `ctx.loader.entries()`, поэтому никакой загрузочный аудит его не покрывает. Поэтому `mount()` сам доказывает пригодность результата и отвергает три вещи.

**Цель без скоупа.** Монтирование в контекст, не несущий скоупа агента, зарегистрировало бы инструменты пресета глобально, для каждого агента процесса.

**Строка, так и не ставшая пригодной.** Загрузчик уже отвергает строку, чей модуль не импортировался или чей плагин бросил исключение; остаётся строка, всё ещё ждущая сервис, который композиция никогда не поставляет, — её называет аудит.

**Строка, опубликовавшая сервис в корневой realm.** Такой сервис глобален для процесса, поэтому второй пресет, публикующий то же имя, сталкивается с первым, а читающий хост разрешал бы экземпляр одного пресета для каждой сессии. Пресет, действительно владеющий сервисом, прячет его за realm `isolate` — локальные для записи realm'ы разводят одноимённые сервисы двух пресетов точно так же, как когда-то разводили две сессии, — либо сервису место в хостовой композиции.

Инвариант пакета перепроверяет последнее правило при каждом уведомлении о сервисах, потому что строка, публикующая из таймера или асинхронного продолжения, ускользнула бы от однократного аудита.

## Файл пресета — вход, но никогда цель персистентности

Загрузчик записывает дерево обратно в исходный файл, когда решит, что конфигурация изменилась, а строка, освобождающая собственный fiber, достаточна для такого решения: запись помечается `disabled`, и дерево записывается. При наследовании это выжгло бы рантаймное состояние одной сессии в файл, который делят все сессии, — с комментариями, стёртыми круговым преобразованием YAML, и с отвергнутым `writeFile` внутри `setTimeout` для read-only штатного пресета.

Поэтому смонтированное поддерево переопределяет `write()` как пустую операцию. Ничто в этом пакете не пишет композицию; её создание — отдельная явная операция.

## Доверие

Пресеты — композиции, поэтому пресет ровно настолько привилегирован, насколько привилегированы названные им плагины. Пресет `user` — созданный человеком или агентом — несёт то же доверие, что доступ к shell; поле `trust` существует, чтобы потребители могли показать эту разницу, а не обеспечить её принудительно.

## Влияние на модель

Опосредованно — через плагины, регистрируемые постоянной композицией: им принадлежат каждая схема инструментов и каждый раздел промпта, которые пресет делает видимыми присоединившимся к нему агентам.

#### Влияние на KV-кэш

Префикс стабилен на всю жизнь агента: композиция устанавливается однократно до публикации агента, а значит до его первого запроса, и никогда не перечитывается, пока агент работает. Выбор другого пресета для новой сессии устанавливает иной префикс для одной этой сессии и не может инвалидировать повторное использование ни для одной уже работающей сессии.

## Известные ограничения и отложенная работа

- **Пресет вне перезаписываемого корня обнаруживаем, но неудаляем** — `remove()` отвергает всё, что не живёт под ПЕРВЫМ корнем `user`, поэтому развёртывание, настраивающее собственный перезаписываемый корень при включённом `includeUserRoot`, перечисляет пресеты home-каталога харнесса, монтирует их, а затем отвечает «он не лежит под перезаписываемым корнем пресетов» на каждое удаление. Ростер по замыслу несёт один перезаписываемый корень; развёртыванию, желающему только свои, следует поставить `includeUserRoot: false`.
- **Пресет нельзя сменить, когда сессия уже что-то произвела** — `recompose` перепривязывает скоуп родителя ПУСТОЙ сессии к другому постоянному монтированию, и только пустой: переключение композиции, которая уже работала, оставило бы осиротевшими инструменты, которые модель уже вызывала. Смена умолчания затрагивает только сессии, созданные после.
- **Поколение ключуется одним лишь файлом композиции** — проверка отметки замечает изменение `agent.cordis.yml`, но не правку файла скилла или ресурса рядом; те доходят до новых сессий, только когда сам файл композиции сдвинулся или процесс перезапустился.
- **Вытесненное поколение никогда не высвобождается** — уже присоединившиеся сессии сохраняют поколение, на котором работают, а ростер не ведёт счётчика присоединений, способного сказать, когда ушла последняя, поэтому всё поддерево остаётся смонтированным до конца процесса. Цена платится за поколение, а не за сессию, но она не бесплатна: `dsh-skill-filesystem` по умолчанию наблюдает свои корни, поэтому каждый цикл «правка — создание» добавляет живой набор наблюдателей. Ограничено частотой правок композиций — поток создания на странице настроек делает это событием каждого сохранения, а не каждого развёртывания. Высвобождение поколения требует счётчика присоединённых агентов на постоянном монтировании; см. `TODO` в `ensureStanding`.
- **Копия никогда не монтируется для проверки** — она байт-в-байт тождественна источнику, поэтому источник, сломанный на диске, даёт копию ровно столь же сломанную; проверка здоровья обнаружения помечает обе строки при следующем чтении ростера, не откладывая сбой до старта сессии.
- **Здоровье — проверка формы, а не монтирование** — обнаружение доказывает, что композиция парсится в диалекте загрузчика и держит именованные строки, но не то, что модуль каждой строки разрешается или активируется; строка, называющая отсутствующий пакет, всё равно отказывает на первой сессии, которая откатывает создание.
- **Копия — расходящийся со временем снапшот** — обновление развёртывания не обновляет копии штатных пресетов, и на этом слое нет семантики патчей, выражающей «standard плюс одно изменение» (это `cordis.patch.yml` слоя бандлов); штатный набор сам платит ту же цену — `cordis` и `code` полные копии `standard`, — поэтому вся сборка остаётся читаемой в одном файле.
- **За корнями нет наблюдателей** — каждое чтение вместо этого бьёт в файловую систему, что держит ростер актуальным, но добавляет по одному `readdir` на корень при каждом `list()`.
