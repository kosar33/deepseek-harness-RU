# dsh-persona

[English](README.md) | [中文](README.zh.md) | Русский

Персона агента как компонуемая строка. Она может либо затенять персону развёртывания, либо владеть полным системным промптом.

[`dsh-system-prompt`](../../core/system-prompt/README.ru.md) владеет персоной развёртывания как собственной конфигурацией и регистрирует эту секцию безусловно, так что у процесса ровно одна персона. [Пресет агента](../agent-presets/README.ru.md) не может монтировать сам реестр промптов — без собственной строки пресет мог бы менять инструменты агента, но никогда его идентичность. Этот пакет и есть такая строка.

## Только внутри scope

Монтирование этой строки вне скоупа агента сталкивается с собственной регистрацией `deployment:persona` реестра и завершается с явной ошибкой. Это не ограничение, которое стоит обходить: у персоны развёртывания уже есть владелец, и весь смысл этой строки — затенить её для одного агента. Монтируйте её внутри композиции пресета, где монтирование пресета снабжает строку скоупом агента.

## Конфигурация

| Поле | Умолчание | Смысл |
|---|---|---|
| `text` | обязательно | Проза персоны, рендеримая как секция `deployment:persona` |
| `complete` | `false` | Восстановить после сборки эту персону как единственную секцию системного промпта |
| `includeRuntimeContext` | `true` | Включить динамические снапшоты runtime-контекста для этого скоупа агента; false подавляет каждый вклад контекста, не отключая владеющие им сервисы |

`text` — шаблон, как всякая секция промпта: полные группы `{{…}}` разрешаются строго против зарегистрированных переменных промпта в момент рендера, а не сборки. Пустой текст всё равно занимает slot, так что он полностью затеняет персону развёртывания, а затем исчезает при рендере. С `complete: true` сборка по-прежнему разрешает контексты, инструменты, переменные и кооперативных слушателей, а затем реестр промптов восстанавливает эту точную персону единственной секцией; ни идентичность, ни руководство по инструментам, ни слушатель не могут добавить текст в промпт. С `includeRuntimeContext: false` провайдеры контекста не вычисляются для этого скоупа, а контексты, добавленные слушателями сборки, отбрасываются.

## Влияние на модель

### Секция персоны

#### Что видит модель

Секцию `deployment:persona` с порядком 0, сразу после открывающего фрагмента идентичности harness, несущую ровно сконфигурированный `text` этой строки с разрешёнными переменными промпта. Для агента, чей пресет монтирует эту строку, она заменяет любую персону, сконфигурированную развёртыванием. В режиме complete модель видит только эту отрендеренную секцию как свой системный промпт. Runtime-контекст включён по умолчанию. При отключении свежий агент не получает никакого снапшота runtime-контекста — ни от политики песочницы, ни от политики разрешений, ни от делегирования, ни от другого провайдера контекста системного промпта.

#### Влияние на токены

Для данного пресета объём фиксирован: собственные токены персоны в каждом запросе этого агента и ни одного — для любого другого агента. Пустой текст не вносит ничего. Режим complete убирает все прочие токены системного промпта у этого агента.

#### Влияние на KV-кэш

Стабильность префикса на всю жизнь агента — строка монтируется однажды, до публикации агента, а значит до его первого запроса, и её текст никогда не меняется, пока агент работает. Два агента на разных пресетах устанавливают разные префиксы начиная с этой секции; ни один не может инвалидировать переиспользование другого.

## Известные ограничения и отложенная работа

- **Нет глобального монтирования** — слот персоны вне скоупа принадлежит реестру промптов, поэтому эта строка применима только из скоупированной композиции. Изменение персоны на уровне всего развёртывания принадлежит собственной конфигурации строки `system-prompt`.
