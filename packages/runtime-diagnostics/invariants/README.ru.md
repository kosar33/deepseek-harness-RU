# dsh-invariants

[English](README.md) | [中文](README.zh.md) | Русский

Настраиваемый сервис-реестр для проверок рантайм-инвариантов, принадлежащих пакетам. Корневой плагин регистрирует `ctx.invariants`; он не содержит ни продуктовых проверок, ни импортов продуктовых пакетов. Каждый пакет рабочего пространства публикует компаньона `./invariant`, регистрирующегося под точным npm-именем своего пакета.

## Сервис: `InvariantRegistry` (`ctx.invariants`)

```ts
interface Config {
  enabled?: boolean
  package_allowlist?: string[]
  package_blocklist?: string[]
}
```

Значения по умолчанию — `enabled: true`, `package_allowlist: []` и `package_blocklist: []`. Пакет выбирается, только когда сервис включён, allowlist пуст или хотя бы один шаблон allowlist совпадает с его полным npm-именем, и ни один шаблон blocklist не совпадает. Совпадения blocklist поэтому переопределяют совпадения allowlist.

Каждая запись — чувствительный к регистру источник регулярного выражения JavaScript, компилируемый через `new RegExp(pattern)`. Совпадение не привязано к краям, пока сам источник не содержит `^` и `$`; синтаксис `/pattern/flags` не разбирается. Пустые, обрамлённые пробелами, некорректные или дублирующиеся записи внутри одного списка приводят к неудаче старта сервиса. Корректный шаблон может не совпадать ни с одним из загруженных в данный момент пакетов — так поздняя загрузка и HMR остаются детерминированными.

`ctx.invariants.register(packageName, installer)` резервирует одну активную регистрацию под полное npm-имя пакета — в том числе когда фильтры оставляют его инсталлятор неактивным — и возвращает её диспоузер. Включённый вклад выполняется в выделенной дочерней Cordis-fiber. Инсталлятор может объявить требуемые сервисы через `installer.inject` и получает `fail(message)`, бросающий `InvariantError`, привязанный к регистрирующемуся пакету. Синхронное или асинхронное завершение инсталлятора дожидается, прежде чем регистрация увенчается успехом; неудача демонтирует дочернюю fiber и отпускает владение атомарно.

Сервис владеет каждым fiber регистрации, но возвращённый диспоузер одновременно принадлежит и fiber компаньона. Выгрузка любой из сторон удаляет слушатели, состояние трассировки и резервацию. Поэтому компаньон может перезагрузиться и снова зарегистрировать то же имя пакета, не удерживая прежнего состояния. Компаньоны на основе сессии перестраивают свою базовую линию из долговечных событий; live-only компаньоны наблюдают операции, начинающиеся после перезагрузки.

`InvariantError` расширяет `Error`, несёт стабильный `code: 'INVARIANT'` и раскрывает владеющий `packageName`, не добавляя продуктовой зависимости к сервису.

Сама Session в любой композиции владеет неизменяемым хранением журнала, всегда корректным относительно поверхности: она делает один снимок каждого кандидата в формате lossless-JSON, проверяет полный охват процитированных исходных событий и позиционную замену, ограничивает замену `tool/result` полем `content` единственного актуального результата, глубоко замораживает принятую запись и раскрывает журнал через неизменяемые снимки массивов. Компаньон-инвариант `dsh-session` проверяет оставшиеся межзаписные правила, которыми Session не владеет.

## Компаньоны пакетов

Публикация и регистрация исчерпывающие; рантайм-утверждения намеренно не синтетические. Компаньон ставит проверку только тогда, когда его пакет владеет наблюдаемым отношением потока событий или уместным отношением изменяемых данных. Подтверждение наличия требуемого метода, имени плагина, внедрения, эффекта или фиксированного результата чистой функции — забота типов, загрузки или юнит-теста, а не рантайм-инвариант.

Когда правдоподобного рантайм-отношения нет, компаньон использует пустой инсталлятор с ведущим комментарием вида `No runtime invariant:`, поясняющим применительно к конкретному пакету, почему проверять нечего. Это обычное дело для чистых утилит, тонких реализаций, чьё поведение уже наблюдается через их интерфейсный пакет, композиционных пакетов, бинарей, адаптеров персистентности, чьи контракты требуют тестов сбоя и полного цикла, и пакетов тестовой поддержки. Объяснение должно пересматриваться, когда владелец обзаводится изменяемым состоянием или протоколом событий.

Нынешние исполняемые компаньоны охраняют эти отношения:

| Компаньон | Проверки |
|---|---|
| `dsh-session`, `dsh-agent`, `dsh-scope`, `dsh-agent-loop` | Охват сессии и трассировка вызов/результат, переходы статусов агента, консервация FIFO инбокса, скоупированные субъекты и реконструкция модельных запросов. |
| `dsh-llm`, `dsh-llm-retry`, `dsh-tools`, `dsh-system-prompt` | Грамматика потока, долговечные позиция и границы повтора, стадии инструментального пайплайна и замороженные результаты, авторитетные данные сборки промпта. |
| `dsh-compaction`, `dsh-hook-protocol`, `dsh-sandbox-policy` | Долговечная парность компакции и хуков, метаданные компакции и словарь режимов песочницы. |
| `dsh-fs`, `dsh-subagent`, `dsh-workflow` | Идентичность событий файловой системы, парность провайдер/дочерний агент и идентичность жизненных циклов воркфлоу и агента. |
| `dsh-goal`, `dsh-goal-round-driver` | Долговечное согласие источника и содержимого цели, переходы версии и жизненного цикла, отметки времени, последовательные допущенные Round'ы и реконструированные промпты продолжения. |
| `dsh-permission-presets`, `dsh-user-approval` | Ссылки на активный пресет и аудиторская парность «спрошено/решено» одобрения. |
| `dsh-jobs`, `dsh-tool-todo` | Поля жизненного цикла/владения в снапшоте задач и долговечная структура целого списка todo. |
| `dsh-time-context` | Долговечные показания часов согласуются с открытым ходом сессии, позицией следующего пре-шага и исходной линией прошедшего времени; отрендеренное время разбирается и не датировано позже собственного события. |

Корневая точка входа каждого владельца остаётся независимой от диагностики. Загрузка одного лишь сервиса не ставит никаких продуктовых проверок, а загрузка компаньона без сервиса ждёт объявленного внедрения `invariants`.

`pnpm run verify-package-invariants` обнаруживает все пакеты рабочего пространства. Он отвергает сгенерированные маркеры, необъяснённые пустые инсталляторы, непустые инсталляторы, опускающие или игнорирующие репортера, неверные имена регистрации и неполную проводку экспорта, публикации, зависимости, TypeScript-ссылки или бандла. Это правило исходников — минимальная проверка принадлежности; семантику каждого исполняемого компаньона доказывают сфокусированные тесты.

## Композиция

```ts
import type { Context } from '@deepseek-ai/cordis'
import InvariantRegistry from '@deepseek-ai/dsh-invariants'
import * as SessionInvariant from '@deepseek-ai/dsh-session/invariant'

declare const ctx: Context

ctx.plugin(InvariantRegistry, {
  enabled: true,
  package_allowlist: ['^@deepseek-ai/dsh-'],
  package_blocklist: ['^@deepseek-ai/dsh-agent-loop$'],
})
ctx.plugin(SessionInvariant)
```

Стандартная агентская композиция монтирует сервис и четырёх core-компаньонов с состоянием. Пользовательские композиции явно добавляют компаньонов для прочих загруженных пакетов, чьи контракты они хотят проверять; фильтры могут отключать или выбирать регистрации, не меняя точки входа пакетов.

Каждая обычная Vitest-топология монтирует явно включённый сервис и компаньона текущего тестируемого пакета. Сфокусированные наборы покрывают корректные и некорректные наблюдения исполняемых компаньонов, а одна исчерпывающая топология монтирует всех компаньонов, доказывая проводку регистрации и освобождения ресурсов.

## Model Experience

Отсутствует: сервис и компаньоны наблюдают рантайм-события и изменяемые снимки, не трогая промпты, сообщения, схемы, потоки и результаты инструментов.

#### KV Cache effect

Отсутствует; проверки инвариантов не собирают и не отправляют запросы провайдерам.

## Известные ограничения и отложенная работа

- Реконструкция запросов покрывает только запросы, явно помеченные циклом до замораживания; прямые одноразовые вызовы LLM остаются вне этого маркерного контракта, даже если вызывающие замораживают их сами или прикрепляют id сессии.
- Live-only компаньоны жизненного цикла не могут реконструировать операции, начавшиеся до их собственной перезагрузки. Стандартная и тестовая композиции монтируют их до начала соответствующих операций.
- Фильтры регулярных выражений зафиксированы на время жизни сервиса; их изменение требует обычной перезагрузки плагина Cordis.
