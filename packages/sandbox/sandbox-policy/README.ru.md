# dsh-sandbox-policy — дом политики песочницы (`ctx.sandboxPolicy`)

[English](README.md) | [中文](README.zh.md) | Русский

Единственный владелец разрешения политики песочницы: заданные развёртыванием [`SandboxMode`](../sandbox/README.md) по умолчанию и резервный корень плюс долговременное переопределение режима каждой сессии и неизменяемый корень рабочего пространства. Каждая принуждающая возможность получает одну разрешённую политику «режим + корень» на вызов; перед каждым запросом модель получает текущую политику без отдельной описи возможностей.

## Зачем общий дом

Инструменты файловой системы, one-shot bash-команды и терминальные сессии могут принуждать один и тот же словарь режимов в разных комбинациях. Разрешай каждый свой `mode` + `workspaceRoot`, они могли бы расползтись в расщеплённый мир — ровно то, против чего предостерегает [Agent Note о песочнице](../../../.agents/notes/implemented/feature/2026-07-06-sandbox.md). Каждый принуждающий бэкенд потребляет полную разрешённую владельцем политику, тогда как текущий контекст описывает лишь то, что эта политика означает для любой доступной операции, которую принуждает файловая песочница DSH. Решение об общей политике фиксирует [Agent Note о кросс-семейной fs-песочнице](../../../.agents/notes/implemented/feature/2026-07-14-cross-family-fs-sandbox.md).

## Конфигурация

- `mode` — заданный развёртыванием `SandboxMode` по умолчанию (`read-only` / `workspace-write` / `danger-full-access`), проверяемый при загрузке. По умолчанию `read-only` (fail-safe).
- `workspaceRoot` — резервный каталог, под которым `workspace-write` может писать при вызовах без агента или в сессиях без cwd. По умолчанию `process.cwd()`, в любом случае разрешаемый до своей абсолютной файловой идентичности. Обычный вызов агента вместо этого использует неизменяемый `cwd` из заголовка своей сессии.

## API

- `ctx.sandboxPolicy.resolve({ session?, mode? })` — разрешает одну полную политику на вызов. Явно одобренный режим главнее последнего события `sandbox/mode` сессии, а оно главнее `defaultMode`; неизменяемый `cwd` сессии канонизируется с файловой семантикой прежде, чем стать `workspaceRoot`, иначе применяется настроенный резервный корень. Канонизация предшествует лексической нормализации, поэтому `symlink/..` согласуется с разрешением рабочего каталога процесса.
- `ctx.sandboxPolicy.defaultMode` / `ctx.sandboxPolicy.workspaceRoot` — используемые `resolve()` значение по умолчанию развёртывания и резервный корень.
- `sandbox:policy` — выводимый напрямую из `resolve({ session })` вклад контекста, безопасный для кэша во время запроса. Он утверждает нейтральный к возможностям контракт файловых эффектов режима и каноническое рабочее пространство сессии при `workspace-write`; владельцы инструментов сохраняют специфичные для операций руководства по отказам и эскалации.
- `effectiveSandboxMode(events)` — чистая свёртка событий `sandbox/mode` сессии (побеждает последнее переключение, иначе `undefined`), используемая внутри `resolve()`.
- `setSandboxMode(session, mode)` — ЕДИНСТВЕННЫЙ путь записи переопределения на сессию: дописывает ровно одно событие `sandbox/mode`. Переключение И ЕСТЬ его событие; ничто не мутирует режим в обход этого пути.
- `SANDBOX_MODES` — все режимы, для предъявления вариантов и проверки во время исполнения.

Необязательный спутник `./invariant` отвергает подделанное долговременное событие `sandbox/mode`, чьё значение выпадает из того закрытого словаря; окружающим хранением и правилами ядра по ограждению исполнения владеют Session со своим спутником. Цикл агента логирует собранный полный снапшот рантайм-контекста как `user/message` с записанным источником, поэтому точный вход политики остаётся восстановимым без живущего в памяти зеркала «что сказали в последний раз».

## Хранилище на сессию

Переключение во время исполнения — одно чисто журнальное событие `sandbox/mode` на той сессии, к которой оно относится. `effective = explicit grant ?? fold(events) ?? deployment default`, поэтому переопределение переживает перезапуск воспроизведением, а две сессии никогда не видят состояний друг друга. Идентичность рабочего пространства не нуждается ещё в одном событии: записанный при создании неизменяемый `SessionHeader.cwd` — корень для каждого вызова этой сессии. Событие остаётся только в журнале; перед следующим запросом владелец добавляет текущий факт в полный снапшот рантайм-контекста.

## Опыт модели

### Текущая политика файловой песочницы

#### Что видит модель

Один вклад `sandbox:policy` в текущем снапшоте рантайм-контекста каждой агентской сессии. Он не перечисляет смонтированных возможностей. Инструментальные плагины сохраняют руководства по операциям и эскалации, политика одобрения вносит вклад в тот же снапшот отдельно, а руководство плана остаётся системной секцией `dsh-plan-mode`.

##### Read-only

```markdown
Current DSH file policy: read-only. Any available operation enforced by the DSH file sandbox cannot modify files in the standing mode. Do not refuse a required modification from this policy alone: try an available tool normally and follow any denial and escalation guidance it returns.
```

##### Workspace-write

```markdown
Current DSH file policy: workspace-write. Any available operation enforced by the DSH file sandbox may modify files under the session workspace: "<workspace root>". Some platform temporary areas may also be writable.
```

##### Danger-full-access

```markdown
Current DSH file policy: danger-full-access. The DSH file sandbox does not restrict file modifications by available operations.
```

#### Влияние на токены

Одно ёмкое долговременное сообщение контекста на первом запросе и при каждом действительном изменении политики; неизменившиеся запросы не добавляют ничего. `workspace-write` несёт только канонический путь рабочего пространства сессии; зависящие от платформы временные пути суммируются без добавления зависящих от хоста байтов.

#### Влияние на KV-кэш

Стабильный системный промпт остаётся байт-в-байт одинаковым при сменах режима. Изменившийся полный снапшот контекста дописывается после удержанной истории, сохраняя прежний кэшированный префикс; последующие неизменившиеся запросы переиспользуют тот удержанный снапшот.

## Известные ограничения и отложенная работа

- **Один первичный корень рабочего пространства на сессию** — политика разрешает `SessionHeader.cwd`; дополнительные доступные для записи корни не входят в `SandboxExecutionPolicy`.
- **Только режимы файловых эффектов** — `SandboxMode` управляет файловыми эффектами; сетевая и процессная политики находятся вне его словаря, поэтому ни одна здешняя ручка их не ограничивает.
- **Временные области намеренно суммируются** — принуждающие бэкенды предоставляют разные временные области платформы, выбираемые уже после разрешения политики, поэтому честно перечислить их в текущем контексте нельзя.
