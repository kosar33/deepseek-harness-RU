# @deepseek-ai/dsh-sandbox

[English](README.md) | [中文](README.zh.md) | Русский

Service Definition песочницы процессов. Владеет сервисным контрактом `ctx.sandbox` ([`SandboxProvider`](src/index.ts)) и общим для harness словарём изоляции: `SandboxMode` (`read-only` / `workspace-write` / `danger-full-access`, только файловые эффекты), `SandboxEnforcement` (`full` / `partial`, по ABI ядра), `SandboxExecutionPolicy` (полный режим каждого вызова плюс корень workspace), `SandboxPolicy` (его ограниченное подмножество) и fail-closed ошибкой `SANDBOX_UNAVAILABLE`. Как роль Service Definition в [разделении на capability seams](../../../.agents/notes/implemented/architecture/2026-06-13-capability-seams.md), он зависит только от cordis (+ базового типа ошибок harness) и никогда — от бэкенда.

Контракт одной строкой: `ctx.sandbox.confine(argv, policy)` возвращает argv для запуска ВМЕСТО вашего собственного — обёрнутый так, что процесс (и всё, что он порождает) выполняется изолированно, — плюс полноту принуждения выбранного бэкенда, диалект отказов (`denialSignatures`) и структурированные свидетельства сбоя раннера (`runnerFailureRules`); когда ни один бэкенд непригоден, происходит бросок, а не пропуск argv без изоляции. Точную форму классификатора описывает [каталог основных типов](../../../docs/subsystems/sandbox.ru.md#обёрнутый-argv-и-диалекты-классификации).

Политика передаётся с вызовом, а не хранится у провайдера: два потребителя могут изолировать процессы под разными политиками в один и тот же момент (bash под `read-only`, пока изолированный дочерний агент сохраняет записываемым свой каталог состояния), а одобренная эскалированная повторная попытка — просто новый вызов с более широкой политикой.

**Только same-world изоляция.** Бэкенд разделяет с хостом файловую систему и ядро (`bwrap`, Landlock, Seatbelt); `workspaceRoot` называет канонический по файловой системе реальный каталог хоста. Идентичность workspace резолвится до лексической нормализации, поэтому корректный cwd, содержащий `symlink/..`, даёт каталог, куда `chdir` попадает фактически, а не неродственный лексический родитель. Контейнеры, microVM и удалённые исполнители — НЕ бэкенды этого seam'а: они заменяют Service Providers целых capability seams (`ctx.shell`, `ctx.fs`) как согласованные по среде группы. Граница и её обоснование: [Agent Note о песочнице](../../../.agents/notes/implemented/feature/2026-07-06-sandbox.md).

Реализации: [`@deepseek-ai/dsh-sandbox-local`](../sandbox-local/) (Linux: `bwrap`, иначе платформозависимый лончер Landlock; macOS: `sandbox-exec`/Seatbelt). Потребители: [`@deepseek-ai/dsh-bash-sandbox`](../../shell/bash-sandbox/) (оборачивает `['bash', '-c', command]`).

## Влияние на модель

### Ошибка изоляции, косвенно

#### Что видит модель

Через [`dsh-bash-sandbox`](../../shell/bash-sandbox/README.ru.md) и [`dsh-tool-bash`](../../shell/tool-bash/README.ru.md) невозможность обеспечить запрошенный режим даёт код `SANDBOX_UNAVAILABLE` и точный текст ошибки ниже. Сбой раннера во время исполнения добавляет ` Runner failure: <detail>`.

##### Точный текст ошибки

```markdown
sandbox mode "<mode>" is requested but no sandbox backend is usable on this host; refusing to run the command unconfined. Install bubblewrap or run a Landlock-enforcing kernel (Linux), ensure sandbox-exec is usable (macOS), or ensure the ACL restricted-token runner can start (Windows) — otherwise switch the consumer to danger-full-access.
```

#### Влияние на токены

Условный текст ошибки виден в этом вызове и удерживается в истории до компакции.

#### Влияние на KV-кэш

append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Файловые эффекты — весь словарь политики** — seam не выражает ограничений на сеть, процессы, syscalls, устройства или учётные данные.
- **Только same-world изоляция** — контейнеры, microVM и удалённое исполнение требуют замены реализаций возможностей, а не добавления провайдера сюда.
- **Отчёт об отказах — это диалект stderr** — seam возвращает сигнатуры бэкендов вместо типизированного канала отказов рантайма, поэтому потребителям, которым нужна классификация, приходится выводить её из вывода дочернего процесса.
- **Диагностика раннера внутриполосная** — статус выхода плюс свидетельства stderr не могут доказать, какой процесс написал совпавшую строку, поэтому изолированный потомок, сознательно мимикрирующий под свой раннер, способен вызвать ложную атрибуцию доступности/диагностики. Обойти изоляцию таким образом нельзя; внеполосный канал статуса раннера отложен.
- **Один провайдер на контекст** — одновременная композиция разных механизмов песочницы требует лестницы на уровне провайдеров или отдельных контекстов Cordis; вызывающие выбирают политику на каждый вызов, а не идентичность бэкенда.
