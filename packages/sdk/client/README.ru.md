# @deepseek-ai/dsh-sdk-client

[English](README.md) | [中文](README.zh.md) | Русский

TypeScript client SDK для управления рантаймом DeepSeek Harness как дочернего процесса поверх stdio JSON-RPC — близнец [Python SDK](../../../python/README.md) (`deepseek-harness`) по дизайну, разделяющий тот же peer-рантайм, протокол и разбиение на слои: `DeepSeekHarness` — высокоуровневый API владеемого запуска, `HarnessClient` — низкоуровневый протокольный клиент. Корень пакета перечисляет потребительский интерфейс: два клиентских слоя, обращённые к вызывающему типы и `JsonRpcResponseError`; исходные модули, помощники нормализации и механика доставки подписок не являются потребительскими импортами. Чистая библиотека: она ничего не регистрирует на контексте Cordis; порождаемый ею процесс рантайма — полный harness, чью композицию решает его собственный `cordis.yml`.

В отличие от Python SDK, спецификация запуска здесь полностью явная (`command`/`args`): этот пакет — для TypeScript-потребителей рядом с репозиторием, включая бэкенд [`dsh-subagent-dsh-sdk`](../../subagent/subagent-dsh-sdk/README.ru.md) и автоматизацию, — которые знают, какой рантайм запускают. Разрешение bundled-рантайма (поиск упакованного исполняемого файла) остаётся заботой Python-дистрибуции.

## DeepSeekHarness

```ts
import { DeepSeekHarness } from '@deepseek-ai/dsh-sdk-client'

await using harness = new DeepSeekHarness({
  launch: { command: 'node', args: ['lib/bin.js', 'cordis.yml'] },
  provider: 'deepseek-official',
  model: 'deepseek-v4-flash',
  maxTokens: 49_152,
})
const result = await harness.run('say hi')
console.log(result.finalResponse)
```

Субпроцесс стартует лениво при первом использовании и остаётся во владении экземпляра между вызовами `run()`; требуется `close()` (или `await using`), чтобы дочерний процесс всегда подчищался. `start()` мемоизирует рукопожатие `initialize` (cwd рабочего пространства — разрешаемый в абсолютный путь ещё до передачи — плюс маршрут провайдера/модели и опциональный положительный лимит вывода `maxTokens`); неудавшееся рукопожатие подчищает рантайм и подменяет клиент свежим, поэтому последующий вызов повторяется с новым субпроцессом (до `close()`, который терминален). Лимит применяется к каждому запросу корневого агента и наследуется внутрипроцессными потомками; плагины компакции владеют своими отдельными лимитами суммаризации. `session(id?)` открывает именованный или свежий дескриптор сессии.

`run(input, { sessionId?, onNotification? })` владеет одним интервалом активности: он ставит промпт в очередь, ждёт, пока его `MessageId` появится в долговечной квитанции `agent/inbox/spliced`, затем собирает события до следующего общего `idle` агента. Он возвращает `RunResult { sessionId, finalResponse, events, notifications }`. `finalResponse` — последний зафиксированный текст ассистента корневой сессии в этом интервале, а не ответ, причинно назначенный промпту; steering, внедрённый контекст и прочая поставленная в очередь работа могут внести вклад перед idle. `events` содержит события корневой сессии, тогда как `notifications` содержит и потомков, обнаруженных из `subagent.started`, всё в порядке следования по протоколу. Результат не несёт статуса уровня промпта или причины завершения хода. Потеря транспорта, таймаут и нарушения протокола отвергаются; исходы модели остаются наблюдаемыми в потоке событий, не приписываясь одному входу.

## HarnessClient

Протокольный клиент под API владеемого запуска: явные `start()`/`initialize()`/`prompt()`/`request()`/`close()` плюс подписки на уведомления. `prompt()` возвращает id поставленного в очередь сообщения, как только рантайм его принимает; он никогда не ждёт активности агента. `subscribe(filter?)` возвращает `NotificationSubscription` (awaitable `next()`, неблокирующий `tryNext()`, асинхронная итерация); `subscribeSessionTree(id)` ограничивает область одной сессией и потомками, обнаруженными по рёбрам родства `subagent.started`, — рантайм уведомляет о каждой сессии своего контекста, а сужение области выполняется на клиенте, точно как в Python SDK. Поверхности ошибок типизированы и экспортированы из этого пакета: `JsonRpcResponseError` (протокольный ответ с ошибкой, код/data сохранены), `RequestTimeoutError` (истёк настроенный предел), `SdkProtocolError` (ответ вне документированного протокола), `TransportClosedError` (рантайма больше нет — сообщение несёт код выхода и ограниченный хвост stderr).

`close()` запрашивает протокольный `shutdown` (ограничен `shutdownTimeoutMs`, по умолчанию 1000 мс), затем спускается по лестнице stdin-EOF → SIGTERM → SIGKILL (`disposeEofGraceMs` по умолчанию 6000, `disposeGraceMs` — 3000), пока процесс действительно не выйдет. Лестница приватна для этого клиента: она выполняется вне какого бы то ни было контекста harness и потому не может использовать сервис [`dsh-subprocess`](../../subprocess/README.md) — документированное исключение seam'а для транспортов, управляемых SDK. Она идемпотентна, а закрытый клиент отказывает в переиспользовании.

`HarnessClientOptions.env` при заданном значении заменяет дочернюю среду целиком (`undefined` наследует родительскую); политика учётных данных — забота вызывающего: `scrubbedParentEnv` из `dsh-subprocess` служит общей очищенной основой для запусков, ориентированных на изоляцию.

## Влияние на модель

Отсутствует: это клиентская процессная библиотека; модель работает в порождённом рантайме, чьим опытом владеют плагины, собранные его `cordis.yml`.

#### Влияние на KV-кэш

Нулевое; этот пакет ни собирает, ни отправляет запрос провайдеру.

## Известные ограничения и отложенная работа

- **Нет разрешения bundled-рантайма** — вызывающие явно называют исполняемый файл рантайма; обнаружение упакованных исполняемых файлов остаётся на стороне Python, пока не появится TypeScript-потребитель дистрибуции.
- **Нет отмены посреди хода** — на уровне протокола нет метода отмены промпта; покинуть ход значит закрыть рантайм (см. [Известные ограничения](../protocol/README.md) протокола).
- **Нет результата или отмены на отдельный промпт** — низкоуровневый `prompt()` возвращает только квитанцию о постановке в очередь; высокоуровневый `run()` владеет сбором от квитанции до idle, и покинуть его значит закрыть рантайм.
- **Уведомления клиент→сервер и запросы сервер→клиент не реализованы** с обеих сторон протокола; транспорт переносит их ради будущих сценариев одобрения.
