# @deepseek-ai/dsh-sdk-protocol

[English](README.md) | [中文](README.zh.md) | Русский

Общий формат протокола рантайма DeepSeek Harness SDK: один класс транспорта JSON-RPC 2.0 с разделением кадров переводами строк плюс именованные типы запросов, результатов и уведомлений, на которых говорят оба конца протокола. Корень пакета перечисляет интерфейс потребителя протокола; исходные модули не экспортируются как deep-импорты. Серверная сторона — плагин [`dsh-sdk-jsonrpc-server`](../server/README.ru.md); клиентами являются [`dsh-sdk-client`](../client/README.ru.md) (TypeScript) и [Python SDK](../../../python/README.md) (он зеркалит эти формы, но не импортирует их). Чистая библиотека — ни плагина, ни Config, ни регистрации.

## Транспорт

`JsonRpcLineTransport` упаковывает JSON-RPC 2.0 в принадлежащие вызывающему байтовые потоки — один компактный JSON-кадр на строку, оканчивающуюся `\n`. Кадр с `id` и `method` — запрос, один `id` — ответ, один `method` — уведомление; искажённые JSON-строки игнорируются. `start()` навешивает слушатели потока, `close()` снимает их и отклоняет ожидающие запросы, не уничтожая сами потоки. При отсутствии обработчика запроса отвечается `-32601`; отклонение обработчика даёт `-32603` с текстом ошибки. Ответ с ошибкой отклоняет ожидающий `request()` исключением `JsonRpcResponseError`, сохраняющим протокольный `code` и необязательный `data`. `JsonRpcTransportPeer` — исходящий интерфейс (request/notify), под который типизирован серверный класс.

## Типы протокола

`types.ts` называет каждую полезную нагрузку протокола, который обслуживает `HarnessSdkJsonRpcServer`:

| Направление | Метод | Типы |
|---|---|---|
| client→server | `initialize` | `InitializeParams` → `InitializeResult` |
| client→server | `session/prompt` | `SessionPromptParams` → `SessionPromptResult` (долговечная квитанция постановки в очередь) |
| client→server | `shutdown` | нет параметров → `{}` |
| server→client | `session.event` | `SessionEventNotification` (все сессии рантайма, без фильтрации) |
| server→client | `session.status` | `SessionStatusNotification` (переход агента целиком `running`/`idle`) |
| server→client | `subagent.started` | `SubagentStartedNotification` |
| server→client | `subagent.finished` | `SubagentFinishedNotification` (только запуски внутри процесса) |

`HarnessSdkRequestMap` и `HarnessSdkNotificationMap` индексируют их по имени метода. `SessionPromptResult.messageId` идентифицирует поставленный в очередь `UserMessage`; он не идентифицирует ни более позднее сообщение ассистента, ни окончание хода, ни результат промпта. Клиенты комбинируют открытый поток `session.event` с охватывающим агента целиком `session.status` по собственному распределению ответственности за активность. `SubagentFinishedNotification.lastAssistantMessage` содержит последнее непустое сообщение ассистента дочернего агента либо, когда такого сообщения нет, накопленный ассистентский текст; поле отсутствует, если ребёнок не произвёл ни того ни другого. `InitializeParams.maxTokens` — необязательный положительный safe integer, ограничивающий вывод диалоговой модели для созданных SDK агентов и их потомков внутри процесса; отсутствие поля позволяет примениться умолчанию точной модели выбранного адаптера, а если такого умолчания нет — сохраняет поведение провайдера. Типы полезных нагрузок уведомлений зависят от `SessionEvent` (`dsh-session`), `ContentBlock` (`dsh-llm`) и `SubagentStopReason` (`dsh-subagent`) — протокол передаёт потоком полные конверты журнала событий, поэтому словарь сессии входит в контракт протокола. `serverInfo.name` остаётся стабильным в протоколе `deepseek-harness-sdk-runtime`.

## Влияние на модель

Отсутствует: этот пакет определяет обращённый к клиенту формат протокола; видимое модели принадлежит плагинам рантайма, собираемым позади обслуживающей точки входа [`dsh-sdk-jsonrpc-server`](../server/README.ru.md).

#### Влияние на KV-кэш

Отсутствует; этот пакет не собирает и не отправляет запросы к провайдеру.

## Известные ограничения и отложенная работа

- **Согласования версий протокола нет** — рукопожатие несёт только `serverInfo.version` (`0.0.1`, клиентами не проверяется); позиция до первого релиза, обещаний совместимости нет.
- **Методов отмены и закрытия сессии нет** — клиент покидает ход, закрывая процесс рантайма; см. [README `dsh-sdk-jsonrpc-server`](../server/README.ru.md).
- **Запросы server→client — мёртвая возможность** — транспорт их поддерживает, но сервер никогда не отправляет; отвечающая сторона Python SDK существует ради будущих сценариев согласования разрешений.
