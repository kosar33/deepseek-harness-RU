# @deepseek-ai/dsh-sdk-jsonrpc-server

[English](README.md) | [中文](README.zh.md) | Русский

Плагин `jsonrpc` обслуживает JSON-RPC, разбитый на сообщения переводами строк, поверх stdio, чтобы SDK-клиенты вне процесса могли управлять агентами harness. [`HarnessSdkJsonRpcServer`](src/server.ts) владеет методами протокола и уведомлениями; транспорт и именованные типы протокола живут в [`dsh-sdk-protocol`](../protocol/README.ru.md), общем с клиентскими SDK; [`jsonrpc-demo`](../../examples/jsonrpc-demo/README.md) поставляет окружающее приложение `cordis.yml`.

## Подключение

`inject: ['agents']`. Сервер получает или создаёт одного агента на каждый `sessionId`. Завершения субагентов пересылаются только тогда, когда снятый сервисом флаг жизненного цикла `local` истинен; имена провайдеров, дочерние id и долговечная родословная локальность не устанавливают. Если адаптер зарегистрирован, используется он; маршрут `deepseek-official` без своего адаптера монтирует `dsh-llm-deepseek`; любой другой провайдер без адаптера делает инициализацию неуспешной. Остальные возможности приходят из окружающего `cordis.yml`.

## Конфигурация

`maxTokensAsSuccess` по умолчанию равен `false` и влияет только на отображаемый развёртыванием статус в `subagent.finished`; у промптов корневой сессии статуса уровня промпта нет. `JsonRpcConfig.input`, `output` и `exit` — транспортные хуки, существующие только в рантайме; в продакшене используются stdio процесса и `process.exit`.

## stdout — это протокол

Stdout несёт только кадры JSON-RPC. Развёртывание **НЕ ДОЛЖНО** включать в композицию логгер, пишущий в stdout; диагностика относится к stderr.

## Семантика завершения и выхода

Плагин отвечает на `shutdown`, сбрасывает ответ, выполняет освобождение ресурсов корневого контекста так, что принадлежащие SDK агенты, подписки и персистентность достигают quiescence (полного завершения всех жизненных циклов), затем выходит с кодом 0. Выходы по EOF и сигналам относятся к app bin, который тоже освобождает корневой контекст. Выгрузка только этого плагина прекращает обслуживание, не завершая процесс.

## Примечания к формату протокола

`initialize` служит границей готовности рантайма: когда сервер смонтирован композицией Loader'а, он ждёт стабилизации текущего дерева плагинов, прежде чем ответить, поэтому асинхронные соседние возможности — например, первичное обнаружение MCP-инструментов — видимы первому промпту. Собранные вручную контексты без Loader остаются пригодными сразу. `initialize.serverInfo.name` — стабильное в протоколе имя `deepseek-harness-sdk-runtime`. Необязательный положительный `initialize.maxTokens` становится потолком вывода запроса каждого созданного SDK агента и его потомков внутри процесса; недопустимые значения отвергают инициализацию, а отсутствие поля не передаёт потолка SDK и позволяет примениться умолчанию выбранного адаптера или маршрута провайдера. `session/prompt` ставит в очередь одно идентифицированное пользовательское сообщение и немедленно возвращает `{ messageId }`. Сервер передаёт потоком каждый долговечный факт как `session.event`, а каждый переход жизненного цикла агента целиком — как `session.status`; он не назначает этому промпту ни сообщение ассистента, ни `turn/end`. Независимые запросы могут поставить в ту же сессию ещё работу. Корни персистентности и персона приходят из `cordis.yml`.

## Влияние на модель

### Пользовательское сообщение SDK

#### Что видит модель

На каждый принятый `session/prompt` диалоговая модель получает переданные вызывающей стороной `contentBlocks` дословно одним пользовательским сообщением в этой SDK-сессии. Этот пакет не добавляет ни прозы системного промпта, ни схемы инструментов; то и другое приходит из плагинов окружающего `cordis.yml`.

#### Влияние на токены

Зависящие от данных токены пользовательского сообщения попадают в удерживаемую историю сессии и повторно отправляются на последующих ходах, пока другой пакет не выполнит их компакцию. Кадры JSON-RPC, уведомления сессии и серверная бухгалтерия не добавляют в модельный контекст ни одного токена.

#### Влияние на KV-кэш

Append-only; заново видимое содержимое следует за повторно используемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **В протоколе нет метода закрытия отдельной сессии или отмены промпта** — созданные SDK агенты остаются живыми до завершения процесса.
- **Результата на промпт нет** — `MessageId` идентифицирует только приём во входящую очередь; клиенты, владеющие интервалом автоматизации, **ДОЛЖНЫ** определить и наблюдать его самостоятельно.
- **Чистоту stdout обеспечивает развёртывание** — окружающая конфигурация всё ещё способна загрузить логгер в stdout и повредить канал JSON-RPC; этот плагин соседние логгеры не инспектирует и не ветирует.
- **Автоматическое монтирование адаптера специфично для DeepSeek** — `initialize` способен переиспользовать любой заранее зарегистрированный адаптер моделей, но его единственный запасной вариант монтирует `dsh-llm-deepseek`.
