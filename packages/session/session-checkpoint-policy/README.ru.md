# dsh-session-checkpoint-policy

[English](README.md) | [中文](README.zh.md) | Русский

Политика семантической долговечности для персистентных агентов. Она ставит event-sourced сессию в чекпоинт до того, как адаптер модели получит запрос, прежде чем тело top-level инструмента сможет произвести внешний побочный эффект, и на каждой границе `agent/pre-step`, так что предыдущий ответ и упорядоченные результаты инструментов становятся долговечными до следующего запроса.

## Плагин (namespace: `session-checkpoint-policy`)

Этот zero-config функциональный плагин использует `ctx.sessions`, `ctx.llm`, `ctx.tools` и наличие `ctx.sessionPersistence`. Загружайте его рядом с одним бэкендом персистентности:

```yaml
- id: session-persistence
  name: '@deepseek-ai/dsh-session-persistence-jsonl'

- id: session-checkpoints
  name: '@deepseek-ai/dsh-session-checkpoint-policy'
```

Персистентность и планирование чекпоинтов — намеренно раздельные плагины Cordis. Бэкенд персистентности запускает ограниченные фоновые батчи для операций добавления `session/event` и превращает каждый запрошенный `session/flush` в немедленный барьер quiescence; эта политика выбирает барьеры запроса, диспетчеризации инструмента и следующего шага. Загрузка бэкенда без этой политики допустима, но крах может потерять события, ещё находящиеся внутри конфигурируемого окна батчирования, или незавершённую запись. First-party персистентные приложения и рантаймы монтируют оба плагина явно; специализированное развёртывание может намеренно опустить или заменить политику.

Политика оборачивает `llm/stream` лениво, поэтому поток ниже по цепочке не создаётся, пока буферизованные события запроса живой сессии не станут долговечными. Она оборачивает `tools/execute` после политики pre-execute и guard'ов: тело top-level инструмента выполняется только после того, как его записанный вызов стал долговечным. Если отмена приходит, пока такой flush ожидает завершения, обёртка возвращает канонический результат `ABORTED_BEFORE_DISPATCH`, не входя в тело инструмента. Вложенные диспетчеризации инструментов переиспользуют чекпоинт внешнего вызова, видимого модели. `agent/pre-step` сохраняет батч предыдущего ответа/результатов до формирования следующего запроса.

Отклонение чекпоинта действует по принципу fail-closed на границах модели и инструментов: не запускается ни адаптер, ни тело top-level инструмента. Отказ на границе шага приводит ход к сбою до старта очередного запроса. Параллельные чекпоинты инструментов разделяют сериализованный канал сохранения данных хранилища сессии и не могут дублировать порядковые номера.

## Model Experience

### Прерванные вызовы

#### Что видит модель

Плагин не добавляет ни промпт, ни схему инструмента. Внезапный крах после чекпоинта инструмента, но до его результата оставляет долговечный вызов без парного результата; восстановление сессии предоставляет видимый модели результат `TOOL_OUTCOME_UNKNOWN` (владелец — `dsh-session`). Сообщение разрешает повтор для read-only или идемпотентной работы и требует проверки состояния либо подтверждения пользователя для вызовов, которые могли иметь побочные эффекты.

#### Влияние на токены

Успешные чекпоинты не добавляют токенов и не меняют запрос. Восстановление добавляет одно короткое сообщение с результатом инструмента, уравновешивающее прерванный транскрипт.

#### Влияние на KV-кэш

Корректирующий результат добавляется после переиспользуемого префикса, поэтому не инвалидирует более ранние записи кэша.

## Известные ограничения и отложенная работа

- Политика долговечно фиксирует намерение выполнения, а не универсальную семантику exactly-once. Для инструментов с побочными эффектами **СЛЕДУЕТ** передавать дальше `exec.callId` в качестве ключа идемпотентности, если их провайдер это поддерживает.
- Потоковые события `assistant/chunk` не имеют почанкового чекпоинта. Ограниченные фоновые батчи обычно сохраняют их до следующего семантического чекпоинта, но внезапный крах может потерять текущий батч в памяти или незавершённую запись.
- Персистентный вызов без результата не может доказать, завершился ли его внешний эффект. Поэтому восстановление фиксирует неизвестный исход вместо автоматического повтора.
