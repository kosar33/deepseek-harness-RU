# @deepseek-ai/dsh-session-persistence-jsonl

[English](README.md) | [中文](README.zh.md) | Русский

Бэкенд долговечной персистентности сессий на JSONL — конкретная реализация `SessionPersistence` (seam `dsh-session-persistence`). У каждой сессии один логический журнал append-only в формате JSONL, по умолчанию хранящийся как `.jsonl.zstd`, а при отключённом сжатии — как несжатый `.jsonl`.

## Раскладка на диске

```
<root>/
  --<normalized-cwd>--/          # readable project directory (or _no-cwd/)
    <encoded-id>/                # session-owned directory
      session.jsonl.zstd         # default: checksummed header frame + append frames
      session.jsonl              # only with compression: 'none'
```

- Первой логической строкой идёт неизменяемый `SessionHeader` с тегом `{ type: 'session', version, id, cwd?, createdAt, parentSession?, seedLength?, origin?, delegationDepth, agentPreset? }`. `delegationDepth` обязателен на диске и равен `0` для сессии верхнего уровня; отсутствие значения или недопустимое значение отвергают журнал. `agentPreset` долговечен, потому что определяет инструменты и промпт возобновляемой сессии — восстановление иной композиции воспроизвело бы историю, на которую модель уже не может воздействовать. Каждая следующая логическая строка — одна запись хранения; события `assistant/chunk` никогда не отбрасываются, а `seq` остаётся непрерывным по всему декодированному журналу (`events[i].seq === i`).
- Записью хранения является JSON события `SessionEvent` дословно либо — для подходящего запуска при включённом `packChunks` — **упакованная строка чанков** (`text-chunks` / `reasoning-chunks` / `tool-call-chunks`; простые теги без слэша, подобные `session` из заголовка, поэтому теги строк нельзя спутать с типами событий): одна строка, содержащая серию из ≥3 последовательных дельта-событий `assistant/chunk` одного блока, где `seq0`/`time0` плюс межчленные промежутки `dt` восстанавливают `seq`/`time` каждого члена в точности. Кодек без потерь находится в `@deepseek-ai/dsh-session` (`packChunkRuns`/`decodeStorageRecord`) и пропускает только точно определённые формы — всё нераспознанное сохраняется дословно. Чтение не зависит от раскладки: `load` всегда декодирует строки, поэтому упакованные, неупакованные и смешанные файлы загружаются одинаково.
- Каталог проекта хранит нормализованный cwd читаемым для навигации и ограничен лимитами компонентов файловой системы. Замена разделителей и усечение намеренно теряют информацию, поэтому строки cwd, нормализующиеся одинаково, попадают в один каталог проекта; идентификаторы сессий по-прежнему выбирают различные каталоги сессий. На файловой системе без учёта регистра валидация идентичности принимает альтернативное написание пути, только если канонизация файловой системы сводит оба написания к одному транскрипту. Настроенный корень остаётся управляемым развёртыванием: он может быть локальным для проекта, общим, временным или централизованным. Этот компромисс зафиксирован в [решении о каталогах проект/сессия](../../../.agents/notes/implemented/architecture/2026-07-24-project-session-directories.md).
- Идентификаторы сессий — невалидируемые branded-строки, поэтому перед использованием они инъективно экранируются в один безопасный сегмент пути (без выхода за пределы дерева и коллизий). Полученный каталог зарезервирован за прочими артефактами самой сессии; обнаружение читает только фиксированное имя файла транскрипта.

## Конфигурация

| Ключ | Тип | Примечания |
|---|---|---|
| `root` | `string` (обязательно) | Корневой каталог всех файлов сессий. **Значения по умолчанию нет** — умолчание `process.cwd()` разбросало бы файлы вслед за сменой cwd процесса (вызовы bash, дочерние процессы). Существующий корень должен быть каталогом, доступным для чтения; отсутствующий корень создаётся при первой материализации. |
| `packChunks` | `boolean` (по умолчанию `true`) | Записывает подходящие серии дельта-чанков упакованными строками (логические журналы примерно на 60% меньше по замерам на реальной сессии программирования). Задайте `false` для диагностики с одним событием на строку; чтение упакованных строк работает независимо от этого переключателя стороны записи. |
| `compression` | `'zstd' \| 'none'` | По умолчанию `'zstd'`; `'none'` сохраняет текст UTF-8 с переводами строк в качестве разделителей. |
| `preparedSessionCacheSize` | положительное целое (по умолчанию `5`) | Максимум неопубликованных сессий, удерживаемых после холодного просмотра истории для повторного использования при возобновлении. |
| `writeBatchMaxDelayMs` | положительное целое (по умолчанию `200`) | Фиксированное окно коалесценции, отсчитываемое после того, как простаивающая очередь живых событий получает работу. Поздние события не сбрасывают его; flush и teardown его минуют. Оно не ограничивает задержки цикла событий, сериализованных операций или бэкенда. Не более таймерного предела Node в `2_147_483_647` мс. |

`locate(meta)` возвращает `{ kind: 'jsonl', path }` фиксированного транскрипта внутри разрешённых каталогов проект/сессия. Файлового ввода-вывода она не выполняет: цель может быть возвращена до существования каталога или файла, а существующий файл содержит только последний сброшенный префикс.

## Физическое кодирование

Артефакт по умолчанию — стандартная конкатенация независимых [фреймов Zstandard](../../../.agents/notes/implemented/architecture/2026-07-19-zstandard-jsonl-session-logs.md): один фрейм с контрольной суммой, содержащий только строку заголовка, затем по одному фрейму с контрольной суммой на каждый долговечный батч добавления. Бэкенд использует встроенный Zstandard API Node с уровнем сжатия по умолчанию и не предоставляет настройки уровня. Чтение списка считывает и валидирует только заголовочный фрейм. `compression: 'none'` хранит те же логические строки в исходном несжатом представлении.

Корень принадлежит одному кодированию. Обнаружение при запуске и адресный поиск отвергают противоположный суффикс ошибкой, называющей несовместимый артефакт и предлагающей вызывающему выбрать соответствующий режим или отдельный корень. Плоские артефакты `<project>/<id>.jsonl*` также отвергаются, а не игнорируются. Миграции, fallback на смешанный корень и двойная запись отсутствуют.

## Долговечность и семантика сбоев

- **Ограниченная идентичность хранилища.** Поиск требует одного совпадающего каталога сессии среди читаемых каталогов проектов, затем проверяет, что id заголовка равен запрошенному id и что id/cwd заголовка порождают выбранный путь транскрипта. Чтение списка применяет ту же проверку пути и отвергает дубликаты id. Сбои идентичности происходят до починки или добавления.
- **Ленивая материализация.** `create(meta)` ничего не записывает; при первом `append` бэкенд записывает и `fsync`-ит закодированные заголовок и первый батч во временный файл. POSIX публикует его без перезаписи через жёсткую ссылку и выполняет `fsync` родительского каталога. Windows публикует его без перезаписи через `MoveFileExW(..., MOVEFILE_WRITE_THROUGH)` и создаёт недостающие каталоги тем же write-through-образом. Созданная, но ни разу не пополнявшаяся сессия не оставляет на диске ничего и отсутствует в `list`.
- **Append-only.** Сброшенные события никогда не переписываются. Последующие несжатые батчи дописывают строки; сжатые батчи дописывают один фрейм. Оба пути выполняют `fsync`, а пойманный сбой записи или синхронизации откатывает файл к прежней длине в байтах.
- **Восстановление после сбоя — сохранить валидную работу хвоста.** `load` валидирует каждый полный сжатый фрейм и сканирует их декомпрессированный JSONL. Если последний фрейм структурно неполон, читатель оставляет его полные декодированные записи, обрезает с начала этого фрейма и перекодирует эти записи с синтетическими закрывателями инструмента, шага и хода, требуемыми общим [контрактом персистентности](../../../.agents/notes/implemented/architecture/2026-06-14-session-persistence.md). Несжатый режим обрезает с первой неполной строки. Существующий сжатый артефакт без полного заголовочного фрейма, со сбоем контрольной суммы или декомпрессии в полном фрейме либо с дефектом на последнем зафиксированном `turn/end` или раньше является повреждением и отвергается.
- **Неизменяющая инспекция.** `inspect()` возвращает неизменяемое сбалансированное логическое представление и может синтезировать закрыватели восстановления в памяти, не обрезая неполный хвост и не меняя легковесную ревизию.
- **Непрерывный seq.** `append` отвергает батч, чей первый `seq` не продолжает сохранённый журнал, и отвергает несериализуемые в JSON `event.data`, называя тип нарушающего события.
- **Легковесные ревизии.** `listSnapshots(signal?)` идентифицирует журнал по устройству, inode, размеру и наносекундным отметкам времени, избегая полного разбора журнала, но меняясь после добавления, починки, замены или изменений хранилища. Полное чтение префикса требует той же идентичности до и после чтения байтов, а `readStoredRevision()` использует эту идентичность, чтобы валидировать удерживаемые подготовки без загрузки журнала. Чтение списка снапшотов пробрасывает сигнал в точности сквозь обнаружение артефактов и проверяет отмену вокруг каждого `stat`; поскольку файловый `stat` непрерываем, отмена ждёт завершения активного вызова, затем отвергает, не запуская новый.

## Путь записи

Плагин копирует замороженные события сессии в один контроллер на каждую живую сессию. Первое ожидающее событие запускает настроенное фиксированное окно батчинга, и поздние события присоединяются, не сбрасывая его. Истечение окна начинает один долговечный батч добавления; события, принятые во время этой записи, образуют отдельно ограниченный последующий батч. `session/flush` отменяет ожидание и вычищает текущие и ожидающие батчи. Посессионный курсор не даёт возобновлённым сессиям повторно дописывать сохранённые события, а для живых сессий курсоры создаются при загрузке плагина. Владеющий экземпляр бэкенда сериализует операции одной сессии; освобождение ресурсов вычищает каждый удерживаемый контроллер перед остановкой. Каждое логическое событие остаётся присутствующим: батчинг лишь позволяет одному сжатому фрейму или одному несжатому `fsync` нести больше записей.

## Model Experience

### История возобновлённого диалога

#### What the model sees

Хранилище JSONL не добавляет ничего в живой промпт или схему. Загрузка восстанавливает сохранённую поверхностную историю и хранит прежние заголовки запросов для реконструкции; новый цикл собирает свой текущий конверт. Восстановление уравновешивает запрос ассистента без долговечного вызова значением `TOOL_NOT_STARTED`; долговечный вызов без результата становится `TOOL_OUTCOME_UNKNOWN`, что предписывает модели повторять только read-only или идемпотентную работу и проверять возможные побочные эффекты либо спросить пользователя. Несжатые записи `assistant/chunk` не дублируют сообщения.

#### Token effect

Ноль токенов в живых запросах. Возобновлённый агент платит за удержанную историю и свой текущий конверт плюс за процитированный результат починки каждого прерванного вызова.

#### KV Cache effect

Хранилище JSONL не изменяет живые префиксы запросов. Возобновлённый цикл может повторно использовать кэш провайдера, только если реконструированная история, текущий конверт и маршрут модели совпадают; результаты восстановления после сбоя дописываются.

## Известные ограничения и отложенная работа

- **Загружаются только настроенное кодирование и текущая `SESSION_FORMAT_VERSION` (v0)** — смена сжатия требует отдельного/свежего корня или выбора прежнего несжатого режима; у предрелизного формата миграции нет.
- **Плоская раскладка хранения не загружается** — используйте отдельный корень или перенесите предрелизные артефакты в раскладку каталогов проект/сессия перед загрузкой.
- **Сжатые файлы не читаются построчно напрямую** — загружайте их через бэкенд или выберите `compression: 'none'` перед записью свежего корня, когда требуются внешние построчные читатели.
- **Ничто не удаляет файлы сессий** — журналы накапливаются под `root`, пока их не удалит кто-то извне (у seam нет API удаления).
- **Один живой писатель на сессию** — добавление и починка координируются только внутри владеющего экземпляра бэкенда. Другой экземпляр бэкенда или процесс не должен записывать ту же сессию, пока владелец не достигнет quiescence при освобождении ресурсов; первичная публикация того же id остаётся безопасной при коллизиях благодаря жёсткой ссылке POSIX без перезаписи или write-through-переименованию Windows без замены.
- **Материализация POSIX требует поддержки жёстких ссылок** — первый `append` использует `link()`, поэтому гонки одного id терпят неудачу вместо перезаписи зафиксированного журнала; Windows использует write-through-переименование без замены.
