# @deepseek-ai/dsh-session-projection-cache

[English](README.md) | [中文](README.zh.md) | Русский

Персистентный кэш проекций (`ctx.sessionProjectionCache`): долговечные чекпоинты состояния каждой единицы проекции, одна запись на сессию в форме данных домена (домен `session_projcache` — поставляемый json-бэкенд кладёт её рядом с `workspace.json` под настроенным корнем хранилища). Проектные полномочия: [RFC session-projection](../../../.agents/notes/proposed/architecture/2026-07-27-session-projection-and-command-log.md) (раздел о персистентном кэше проекций).

Сохранённая строка `(key → {ver, seq, val})` — лишь ярлык свёртки, но никогда не полномочие: возможно устаревшая (`seq` говорит точно, насколько), но никогда не неверная. Обязательства, которые берёт на себя реализация:

- **Каждая фоновая запись — fail-soft.** Неудавшаяся долговечная запись пишет предупреждение в журнал и оставляет кэш устаревшим; следующая запись или холодное чтение самолечатся. Сбой между записями стоит более длинного воспроизведения хвоста, но никогда неверного значения.
- **Несовпадение `ver` со `stateVersion` живой единицы отбрасывает, а не мигрирует.** Подъём версии единицы инвалидирует её строки во время чтения; ключ пересворачивается из журнала.
- **Проверка строк схемой.** Каждая строка **ДОЛЖНА** проходить `stateSchema` живой единицы. Некорректная строка исключается из zero-I/O view и отвергается восстановлением, чтобы лестница холодного чтения пересворачивала её из журнала.
- **Записи целиком.** Каждая запись заменяет полный чекпоинт сессии (срез реестра всегда полон), снимаемый через границу lossless-JSON, — состояние единицы, нарушающее контракт простого JSON, падает громко.
- **Записи привязаны к жизненному циклу журнала, а не только к id.** Каждая запись хранит идентичность заголовка (`createdAt`, `cwd`), из которого была свёрнута; каждое чтение проверяет её (свидетель — живой или сохранённый заголовок), прежде чем принять строку, поэтому удалённый-и-заново-созданный id или подменённое хранилище персистентности при выжившем кэше отбросят постороннюю запись вместо посева фантомных значений.
- **Журнал ведёт, кэш следует.** Живой чекпоинт долговечно сбрасывает буферизованные события сессии ДО того, как ляжет строка кэша, поэтому сбой может оставить кэш позади журнала (более длинное воспроизведение хвоста), но никогда впереди него.

## Политика записи

Две обязательные точки, между ними — троттлинг:

| Триггер | Характер |
|---|---|
| `turn/end` | Обязательная — финальное значение хода и есть то, чего хотят холодные чтения. |
| Освобождение сессии (detach) | Обязательная — момент перехода от живого к холодному; после него эту сессию обслуживает холодная лестница. |
| `writeEveryEvents` зафиксированных событий | Троттлинг конфигурации (счётчик). |
| `writeIntervalMs` с первого грязного события | Троттлинг конфигурации (интервал). |

Оба поля `Config` обязательны (без дефолтов): частота сброса — выбор развёртывания без универсально правильного значения, фиксируемый в cordis.yml.

## Чтение списка (`cachedSnapshot(meta)`)

Ступень нулевого ввода-вывода: клиентские значения читаются прямо из совпадающей по идентичности сохранённой записи (только ключи с совпадающими версией и state-схемой) и возвращаются как срез `{asOfSeq, values}` — `asOfSeq` служит нижней водяной отметкой обслуженных строк, поэтому клиент, засевающий своё хранилище значений на сессию по правилу higher-seq-wins, никогда не позволит блоку устаревшего списка перезаписать более новый push-кадр. Host-only строки не возвращаются никогда. Возвращается `undefined`, когда пригодной клиентской строки нет (неизвестный id, посторонний жизненный цикл или нет пригодных строк); носитель списка api-proxy превращает это в отсутствующий столбец.

## Холодное чтение (`coldSnapshot(id, signal?)`)

Лестница чтения, на счастливом пути — ноль полных загрузок журнала: кэшированные строки → `sessionProjections.restoreFloor` (якорь на одно событие ниже самой низкой пригодной водяной отметки) → `readFrom(id, floor)` персистентности → `sessionProjections.restore` → fail-soft обратная запись обновлённых строк. Якорь делает доказуемым сократившийся журнал (усечение при починке после сбоя): строка, забравшаяся слишком далеко, запускает ровно одно полное перечтение с seq 0 вместо обслуживания призрачного значения. Если зарегистрированных единиц нет, возвращается `{asOfSeq: -1, values: {}}` без касания персистентности; сессия без сохранённого журнала отвергается с `not found` на стороне seam.

`write(session)` — чекпоинт синхронного среза, который используют обе обязательные точки; носители могут вызывать его напрямую (не fail-soft — сдерживание принадлежит обёрткам fail-soft).

## Композиция

```yaml
- id: session-projection-cache
  name: '@deepseek-ai/dsh-session-projection-cache'
  config:
    writeEveryEvents: 200
    writeIntervalMs: 5000
```

Внедряет `storageDomain`, `sessionProjections`, `sessionPersistence`, `sessions`. Без этой строки система проекций работает только вживую (кэш водяных отметок; холодные чтения откатываются к полным загрузкам журнала там, где носитель их реализует).

## Влияние на модель

Нет: кэш лишь персистирует и восстанавливает read-модели на стороне хоста для уже записанного состояния сессии и не касается ни промпта, ни сообщения, ни схемы, ни потока, ни результата инструмента.

#### Влияние на KV-кэш

Нет; кэш никогда не собирает и не отправляет запросы провайдерам.

## Известные ограничения и отложенная работа

- **Нет поверхности вытеснения или удержания** — записи накапливаются по сессиям; подрезка сохранённых чекпоинтов — внесистемное обслуживание, та же позиция, что и у самой персистентности сессий.
- **Интервальный троттлинг груб в рамках сессии** — таймер взводится первым грязным событием после чистой записи; равномерный подпороговый ручеёк пишет один раз за интервал, а не скользящим окном.
- **Чтения `coldSnapshot` не дедуплицируются** — два параллельных холодных чтения одной сессии проходят лестницу каждое; побеждает последняя обратная запись (строки эквивалентны), что приемлемо для частоты вызовов масштаба составления списков.
