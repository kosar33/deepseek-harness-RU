# @deepseek-ai/dsh-session-projection

[English](README.md) | [中文](README.zh.md) | Русский

Service Definition проекций сессии и реестр прогонов. Он владеет `ctx.sessionProjections` — реестром, который ведёт каждую зарегистрированную единицу проекции по зафиксированным событиям сессии и отдаёт готовые целые значения носителям, сейчас это страница хвоста истории api-proxy и push-кадр `session/projection`. Домен регистрирует чистую математику; фреймворк владеет прогоном. Проектное обоснование записано в [RFC session-projection](../../../.agents/notes/proposed/architecture/2026-07-27-session-projection-and-command-log.md).

## Сервис: `SessionProjectionRegistry` (ключ ctx: `sessionProjections`)

### Публичный API

- `ctx.sessionProjections.register(definition): () => void` Регистрирует единицу одного домена. Дубликаты ключей и неверный `stateVersion` бросают исключение; регистрация — эффект на вызывающей fiber, поэтому ключ незагруженного плагина домена (вместе с его кэшированными ячейками) исчезает из последующих прогонов и снапшотов — клиенты читают это как отсутствие возможности.
- `ctx.sessionProjections.onChanged(listener): () => void` Подписка на ленту изменений: по одному вызову на каждую видимую клиенту единицу за каждое зафиксированное событие, изменившее ссылку её состояния; вызов несёт проверенное схемой view и вызвавший его seq. Привязана к эффектам, как `register`.
- `ctx.sessionProjections.stateOf(session, key)` Читает текущее host-состояние одной зарегистрированной единицы, не вычисляя посторонних view. Возвращённое значение — живая ссылка только для чтения; вызывающие НЕ ДОЛЖНЫ её мутировать.
- `ctx.sessionProjections.snapshot(session): ProjectionSnapshot` Один согласованный синхронный срез по всем зарегистрированным видимым клиенту единицам — `{ asOfSeq, values }`, где `asOfSeq` = seq последнего события, которое отражает каждое значение (`-1` для пустого журнала). Host-only состояние доступно только через `stateOf`.

### Ключевые типы

- `SessionProjectionMap` — расширяемая слиянием таблица клиентских view, разделяемая wire-блоками и клиентскими хуками. Значения — целые wire-JSON значения; отрисовка принадлежит системе slot'ов, но никогда этому слою.
- `SessionProjectionStateMap` — расширяемая слиянием таблица host-состояний свёртки. Каждый видимый клиенту ключ присутствует в обеих таблицах; host-only ключи — только здесь.
- `ProjectionDefinition<K, S>` — `{ key, stateSchema, init(), apply(state, event), wire?, stateVersion }`: синхронная вычислительная единица, управляемая состоянием. `wire` поставляет `viewSchema` и `view`; его отсутствие делает единицу host-only.

## Контракт

- **Фреймворк ведёт, домен вычисляет.** Реестр подписывается на `session/event` один раз; каждое зафиксированное событие жадно проходит через `apply` каждой единицы. Домены не держат подписок. Ячейки (`{state, observedSeq}` на единицу на сессию, ключуемые WeakMap) строятся лениво — единица, зарегистрированная после того, как события уже прошли, или чтение сессии, предшествующей регистрации, сворачивает `init` по журналу в памяти при первом касании.
- **Та же ссылка означает отсутствие работы.** `apply` ДОЛЖЕН возвращать ту же ссылку состояния для событий, не касающихся единицы; прогон гейтит ленту изменений через `Object.is`, поэтому несовпадающее событие стоит одного вызова и ничего дальше по цепочке.
- **Правило целого значения события (на нём всё держится).** Событие журнала, несущее состояние, ДОЛЖНО содержать полное состояние после изменения, а не голую дельту — это делает каждый переход тривиально дешёвым, а каждое отдаваемое значение самодескриптивным (для потребителей — last-wins).
- **Синхронная дисциплина единиц.** `init`/`apply`/`wire.view` ДОЛЖНЫ быть синхронными; носители читают `snapshot()` в том же тике, что и свой срез страницы, — именно это делает `asOfSeq` одним согласованным срезом. Случайно асинхронный view вернёт Promise, который провалит `wire.viewSchema.parse`.
- **Состояние — проверенный простой JSON, `stateVersion` — его якорь инвалидации.** Персистентный кэш проекций хранит строки `(sessionId, key, ver, seq, val)` и проверяет `val` через `stateSchema` перед использованием; повышайте `stateVersion` всякий раз, когда меняются поля состояния или семантика свёртки. Состояние каждой единицы попадает в чекпоинты — как видимое клиенту, так и host-only.
- **Никакого wire-словаря здесь.** Реестр предоставляет наружу только ленту изменений и интерфейс чтения снапшота; носители (api-proxy) формируют из них собственные кадры (`session/projection`) и блоки.
- **Опциональная возможность.** Плагины доменов регистрируются под `ctx.inject(['sessionProjections'], …)`, чтобы headless-сборки без реестра не затрагивались; носители используют `ctx.get('sessionProjections')` и целиком опускают свои блоки/кадры, когда реестра нет.

## Роль

Этот пакет владеет ролями Service Definition и прогона в capability seam: плагины host-доменов (например `dsh-tool-todo`) вносят единицы, носители (`dsh-host-apiproxy`) используют снапшот и ленту изменений, и ни одна из сторон не знает о другой.

## Влияние на модель

Отсутствует: реестр лишь вычисляет обращённые к клиенту read-модели уже записанных в журнал состояний сессии и не касается ни промпта, ни сообщения, ни схемы, ни потока, ни результата инструмента.

#### Влияние на KV-кэш

Нулевое; проекции никогда не собирают и не отправляют запросы провайдеру.

## Известные ограничения и отложенная работа

- **Каждая страница хвоста несёт каждый видимый клиенту ключ** — пока нет ни opt-out по ключу, ни формы запроса с ленивыми ключами; приемлемо, пока значения — целые состояния масштаба UI (список todo, снапшот цели); стоит вернуться к этому вопросу, если значение какого-то домена сильно вырастет.
- **Таблица единиц общая для всего процесса, поэтому наличие ключа — не сигнал о возможностях конкретной сессии** — ключ, зарегистрированный ЛЮБЫМ агентским пресетом, появляется в снапшоте каждой сессии, включая те, чья собственная композиция не монтирует ничего, что его производит. Клиент ДОЛЖЕН читать ЗНАЧЕНИЕ (`plan.active`, пустой список todo), а не считать отсутствующий ключ отсутствием функции; единица, чьё пустое значение неотличимо от реального, должна вместо этого находиться на host-плоскости — именно поэтому `dsh-token-meter` размещён там.
- **Жадный прогон обрабатывает каждую единицу при каждом событии** — дёшево по построению (правило целого значения, гейт той же ссылки), но горячий путь оправдал бы префильтры по типу события на единицу, добавимые без изменения контракта.
- **Ячейки реестра живут только в памяти** — перезапуск перестраивает их свёрткой журнала при первом касании; композиции, монтирующие `dsh-session-projection-cache`, вместо этого иницируют эту свёртку из персистентных строк.
- **Синхронная дисциплина единиц лишь частично обеспечена механикой** — `wire.viewSchema.parse` отвергает возвращающий Promise view, но `apply`, который блокирует выполнение или читает частично изменённое (torn) не-сессионное состояние, остаётся заботой ревью; сопровождающий инвариант документирует, почему проверки во время выполнения нет.
