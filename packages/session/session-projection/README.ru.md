# @deepseek-ai/dsh-session-projection

[English](README.md) | [中文](README.zh.md) | Русский

Service Definition проекций сессии и реестр драйва. Он владеет `ctx.sessionProjections` — реестром, который ведёт каждую зарегистрированную единицу проекции по зафиксированным событиям сессии и отдаёт готовые целые значения носителям, сейчас это страница хвоста истории api-proxy и push-кадр `session/projection`. Домен регистрирует чистую математику; фреймворк владеет прогоном. Замысел дизайна записан в [RFC session-projection](../../../.agents/notes/proposed/architecture/2026-07-27-session-projection-and-command-log.md).

## Сервис: `SessionProjectionRegistry` (ключ ctx: `sessionProjections`)

### Публичный API

- `ctx.sessionProjections.register(definition): () => void` Регистрирует единицу одного домена. Дубликаты ключей и неверный `stateVersion` бросают исключение; регистрация — эффект на вызывающей fiber, поэтому ключ незагруженного плагина домена (вместе с его кэшированными ячейками) исчезает из последующих прогонов и снапшотов — клиенты читают это как отсутствие возможности.
- `ctx.sessionProjections.onChanged(listener): () => void` Подписка на ленту изменений: один вызов на каждую видимую клиенту единицу, чья ссылка состояния изменилась, за каждое зафиксированное событие, несущая проверенное схемой view и вызвавший его seq. Привязано к эффектам, как `register`.
- `ctx.sessionProjections.stateOf(session, key)` Читает текущее host-состояние одной зарегистрированной единицы, не вычисляя посторонних view. Возвращённое значение — живая ссылка только для чтения; вызывающие **НЕ ДОЛЖНЫ** её мутировать.
- `ctx.sessionProjections.snapshot(session): ProjectionSnapshot` Один согласованный синхронный срез по всем зарегистрированным видимым клиенту единицам — `{ asOfSeq, values }`, где `asOfSeq` = seq последнего события, которое отражает каждое значение (`-1` для пустого журнала). Host-only состояние доступно только через `stateOf`.

### Ключевые типы

- `SessionProjectionMap` — расширяемая слиянием таблица клиентских view, разделяемая wire-блоками и клиентскими хуками. Значения — целые wire-JSON значения; отрисовка принадлежит системе slot'ов, но никогда этому слою.
- `SessionProjectionStateMap` — расширяемая слиянием таблица host-состояний свёртки. Каждый видимый клиенту ключ присутствует в обеих таблицах; host-only ключи — только здесь.
- `ProjectionDefinition<K, S>` — `{ key, stateSchema, init(), apply(state, event), wire?, stateVersion }`: синхронная вычислительная единица, управляемая состоянием. `wire` поставляет `viewSchema` и `view`; его отсутствие делает единицу host-only.

## Контракт

- **Фреймворк ведёт, домен вычисляет.** Реестр подписывается на `session/event` один раз; каждое зафиксированное событие жадно проходит через `apply` каждой единицы. Домены не держат подписок. Ячейки (`{state, observedSeq}` на единицу на сессию, ключуемые WeakMap) строятся лениво — единица, зарегистрированная после того, как события уже текли, или чтение сессии, предшествующей регистрации, сворачивает `init` по журналу в памяти при первом касании.
- **Та же ссылка — никакой работы.** `apply` **ДОЛЖЕН** возвращать ту же ссылку состояния для событий, не касающихся единицы; драйв гейтит ленту изменений через `Object.is`, поэтому несовпадающее событие стоит один вызов и ничего ниже по течению.
- **Правило целого значения события (несущее нагрузку).** Событие журнала, несущее состояние, **ДОЛЖНО** нести полное пост-изменённое состояние и никогда голую дельту — это делает каждый переход тривиально дешёвым, а каждое отданное значение самодескриптивным (последний побеждает для потребителей).
- **Синхронная дисциплина единиц.** `init`/`apply`/`wire.view` **ДОЛЖНЫ** быть синхронными; носители читают `snapshot()` в том же тике, что и свой срез страницы, — именно это делает `asOfSeq` одним согласованным срезом. Случайно асинхронный view вернёт Promise, который провалит `wire.viewSchema.parse`.
- **Состояние — проверенный простой JSON, `stateVersion` — его якорь инвалидации.** Персистентный кэш проекций хранит строки `(sessionId, key, ver, seq, val)` и проверяет `val` через `stateSchema` перед использованием; повышайте `stateVersion` всякий раз, когда меняются поля состояния или семантика свёртки. Состояние каждой единицы чекпоинтируется — как видимое клиенту, так и host-only.
- **Никакого wire-словаря здесь.** Реестр выставляет наружу только ленту изменений и грань чтения снапшота; носители (api-proxy) чеканят из них собственные кадры (`session/projection`) и блоки.
- **Опциональная возможность.** Плагины доменов регистрируются под `ctx.inject(['sessionProjections'], …)`, чтобы headless-сборки без реестра оставались незатронутыми; носители используют `ctx.get('sessionProjections')` и целиком опускают свои блоки/кадры, когда реестра нет.

## Роль

Этот пакет владеет ролями Service Definition и драйва capability seam: плагины host-доменов (например `dsh-tool-todo`) вносят единицы, носители (`dsh-host-apiproxy`) потребляют снапшот и ленту изменений, и ни одна сторона не знает другую.

## Влияние на модель

Отсутствует: реестр лишь вычисляет обращённые к клиенту read-модели уже записанных в журнал состояний сессии и не касается ни промпта, ни сообщения, ни схемы, ни потока, ни результата инструмента.

#### Влияние на KV-кэш

Нулевое; проекции никогда не собирают и не отправляют запросы провайдеру.

## Известные ограничения и отложенная работа

- **Каждая страница хвоста несёт каждый видимый клиенту ключ** — пока нет ни opt-out по ключу, ни формы запроса ленивых ключей; приемлемо, пока значения — целые состояния масштаба UI (список todo, снапшот цели); вернитесь к этому вопросу, если значение какого-то домена вырастет.
- **Таблица единиц общая на процесс, поэтому наличие ключа — не сигнал о возможностях конкретной сессии** — ключ, зарегистрированный ЛЮБЫМ агентским пресетом, появляется в снапшоте каждой сессии, включая те, чья собственная композиция не монтирует ничего его производящего. Клиент **ДОЛЖЕН** читать ЗНАЧЕНИЕ (`plan.active`, пустой список todo), а не считать отсутствующий ключ отсутствием функции; единица, чьё пустое значение неотличимо от реального, должна вместо этого жить на host-плоскости — именно поэтому `dsh-token-meter` сидит там.
- **Жадный драйв касается каждой единицы на каждом событии** — дёшево по построению (правило целого значения, гейт той же ссылки), но горячий путь оправдал бы префильтры по типу события на единицу, добавимые без изменения контракта.
- **Ячейки реестра живут только в памяти** — перезапуск перестраивает их свёрткой журнала при первом касании; композиции, монтирующие `dsh-session-projection-cache`, засевают эту свёртку персистентными строками вместо этого.
- **Синхронная дисциплина единиц обеспечена механикой лишь частично** — `wire.viewSchema.parse` отвергает возвращающий Promise view, но `apply`, который блокирует или читает разорванное не-сессионное состояние, остаётся заботой ревью; компаньон-инвариант документирует, почему проверки во время выполнения нет.
