# @deepseek-ai/dsh-session-title-first-prompt-llm

[English](README.md) | [中文](README.zh.md) | Русский

Опциональный провайдер `ctx.sessionTitle`, который суммирует первое подходящее сообщение человека через `ctx.llm`. Он регистрирует периодичность `first-prompt` и запускается автоматически только когда свежая не-fork сессия впервые создаёт свой фолбэк, а результат относит к точному seq этого сообщения. Автоматический отказ сохраняет фолбэк и повторяется только через `ctx.sessionTitle.refresh()`.

Плагин использует полную обязательную [общую конфигурацию LLM](../session-title-llm/README.ru.md#конфигурация). Опустите и `provider`, и `model`, чтобы унаследовать точный маршрут из текущего записанного в журнале основного запроса, или задайте оба, чтобы маршрутизировать генерацию заголовков независимо.

## Влияние на модель

### Запрос заголовка по первому сообщению

#### Что видит модель

Модель заголовков получает общую инструкцию заголовка и JSON-массив, содержащий только первое подходящее сообщение человека. Поздние промпты и унаследованная fork-история не запускают ещё один автоматический вызов.

#### Влияние на токены

Для свежей сессии выполняется не более одного автоматического вспомогательного запроса с потолками `maxInputBytes` и `maxOutputTokens`; явные обновления могут делать дополнительные вызовы. Основной запрос агента не получает ни одного токена.

#### Влияние на KV-кэш

Инвалидации основного запроса нет. Вспомогательный запрос использует настроенный или записанный в журнале маршрут и имеет зависящее от провайдера поведение кэша.

## Известные ограничения и отложенная работа

- Одного первого сообщения может перестать хватать для представления долгоживущей сессии; используйте провайдера all-messages, когда поздние промпты должны задать ей новый заголовок.
- Fork сохраняет унаследованный заголовок и никогда не запускает этого провайдера автоматически, даже когда его засеянное первое сообщение пришло из родителя.
