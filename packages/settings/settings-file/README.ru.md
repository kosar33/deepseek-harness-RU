# @deepseek-ai/dsh-settings-file

[English](README.md) | [中文](README.zh.md) | Русский

Провайдер настроек на файловой основе. Один документ YAML или JSON несёт все секции пространств имён; внешние правки горячо публикуются через `ctx.settings`, а `update()` перечитывает документ под блокировкой писателя, прежде чем атомарно записать обратно, сохраняя комментарии пользователя в YAML, любую секцию, принадлежащую сейчас не загруженному плагину, и любое изменение на диске, которое этот процесс ещё не наблюдал.

## Конфигурация

| Поле | Значение | По умолчанию |
|---|---|---|
| `path` | Путь к документу настроек; расширение выбирает формат (`.yaml`/`.yml`/`.json`) | `settings.yaml` в домашнем каталоге harness |
| `dshHome` | Домашний каталог harness, используемый, когда `path` опущен | `$DSH_HOME` или `~/.dsh` |
| `watch` | Наблюдать за документом и горячо публиковать внешние правки | `true` |
| `debounceMs` | Окно устаканивания записи наблюдателя в миллисекундах | `100` |

Назначение дефолтов — один явный шаг `resolveSpec(config)`; неподдерживаемое расширение вызывает отказ при загрузке.

## Поведение

- **Загрузка падает громко, перезагрузка хранит последнюю рабочую версию.** Существующий, но недопустимый документ роняет загрузку плагина; когда провайдер уже жив, нечитаемая или непарсируемая правка даёт предупреждение и сохраняет последние хорошие секции. Отсутствующий документ разрешает каждое пространство имён из дефолтов и `base`; его удаление публикует то же пустое состояние.
- **Каждая запись — это read-modify-write.** Сохранение сперва перечитывает документ и публикует любую обнаруженную разницу в seam — внешнюю правку, ещё остающуюся внутри окна debounce наблюдателя, изменение, которое наблюдатель пропустил, или запись другого процесса, — затем рендерит по этому свежему тексту, поэтому запись никогда не воскресит устаревший документ и не уронит незамеченную соседнюю секцию. Если документ на диске стал недопустимым, запись громко отвергается вместо перезаписи ручной правки пользователя.
- **Записи держат межпроцессную блокировку писателя.** Цикл чтение-рендер-переименование идёт под созданным через `wx` соседним файлом `<file>.lock` с экспоненциальной задержкой и предельным сроком захвата 2 с. Претендент выходит по таймауту, не удаляя существующую блокировку, потому что возраст файла не отличит упавшего владельца от приостановленного живого писателя; восстановление осиротевшей блокировки — действие оператора. Читатели блокировку никогда не берут: коммит переименованием атомарен, поэтому перезагрузки всегда согласованы.
- **Обратная запись атомарна, доступна только владельцу и защищена от symlink.** Рендер эксклюзивно создаёт временный соседний файл со случайным суффиксом и режимом `0600` (`wx` отказывается следовать подложенному symlink) и переименовывает его поверх цели, подчищая временный файл при отказе.
- **Правки YAML — это диффы уровня листьев.** Запись выставляет только изменившиеся значения и удаляет только убранные ключи, поэтому комментарии, якоря и форматирование переживают каждый нетронутый узел и ключ каждой изменённой пары; изменённый массив (или другое не-словарное значение) заменяется целиком, забирая комментарии внутри себя. JSON пересериализуется без комментариев.
- **Перезагрузки и записи делят одну цепочку операций.** Обновления наблюдателя и сохранения из очереди каждого пространства имён выполняются по одному в порядке очереди; каждый рендер видит текст, зафиксированный предыдущей операцией.
- **Сигнал готовности наблюдателя сверяет состояние один раз.** Начальная загрузка соревнуется с собственным запуском наблюдателя, поэтому записанное между ними изменение никогда не породит событие; сверка в момент готовности закрывает этот стартовый разрыв.
- **Нативный наблюдатель получает канонический путь.** Прежде чем Chokidar откроет цель, провайдер realpath'ом разворачивает её глубочайшего существующего предка и восстанавливает недостающий суффикс. Доступ к файлам и диагностика для пользователя сохраняют настроенный путь, поскольку Windows не может смешать 8.3-алиас с путями событий в длинной форме внутри libuv.
- **Освобождение ресурсов доводит до quiescence все режимы наблюдения.** Разборка помечает провайдера закрытым, закрывает наблюдателя, если он есть, затем выжидает каждую стоящую в очереди или выполняющуюся операцию над документом, так что после освобождения ничего не публикуется.
- **Подавление собственной записи по содержимому.** Провайдер кэширует последний хороший текст; событие наблюдателя, чьё содержимое равно кэшу (включая его собственную запись), является no-op.
- **Конфигурационные адаптеры хоста получают разрешённый путь.** `ctx.settings.documentPath` — абсолютное имя файла из `resolveSpec()`, включая пользовательский путь YAML/JSON; `prepareDocument()` сохраняет существующий файл или эксклюзивно создаёт отсутствующий пустой файл с правами только для владельца, прежде чем Host откроет его. Браузер получает только флаг доступности, никогда не восстанавливает `$DSH_HOME` и никогда не передаёт цель в файловой системе.

## Влияние на модель

Косвенно, через потребителей `ctx.settings`: этот провайдер лишь хранит и публикует секции пространств имён, а любое влияние на модель документирует собственная поверхность потребителя.

#### Влияние на KV-кэш

Прямой инвалидации нет; любые изменения префикса запроса — забота потребляющего плагина.

## Известные ограничения и отложенная работа

- **Конфликты одного пространства имён остаются last-write-wins** — блокировка писателя и read-modify-write мешают параллельным писателям уронить пространства имён друг друга, но два писателя, редактирующие одно пространство имён, всё равно сходятся к более поздней записи; слияния по значению и проверки ревизий нет.
- **Пропущенное событие наблюдателя остаётся невидимым до следующего сигнала** — чтения никогда не переставляют stat файла, поэтому изменение, которое наблюдателю не удалось сообщить, попадает в картину только со следующим событием, следующей записью или перезапуском.
- **Сохранение комментариев работает только в YAML и только для словарей** — документы JSON пересериализуются без комментариев (в JSON их нет), а комментарии внутри изменённого массива (или прикреплённые в строку к изменённому скалярному значению) уходят вместе с описанным ими значением.
- **Нет косвенности значений** — секции держат литеральные значения; ссылки в стиле `${env:VAR}` для секретов — отложенная возможность уровня seam.
