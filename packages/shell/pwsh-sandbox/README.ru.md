# @deepseek-ai/dsh-pwsh-sandbox

[English](README.md) | [中文](README.zh.md) | Русский

Использующая песочницу PowerShell-реализация seam'а исполнителя [`ctx.shell`](../shell/): каждая команда запускается как `pwsh -NoLogo -NoProfile -NonInteractive -Command <command>` **в изоляции через `ctx.sandbox`**, причём выбранный режим, применение политики и факты об отказах проставляются на каждом завершившемся результате. Парный pwsh-исполнитель к [`@deepseek-ai/dsh-bash-sandbox`](../bash-sandbox/), зеркало вызов-за-вызовом согласно [решению о pwsh-инструменте и исполнителе](../../../.agents/notes/implemented/feature/2026-08-01-pwsh-tool-and-executor.md) — сама изоляция платформо-нейтральна: на Windows seam песочницы разрешается в цепочку раннеров ограниченного токена ACL ([`@deepseek-ai/dsh-sandbox-windows-acl`](../../sandbox/sandbox-windows-acl/)), на Linux/macOS — в bwrap/Landlock/Seatbelt.

Исполнитель наследует процессную механику [`@deepseek-ai/dsh-pwsh-local`](../pwsh-local/) и использует её seam уровня argv (`argv()` / `runArgv()` / `startArgv()` / `onProcessDone()`), чтобы завернуть точный вызов pwsh через провайдера. Политика песочницы (режим + корень рабочего пространства) — НЕ конфигурация этого пакета: она поступает с каждым вызовом из `ctx.sandboxPolicy` (вызовы инструментов передают итоговую политику вызывающей сессии; прямые вызовы откатываются к политике развёртывания).

## Поведение

- `danger-full-access`: команды проходят через локальный исполнитель без изменений; результаты несут `sandbox: { mode, denied: false }`.
- Изолированные режимы (`read-only`, `workspace-write`): argv pwsh оборачивается вызовом `ctx.sandbox.confine()`; отказ запуска раннера приводит к отказу fail-closed с `SANDBOX_UNAVAILABLE` (throw на переднем плане, факт `runnerFailed` на фоне), а отклонённая операция записи классифицируется по `denialSignatures` выбранного бэкенда в `sandbox.denied`.

## Влияние на модель

### Изоляция работает, отказ проявляется как сбой команды

#### Что видит модель

Собственный stderr изолированной команды (например, `Access to the path '...' is denied.` под раннером ACL Windows); слой инструментов преобразует классифицированные отказы в стандартную поверхность «отказано в доступе» ровно так же, как он делает это для bash-инструмента.

#### Влияние на токены

Никакого видимого модели текста сверх stderr самой команды и стандартной поверхности отказа слоя инструментов.

#### Влияние на KV-кэш

Напрямую никакого; поверхность отказа принадлежит слою инструментов.

## Известные ограничения и отложенная работа

- **Чтения не ограничены** на Windows (раннер ACL ограничивает только записи); граница чтения задокументирована в `@deepseek-ai/dsh-sandbox-windows-acl`.
- **Временные полномочия Windows в workspace-write приватны** для каждой активной пары сессия/рабочее пространство; вызовы без агента получают свежий приватный каталог на каждый вызов. Корень temp окружения никогда не выдаётся, а раннер переписывает TMP/TEMP на приватный каталог перед запуском процесса.
- **read-only на Windows не выдаёт явного записываемого корня, но остаётся частичным**, потому что ограниченный токен обязан сохранить Everyone. Объекты, чей DACL даёт Everyone доступ на запись — включая совместимые открытия устройства NUL — остаются обычными полномочиями окружения; перенаправление `> $null` в PowerShell продолжает работать без открытия NUL.
