# @deepseek-ai/dsh-shell-env

[English](README.md) | [中文](README.zh.md) | Русский

Независимый от инструментов плагин оболочечного окружения: владеет реестром `ctx.shellEnv` доверенных переменных `DSH_*`, собираемых на каждое выполнение, которые видимые модели инструменты оболочки (`dsh-tool-bash`, `dsh-tool-pwsh`) вливают в окружение каждого вызова оболочки. Встроенные факты оболочки (`DSH_HOME`, `DSH_SHELL=1`, `DSH_SESSION_ID`) принадлежат самому реестру; другие плагины регистрируют дополнительные перечислимые факты с освобождением ресурсов в рамках эффекта, а дублирующее владение или необъявленные ключи рантайма обнаруживаются громким сбоем.

Корень пакета экспортирует контракт плагина Cordis (`name`, `inject`, `Config`, `apply`) плюс класс сервиса `ShellEnvRegistry` и типы его контрибьюторов; потребители используют `ctx.shellEnv` после загрузки этого плагина.

## Конфигурация

```yaml
- id: shell-env
  name: '@deepseek-ai/dsh-shell-env'
  config:
    dshHome: C:\Users\me\.dsh   # default: $DSH_HOME, then ~/.dsh
```

## Управляемое окружение

Каждый вызов модельной оболочки — на переднем плане или фоновый — получает заново собранное доверенное окружение `DSH_*`. `DSH_HOME` — это абсолютный домашний путь Harness, который разрешает [`@deepseek-ai/dsh-home-paths`](../../util/home-paths/README.md) (конфигурация `dshHome`, затем внешняя переменная `$DSH_HOME`, затем `~/.dsh`), а `DSH_SHELL=1` опознаёт управляемого потомка. Вызовы агента дополнительно получают `DSH_SESSION_ID=agent.session.header.id`; когда активный seam персистентности находит JSONL-артефакт, они также получают `DSH_SESSION_JSONL=<абсолютный целевой путь>`. Путь JSONL — лишь подсказка о расположении: он может не существовать до первого flush или не содержать текущий буферизованный ход, и он не является учётным полномочием.

Сбором владеет `ctx.shellEnv`. Другие плагины могут регистрировать контрибьютора с областью действия эффекта: со стабильным именем, объявленными ключами и описаниями и функцией `resolve(execution: ToolExecution)`; дублирующее владение и необъявленные ключи рантайма обнаруживаются громким сбоем, тогда как `list()` перечисляет объявления, не исполняя провайдеров. Встроенные факты Harness резервируют `DSH_HOME`, `DSH_SHELL` и `DSH_SESSION_ID`; транслятор персистентности этого плагина владеет `DSH_SESSION_JSONL`, читая независимый от бэкенда seam `sessionPersistence.locate()`.

```ts
import type { Context } from '@deepseek-ai/cordis'
import type {} from '@deepseek-ai/dsh-shell-env'

export const inject = ['shellEnv']

export function apply(ctx: Context): void {
  ctx.shellEnv.register({
    name: 'deployment-region',
    variables: { DSH_DEPLOYMENT_REGION: { description: 'Current deployment region.' } },
    resolve: execution => execution.agent === undefined ? {} : { DSH_DEPLOYMENT_REGION: 'cn-north' },
  })
}
```

Оверлей вычисляется из текущего `ToolExecution` и передаётся через выделенный канал `ShellExecRequest.dshEnv`. Локальные исполнители удаляют все унаследованные `DSH_*` перед слиянием этого снимка, поэтому вложенные harness'ы и параллельные родительские и дочерние агенты не могут протечь устаревшими идентичностями. `process.env` никогда не изменяется. Описания инструментов оболочки обучают общему соглашению `$DSH_*`, а не называют специфичные для персистентности переменные и не добавляют постоянную секцию системного промпта.

## Влияние на модель

Косвенно, через инструменты оболочки (`dsh-tool-bash`, `dsh-tool-pwsh`), которые вливают управляемый снимок `DSH_*` этого реестра в каждый вызов инструмента оболочки.

#### Влияние на KV-кэш

Прямой инвалидации нет; изменения префикса запроса — забота названных потребителей.

## Известные ограничения и отложенная работа

- **`list()` перечисляет только переменные, объявленные контрибьюторами** — встроенные переменные самого реестра (`DSH_HOME`, `DSH_SHELL`, `DSH_SESSION_ID`) в него не входят, поэтому коду диагностики, промптов или UI **НЕ СЛЕДУЕТ** трактовать `list()` как исчерпывающий каталог окружения.
