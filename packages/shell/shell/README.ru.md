# @deepseek-ai/dsh-shell

[English](README.md) | [中文](README.zh.md) | Русский

**`ShellExecutor`** (`ctx.shell`) определяет, ЧТО делает баш-бэкенд, — выполнять команды на переднем плане и запускать фоновые процессы, — не говоря КАК. Идентификаторы заданий, владение, сбор, отмена и уведомления принадлежат универсальному рантайму `ctx.jobs`.

Этот пакет владеет ролью Service Definition возможности bash, разделённой так, чтобы каждая роль могла развиваться (и заменяться) независимо:

| Пакет | Роль |
|---|---|
| `@deepseek-ai/dsh-shell` (этот пакет) | Service Definition: абстрактный сервис + типы словаря |
| `@deepseek-ai/dsh-bash-local` | Service Provider: локальные подпроцессы |
| `@deepseek-ai/dsh-bash-sandbox` | Service Provider: механика `dsh-bash-local` с ограничением каждого запуска через [`ctx.sandbox`](../../sandbox/sandbox/); отказы докладываются как факты результата |
| `@deepseek-ai/dsh-tool-bash` | обращённые к модели схемы инструментов поверх `ctx.shell` |

Это разделение — стандартный capability seam ([Agent Note о capability seams](../../../.agents/notes/implemented/architecture/2026-06-13-capability-seams.md)): `dsh-bash-sandbox` — изолирующий исполнитель за тем же Service Definition, Consumer распознаёт его возможность `sandboxMode` и добавляет поля эскалации, не импортируя провайдера, а контейнеризованный или удалённый исполнитель встаёт туда же таким же образом.

## API сервиса (`ctx.shell`)

| Член | Семантика |
|---|---|
| `run(spec)` | Исполнение на переднем плане. Разрешается, когда команда завершилась. **Отклоняется только при сбоях инфраструктуры** (непригодный workdir, отсутствующая оболочка, заранее прерванный сигнал); ненулевые коды выхода, убийства по таймауту и по отмене разрешаются описательным `ShellRunResult`. |
| `start(spec)` | Фоновое исполнение. Немедленно возвращает свободный от задач дескриптор `ShellProcess`; **таймаут не применяется**. Вызывающий может адаптировать его в `ctx.jobs`. |
| `sandboxMode` | Факт-возможность для слоя инструментов: режим по умолчанию, под которым ИЗОЛИРУЮЩИЙ исполнитель ограничивает запуски (`undefined` в базовом классе — «этот исполнитель не изолирует»). `dsh-tool-bash` читает его при регистрации, чтобы рекламировать поля эскалации, только когда композиция их поддерживает. |
| `ShellProcess.readOutput()` | **Инкрементальное** чтение вывода — последовательные чтения никогда не доставляют повторно. Чтения, потерявшие данные из-за границ буфера, помечаются флагом `lossy` и указывают на spill-файлы полного потока. |
| `ShellProcess.kill()` | Убить группу процессов. Возвращает `false`, если процесс уже завершился. |

Реализации наследуют `ShellExecutor` и реализуют абстрактные методы. Освобождение ресурсов обязано убить каждый работающий процесс и дождаться его выхода.

`SHELL_SETTINGS_NAMESPACE` (`bash`) экспортируется здесь, а не провайдером, потому что именует возможность, а не реализацию. Хост собирает ровно одного провайдера `ctx.shell` — слой win32 меняет POSIX-строки на pwsh, а монтаж обоих громко отказывает на дублирующей регистрации сервиса, — поэтому каждый провайдер может зарегистрировать это единственное пространство имён со своей схемой и записью композиции, и два никогда не столкнутся, а перенесённый между платформами `settings.yaml` продолжит разрешаться на обеих.

## Словарь типов

`ShellExecRequest` (command, workdir?, timeoutMs?, stdoutMaxBytes?, signal?, stdin?, env?, dshEnv?, sandboxPolicy?) разрешается в `ShellExecSpec` (command, workdir, timeoutMs, stdoutMaxBytes, signal?, stdin?, env?, dshEnv?, sandboxPolicy) до исполнения. `stdoutMaxBytes` — доверенный бюджет захвата запуска на переднем плане для потребителей, которым нужно разобрать полный ограниченный stdout; обращённый к модели bash-инструмент его не выставляет. `sandboxPolicy` необязателен в запросе и обязателен, но обнуляем в разрешённой спецификации: он несёт полный режим на вызов и корень рабочего пространства. Путь инструмента песочницы разрешает его из вызывающей сессии через `ctx.sandboxPolicy`; прямой вызывающий изолирующего исполнителя возвращается к политике развёртывания, а неизолирующий исполнитель носит поле и не ограничивает ничего.

Словарь посессионного переопределения режима песочницы (событие `'sandbox/mode'`, свёртка `effectiveSandboxMode(events)` и путь записи `setSandboxMode(session, mode)`) находится НЕ здесь — это состояние политики, разделяемое всеми применяющими семействами, которым владеет [`@deepseek-ai/dsh-sandbox-policy`](../../sandbox/sandbox-policy/). `run()` возвращает `ShellRunResult`; `start()` возвращает `ShellProcess`, чьи инкрементальное чтение и kill адаптируются `dsh-tool-bash` в универсальную регистрацию задачи. Изолирующий исполнитель штампует `ShellSandboxInfo` на результатах переднего плана и устоявшихся дескрипторах процессов. См. `src/types.ts` и [subsystems/shell.md](../../../docs/subsystems/shell.ru.md).

`stdin` и обычный `env` задают внутрипроцессные плагины (мосты хуков, нативные плагины), чтобы скормить команде хука её JSON payload и значения `CLAUDE_PROJECT_DIR`/`CLAUDE_PLUGIN_ROOT`. `dshEnv` — отдельное доверенное перекрытие, ограниченное типом управляемыми ключами; экспортируемый `DSH_ENV_PREFIX` — единственный источник этого пространства имён, его шаблонного типа `DshEnvironmentKey`, очистки у исполнителя, валидации в реестре, производных встроенных имён и руководства для модели. Баш модели использует текущий снапшот, собранный `ctx.shellEnv`. Реализации убирают унаследованные управляемые ключи, затем сливают `dshEnv` после обычного `env`, поэтому пропущенный текущий факт не может откатиться к устаревшему внешнему состоянию, а запись `env` не может вытеснить управляемое значение. Обращённый к модели инструмент не выставляет ничего из этого параметрами. Все три остаются необязательными в разрешённой спецификации; отсутствие означает «нет ввода/перекрытия». См. [Agent Note о bash stdin/env](../../../.agents/notes/implemented/architecture/2026-06-30-bash-stdin-env-trusted-plugin-api.md) и [Agent Note об окружении сессии](../../../.agents/notes/implemented/feature/2026-07-10-agent-session-identity-and-log-location.md).

Экспортируемый `parseExitStatus` (вместе с `ParsedExitStatus`) — общая для инструментов оболочки половина контракта рендеринга: обратное маркерам `[exit code: N]` / `[killed by signal: X]`, которые дописывают `renderResult` у `dsh-tool-bash` и `renderPwshResult` у `dsh-tool-pwsh`. `presentResult` обоих инструментов использует его, чтобы разделить отрендеренный текст на тело вывода терминальной карточки и её пилюлю статуса выхода; он живёт вместе с Service Definition, поэтому два инструмента никогда не разойдутся в маркерном контракте.

## Опыт модели

Косвенно, через `dsh-tool-bash`, который превращает вывод исполнителя и факты песочницы в руководство и удерживаемые токены результата инструмента.

#### Влияние на KV-кэш

Прямой инвалидации нет; изменениями префикса запроса владеет названный потребитель.

## Известные ограничения и отложенная работа

- **Нет словаря интерактивного ввода** — `stdin` пишется один раз при запуске и закрывается; у seam нет канала, чтобы кормить работающую задачу, и нет понятия PTY-сессии.
- **Таймауты переднего плана всегда во владении исполнителя** — режим дедлайна на стороне вызывающего на seam явно отложен [Agent Note о политике таймаута вызовов инструментов](../../../.agents/notes/implemented/architecture/2026-07-07-tool-call-timeout-policy.md).
