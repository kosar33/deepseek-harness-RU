# @deepseek-ai/dsh-tool-bash-persistent

[English](README.md) | [中文](README.zh.md) | Русский

Обращённый к модели `bash(command)` поверх одной оболочки `ctx.terminals` в области владельца. Пакет владеет контрактом инструмента и переиспользованием оболочки; развёртывания выбирают PTY-бэкенд и политику песочницы.

## Конфигурация

| Ключ | По умолчанию | Смысл |
|---|---:|---|
| `backendType` | `shell` | Зарегистрированный PTY-бэкенд, используемый для каждой оболочки агента. |
| `timeoutMs` | `300000` | Предел по реальному времени (wall-clock) для одной команды; тайм-аут закрывает оболочку. |
| `maxOutputChars` | `16000` | Максимум сохраняемых символов вывода команды; фиксированные диагностики добавляются затем. |
| `description` | Описание постоянной оболочки | Обращённый к модели контракт окружения. |

## Model Experience

### Схема инструмента

#### What the model sees

Генерируемая [схема `bash`](../../../docs/tool-catalog.ru.md#deepseek-aidsh-tool-bash-persistent), включая сконфигурированное `description`. Плагин не добавляет собственной отдельной секции системного промпта; персона и руководство по окружению принадлежат развёртыванию.

#### Token effect

Фиксированная стоимость схемы, пока `bash` видим.

#### KV Cache effect

Стабильно по префиксу, пока сконфигурированное описание и схема не меняются.

### Результаты инструмента

#### What the model sees

Команды используют одну общую оболочку на агента, поэтому cwd, экспортированные переменные, активированные окружения, функции и фоновые задания сохраняются между вызовами. Результаты исключают приватные маркеры завершения. Когда оболочка вновь читает stdin, не напечатав маркер завершения, — после `exec`, прерывания или интерактивного дочернего процесса на переднем плане, чьё ожидание stdin провайдер может доказать, — вызов возвращает захваченный частичный вывод, который может закончиться собственным текстом промпта бэкенда. Обёрнутая команда с ненулевым кодом выхода добавляет `[exit code: N]`; оболочка, вышедшая до сообщения этого статуса, вместо него добавляет `[shell exited: code N]`, `[shell killed by signal: SIG]` или `[shell exited]`, когда бэкенд не даёт ни того ни другого, затем сбрасывается и сообщает модели, что следующий вызов начнётся с чистой оболочки. Длинный вывод оставляет самый ранний сохранённый префикс плюс уведомление об обрезке. Если PTY уже потерял этот префикс, результат говорит об этом явно, а не выдаёт хвост за полный вывод. Тайм-аут возвращает ограниченный частичный вывод, закрывает оболочку с неопределённым состоянием и сообщает о сбросе.

#### Token effect

Зависит от данных. `maxOutputChars` ограничивает сохраняемый вывод команды; фиксированные диагностики обрезки, потерянного префикса, статуса, тайм-аута и сброса могут удлинить результат.

#### KV Cache effect

Append-only результаты инструмента следуют за пригодным для переиспользования префиксом запроса.

## Известные ограничения и отложенная работа

- Инструмент требует агента-владельца и реального PTY-бэкенда.
- Интерактивный дочерний процесс на переднем плане (например, REPL) возвращается досрочно с частичным выводом только там, где провайдер подпроцессов может доказать его ожидание stdin; в остальных случаях вызов идёт до `timeoutMs`.
- Явный `exit` и тайм-аут отбрасывают состояние оболочки. Отмена также сбрасывает и отбрасывает результат, даже когда полный статусный маркер уже наблюдаем; следующий вызов начинает свежую оболочку.
- Факты окружения вроде сетевого доступа и зеркал пакетов должны указываться в настроенном `description`, а не в дефолте этого пакета.
