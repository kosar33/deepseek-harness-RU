# @deepseek-ai/dsh-tool-bash

[English](README.md) | [中文](README.zh.md) | Русский

Обращённый к модели инструмент `bash`, регистрируемый поверх исполнительского seam'а `ctx.shell`. Исполнение на переднем плане остаётся за этим seam'ом; дескриптор фонового процесса регистрируется в универсальном рантайме `ctx.jobs` и управляется через `job_output`, `job_list` и `job_kill` из `@deepseek-ai/dsh-tool-jobs`.

Требует загруженного Service Provider исполнителя (например, `@deepseek-ai/dsh-bash-local`) и реестра [`@deepseek-ai/dsh-shell-env`](../shell-env/README.md); плагин остаётся в состоянии PENDING, пока не существует каждая внедряемая служба (`inject: ['tools', 'bash', 'systemPrompt', 'bashEnv']`). Контракт инструмента — диалект bash: монтируйте исполняющую сторону, разбирающую bash.

Корень пакета предоставляет только контракт плагина Cordis (`name`, `inject`, `Config`, `apply`); рендеринг результатов и адаптация фоновых процессов остаются внутренним делом пакета.

Плагин также привносит секцию промпта `tool:bash` (порядок 105): проверяйте маркер `[exit code: N]` на каждом результате и разбирайтесь в сбоях, прежде чем двигаться дальше.

## Инструменты

### `bash`

| Аргумент | Тип | Примечания |
|---|---|---|
| `command` | string (обязателен) | Запуск через `bash -c`. Никакое состояние не переживает вызовы — используйте `workdir`, а не `cd`. |
| `description` | string (обязателен) | Однострочная сводка команды в активном залоге (5–10 слов), только для показа в UI/логе — на исполнение не влияет. |
| `timeoutMs` | number | Переопределение тайм-аута в миллисекундах. Исполнитель применяет свой настроенный дефолт и потолок. |
| `workdir` | string | Рабочий каталог для этого вызова. По умолчанию берётся файловая идентичность cwd сессии вызывающего агента (`session.header.cwd`), поэтому каждая сессия работает в собственной рабочей области; относительный `workdir` разрешается против той же идентичности. |
| `run_in_background` | boolean | Немедленно возвращает id задания; тайм-аут не применяется. |
| `sandbox_permissions` | строковое перечисление | ОБЪЯВЛЯЕТСЯ ТОЛЬКО тогда, когда смонтированный исполнитель сажает команды в песочницу (`ctx.shell.sandboxMode` сообщает об ограничивающем дефолте): более широкий режим, который нужен отклонённой команде, из замкнутого набора целевых значений `workspace-write`/`danger-full-access` (никогда не урезается до дефолта исполнителя — действующий режим задаётся на сессию; строгость расширения проверяется при исполнении против него, а запрос без расширения прав падает, никого не спрашивая). |
| `justification` | string | Требуется вместе с `sandbox_permissions` (каждый без другого — ошибка валидации): одно предложение для пользователя, объясняющее, почему именно этой команде нужен более широкий доступ. |

Аргументы `command`, `workdir` и `timeoutMs` разрешаются против конфигурационных дефолтов исполнителя через `ctx.shell.resolve()` до исполнения, так что Service Definition (`ShellExecSpec`) получает явные значения `workdir`/`timeoutMs`. Дефолт workdir применяется в слое инструмента из `session.header.cwd` вызывающего агента ДО `resolve()` — посессионный cwd обязан приходить от `exec.agent`, поскольку N сессий делят одного исполнителя; и лишь когда cwd сессии недоступен, исполнитель возвращается к собственной конфигурации / `process.cwd()`. Когда присутствует политика песочницы, инструмент переиспользует её уже канонический `workspaceRoot` как базу workdir, чтобы ограничение и запуск процесса не могли разрешить одно и то же написание сессии по-разному.

### Управляемое окружение оболочки

Каждый модельный вызов bash на переднем плане и в фоне получает свежесобранное доверенное окружение `DSH_*` через общий реестр [`dsh-shell-env`](../shell-env/README.md): `DSH_HOME` (абсолютный домашний каталог Harness), `DSH_SHELL=1`, `DSH_SESSION_ID` агента и `DSH_SESSION_JSONL`, когда активный бэкенд персистентности находит такой файл. Контракт реестра — регистрация участников, явный отказ при дубликате или необъявленном ключе, встроенные зарезервированные ключи и пример участника — живёт в README того пакета. Снапшот проходит через выделенный канал `ShellExecRequest.dshEnv`; локальный исполнитель удаляет все унаследованные `DSH_*` перед слиянием, поэтому вложенные harness-процессы и параллельные родительские/дочерние агенты не могут утекать устаревшие идентичности, а `process.env` никогда не изменяется. Описание инструмента обучает универсальному соглашению `$DSH_*`, а не называет переменные конкретной персистентности и не добавляет постоянную секцию системного промпта.

Текст результата содержит stdout, опциональную секцию `[stderr]`, затем применимые маркеры отказа песочницы, тайм-аута, сигнала, кода выхода и усечения. Тайм-аут сообщается независимо от итогового статуса выхода; ненулевой выход остаётся результатом, который интерпретирует модель, а не `isError`. Усечение ссылается на безопасный полный spill-файл либо сообщает о его недоступности. Только инфраструктурные отказы вроде ошибок spawn и прерываний дают `isError`.

Канонический успех — `{ kind: 'foreground', ...ShellRunResult }` для завершившегося процесса на переднем плане или `{ kind: 'background', jobId }` для опубликованного задания. Нативный рендерер сохраняет текст выше, включая ровно `started background job <id>`; программные потребители используют типизированные поля без разбора этих строк. Потолки потоков исполнителя остаются лимитами захвата на `ShellRunResult` и несут свои spill-пути.

Когда `run_in_background` истинен, этот плагин предварительно проверяет `ctx.jobs.start()` до запуска, регистрирует вызывающего агента владельцем и адаптирует возвращённый дескриптор `ShellProcess` в универсальные хуки отмены/завершения/инкрементального вывода. Рантайм заданий владеет идентификаторами, межсессионной изоляцией, уведомлениями о завершении, ожиданием и очисткой при освобождении ресурсов; этот плагин лишь отображает факты выхода/песочницы bash в вывод задания и детали исхода. `enableRunInBackground: false` убирает параметр и отвергает принудительный фоновый вызов во время исполнения.

## Представление в UI

Инструмент владеет своим намерением рендера `presentCall`/`presentResult`. Вызов на переднем плане — терминальная карточка, несущая команду, описание, cwd, вывод и разобранный статус выхода. Поскольку карточка показывает выход отдельной пилюлей, маркер `[exit code: N]` / `[killed by signal: …]`, который извлекает разбор, покидает вывод; все прочие маркеры (усечение, тайм-аут, песочница) остаются в нём. Фоновый старт — обобщённая карточка исполнения, потому что возвращает только id задания; обобщённые инструменты `job_*` владеют собственными карточками. Эти презентеры чистые и безопасные для воспроизведения.

## Инструмент строит запрос только из именованных аргументов

`ShellExecRequest` несёт опциональные `stdoutMaxBytes`, `stdin`, обычное `env` и управляемое `dshEnv`, используемые доверенными внутрипроцессными плагинами и реестром окружения этого инструмента. Обращённый к модели инструмент не предоставляет ни `stdoutMaxBytes`, ни `stdin`, ни `env`: он строит запросы из именованных полей command/workdir/timeout/signal/sandbox плюс собранного реестром `dshEnv`. Лишние модельные ключи игнорируются и не могут подменить управляемые значения. Синтаксис оболочки даёт эквивалентное поведение на уровне команды, а локальный исполнитель вычищает учётные данные окружения и устаревшие значения `DSH_*`. См. [Agent Note о stdin/env](../../../.agents/notes/implemented/architecture/2026-06-30-bash-stdin-env-trusted-plugin-api.md).

## Разрешения и эскалация

Команды исполняются с полной властью исполнителя, если помещающий их в песочницу исполнитель ([`dsh-bash-sandbox`](../bash-sandbox/)) их не ограничивает — deny-only песочница сообщает об отказах как о фактах результата, отображаемых здесь маркером отказа; политика allow/deny/ask на каждый вызов — это каскад `tools/pre-execute` (см. docs/architecture.ru.md).

Эскалирующие вызовы bash разрешают `ctx.approval` до исполнения. `allowed-once` применяет запрошенный режим только к этому вызову; отказ, отмена, недоступность или отсутствующий контекст одобрения не исполняют ничего и возвращают отличимую ошибку. При настоящем отказе модель может повторить ту же команду однократно в том же ходу с самым узким достаточным режимом и обоснованием; сам промпт одобрения и есть шаг согласия. Эскалация никогда не спекулятивна, а отключённое или отклонённое одобрение окончательно. Обоснование живёт в [Agent Note о песочнице](../../../.agents/notes/implemented/feature/2026-07-06-sandbox.md).

## Переключение режима на уровне сессии

Для исполнителей с песочницей каждый вызов разрешает режим как одноразовую эскалацию, затем переопределение сессии, затем дефолт исполнителя. Вызовы без песочницы и без агента не несут переопределения сессии. Владелец политики привносит текущий нейтральный к возможностям постоянный режим; результаты отказов по-прежнему владеют специфичным для операции действующим режимом и руководством по повторной попытке. См. [раздел о `dsh-shell`](../shell/README.md) и [контракт переключения песочницы](../../../.agents/notes/implemented/feature/2026-07-06-sandbox.md).

## Model Experience

### Системный промпт

#### What the model sees

Каждый запрос в скоупе регистрации этого плагина содержит приведённое ниже руководство для bash. Владелец политики привносит текущее состояние песочницы через свой безопасный для кэша рантайм-контекст, а не изменяя эту секцию. Скоупные ограничения инструментов могут скрыть схемы, не убирая эту независимо зарегистрированную секцию.

##### Руководство для bash

```markdown
Check the [exit code: N] marker on every bash result; investigate failures before moving on.
```

#### Token effect

Небольшая фиксированная стоимость входа на каждый запрос, пока плагин активен, — неизменная при любом режиме песочницы и его переключениях.

#### KV Cache effect

Префиксно-стабильно, пока скоуп регистрации и текст промпта неизменны. Активация или освобождение ресурсов плагина могут инвалидировать переиспользование начиная с этой секции промпта; переключения режима песочницы — нет.

### Схемы инструментов

#### What the model sees

Модель видит сгенерированную [схему `bash`](../../../docs/tool-catalog.md#deepseek-aidsh-tool-bash). `run_in_background` появляется, только когда этот производитель его включает; `sandbox_permissions` и `justification` появляются, только когда смонтированный исполнитель объявляет песочницу. Ограничения инструментов на уровне агента могут убрать определение для такого агента.

#### Token effect

Фиксированная цена схемы на каждом запросе, где инструменты видимы; поддержка песочницы добавляет поля эскалации и свой условный абзац описания.

#### KV Cache effect

Префиксно-стабильно, пока видимость, поддержка фона и возможности песочницы исполнителя неизменны. Ограничение, изменение конфигурации или смена исполнителя могут инвалидировать переиспользование с первого изменившегося определения инструмента.

### Результат на переднем плане

#### What the model sees

Рендерер выдаёт зависящий от данных хвост stdout, затем опциональный `[stderr]` и хвост stderr. Без вывода выдаётся ровно `(no output)`. Условные строки — это ровно `[output truncated; full output: <path-or-(unavailable)>]`, `[sandbox: file access denied under <mode> mode]`, `[timed out after <timeoutMs>ms]`, `[killed by signal: <signal>]` и `[exit code: <exitCode>]`; строки эскалации песочницы и отказа раннера цитируются в [`dsh-bash-sandbox`](../bash-sandbox/README.md).

#### Token effect

Ноль токенов результата до вызова. Вывод ограничивается на каждый поток, при этом каждая выданная строка остаётся в истории до компакции.

#### KV Cache effect

Append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Контекст и результаты фоновых заданий

#### What the model sees

Старт возвращает ровно `started background job <jobId>`. Этот производитель поставляет универсальному рантайму заданий инкрементальный вывод процесса, опциональный `[some output was dropped from memory; full output: <paths-or-(unavailable)>]`, факты песочницы и итоговые детали вроде `exit code: <exitCode>` или `signal: <signal>`. [`dsh-tool-jobs`](../../jobs/tool-jobs/README.md) владеет видимой строкой статуса, уведомлением о завершении, перечислением и ответом на отмену.

#### Token effect

Подтверждение старта невелико и удерживается; собираемый вывод зависит от данных и ограничен потоковыми буферами исполнителя. Вычитывающие чтения не повторяют прежнего вывода.

#### KV Cache effect

Append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Ошибки инструментов

#### What the model sees

Отказы валидации и политики нормализуются как `Error: <message>`. Стабильные сообщения этого пакета: `invalid command: expected a non-empty string`, `invalid description: expected a non-empty string`, `invalid timeoutMs: expected a positive number, got <value>`, `invalid escalation: sandbox_permissions requires a justification`, `invalid escalation: justification is only valid together with sandbox_permissions`, `invalid justification: expected a non-empty sentence`, `background execution is disabled for this bash tool`, `background jobs unavailable: load @deepseek-ai/dsh-jobs and @deepseek-ai/dsh-tool-jobs`, `sandbox_permissions is not available in this composition (no sandboxing executor to escalate)`, `sandbox escalation to "<mode>" is not strictly wider than this call's current "<mode>" mode`, варианты доступности/отказа/отмены одобрения и `tool call aborted`.

#### Token effect

Только неудавшийся вызов добавляет эти удержанные токены; отклонённая эскалация не добавляет вывода команды, потому что команда не исполняется.

#### KV Cache effect

Append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Known Limitations and Deferred Work

- **Пилюли выхода при воспроизведении разбираются из текста результата** — вывод, чья последняя строка случайно оказывается ровно `[exit code: N]` / `[killed by signal: …]`, показывает неверную пилюлю при воспроизведении сессии и теряет эту строку из тела карточки, потому что разбор принимает её за извлекаемый маркер; известный остаток, влияющий только на отображение.
- **Инструмент `bash` отказывается от бюджетов `timeout-policy`** — он сохраняет принадлежащий исполнителю путь `BASH_TIMEOUT`, см. [Agent Note о timeout-policy для вызовов инструментов](../../../.agents/notes/implemented/architecture/2026-07-07-tool-call-timeout-policy.md).
- **У фоновых процессов нет тайм-аута исполнителя** — когда работа перестаёт быть нужна, вызывающие должны использовать `job_kill` либо полагаться на освобождение ресурсов владельцем/службой.
