# @deepseek-ai/dsh-tool-pwsh-persistent

[English](README.md) | [中文](README.zh.md) | Русский

Обращённый к модели `pwsh(command)` поверх одного owner-scoped shell'а `ctx.terminals`. Пакет владеет контрактом инструмента и переиспользованием shell'а; развёртывания выбирают бэкенд терминала (экземпляр `terminal-bash`, настроенный с `shellDialect: pwsh`) и политику песочницы. Это Windows-двойник `tool-bash-persistent`: тот же контракт персистентного состояния, диалект PowerShell.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `backendType` | `shell` | Зарегистрированный бэкенд терминала, используемый для shell'а каждого агента. |
| `timeoutMs` | `300000` | Предел по настенным часам для одной команды; тайм-аут закрывает shell. |
| `maxOutputChars` | `16000` | Максимум удерживаемых символов вывода команды; фиксированные диагностики добавляются после. |
| `description` | Описание персистентного shell'а | Обращённый к модели контракт окружения. |

## Влияние на модель

### Схема инструмента

#### Что видит модель

Сгенерированная [`pwsh`-схема](../../../docs/tool-catalog.md#deepseek-aidsh-tool-pwsh-persistent), включая настроенный `description`. Плагин не добавляет отдельной секции системного промпта; персона и руководство по окружению остаются за развёртыванием.

#### Влияние на токены

Фиксированная стоимость схемы, пока `pwsh` видим.

#### Влияние на KV-кэш

Префиксно-стабильно, пока настроенное описание и схема неизменны.

### Результаты инструмента

#### Что видит модель

Команды разделяют один shell на агента, поэтому cwd, переменные `$env:`, функции и фоновые задачи переживают вызовы. Результаты исключают приватные маркеры завершения, промпт shell'а и повторённую строку ввода (PSReadLine возвращает поданный ввод в поток; привязанное к маркерам извлечение и срез источника обёртки убирают его). Ненулевая обёрнутая команда добавляет `[exit code: N]` — точный нативный код выхода, когда команда запускала нативную программу, `1` для завершающей ошибки PowerShell. Shell, вышедший до отчёта об этом статусе, вместо этого добавляет `[shell exited: code N]`, `[shell killed by signal: SIG]` или `[shell exited]`, когда бэкенд не даёт ни того ни другого (принудительное завершение Windows сообщает код выхода 1 без сигнала), затем сбрасывается и говорит модели, что следующий вызов начнётся с чистого листа. Длинный вывод сохраняет начальный удержанный префикс плюс уведомление об усечении; если терминал уже выбросил тот префикс, результат говорит об этом явно. Тайм-аут возвращает ограниченный частичный вывод, закрывает находящийся в неопределённости shell и сообщает о сбросе.

#### Влияние на токены

Зависит от данных. `maxOutputChars` ограничивает удерживаемый вывод команды; фиксированные диагностики усечения, потерянного префикса, статуса, тайм-аута и сброса могут расширить результат.

#### Влияние на KV-кэш

Результаты инструмента append-only следуют за переиспользуемым префиксом запроса.

## Известные ограничения и отложенная работа

- Инструменту требуются владеющий агент и настоящий бэкенд терминала с диалектом pwsh (Windows ConPTY или POSIX pwsh).
- **Эхо ввода неустранимо**: PSReadLine в PowerShell возвращает поданный ввод в поток терминала, а эквивалента `stty -echo` нет. Привязанное к маркерам извлечение исключает эхо в полных результатах; срез источника обёртки покрывает резервные пути, но обёртка, переносящая строки по ширине терминала, может оставить частичное эхо в результатах частичного вывода, ограниченное `maxOutputChars`.
- Сырые ESC-символы внутри команд модели не поддерживаются: PSReadLine поглощает их до исполнения. Обёртка экранирует нужные ей управляющие байты (OSC-маркеры, собранные через `[char]27`, backtick-экранирование для тела).
- Переопределение моделью функции `prompt` убирает маркер готовности; готовность shell тогда определяет по уровню тишины вместо быстрого пути маркера.
- Интерактивного stdin во время команды нет: команда переднего плана, читающая ввод, блокируется до тайм-аута готовности, который сбрасывает shell.
- SIGTSTP/SIGHUP недоступны на Windows (отвергаются бэкендом); SIGINT доставляется как запись Ctrl-C в консоль в масштабе всей консоли, которая на промпте отменяет ожидающую строку вместо сигнализации процессу.
- В read-only-режиме песочницы Windows ACL pwsh стартует в ConstrainedLanguage, который может отвергнуть закрепление кодировки `[Console]::` и маркер промпта из bootstrap. Команды всё же могут завершаться через печатаемый промпт и уровень тишины, но не-ASCII вывод может пойти в кодовой странице хоста.
- OSC-маркер с терминатором BEL остаётся только сигналом готовности; канал событий BEL к модели остаётся отложенным, в согласии с текущей реализацией.
