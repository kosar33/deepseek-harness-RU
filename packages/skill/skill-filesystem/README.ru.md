# @deepseek-ai/dsh-skill-filesystem

[English](README.md) | [中文](README.zh.md) | Русский

Локальный провайдер файловой системы для реестра `ctx.skills`.

Этот пакет реализует один источник скиллов. Он сканирует локальные корни скиллов проекта, настраиваемые и пользовательские, разбирает `SKILL.md` или плоские Markdown-файлы скиллов и регистрирует провайдер на `ctx.skills`. Реестр остаётся в `@deepseek-ai/dsh-skill`; долговременные каталоги сессий и обращённый к модели инструмент загрузки остаются в `@deepseek-ai/dsh-tool-skill`.

## Плагин

Требует `ctx.skills` (`inject: ['skills']`).

### Конфигурация

| Поле | По умолчанию | Смысл |
|---|---|---|
| `providerName` | `filesystem` | Уникальное имя, под которым провайдер регистрируется на `ctx.skills`. |
| `includeDefaultRoots` | `true` | Включать корни проекта и пользователя вокруг `customSkillDirs`; установите false для изолированного провайдера только с настраиваемыми корнями. |
| `dshHome` | `$DSH_HOME` или `~/.dsh` | Корень конфигурации DeepSeek Harness, разрешаемый пакетом [`@deepseek-ai/dsh-home-paths`](../../util/home-paths/README.md); под этим каталогом сканируется `skills`. |
| `agentsHome` | `$DSH_AGENTS_HOME` или `~/.agents` | Общий корень конфигурации агентов, сканируемый на совместимые скиллы. |
| `customSkillDirs` | `[]` | Дополнительные локальные корни скиллов, сканируемые после корней проекта и до пользовательских корней. |
| `watch` | `true` | Наблюдать за локальными для хоста корнями и инвалидировать локального провайдера, когда состав каталога или фронтматтер могли измениться. |
| `watchUsePolling` | `false` | Использовать опрос Chokidar вместо нативных событий для существующих корней скиллов. |
| `watchStabilityThresholdMs` | `200` | Окно стабильной записи для событий Chokidar `add` и `change`. |
| `watchPollIntervalMs` | `100` | Интервал опроса/стабильности Chokidar и интервал проверки отсутствующих путей. |
| `watchMaxProjects` | `128` | Максимум различных корней проектов, удерживаемых в LRU наблюдателя. |
| `watchFollowSymlinks` | `true` | Переходить по символическим ссылкам при наблюдении за существующими корнями. |

## Обнаружение

Корни по умолчанию разрешаются в порядке рангов этого провайдера:

| Ранг | Источник | Путь |
|---|---|---|
| 100 | `project-dsh` | `<projectRoot>/.dsh/skills` |
| 200 | `project-agents` | `<projectRoot>/.agents/skills` |
| 300 | `custom` | `Config.customSkillDirs` |
| 400 | `user-dsh` | `<dshHome>/skills` |
| 500 | `user-agents` | `<agentsHome>/skills` |

Корень проекта — ближайший предок, содержащий `.git`; без него используется текущий cwd. Пользовательский DSH-корень пропускает дочерний каталог `.system`, чтобы принадлежащие системе каталоги не считались обычными пользовательскими скиллами. `includeDefaultRoots: false` опускает строки проекта и пользователя и переменную окружения `$DSH_BUNDLED_SKILL_DIR` по умолчанию, сохраняя явно сконфигурированные настраиваемые и встроенные корни, что позволяет нескольким изолированным провайдерам с уникальными именами видеть только свои корни. Этот провайдер поставляет скиллы проекта и пользователя; встроенные системные скиллы может поставлять другой провайдер.

Когда доступен `ctx.fs`, обнаружение перечисляет корни через `ctx.fs.listDir`, читает файлы скиллов через `ctx.fs.readText` и проверяет `.git` через сервис файловой системы. Полные загрузки скиллов передают сигнал прерывания поиска операциям метаданных и чтения содержимого файловой системы. Без сервиса файловой системы провайдер переключается на прерываемый ввод-вывод файловой системы Node, чтобы минимальные локальные контексты тоже могли загружать скиллы. Пути, отсутствие которых подтверждено, — допустимое пустое состояние; некорректные или нетекстовые записи предупреждают и пропускаются, а неожиданные сбои обнаружения/чтения делают снапшот реестра неполным, а не заменяют последний исправный модельный каталог вводящим в заблуждение удалением.

## Определение изменений каталога

Существующие корни скиллов наблюдаются через Chokidar. Перед открытием нативного наблюдателя провайдер приводит существующий корень или предка к realpath и восстанавливает следующий отсутствующий сегмент; когда `watchFollowSymlinks` равен false, а сам корень — символическая ссылка, он сохраняет эту последнюю ссылку, чтобы Chokidar мог соблюсти сконфигурированную границу. Обнаружение и диагностика хранят сконфигурированный путь, поскольку Windows иначе не способна смешивать псевдоним 8.3 с libuv-событиями длинной формы. Провайдер наблюдает прямые добавления/удаления каталогов-бандлов, добавления/удаления плоских Markdown-файлов и прямые добавления/удаления/изменения `SKILL.md`; `change` существует ради повторного обнаружения фронтматтера каталога, например `name` и `description`. Изменения ниже `references`, `scripts`, `assets` и прочих ресурсов бандла каталог не инвалидируют. События, доставленные в одном микротасковом пакете, схлопываются в одну инвалидацию провайдера.

Наблюдение за несуществующим корнем ведётся от ближайшего существующего предка по одному отсутствующему сегменту пути за раз. Следующий сегмент проверяется через `fs.watchFile`; как только появляются `.agents`, `skills` или сконфигурированный корень, наблюдение продвигается, пока Chokidar не сможет прикрепиться к настоящему корню. Удаление корня обращает этот процесс, поэтому удаление и повторное создание целого каталога скиллов остаётся наблюдаемым. Наблюдатели с областью проекта ограничены `watchMaxProjects`; возврат к вытесненному проекту заново прикрепляет наблюдение во время обнаружения.

Штатные инструменты файловой системы `write` и `edit` также синхронно инвалидируют провайдера через `fs/observed`, когда их цель может затронуть наблюдаемую запись скилла. Этот быстрый путь заставляет следующий шаг модели наблюдать собственную мутацию файловой системы, не дожидаясь хостового наблюдателя. Внешние изменения со стороны IDE, Git, shell и процессов полагаются на Chokidar или проверку отсутствующих путей. Наблюдатели существующих корней остаются персистентными до освобождения ресурсов эффекта, чтобы асинхронные нативные события ошибок оставались во владении Chokidar; сбои наблюдателя при старте и во время исполнения журналируются и повторяются. Обнаружение всё равно сканирует читаемые корни и возвращает их кандидатов для прямой загрузки, но помечает наблюдение неполным, чтобы оно не кешировалось и не публиковалось как авторитетный модельный каталог. Освобождение ресурсов эффекта закрывает каждый наблюдатель и локализует поздние обратные вызовы.

## Формат скилла

Скиллы могут быть одноуровневыми каталогами-бандлами (`<name>/SKILL.md`) или плоскими Markdown-файлами (`<name>.md`). Вложенное обнаружение `**/SKILL.md` намеренно исключено. Фронтматтер разбирается как открытый YAML-объект пакетом `yaml`; этот провайдер интерпретирует обязательные `name` и `description`, плюс необязательные `whenToUse`, `metadata`, `disable-model-invocation` и `user-invocable`. Имена должны быть kebab-case.

Оба поля вызовов принимают YAML-булевы значения и нечувствительные к регистру формы `true`/`false`, `yes`/`no`, `on`/`off` и `1`/`0`. `disable-model-invocation: true` исключает скилл из обращённых к модели каталогов и загрузчиков; `user-invocable: false` исключает его из команд для человека. Каждое опущенное поле по умолчанию разрешает свою поверхность, а провайдер всегда выдаёт оба положительных внутренних значения политики, даже когда оба ключа отсутствуют. Отвергнутое camel-case написание или небулево значение поля вызова удаляет весь скилл из обнаружения с предупреждением, а не отбрасывает лишь это поле и не откатывается к разрешающему умолчанию. Политика вызовов спроектирована fail closed: игнорирование недопустимых данных могло бы показать скилл на отключённой поверхности; значения необязательных `whenToUse` и `metadata` неверного типа просто опускаются, потому что ни одно из них сейчас не даёт права вызова.

Каталог и тело имеют раздельные жизненные циклы. Обнаружение разбирает фронтматтер, чтобы получить сводку. Каждая загрузка `skill(name)` перечитывает и заново разбирает текущий файл, поэтому правкам тела не нужны ни хеш, ни версия, ни инвалидация кеша, ни упреждающее уведомление модели. Переименование во фронтматтере между обнаружением и загрузкой отвергает устаревшее имя и инвалидирует провайдера; следующее наблюдение каталога публикует новое имя.

## Model Experience

Опосредованно — через `dsh-tool-skill`, который рендерит вызываемые имена этого провайдера и ограниченные описания в начальный или замещающий каталог, а выбранное текущее тело инструкций плюс указание о базе ресурсов — в удерживаемую историю инструментов, пока пути, ранги провайдеров и отключённые скиллы остаются скрытыми.

#### KV Cache effect

Инвалидация наблюдателя может заставить названного потребителя добавить замещающий каталог к существующей истории запроса. Правки одного тела оставляют дайджест каталога неизменным.

## Известные ограничения и отложенная работа

- **Обнаружение одноуровневое** — распознаются только `<root>/<name>/SKILL.md` и `<root>/<name>.md`; вложенные деревья скиллов и манифесты пакетов игнорируются.
- **Область проекта — ближайший предок с `.git`** — рабочие области без такого маркера откатываются к переданному cwd; альтернативного маркера корня проекта или выбора субпроекта монорепозитория нет.
- **Некорректные записи исчезают с предупреждением** — модельный каталог не получает диагностики по отдельному скиллу и не отличит отсутствующий скилл от недопустимого; неожиданные сбои ввода-вывода вместо этого сохраняют последний исправный каталог.
- **Наблюдение отсутствующего корня опрашивает один сегмент пути** — корни, отсутствующие на старте, используют `fs.watchFile` с интервалом `watchPollIntervalMs`, пока Chokidar не сможет прикрепиться, обменивая ограниченную задержку обнаружения на надёжное распознавание создания в сценариях IDE, Git и shell.
- **Нет протокола версий тела** — загруженное тело — обычная удерживаемая история инструментов; поздние правки файла влияют на поздние вызовы, но и не переписывают старые результаты, и не объявляют об изменении тела.
