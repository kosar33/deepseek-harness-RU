# @deepseek-ai/dsh-skill

[English](README.md) | [中文](README.zh.md) | Русский

Чистый реестр провайдеров агентских скиллов.

Этот пакет владеет интерфейсом `ctx.skills`. Он не знает, приходят ли скиллы из локальных файлов, встроенных данных плагинов, HTTP или другого бэкенда; провайдеры регистрируют эти источники через `ctx.skills.registerProvider(...)`. Поставляемая локальная реализация — [`@deepseek-ai/dsh-skill-filesystem`](../skill-filesystem).

Реестр слоится по схеме хост+скоуп поверх [`@deepseek-ai/dsh-scope`](../../core/scope) — той формы, которую задал реестр инструментов: регистрация ложится в слой скоупа своего вызывающего контекста — строки хоста и плагины репозитория попадают в глобальный слой, плагин, смонтированный постоянной композицией агентского пресета, — в слой того пресета, — а чтение сливает глобальный слой с цепочкой смотрящего скоупа, причём ближайший слой безусловно забирает дублирующееся имя, а ранг решает дубликаты только внутри одного слоя.

## Сервис: `SkillRegistry` (ключ ctx: `skills`)

### Публичный API

- `ctx.skills.registerProvider(create): () => void` Вызывает синхронную фабрику провайдера с `{ signal, invalidate }`, затем регистрирует её readonly-результат по `provider.name`, уникальному внутри слоя вызывающего контекста. Дублирующиеся имена в одном слое бросают исключение, `runtime` зарезервирован, а неудавшаяся регистрация прерывает сигнал. Точный disposer Cordis снимает провайдера с регистрации, прерывает сигнал и сохраняет упорядоченный составной teardown.
- `ctx.skills.snapshot({ cwd?, signal?, scope? })` Возвращает нейтральное к вызову наблюдение `{ skills, complete }` для слитых слоёв смотрящего скоупа. `complete` ложен, когда любой провайдер отклонился или явно отчитался о неполном обнаружении либо когда вторая ревизия каталога состязается с ограниченной повторной попыткой; кандидаты, поставленные таким наблюдением, остаются в этом результате, который никогда не кэшируется.
- `ctx.skills.list({ cwd?, signal?, scope? })` Заимствует readonly-опции просмотра, затем возвращает каждую победившую сводку для текущего рабочего пространства, слитую через глобальный слой и цепочку смотрящего скоупа и отсортированную по имени. Потребители применяют `isModelInvocable(skill)` или `isUserInvocable(skill)` на собственной границе.
- `ctx.skills.get(name, { cwd?, signal?, scope? })` Пользуется теми же readonly-опциями и победившим кандидатом для обнаружения и загрузки, перепроверяет отмену после обнаружения или попадания в кэш, запускает загрузку у провайдера наперегонки с сигналом, валидирует загруженное определение и возвращает его независимо от политики вызова.
- `ctx.skills.register(skill): () => void` Регистрирует встроенный readonly-рантайм-скилл в слой вызывающего контекста, добавляя политику всеобщей вызываемости и `provider: "runtime"`, когда они опущены. Рантайм-регистрации одного имени в одном слое действуют по first-wins: дубликат журналирует предупреждение и получает no-op disposer. Удачные регистрации возвращают точный disposer Cordis для упорядоченного составного teardown.

### События

- `skills/change` — неотфильтрованное уведомление об инвалидации, испускаемое после регистрации или освобождения вклада провайдера или рантайма и после инвалидации регистрационного управления активным провайдером. Оно не несёт ни каталога, ни диффа: каждый потребитель заново запрашивает `snapshot()` со своими опциями поиска. Броски слушателей и отклонённые промисы журналируются и не могут наложить вето на мутацию реестра или оставить последующих слушателей без исполнения.

### Конфигурация

| Поле | По умолчанию | Значение |
|---|---|---|
| `collectCacheMaxEntries` | `128` | Максимум завершённых каталогов cwd/провайдера, удерживаемых в памяти. |

### Политика вызова

`SkillSummary.invocation` — обязательный типизированный объект политики, чьи положительные булевы `modelInvocable` и `userInvocable` описывают две поверхности независимо. Провайдеры возвращают эту уже разрешённую форму на каждом кандидате и определении; опустить её может только вход `SkillRegistration`, и тогда `register()` подставляет `{ modelInvocable: true, userInvocable: true }`. Реестр хранит все четыре комбинации, чтобы один результат обнаружения мог обслуживать обращённые к модели инструменты, обращённые к человеку команды и доверенных внутренних вызывающих, не смешивая их каталоги.

| Политика | Модель | Пользователь |
|---|---|---|
| `{ modelInvocable: true, userInvocable: true }` | включён | включён |
| `{ modelInvocable: true, userInvocable: false }` | включён | исключён |
| `{ modelInvocable: false, userInvocable: true }` | исключён | включён |
| `{ modelInvocable: false, userInvocable: false }` | исключён | исключён |

### Общий обращённый к модели рендер

`renderSkillContent(skill)` отрисовывает один загруженный скилл как канонический блок `<skill_content>` (экранированный атрибут `name`, подсказки ресурсов, дословное тело). Это единственная истина для обоих путей загрузки: `dsh-tool-skill` возвращает её как результат инструмента `skill` и инъецирует на границе явно выраженного пользователем жеста, поэтому модель видит одну форму независимо от того, кто начал загрузку. Рядом экспортируется `escapeText` для потребителей, встраивающих прозу в ту же разметочную рамку. Пакет также объявляет вид `MessageSource` с именем `skill-invocation` ({ name, form: 'instructions' }), которым помечаются сообщения явно инициированной пользователем инъекции, — потребители транскрипта показывают вызов из этих метаданных вместо повторного разбора тела.

`isModelInvocable(skill)` и `isUserInvocable(skill)` читают соответствующее положительное поле напрямую. `ctx.skills.get()` остаётся доверенным, нейтральным к политике примитивом загрузки, поэтому каждый обращённый к пользователю или модели потребитель должен применять предикат, соответствующий его поверхности, прежде чем показывать или загружать скилл.

## Контракт провайдера

Фабрика провайдера исполняется синхронно и получает один объект управления в рамках регистрации. `control.signal` прерывается, когда регистрация терпит неудачу или освобождается; `control.invalidate()` очищает завершённые каталоги, лишь пока та самая регистрация остаётся активной, поэтому поздние callback-и не могут повлиять на замену с тем же именем. Неизменяемые провайдеры могут игнорировать управление. Удалённая настройка, аутентификация и обнаружение принадлежат ожидаемому вызову `list(options)` провайдера. Возврат массива — краткая форма полного обнаружения; провайдер, собравший пригодных кандидатов, но не способный установить авторитетное наблюдение, возвращает `{ candidates, complete: false }`. Объекты провайдеров, опции поиска, кандидаты и определения заимствуются readonly, а не клонируются и не перепривязываются. Провайдерам следует уважать `options.signal`; реестр также перестаёт ждать обнаружение или загрузку, не реагирующие на отмену.

Реестр валидирует кандидатов до кэширования и определения до возврата. Победивший провайдер получает те же кандидат и непрозрачный `locator`, что он вернул из `list()`, что допускает специфичные для бэкенда дескрипторы файлов, URL, id или версий. Вызывающие и провайдеры должны сохранять readonly-контракт.

Нарушения контракта немедленно приводят к отказу. Отклонённый `list()` провайдера трактуется как временный сбой источника и опускается. Явно неполное наблюдение всё же отдаёт своих кандидатов `list()` и `get()`, но делает агрегатный снапшот неполным и некэшируемым. Смена ревизии провайдера или рантайма отбрасывает незавершённый результат и однократно повторяет попытку. Если попытку тоже перебили, её кандидаты возвращаются неполными и без кэша, чтобы непрерывно инвалидирующий провайдер не мог монополизировать вызывающего. Внутри одного слоя дублирующиеся имена разрешаются по рангу, порядку регистрации провайдера, затем локальному порядку провайдера; между слоями запись ближайшего скоупа забирает имя. Сводки сортируются по имени скилла.

Определения остаются прогрессивно загружаемыми. `get()` спрашивает тело у победившего провайдера при каждом вызове, а не кэширует его в этом реестре. Если возвращённое определение носит имя, отличное от выбранного кандидата, устаревший выбор отвергается, а реестр внутренне инвалидирует именно этого провайдера, чтобы следующий снапшот заново открыл его каталог.

## Рантайм-скиллы

`ctx.skills.register(...)` — удобный способ регистрировать встроенные рантайм-скиллы. Рантайм-скиллы используют ранг `250`: проектные провайдеры могут их перекрыть, тогда как сами они перекрывают корни custom и user поставляемого локального провайдера. Рантайм-определения и метаданные вложенных ресурсов заимствуются readonly; сервис материализует одно верхнеуровневое определение, чтобы подставить опущенные политику вызова и дефолты провайдера. Регистрация действует по first-wins внутри рантайм-вкладов, поэтому дублирующий вклад не может убрать активный через свой disposer.

## Граница потребителя

Реестр не отрисовывает руководство для модели и не регистрирует обращённых к модели инструментов. [`@deepseek-ai/dsh-tool-skill`](../tool-skill) использует `ctx.skills`, чтобы поставлять долговечные каталоги сессий и инструмент `skill`, поэтому провайдеры остаются независимыми от обращённого к модели поведения.

## Model Experience

Опосредованно, через `dsh-tool-skill`, который отрисовывает сводные данные провайдеров в долговечные сообщения первичного или замещающего каталога, а загруженные инструкции — в удерживаемые результаты инструмента.

#### KV Cache effect

Прямого промпт-эффекта нет. Названный потребитель владеет долговечным первичным каталогом и append-only замещениями после инвалидации.

## Known Limitations and Deferred Work

- **Инвалидация управляется провайдером** — у реестра нет TTL, и он не может заключить, что произвольный удалённый источник изменился; каждый изменяемый провайдер должен удерживать свою привязанную к регистрации возможность `invalidate()` и вызывать её из собственного механизма наблюдения.
- **Провайдеры опрашиваются последовательно** — один медленный кооперирующийся провайдер задерживает каждого зарегистрированного после него; отмена останавливает ожидание вызывающего, но не может принудительно завершить работу провайдера, игнорирующего отмену.
- **Неполные наблюдения не удерживаются** — отклонённые провайдеры опускаются, а явно поставленные кандидаты остаются доступными только текущему поиску; реестр не владеет ни последним исправным каталогом, ни диагностиками по провайдерам.
- **Разрешение дубликатов — first-wins** — поздние низкоприоритетные кандидаты внутри слоя журналируются и скрываются, а ближайший слой молча затеняет более дальний; API осмотра всех затенённых определений нет.
