# @deepseek-ai/dsh-tool-skill

[English](README.md) | [中文](README.zh.md) | Русский

Обращённый к модели каталог скиллов и инструмент `skill`.

Требует `ctx.agents`, `ctx.tools` и `ctx.skills` (`inject: ['agents', 'tools', 'skills']`).

## Жизненный цикл каталога

На каждом подходящем `agent/pre-step` плагин вызывает `ctx.skills.snapshot()` для cwd вызывающей сессии, передаёт сигнал прерывания pre-step в обнаружение, применяет точную видимость инструмента `skill` и отрисовывает упорядоченные записи `name` и `description`. Когда прежнего каталога нет, а это представление непусто, он добавляет начальный долговечный `<system-reminder>` роли user в нижестоящее решение `enter`. Сообщения каталога содержат только эти сводки; тела скиллов, пути, источники, провайдеры и подсказки `whenToUse` остаются за пределами каталога.

Каждое сообщение каталога несёт источник `skill-catalog`: контекст формы `catalog`, чьи `entries` записывают ровно те пары `name` и `description`, которые он опубликовал, плюс `update` при замене. Дайджест покрывает эти долговечные записи, а не отрисованную прозу, поэтому окружающее оформление `<system-reminder>` не может решить, нужна ли перепубликация, и потребители никогда не перепарсивают блок `<available_skills>`. Плагин сканирует долговечные события сессии в обратном порядке, не копируя их, и выводит базу сравнения из новейшего видимого сообщения `skill-catalog`, которое способен прочитать; нечитаемые и чужие записи пропускаются. Когда дайджест меняется, нижестоящее решение `enter` получает долговечное сообщение роли user с полным замещающим каталогом; пустая замена явно выводит прежние имена из обращения. Если видимого каталога не осталось, но узнаваемый исторический каталог существует, его спрятала компакция, и следующее полное наблюдение восстанавливает текущий каталог. Неполный снапшот провайдера не испускает ничего и сохраняет последнее исправное модельное представление для повторной попытки на следующем pre-step. Если прежнего каталога нет, а текущее представление пусто, надгробие не нужно.

Каталог опускается, когда изначально нет ни одного вызываемого моделью скилла, а также когда представление инструментов агента ограничениями убирает поставляемый инструмент `skill` или вместо него разрешает одноимённую скоупную тень. Идентичность сравнивается с определением, которое этот плагин сам зарегистрировал, а не поиском по собственному имени, поэтому плагин работает и в глобальном монтировании, и внутри композиции одного агента, где `register()` записывается в слой только этого агента. Изменения видимости участвуют в дайджесте, удерживая руководство промпта, видимую модели схему и исполнительскую диспетчеризацию согласованными.

`catalogDescriptionMaxLength` управляет нормализованными описаниями каталога; отрисовка XML-экранирует их. Значение по умолчанию — `500`, а допустимы целые числа не меньше `3`, что резервирует место под многоточие усечения. Жизненным циклом долговечного начального каталога и замен владеет [Agent Note о горячем обновлении каталога скиллов](../../../.agents/notes/implemented/feature/2026-07-27-skill-catalog-hot-refresh.md).

## Инструмент: `skill`

| Аргумент | Тип | Примечания |
|---|---|---|
| `name` | string (обязателен) | Точное имя скилла в kebab-case из списка доступных скиллов. |

Исполнение использует `session.header.cwd` вызывающего агента, чтобы чувствительные к рабочей области провайдеры разрешали побеждающий скилл. Успешный вызов возвращает каноническое `{ name, provider, resourceBase?, content }`, без каталожного ранжирования и внутренностей провайдера; его нативный презентер выдаёт один текстовый результат, содержащий `<skill_content name="...">`, `<skill_resources>` и `<skill_instructions>`.

Руководство по ресурсам разрешает относительно `resourceBase` только пути или URL, явно упомянутые инструкциями; скрипты, справочники и ассеты загружаются по требованию, и результат не перечисляет каталог скилла. Локальные провайдеры могут поставлять каталог, а удалённые или встроенные — URL или непрозрачное руководство по загрузке.

Неразрешённое имя сообщает, что скилл неизвестен или более недоступен. Недопустимые имена и скиллы, у которых `invocation.modelInvocable` равен `false`, дают различные результаты ошибок. `invocation.userInvocable` этот обращённый к модели инструмент не ограничивает.

Исполнение инструмента не добавляет синтетического контекстного сообщения. Его свежезагруженный результат уже записан как результат инструмента и доступен следующему шагу модели без дублирования тела. Только проекция каталога добавляет замещающие сводки.

## Model Experience

### Каталог сессии

#### What the model sees

Если существуют скиллы, вызываемые моделью, и этот точный инструмент `skill` видим, агент получает шаблон каталога ниже как долговечное сообщение роли user перед первым запросом, с одной зависящей от данных записью на каждый отсортированный скилл. Позднейшие изменения членства, описания или видимости дописывают полную замену в том же конверте `<available_skills>`; удаление всех скиллов дописывает пустой конверт с явным предписанием не использовать прежние имена. Заключительное предложение шаблона — правило против двойной загрузки: граница явного пользовательского жеста (описанный ниже слушатель pre-step) внедряет тот же вывод `renderSkillContent` (общий с `@deepseek-ai/dsh-skill`) инлайн, и каталог велит модели следовать этому блоку вместо повторной загрузки скилла через инструмент; шаблон замещающего каталога несёт то же предложение в обеих ветвях, включая опустошённый каталог.

##### Шаблон каталога скиллов

```markdown
<system-reminder>
A skill is a reusable set of task-specific instructions. The following skills are available in this session:

<available_skills>
- `<name>`: <normalized-and-capped-description>
</available_skills>

If the user names a skill, or the task clearly matches a skill's description, call the `skill` tool with the exact skill name before taking task actions. Load all applicable skills, then follow their full instructions. This catalog contains summaries only; do not infer or follow a skill's instructions until it has been loaded.
A user may also invoke a skill directly; its <skill_content> block then appears in this conversation. Follow it, and do not call the `skill` tool again for that skill.
</system-reminder>
```

#### Token effect

Повторяющаяся цена ввода растёт с числом скиллов и `catalogDescriptionMaxLength`; начальные токены каталога не отправляются, когда список пуст или инструмент скрыт либо затенён. Каждое действительное изменение каталога добавляет одно удержанное сообщение полной замены.

#### KV Cache effect

Начальный долговечный каталог дописывается после существующего переиспользуемого префикса. Динамические изменения — append-only история после этого каталога, поэтому более ранние переиспользуемые токены остаются нетронутыми, пока каждый заново дописанный каталог и позднейшие ходы образуют новый суффикс. Новый или возобновлённый экземпляр с изменившимся дайджестом может повлиять на переиспользование кэша с позиции заново дописанного каталога.

### Схема инструмента

#### What the model sees

Модель видит сгенерированную [схему `skill`](../../../docs/tool-catalog.ru.md#deepseek-aidsh-tool-skill).

#### Token effect

Фиксированная цена схемы на каждый запрос, где инструмент видим.

#### KV Cache effect

Префиксно-стабильно, пока определение и видимость инструмента не менялись. Затенение, ограничения или изменения жизненного цикла плагина могут инвалидировать переиспользование с этой схемы.

### Результат инструмента

#### What the model sees

Успешный вызов использует шаблон результата и приведённые ниже варианты руководства по ресурсам — управляемое провайдером, базовым каталогом, URL или непрозрачное.

##### Шаблон результата скилла

```markdown
<skill_content name="<escaped-name>">
<skill_resources>
<resource-guidance>
</skill_resources>

<skill_instructions>
<provider-owned-instruction-body>
</skill_instructions>
</skill_content>
```

##### Руководство по ресурсам, управляемым провайдером

```markdown
Resources for this skill are managed by provider "<provider>".
Load referenced resources only as needed.
```

##### Руководство по ресурсам: базовый каталог

```markdown
Base directory for this skill: <path>
Resolve relative paths mentioned by this skill against the base directory before using them. Load referenced resources only as needed.
```

##### Руководство по ресурсам: базовый URL

```markdown
Base URL for this skill: <url>
Resolve relative URLs mentioned by this skill against the base URL before using them. Load referenced resources only as needed.
```

##### Непрозрачное руководство по ресурсам

```markdown
Resources for this skill: <description>
Load referenced resources only as needed.
```

#### Token effect

Загруженные инструкции — зависящие от данных токены результата инструмента, повторно отправляемые на позднейших шагах до компакции; дублирующей копии через `agent.inject()` не создаётся.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Ошибки инструментов

#### What the model sees

Недопустимые или устаревшие выборы возвращают ровно `Error: invalid skill name "<name>"`, `Error: skill "<name>" is unknown or no longer available` или `Error: skill "<name>" is not available for model invocation`. Текст, который бросает провайдер при поиске, зависит от данных и получает ту же обёртку `Error: <message>`.

#### Token effect

Только неудавшийся вызов добавляет эти удержанные токены.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Внедрение при явном пользовательском вызове

#### What the model sees

Ограниченный пробельными границами токен `/name` где угодно в заявленном сообщении пользователя, называющий вызываемый пользователем скилл из каталога рабочей области, внедряет полную отрисовку `<skill_content>` этого скилла (точная форма шаблона результата выше) как контекст инструкций роли `user`, дописываемый после всех прочих внедрений этого шага — сначала фон, материал для действия последним. Сканируется только прямой пользовательский ввод, проверка выполняется по загруженному определению, а неизвестные или отключённые пользователем имена остаются обычной прозой. Это единственная точка входа для скиллов `disable-model-invocation`, которые каталог и инструмент `skill` никогда не раскрывают; заключительное предложение каталога велит модели следовать внедрённому блоку вместо его повторной загрузки.

#### Token effect

Каждый жест добавляет в этот ход одно отрисованное тело скилла как внедрённый контекст — того же размера, что результат инструмента для того же скилла, оплачиваемый детерминированно по запросу пользователя, а не по усмотрению модели. Повторные жесты для одного скилла внутри одного шага внедряются один раз.

#### KV Cache effect

Append-only; внедрение оказывается после переиспользуемого префикса запроса внутри пакета сообщений шага и не инвалидирует существующие записи KV-кэша.

## Known Limitations and Deferred Work

- **Каталог опускает `whenToUse`, источник и метаданные провайдера** — маршрутизация основана только на имени и ограниченном описании; `whenToUse` остаётся метаданными провайдера и не отрисовывается даже загружающей обёрткой.
- **Загруженные тела инструкций не имеют потолка размера** — провайдер может вернуть скилл, достаточно крупный, чтобы поглотить значительный контекст следующего шага; усекаются только описания каталога.
- **Ресурсы — руководство, а не вложения** — инструмент сообщает базовый каталог/URL/непрозрачную подсказку, но не перечисляет и не подтягивает упомянутые файлы ради модели.
- **Загрузка — одноразовый текст** — нет частичного, потокового или кэшированного доступа к содержимому, когда удалённый провайдер медлителен или тело скилла крупно.
- **Замена каталога — целым списком** — одно изменившееся имя или описание дописывает все текущие видимые сводки; это удерживает вывод устаревших имён явным, но стоит токенов, пропорциональных каталогу.
- **Тела не версионируются** — правки только тела не меняют дайджест каталога и не уведомляют модель; позднейший вызов инструмента читает текущее содержимое провайдера, тогда как более ранние результаты инструментов остаются историческими фактами.
