# @deepseek-ai/dsh-storage-domain

[English](README.md) | [中文](README.zh.md) | Русский

Доменная форма данных для хаба хранения DeepSeek Harness: открывает вводимый сервис `ctx.storageDomain` и соответствующую проекцию `ctx.storage.domain` после регистрации каждого настроенного бэкенда. Домен объявляется однократно через `defineDomain` (zod-схемы записей, типы, выведенные из `z.infer`), открывается через `DomainFacility.open` и обслуживается из авторитетного состояния в памяти — чтения синхронны, записи сериализуются на одной цепочке для каждого домена, достигают долговечности сначала на маршрутизированном бэкенде, затем обновляют память и порождают `domain/changed`. Открывающий потребитель владеет жизненным циклом дескриптора и освобождает его через `Domain.close()` (идемпотентно; обычно это его собственный disposer `ctx.effect`); домены, оставшиеся открытыми к моменту размонтирования плагина, закрывает сама facility.

Обоснование дизайна, семантика открытия и разделение storage/доменного слоя живут в [Agent Note](../../../.agents/notes/proposed/architecture/2026-07-24-domain-kv-storage-and-workspace.md).

## Конфигурация

| ключ | значение |
| --- | --- |
| `backend` | Имя бэкенда по умолчанию для каждого домена (обязательно; универсально правильного носителя не существует). |
| `routes` | Переопределения по доменам: имя домена → имя бэкенда. |

## Влияние на модель

### Долговечное доменное состояние

#### Что видит модель

Ничего. Пакет не регистрирует инструментов, не вводит промптов и не дописывает событий сессии; он хранит внесессионные данные (записи рабочих пространств, будущие сопутствующие записи сессий) за `ctx.storageDomain` и порождает только внутрипроцессное событие `domain/changed`, которое доходит до модели, лишь если какой-нибудь пакет-потребитель отрисует его через собственную задокументированную поверхность.

#### Влияние на токены

Ноль. Ни один текст этого пакета не входит ни в один запрос к модели.

#### Влияние на KV-кэш

Не зависит от них: чтения и записи доменов никогда не касаются префиксов запросов, поэтому ничто здесь не может инвалидировать переиспользование провайдерского кэша.

## Известные ограничения и отложенная работа

- **Видимость изменений ограничена одним процессом** — `domain/changed` — внутрипроцессное событие; второй хостовый процесс или переподключающийся GUI не увидит изменений, пока не приземлится отложенный в Agent Note межпроцессный паттерн ревизий.
- **Нет транзакций между таблицами, вторичных индексов или многосегментных ключей** — каждая операция записи затрагивает ровно одну запись; триггеры и точки переделки для этих расширений перечислены в списке отложенной работы Agent Note.
