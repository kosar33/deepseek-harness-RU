# @deepseek-ai/dsh-subagent-claude-code

[English](README.md) | [中文](README.zh.md) | Русский

Этот пакет регистрирует провайдера субагентов Claude Code, именуемого через Profile и по умолчанию называющегося `claude-code`. Каждый принятый запуск вызывает официальный Claude Agent SDK в рабочем каталоге делегирующей Session, позволяет закреплённому SDK выбрать установленный платформенный CLI, подаёт одно самодостаточное текстовое задание и возвращает либо строгий финальный ответ, либо отдельную безопасную диагностику отказа через общий контракт результата [`dsh-subagent`](../subagent/README.ru.md).

## Старт и владение

`start(request)` принимает только непустую последовательность текстовых блоков и выводит cwd ребёнка из родительской Session. Он создаёт один приватный `AbortController`, вызывает официальный SDK-метод `query()` и публикует запуск лишь после того, как hook `spawnClaudeCodeProcess` SDK предоставил живой CLI-дескриптор, которым владеет [`dsh-subprocess`](../../subprocess/subprocess/README.md). Неудача или отмена до публикации закрывает query, завершает любое захваченное дерево процессов, дожидается его выхода и отклоняет `start()`.

SDK получает точную склеенную текстовую задачу. Провайдер итерирует полный поток сообщений SDK и принимает только сообщение `result` с `subtype: "success"`, `is_error: false` и непустым `result`, за которым следует нормальное завершение итератора. Каждая неудача по-прежнему отображается в `error`: четыре error-подтипа в Agent SDK 0.3.220 сохраняют свою точную категорию, успех с пометкой ошибки или пустой становится `invalid-success`, отсутствующий результат становится `missing-result`, неклассифицированная неудача query становится `unknown`, а ранний выход CLI становится `process-exit`. Диагностика также называет текущую стадию `query-start`, `query-run`, `process` или `teardown` и независимо включает наблюдаемые код выхода и сигнал. Провайдер не производит ни `max-tokens`, ни `refusal`.

Локальная отмена выигрывает гонку за результат и отображается в `aborted` без диагностики отказа. `dispose()` идемпотентна: она прерывает запуск, просит SDK-query закрыться, вызывает общую эскалацию завершения дерева процессов и дожидается выхода всего дерева. Грациозное закрытие SDK выражает намерение протокола; дескриптор subprocess остаётся авторитетом по полному завершению процессов. Отклонения на старте и teardown выставляют через сообщение Error одни и те же фиксированные безопасные факты стадии и процесса, тогда как исходная ошибка продукта или Host остаётся на внутренней цепочке причин и в Host-журнале Provider. Неудача результата и независимая неудача teardown остаются раздельными.

## Нативные настройки и взаимодействие

Провайдер намеренно опускает опцию SDK `settingSources`. Поэтому официальный SDK читает обычные пользовательские, проектные и локальные настройки Claude хоста относительно cwd родительской Session, включая нативное состояние аккаунта и конфигурацию продукта. Провайдер ни копирует, ни фильтрует эти файлы и не создаёт и не изменяет состояние входа в аккаунт. Выбранный Profile `permissionMode` — единственная override на уровне query: Claude Code по-прежнему владеет своими настройками и песочницей, а выбранный нативный режим решает, как этот безнадзорный query обрабатывает проверки разрешений.

Каждый query задаёт `persistSession: false` и отключает `AskUserQuestion`. Кроме bypass-режима, `canUseTool` немедленно отклоняет запросы, всё ещё требующие человеческого одобрения. Plan-режим также помещает `ExitPlanMode` в `disallowedTools` SDK, поэтому нативные настройки не могут заранее одобрить переход обратно к исполнению, и модель обязана вернуть готовый план своим финальным ответом. MCP elicitation отклоняется, известный отказный fallback-диалог отменяется, а необъявленные виды диалогов используют поведение SDK «нет диалога — неудача». Эти решения никогда не ждут пользовательского интерфейса. Когда к неудавшемуся запуску причастны оба факта, `SubagentResult.diagnostic` содержит структурированную строку отказа первой, а последнее безопасное решение о разрешениях — второй; общий результатный предел ограничивает весь текст 4096 байтами UTF-8. Успешные и локально отменённые запуски не раскрывают ни один из захваченных фактов.

## Возможности и контекст

Провайдер не объявляет опциональных стартовых возможностей и сообщает `inheritsParentContext: false`. Claude Code получает автономное текстовое задание и cwd родительской Session, но не родительский диалог, персону, фильтр инструментов, политику глубины или контракт структурированного вывода. Каждый запуск располагает независимым SDK-query, контроллером отмены, процессом CLI и неперсистентной продуктовой сессией.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---|---|
| `providerName` | `claude-code` | Непустое имя в реестре `ctx.subagents`; каждому смонтированному экземпляру нужно уникальное значение. |
| `env` | `{}` | Явная среда SDK/CLI, накладываемая поверх общей очищенной от учётных данных родительской среды. |
| `permissionMode` | `dontAsk` | Нативная неинтерактивная политика разрешений, фиксированная для каждого запуска этого экземпляра Provider. |
| `disposeGraceMs` | `3000` | Положительная конечная отсрочка в миллисекундах, не больше [`MAX_TIMER_DELAY_MS`](../../util/timeout/README.md), между ступенями завершения общего владельца дерева процессов; затем освобождение ресурсов дожидается выхода всего дерева. |

| Значение `permissionMode` | Нативное поведение |
|---|---|
| `dontAsk` | Отклонять операции, ещё не получившие авторизации, вместо показа запроса. |
| `acceptEdits` | Принимать правки файлов; любой оставшийся запрос разрешения отклоняется безнадзорным callback-ом. |
| `auto` | Позволять нативному классификатору Claude Code разрешать или отклонять запросы разрешений. |
| `plan` | Работать в нативном режиме планирования, отклонять одобрение исполнения и вернуть готовый план как финальный ответ. |
| `bypassPermissions` | Явно выставлять опасное подтверждение SDK и обходить проверки разрешений. |

В production `pathToClaudeCodeExecutable` опускается, поэтому Agent SDK 0.3.220 сам выбирает подходящий нативный `claude` или `claude.exe` из собственного платформенного пакета и передаёт эту абсолютную команду через custom-spawn hook в `dsh-subprocess`. Провайдер не инспектирует `PATH`, не реализует выбор платформы и не откатывается к host-овому `claude`. Нативные настройки и аутентификация остаются авторитетными, а `permissionMode` — единственная policy-override на уровне query. Плагин не выбирает модель, не создаёт домашний каталог продукта, не входит в аккаунт и не прощупывает его. Переменные окружения, похожие на учётные данные, удаляются до применения явной накладки `env`, поэтому API-ключ или токен, предназначенный ребёнку, должен передаваться там. Нецелевые переменные конечных точек вроде `ANTHROPIC_BASE_URL`, как и обычные значения окружения вроде `PATH` и `HOME`, остаются унаследованными, пока их не переопределят; `PATH` не выбирает исполняемый файл Claude.

Этот пакет — опциональный Profile Bundle. Установите его в целевой Profile, затем перезапустите этот Profile; установка приносит в него закреплённый Agent SDK и один совместимый платформенный CLI-payload, тогда как объявленный слой `cordis.patch.yml` регистрирует только спящего Host-провайдера `claude-code` и не запускает никакого процесса Claude. Удаление пакета отзывает этого провайдера и его приватное runtime-замыкание при следующем старте Profile.

```sh
dsh plugin --profile <name> add @deepseek-ai/dsh-subagent-claude-code
dsh plugin --profile <name> remove @deepseek-ai/dsh-subagent-claude-code
dsh --profile <name>
```

Установка управляет доступностью на Host, а не разрешениями модели. Bundle поставляет спящую строку `claude-code` по умолчанию; Profile может заменить полный config этой строки или смонтировать дополнительные строки с отличающимися значениями `providerName`, `permissionMode` и `env`. Загрузка экземпляра не запускает процесс Claude, пока связанный инструмент его не вызовет. Каждая строка `dsh-tool-subagent` называет одного провайдера и нуждается в собственном `toolName`, поэтому модель видит статические инструменты, а не динамический селектор провайдеров. Полные Agent Presets несут соответствующую дефолтную продуктовую строку инструмента с `disabled: true`; скопируйте пресет и удалите это поле, чтобы показать `subagent_claude_code` только агентам, собранным из копии. Его политика `one-shot` держит вызовы с опущенным или `false` `run_in_background` на переднем плане, тогда как явный `true` возвращает принадлежащий родителю Job id для `job_output` или `job_kill`. Базовый host- и full-пресеты уже дают общий реестр Job и управление.

Автономная композиция ниже показывает полную явную возможность. Profile на основе `@deepseek-ai/dsh-base` сохраняет свои существующие строки Job, добавляет продуктовые строки провайдера и инструмента и не монтирует дублирующих Job-сервисов.

```yaml
- id: subagent-claude-safe
  name: '@deepseek-ai/dsh-subagent-claude-code'
  config:
    providerName: claude-safe
    permissionMode: dontAsk
    env:
      ANTHROPIC_API_KEY: !!js process.env.ANTHROPIC_API_KEY

- id: subagent-claude-bypass
  name: '@deepseek-ai/dsh-subagent-claude-code'
  config:
    providerName: claude-bypass
    permissionMode: bypassPermissions
    env:
      ANTHROPIC_API_KEY: !!js process.env.ANTHROPIC_API_KEY
```

```yaml
- id: jobs
  name: '@deepseek-ai/dsh-jobs-local'

- id: tool-jobs
  name: '@deepseek-ai/dsh-tool-jobs'

- id: tool-subagent-claude-safe
  name: '@deepseek-ai/dsh-tool-subagent'
  disabled: true
  config:
    provider: claude-safe
    toolName: subagent_claude_safe
    backgroundMode: one-shot
    maxDepth: provider-managed

- id: tool-subagent-claude-bypass
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: claude-bypass
    toolName: subagent_claude_bypass
    backgroundMode: one-shot
    maxDepth: provider-managed
```

## Продуктовая совместимость и свидетельства

Runtime-зависимость закреплена на `@anthropic-ai/claude-agent-sdk@0.3.220`, чьи восемь платформенных пакетов несут Claude Code 2.1.220. Обычная установка выбирает один payload под текущие ОС, CPU и libc Linux. Для текущего payload darwin-arm64 `npm pack --dry-run --json` сообщает 74 858 812 упакованных байт и 256 908 856 распакованных; другие платформы могут отличаться, и эти значения — раскрытие информации, а не порог установки. Безключевой тест реального продукта прогоняет выбранный SDK CLI против loopback-фикстуры Messages и утверждает, что argv общего subprocess начинается с нативного исполняемого файла того платформенного пакета. Композиция Loader доказывает, что установка Bundle регистрирует только спящего провайдера Claude Code и не запускает продуктовых процессов.

Установка с опущенными опциональными зависимостями, использование неподдерживаемой платформы или потеря выбранного payload оставляют регистрацию провайдера спящей, но заставляют первую делегацию упасть на стартовой черте SDK. Вызывающий получает безопасный факт отказа `query-start` / `unknown`; нативная ошибка payload остаётся только на внутренней цепочке причин и в Host-журнале Provider. Провайдер ни прощупывает host-CLI, ни повторяет попытку с ним.

Композиция Loader доказывает, что дефолт Bundle, два дополнительных именованных экземпляра Claude и существующий пакет Codex сосуществуют, не запуская ни одного из двух продуктов.

Авторизация распространения владельца проекта, ограниченная идентичностью, покрывает официальный SDK и официальные CLI/платформенные payload, объявляемые каждой версией SDK. [`THIRD_PARTY_NOTICES.md`](../../../THIRD_PARTY_NOTICES.md) раскрывает текущее замыкание опциональных payload, не классифицируя их заявленные условия как пермиссивные; несвязанные непермиссивные runtime-зависимости по-прежнему валят гейт notices.

## Model Experience

### Запрос ребёнка

#### What the model sees

Ребёнок Claude Code получает автономное текстовое задание как один свежий SDK-query. Его рабочее пространство — cwd родительской Session; модель, системные инструкции, инструменты, песочница и аутентификация приходят из нативных настроек Claude, конфигурация Profile выбранного экземпляра Provider фиксирует среду и неинтерактивный режим разрешений query, а версия исполняемого файла приходит из закреплённого платформенного payload SDK в Bundle.

#### Token effect

Ребёнок платит за независимый контекст и query Claude Code. Токены ребёнка не попадают в контекст родителя.

#### KV Cache effect

Независимо от кэша родительского запроса. Переиспользование зависит только от собственной модели, инструкций, инструментов, нативных настроек Claude Code и свежего query.

### Планирование и результаты родителя, опосредованно

#### What the model sees

Через `dsh-tool-subagent` вызов на переднем плане даёт родителю строгий финальный ответ Claude Code либо ошибку, содержащую причину остановки и опциональную безопасную диагностику для незавершённого результата. Та диагностика может различить фиксированную категорию ошибки SDK, стадию жизненного цикла и наблюдаемый исход процесса, не копируя сырой продуктовый текст. Фоновый вызов сначала возвращает Job id; общие job-управления позже доставляют уведомление о завершении, выставляют тот же финальный ответ или детали статуса неудачи через `job_output` и позволяют `job_kill` запросить отмену. Рассуждения Claude Code, активность инструментов, промежуточные сообщения, stderr, диффы рабочего пространства, расход токенов, продуктовые id, входы инструментов и сырые payloads протокола не копируются в родительскую Session.

#### Token effect

Ввод на переднем плане растёт на удержанный финальный ответ или ошибку. Фоновый ввод также включает подтверждение старта, уведомление о завершении и любые результаты `job_output`, `job_kill` или последующих статусов; токены ребёнка по-прежнему не попадают в родительский контекст. Сам по себе этот провайдер не добавляет никакой схемы родительского инструмента.

#### KV Cache effect

Append-only: передний план добавляет один результат после переиспользуемого родительского префикса, а фон дописывает подтверждение Job, уведомление и последующие управляющие результаты или результаты сбора. Фоновое планирование может добавить ход, вызванный уведомлением, но ни одно из этих сообщений не переписывает прежний префикс.

## Known Limitations and Deferred Work

- **Один свежий query и процесс на запуск** — нет продолжения, возобновления, пула, потока прогресса или персистентности продуктовой сессии.
- **Статичный выбор экземпляра** — строки Profile фиксируют имена провайдеров и привязки инструментов; вызовы не могут выбрать провайдера динамически, и каждому выставленному инструменту нужен уникальный `toolName`.
- **Настройки хоста намеренно авторитетны** — проектные и пользовательские настройки могут менять модель, инструменты и поведение; провайдер не даёт фильтрованного или герметичного production-режима.
- **Аутентификация и состояние аккаунта остаются нативными** — Bundle поставляет CLI, но не создаёт аккаунт, не входит в него и не переписывает настройки Claude; неудачи конфигурации и аутентификации проявляются со своей стадией жизненного цикла и безопасным fallback `unknown`, а не отдельной публичной классификацией.
- **Платформенный payload SDK требуется к моменту делегации** — установки без опциональных зависимостей, неподдерживаемые платформы и отсутствующие или повреждённые payload падают на первом query; host-CLI fallback отсутствует.
- **Пути человеческого взаимодействия нет** — `AskUserQuestion` отключён, запросы разрешений отклоняются, MCP elicitation отклоняется, а блокирующие диалоги завершаются закрытым отказом вместо приостановки.
- **Payload ассистента — только финальный текст** — неудавшийся запуск может вдобавок раскрыть отдельную безопасную диагностику; рассуждения, промежуточные сообщения, трафик инструментов, расход токенов, stderr и диффы рабочего пространства остаются внутри продукта, а общие Job id, уведомления и статус приходят из общего job-рантайма.
- **Опциональных общих возможностей нет** — схемы вывода, персоны детей, фильтрация инструментов и контроль глубины harness отклоняются общим сервисом для этого провайдера.
- **Нет тайм-аута по настенным часам и отката побочных эффектов** — длительную работу отменяет вызывающий, а файлы или внешние системы, изменённые до отмены, не восстанавливаются.
