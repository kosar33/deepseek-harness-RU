# @deepseek-ai/dsh-subagent-dsh-sdk

[English](README.md) | [中文](README.zh.md) | Русский

Провайдер SDK запускает каждый субагент как полный рантайм DeepSeek Harness в свежем субпроцессе, управляя им через stdio JSON-RPC посредством [клиента TypeScript SDK](../../sdk/client/README.md). Это второй out-of-process бэкенд рядом с [`subagent-acp`](../subagent-acp/README.ru.md); различие — в формате передачи и контракте ребёнка: бэкенд ACP управляет любым агентом Agent Client Protocol, а этот управляет именно рантаймом SDK харнесса (bin `dsh-jsonrpc-agent` или упакованный исполняемый файл), поэтому ребёнок — полный равноправный харнесс: собственная композиция, задаваемая `cordis.yml`, персистентность сессии, маршрут модели и инструменты.

## Запуск и владение

`start(request)` разрешает рабочий каталог ребёнка, порождает рантайм через `DeepSeekHarness` и завершает рукопожатие `initialize` (с настроенным маршрутом `provider`/`model` и опциональным ограничением выходных токенов `maxTokens`), прежде чем разрешиться. Разрешение поэтому означает, что рантайм ребёнка готов и владение перешло к вызывающему. При сбое порождения, рукопожатия или отмене до публикации операция отклоняется только после того, как субпроцесс завершил работу и был собран; сбой разрешения рабочего каталога отклоняется ещё до порождения какого-либо процесса.

Рабочий каталог разрешается точно как в бэкенде ACP — через общие out-of-process помощники seam'а ([`dsh-subagent`](../subagent/README.ru.md)): настроенное переопределение `cwd`, когда задано (валидируется однократно при загрузке), иначе cwd делегирующей родительской сессии — никогда собственный cwd серверного процесса. Разрешённый путь становится cwd процесса ребёнка и cwd рабочего пространства его сессии SDK.

Возвращаемый id запуска создаётся в пространстве имён родителя; id сессии рантайма ребёнка существует только внутри процесса ребёнка. После публикации провайдер владеет одной активностью SDK и читает ответ ребёнка из его событий сессии: последнее полное непустое `assistant/message` (сообщение с пустым содержимым, записывающее usage, пропускается) либо накопленный поток `text-delta`, когда такого сообщения нет. Частичный вывод остаётся доступным после отмены или ошибки.

`dispose()` идемпотентен: он локально завершает результат как `aborted` (отмены промпта на уровне передачи нет), затем закрывает рантайм — ограниченный по времени протокольный запрос `shutdown`, за которым следует общая лестница stdin-EOF → SIGTERM → SIGKILL до фактического выхода.

## Отображение причин завершения

Клиент SDK возвращает собственную дочернюю активность, а не результат промпта. Провайдер читает последнее долговечное `turn/end` внутри этой активности и отображает его в словарь seam'а: `completed` → `completed`, `max-tokens` → `max-tokens`, `aborted` → `aborted`; всё прочее — `error`, `interrupted`, `disposed`, будущий вариант или активность без хода — отображается в `error`, поэтому некорректная остановка никогда не сообщается как успех. Транспортные сбои после публикации сводятся к `stopReason: 'error'` через диагностический приёмник `onError` (подключённый к `ctx.logger.warn`); контракт seam'а запрещает отклонение `result`.

## Возможности и контекст

Провайдер не объявляет стартовых возможностей (`outputSchema`/`depthLimit`/`toolFilter`/`persona` — все false) и сообщает `inheritsParentContext: false`: ребёнок — свежий рантайм в другом процессе, и единственный производный от родителя ввод — cwd рабочего пространства. Развёртывания `dsh-tool-subagent` над этим провайдером задают `maxDepth: 'provider-managed'` — дочерний харнесс владеет собственным бюджетом рекурсии.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---|---|
| `providerName` | `dsh-sdk` | Имя в реестре `ctx.subagents`. |
| `command` | требуется | Исполняемый файл, порождаемый на каждый запуск (bin рантайма ребёнка или упакованный exe). |
| `args` | `[]` | Аргументы команды (обычно путь к `cordis.yml` ребёнка). |
| `cwd` | cwd родительской сессии | Переопределение рабочего каталога; та же валидация, что у [`subagent-acp`](../subagent-acp/README.ru.md). |
| `provider` | `deepseek-official` | Маршрут провайдера, отправляемый в `initialize` ребёнка. |
| `model` | `deepseek-v4-flash` | Модель, отправляемая в `initialize` ребёнка. |
| `maxTokens` | умолчание адаптера или маршрута провайдера | Ограничение выходных токенов на запрос, отправляемое в `initialize` ребёнка; применяется к корневому агенту ребёнка и его внутрипроцессным потомкам. |
| `env` | `{}` | Явное окружение ребёнка, наложенное поверх очищенного от учётных данных окружения родителя (например собственный `DEEPSEEK_API_KEY` ребёнка или `DSH_CORDIS_CONFIG`). |
| `shutdownTimeoutMs` | `1000` | Ограничение времени на протокольный обмен `shutdown` при освобождении ресурсов. |
| `disposeEofGraceMs` | `6000` | Grace-период после stdin EOF до платформенного завершения. |
| `disposeGraceMs` | `3000` | Grace-период подтверждения выхода после завершения; POSIX также ждёт столько же после SIGTERM до SIGKILL. |

```yaml
- id: subagent-dsh-sdk
  name: '@deepseek-ai/dsh-subagent-dsh-sdk'
  config:
    providerName: dsh-sdk
    command: node
    args: ['./packages/examples/jsonrpc-demo/lib/bin.js', './examples/jsonrpc-agent/cordis.yml']
    maxTokens: 49152
    env:
      DEEPSEEK_API_KEY: !!js process.env.DEEPSEEK_API_KEY
- id: tool-subagent
  name: '@deepseek-ai/dsh-tool-subagent'
  config: { provider: dsh-sdk, toolName: subagent, maxDepth: 'provider-managed' }
```

## Граница процесса

Окружение ребёнка — это база `scrubbedParentEnv()` seam'а [`dsh-subprocess`](../../subprocess/README.md): ambient-имена, похожие на учётные данные, и `DSH_*` отброшены, а явные значения `config.env` вливаются после очистки. Ребёнка порождает клиент SDK, а не `ctx.subprocess` (задокументированное в README субпроцессов исключение для транспортов под управлением SDK), поэтому этот бэкенд применяет очистку сам. Формат протокола JSON-RPC — настоящая граница сериализации.

У пакета нет default export. Иначе разворачивание загрузчиком Cordis скрыло бы именованные метаданные `inject`; см. [постмортем 0001](../../../docs/postmortem/0001-acp-default-export-drops-inject.ru.md).

## Влияние на модель

### Запрос дочернего агента

#### Что видит модель

Модель рантайма ребёнка получает автономную задачу как сообщение пользователя плюс собственные настроенные системный промпт, инструменты и свежую сессию этого рантайма. Она не получает беседу родителя. Этот провайдер не объявляет опциональных стартовых возможностей, поэтому локальный сервис отклоняет запросы персоны, фильтрации инструментов, ограничения глубины или структурированного вывода вместо того, чтобы молча их опускать.

#### Влияние на токены

Ребёнок платит за независимый полный контекст и собственную многошаговую историю. Эти токены никогда не входят в контекст родителя.

#### Влияние на KV-кэш

Независимо от родительского кэша запросов. Каждый SDK-ребёнок может повторно использовать только префиксы, идентичные при его собственных провайдере, модели, композиции и истории; шаги ребёнка в остальном растут append-only.

### Результат инструмента родителя, опосредованно

#### Что видит модель

Через `dsh-tool-subagent` родитель получает только финальный текст ассистента ребёнка (или накопленный частичный текст) либо точную ошибку причины завершения того потребителя, но не промежуточные сообщения и не трафик инструментов.

#### Влияние на токены

Ввод родителя растёт только на финальный результат или ошибку, которые зависят от данных и удерживаются до компакции. Сам провайдер не добавляет никакой родительской схемы.

#### Влияние на KV-кэш

Append-only; новое видимое содержимое следует за повторно используемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Свежий процесс рантайма на каждый запуск** — без пула; рантайм харнесса поднимает полное дерево плагинов, поэтому стоимость порождения на запуск выше, чем у типичного ребёнка бэкенда ACP.
- **Нет опциональных стартовых возможностей** — родитель не может применить внутри процесса ребёнка `outputSchema`, ограничение глубины, фильтры инструментов или персону; настройте вместо этого собственный `cordis.yml` ребёнка.
- **Транскрипт ребёнка остаётся в собственном корне сессий ребёнка** — журнал родителя записывает лишь вызов/результат инструмента делегирования (правило изоляции ребёнка в seam'е); потоковый канал `session.event` используется для извлечения вывода и не переносится в журнал родителя.
- **Только локальные процессы детей** — разрешённый cwd — локальный путь; удалённому рантайму понадобился бы собственный бэкенд.
