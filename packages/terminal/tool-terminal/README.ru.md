# @deepseek-ai/dsh-tool-terminal

[English](README.md) | [中文](README.zh.md) | Русский

Шесть инструментов, видимых модели, над `ctx.terminals`: `terminal_open`, `terminal_send`, `terminal_read`, `terminal_signal`, `terminal_close` и `terminal_list`. Каждая операция требует точного инициирующего `Agent`, поэтому модель не может адресовать терминал другого агента, даже если узнает его id.

`terminal_send(run_in_background: true)` переиспользует `ctx.jobs`; предпроверка задачи и эксклюзивная на уровне сессии резервация отправки PTY-сервисом происходят до возврата id задачи, завершение собирается через `job_output`, а `job_kill` доставляет `SIGINT` группе процессов переднего плана. Отправки переднего плана используют карточки вызова/результата терминала. Фоновые отправки используют универсальную карточку execute; open, read, signal, close и list используют универсальные карточки `execute`, `read`, `execute`, `delete` и `read` соответственно. Ни один инструмент не объявляет `locations`.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `enableRunInBackground` | `true` | открывает и принимает `run_in_background`; false опускает поле схемы и отвергает принудительный необъявленный аргумент |
| `maxResultBytes` | `262144` | потолок UTF-8 (минимум `64`) для каждого полного результата терминала или вывода PTY-задачи после метаданных ожидания, сессии, пагинации, усечения и статуса задачи |

Оба значения проверяются при загрузке. Минимальный потолок результата удерживает каждый выданный реестром id сессии или задачи видимым в подтверждении его создания. Когда результат превышает `maxResultBytes`, рендер резервирует место под управляющие метаданные и маркер усечения, если те помещаются; разрезы сохраняют границы UTF-8. Колбэк финального содержимого каждого определения терминала применяет тот же потолок после нормализованных отказов политики pre-, around- и post-execute, запретов, коротких замыканий, замен или блокировок; структурированный многоблочный результат политики сохраняет свою форму.

## Опыт модели

### Системный промпт

#### Что видит модель

Плагин вносит эту фиксированную секцию наставлений:

##### Наставления терминала

```markdown
Use a terminal session only when work needs persistent terminal state or interactive stdin; prefer shell/read/write/edit for bounded one-shot operations. Track every terminal session id and close sessions that no longer matter. An inferred_idle or timeout result does not prove the foreground command exited.
```

#### Влияние на токены

Небольшая фиксированная стоимость входа на каждом запросе, пока плагин активен.

#### Влияние на KV-кэш

Префикс стабилен, пока область регистрации и текст наставлений неизменны.

### Схемы инструментов

#### Что видит модель

Шесть сгенерированных схем перечислены в [разделе каталога `dsh-tool-terminal`](../../../docs/tool-catalog.ru.md#deepseek-aidsh-tool-terminal). Их фиксированные токены схем присутствуют всякий раз, когда этот плагин активен; привязанная к агенту фильтрация инструментов может их скрыть.

#### Влияние на токены

Фиксированная стоимость схем на запросах, где инструменты видимы.

#### Влияние на KV-кэш

Префикс стабилен, пока видимость инструментов и их определения неизменны.

### Результаты инструментов и контекст задачи

#### Что видит модель

Spawn возвращает id и ограниченный MOTD. Send/read возвращают ограниченный текст терминала плюс маркеры готовности/истории. Фоновый режим возвращает универсальный id задачи. Каждый принадлежащий терминалу или произведённый политикой однотекстовый результат ограничивается значением `maxResultBytes` после нормализованных ошибок инструмента или пайплайна, запретов, коротких замыканий, замен, блокировок и универсального текста статуса задачи. Структурированные многоблочные результаты политики сохраняют свою форму. Результаты остаются в истории сессии до компакции; инкрементальные чтения задачи не повторяют уже использованный вывод. Программные вызывающие получают типизированные снапшоты сессии, ограниченные read/send DTO провайдера, исходы signal и close либо `{ kind: "background", jobId }`; нативный рендер применяет описанный выше потолок представления.

#### Влияние на токены

Принадлежащие терминалу и произведённые политикой однотекстовые результаты зависят от данных и ограничены значением `maxResultBytes`; политика, намеренно замещающая содержимое структурированным многоблочным, сама задаёт границу этого содержимого. Каждый возвращённый результат остаётся в истории до компакции.

#### Влияние на KV-кэш

Append-only; новые результаты следуют за переиспользуемым префиксом запроса.

## Известные ограничения и отложенная работа

- Не открыто ни одной схемы именованной последовательности клавиш, TUI, BEL, изменения размера, автозапуска или разделения между агентами.
- Фоновый режим требует и `@deepseek-ai/dsh-jobs`, и его видимого модели контроллера.
