# @deepseek-ai/dsh-client-test-runtime

[English](README.md) | [中文](README.zh.md) | Русский

jsdom-рантайм slot-тестов для спецификаций клиентских возможностей: настоящий `Context` Cordis, производственные `SlotRegistry` и UI-рендерер, собранные вокруг типизированных двойников сессий и рабочих пространств. Наборы тестов возможностей упражняют объявление, регистрацию, скоуп, хранилище, inject, отрисовку, обновления и освобождение ресурсов без ручной сборки механизма под каждый набор — и без второй реализации какой-либо производственной логики.

Двойники реализуют те же внешние интерфейсы, которые возможности получают через ctx (`TestSessions implements ISessions`, `TestWorkspaces implements IWorkspaces`; каждая сессия-фикстура — это `FixtureSession implements SessionFace`; `stubSettingsScope` — это `SettingsScope` с управляемыми тестом публикациями и шпионом записи), поэтому изменение производственного интерфейса ломает стенд на этапе компиляции вместо тихого расползания. Материализация provide-бандлов исполняет производственный `SessionProvideChannel` — единственную реализацию, разделяемую с `SessionRuntime`. Фикстуры подают простые данные: строки списков, снапшоты беседы (патчируемые immer через `updateSnapshot`), значения проекций и стабы поведения, типизированные как `ISession` и падающие громко, когда спецификация вызывает нестабленный глагол. Типизированный `provide()` ограничивает фейки для объявленных имён сервисов значением `Partial` внешнего интерфейса этого сервиса.

Локальные DOM-снапшоты: `declare(children)` регистрирует автоматический фрейм, чьи обёртки `<div data-slot>` по каждому ключу служат корнями снапшотов; `renderSlot(key, owner)` возвращает локальный для slot'а вид (контейнер, скоупированные запросы Testing Library, обновление на месте через `update(owner)`); зарегистрированный сериализатор снапшотов сворачивает хэши классов CSS-модулей (`_frame_a1b2c3` → `frame`), чтобы файлы `.snap` оставались структурными, и сжимает внутренности `<svg>` до отпечатка `data-content`. Наборам, которым нужен собственный фрейм страницы, служит `root.declare(children, Frame)`; `mount(plugin)` запускает настоящий fiber с падающими громко предварительными проверками сервисов, а `dispose()` разбирает виды, fiber'ы возможностей, отчеканенные скоупы и сохранённое состояние хранилищ по одной оси.

Не входит в граф плагинов продукта (нет `dsh.client`); пакеты возможностей зависят от него только через `devDependencies`.

## Model Experience

Нет: этот пакет — браузерная тестовая инфраструктура; ничто отсюда не доходит до запроса к модели.

#### KV Cache effect

Нет; этот пакет ни собирает, ни отправляет запрос к провайдеру.

## Известные ограничения и отложенная работа

- **Потребляется только через исходные алиасы репозитория.** Спецификации разрешают пакет через tsconfig `paths` к `src`; собранный артефакт `lib/` реэкспортирует `@deepseek-ai/dsh-client-runtime/client`, чей бандл — браузерный скрипт-загрузчик без Node ESM экспортов, поэтому `lib/index.js` не импортируется под обычным Node. Каждый потребитель — Vitest-набор внутри репозитория; Node-совместимого рантайм-входа нет.
- **Снапшоты беседы — данные фикстур, а не воспроизведённая история.** `updateSnapshot` пишет в хранилище снапшотов напрямую; вычисление снапшота из wire-данных остаётся покрытым собственными тестами пакета runtime и replay e2e. Фикстура потому может выразить состояния, которые производственная проекция никогда бы не породила.
