# `@deepseek-ai/dsh-llm-mock-server`

[English](README.md) | [中文](README.zh.md) | Русский

Скриптуемый HTTP/SSE-сервер, совместимый с OpenAI, для упражнения настоящих LLM-адаптеров, agent-loop и политики восстановления без ключа провайдера. Он принимает `POST /chat/completions` и `POST /v1/chat/completions`; каждый принятый запрос расходует одно сконфигурированное поведение в порядке поступления. Неверные метод, путь, bearer-токен и JSON скрипт не расходуют.

Библиотечная точка входа экспортирует `startMockLlmServer(options)`, типы поведений и телеметрии, веса случайного стресса по умолчанию, допустимую границу таймеров Node и дескриптор работающего сервера с привязанным `baseURL`, сгенерированным либо сконфигурированным `randomSeed`, захваченными запросами и идемпотентным `close()`. Закрытие принудительно завершает зависшие соединения.

## Автономный запуск

Запустите точку входа из исходников этого репозитория:

```sh
pnpm run mock:llm -- \
  --port 8000 \
  --api-key mock-key \
  --sequence partial_disconnect,success \
  --partial-text "discard this half"
```

Направьте поставляемый DeepSeek-адаптер на сервер; он добавляет `/chat/completions` к сконфигурированной базе:

```sh
DEEPSEEK_BASE_URL=http://127.0.0.1:8000/v1 \
DEEPSEEK_API_KEY=mock-key \
pnpm dsh --profile headless "test provider recovery"
```

Репозиториевый скрипт пишет JSONL в stdout: запись `ready` несёт базовый URL `/v1` и случайный seed, за которыми следуют записи request/result, называющие и заскриптованное поведение, и конкретное выбранное поведение. Приватный пакет поддержки не предоставляет устанавливаемого бинарника.

## Скрипт поведения

`--sequence` — FIFO со значениями через запятую. Исчерпание возвращает структурный HTTP 500; `--repeat-last` явным образом повторно использует последнюю запись.

| Поведение | Результат на проводе |
|---|---|
| `connection_reset` | Разрушить сокет до HTTP-заголовков |
| `stream_disconnect` | Отправить SSE-заголовки, затем сбросить соединение до первого события |
| `partial_disconnect` | Отправить текстовые дельты, затем сбросить сокет |
| `stall` | Отправить SSE-заголовки и простаивать до отмены клиентом или сервером |
| `empty` | Отправить корректный stop без содержимого и `[DONE]` |
| `empty_body` / `stream_eof` / `partial_eof` | Завершить чисто, без обязательной границы `[DONE]` |
| `malformed_json` / `malformed_event` | Отправить неверный SSE JSON или чанк провайдера неверной формы |
| `rate_limit` / `server_error` / `service_unavailable` | Вернуть ориентированные на повтор JSON-ошибки 429/500/503 |
| `auth_error` / `invalid_request` / `context_overflow` / `quota_exceeded` | Вернуть терминальные или отдельно восстанавливаемые ошибки провайдера |
| `success` / `slow_success` / `reasoning_success` | Передавать полный текстовый ответ потоком, опционально с задержкой или с предшествующим рассуждением |
| `tool_call_success` / `max_tokens` | Завершить вызовом инструмента или причиной завершения `length` |
| `wrong_content_type` | Отправить корректное SSE-тело под `application/json` |
| `random` | Выбрать конкретное поведение запроса из взвешенной сидированной случайности |

Запись `connection_refused` существует только в CLI и **ДОЛЖНА** быть первой. Она откладывает привязку указанного вызывающим ненулевого порта, поэтому запросы в течение `--listen-delay-ms` получают настоящий отказ TCP; остальные записи начинаются после старта слушателя.

## Случайный режим

Используйте повторяющуюся запись `random` для открытого смешанного прогона:

```sh
pnpm run mock:llm -- \
  --port 8000 \
  --sequence random \
  --repeat-last \
  --seed 42 \
  --random-weights 'success=60,slow_success=10,connection_reset=5,stream_disconnect=5,partial_disconnect=10,empty=5,server_error=5'
```

Пропуск `--seed` генерирует его и печатает в записи `ready`. Опция `--random-weights` принимает неотрицательные относительные пары `behavior=weight` и требует хотя бы одного положительного конкретного поведения. Экспортируемое значение по умолчанию — профиль стресса с перевесом успехов, содержащий reset, разъединение, частичный вывод, пустое завершение, stall, 429/5xx, чистую обрезку и неверный JSON; это тестовая нагрузка, а не оценка частоты производственных инцидентов. Запись `connection_refused` исключена, потому что привязанный обработчик запросов не может произвести настоящий отказ.

Если случайные веса включают `stall`, настройте тестируемый клиент с коротким таймаутом простоя потока, чтобы сценарий завершался оперативно.

## Управление таймингом и содержимым

CLI раскрывает `--success-text`, `--partial-text`, `--reasoning-text`, `--chunk-size`, `--chunk-delay-ms`, `--disconnect-delay-ms`, `--retry-after-ms`, `--request-id`, `--tool-name` и `--tool-arguments`. Задержки в миллисекундах — ограниченные целые числа в диапазоне таймеров Node; `retryAfterMs` сверх того **ДОЛЖНО** быть положительным. Библиотека принимает те же опции в camelCase. Необязательный точный `apiKey` проверяет заголовок `Authorization: Bearer <token>`; его отсутствие допускает любой токен.

## Model Experience

Отсутствует: этот тестовый сервер подменяет поведение провайдера на проводе, не вызывая настоящую модель.

#### KV Cache effect

Отсутствует: запросы завершаются локально и никогда не достигают кэша провайдера.

## Known Limitations and Deferred Work

- **Случайные веса моделируют тестовую нагрузку, а не производственную встречаемость** — вызывающие, которым нужно распределение под конкретную среду, **ДОЛЖНЫ** предоставить измеренные веса и записать выданный seed.
- **Скрипты запросов упорядочены по прибытию** — конкурентные вызывающие делят один курсор, поэтому детерминированное назначение сбоев по сессиям требует отдельных экземпляров сервера.
- **Настоящий отказ соединения — фаза жизненного цикла слушателя** — задержка CLI **ДОЛЖНА** перекрываться с попыткой клиента; случайный выбор на уровне запроса способен лишь сбросить уже принятое соединение.
