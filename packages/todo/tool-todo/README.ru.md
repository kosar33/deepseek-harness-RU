# @deepseek-ai/dsh-tool-todo

[English](README.md) | [中文](README.zh.md) | Русский

Обращённый к модели инструмент `todo_write`: весь список задач агента, заменяемый целиком при каждом вызове.

## Что он делает

Регистрирует один инструмент, `todo_write(todos: [{ content, status }])`, на `ctx.tools`. Модель отправляет ВЕСЬ список при каждом вызове — частичных обновлений и поэлементных правок нет. Каждый вызов дописывает событие `todo/write` (полный снапшот списка) в журнал сессии вызывающего агента через `agent.session.append('todo/write', { todos })`; текущий список — самое недавнее такое событие (last-write-wins при воспроизведении).

`status` — одно из значений `pending`, `in_progress` или `completed`.

## Единственный владелец

Список принадлежит той ЕДИНСТВЕННОЙ сессии агента, которая вызвала инструмент. Никаких скоупов subagent/shared/swarm: не-агентскому вызывающему (без `exec.agent`) некуда записать список, и он отвергается. Это сознательное ограничение скоупа — см. Agent Note.

## Конфигурация

`allowParallelInProgress` обязателен: каждая композиция должна выбрать, могут ли несколько пунктов todo быть `in_progress` одновременно. Это выбор развёртывания, а не фиксированное правило: допустимость параллельных активных задач зависит от конкурентности рантайма, которую инструмент наблюдать не может. Используйте `true` для агентов, способных веером раздавать работу, и `false`, чтобы обеспечить соблюдение дисциплины единственной активной задачи.

Флаг двигает вместе обращённую к модели инструкцию и принимаемый ввод — `true` просит модель отмечать каждую задачу, над которой активно работают, и принимает любое число, `false` просит ровно одну и отвергает вызов, отмечающий больше, с `Error: invalid todos: at most one task may be in_progress (got <n>)`. Инвариант долговечного журнала от него НЕ зависит: журнал, записанный, когда параллельная работа была разрешена, ДОЛЖЕН оставаться воспроизводимым после того, как развёртывание ужесточило политику, поэтому инвариант молчит о числе активных.

## Валидация

Помимо проверок типа/обязательности/перечисления в схеме, `execute` отвергает пустой или дублирующийся `content` и любой ключ пункта сверх `content`/`status` — расширенная форма пункта (ids, вложенность) отвергается с явной ошибкой вместо тихого приведения к плоской форме, так что залогированный снапшот остаётся равным тому, что модель считает записанным. Сколько задач может быть `in_progress` одновременно, решает развёртывание (§ Конфигурация): композиция, выбравшая `true`, разрешает параллельной работе (параллельным субагентам, фоновым командам) отмечать несколько задач одновременно. Порядок и дисциплина поддержания актуальности списка оставлены модели через описание инструмента.

## Рендеринг

Канонический результат — `{ todos, counts: { pending, inProgress, completed } }`; его Native-рендерер возвращает компактное подтверждение обновления. Инструмент также пишет полное событие сессии `todo/write`. UI подписываются на поток событий и рендерят этот долговечный список сами: [веб-клиент](../../client/ui-conversation) показывает полосу плана плюс отдельную строку инструмента на основе постоянного плана — последний `todo/write` без более позднего `turn/start` ([отображение](../../../.agents/notes/implemented/feature/2026-07-23-web-todo-display.md), [жизненный цикл](../../../.agents/notes/implemented/feature/2026-07-28-todo-plan-clears-on-next-turn.md)).

## Проекция сессии

Когда композиция монтирует `ctx.sessionProjections` ([`@deepseek-ai/dsh-session-projection`](../../session/session-projection/README.md)), этот пакет регистрирует проекционный юнит `todos` под внедрённым потомком: `init` = `null` (записи ещё не было), `apply` = берёт весь список из каждого `todo/write` и очищает в `null` на каждом `turn/start` (постоянный план; `turn/end` сохраняет завершённый чеклист; всякое другое событие возвращает ту же ссылку состояния), `view` = тождество, `stateVersion` = 2. Ключ сливается в `SessionProjectionMap` здесь (через выход `/types` пакета Service Definition); фреймворк ведёт юнит, а носители подают значение на странице хвоста истории и в push-кадре `session/projection`. Композиции без реестра не затронуты. Обоснование жизненного цикла: [план todo очищается со следующим ходом](../../../.agents/notes/implemented/feature/2026-07-28-todo-plan-clears-on-next-turn.md).

## Форма экспорта

Функциональный/namespace-плагин: экспортирует `name` / `inject` / `apply` и НЕ имеет default. Случайный `export default` схлопнул бы модуль через `unwrapExports` загрузчика и привёл бы к потере `inject` (см. [docs/postmortem/0001](../../../docs/postmortem/0001-acp-default-export-drops-inject.ru.md)).

## Model Experience

### Схема инструмента

#### What the model sees

Модель видит сгенерированную [схему `todo_write`](../../../docs/tool-catalog.md#deepseek-aidsh-tool-todo).

#### Token effect

Фиксированная стоимость схемы в каждом запросе, где инструмент видим.

#### KV Cache effect

Стабильность префикса, пока определение и видимость неизменны. Жизненный цикл плагина или scoped-ограничения могут инвалидировать повторное использование начиная с этой схемы.

### История вызовов инструмента и результат

#### What the model sees

Каждый вызов инструмента ассистентом хранит весь заменяющий список в своих аргументах. Успех возвращает точно `Updated todo list: <pending> pending, <inProgress> in progress, <completed> completed.` Стабильные отказы: ``Error: invalid todo: `content` must be a non-empty string``, `Error: invalid todos: duplicate content "<content>"`, `Error: todo_write requires an owning agent session` и — только там, где развёртывание установило `allowParallelInProgress: false` — `Error: invalid todos: at most one task may be in_progress (got <n>)`. Полное событие сессии `todo/write` — состояние UI и воспроизведения, а не второе сообщение модели.

#### Token effect

Рост токенов масштабируется с каждым полным списком, который отправляет модель, и эти аргументы вызова остаются до компакции. Сам результат мал и фиксированной формы.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Только scope единственного владельца** — список принадлежит одной вызывающей сессии агента; скоупы subagent/shared/swarm сознательно не поддерживаются (см. § Единственный владелец), а не-агентский вызывающий отвергается.
- **Форма пункта сознательно минимальна** — `content` плюс `status` с тремя состояниями; замена целого списка не нуждается в стабильном id, приоритете или поле активной формулировки.
- **Замена целого списка — единственная операция** — ни частичных обновлений, ни инструмента обратного чтения; модель ДОЛЖНА заново отправлять весь список при каждом вызове.
