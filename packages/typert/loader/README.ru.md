# @deepseek-ai/dsh-typert-loader

[English](README.md) | [中文](README.zh.md) | Русский

Интеграция с Loader только для Node для сгенерированных артефактов Typert. Плагин требует `ctx.loader` и `ctx.typert`; сам реестр он не предоставляет.

При активации плагин сканирует существующие записи Loader. Затем он следит за уведомлениями жизненного цикла Cordis `internal/plugin`, разрешает `package.json` пакета каждой записи, импортирует `./typert`, когда тот экспортируется, проверяет его манифест `TYPERT` и регистрирует вклад, пока запись или сам плагин не размонтированы. Импорт, завершившийся после того, как исчез любой из двух владельцев, отбрасывается.

Поле `packages` перечисляет дополнительные пакетные артефакты для регистрации за плагинами, вложенными за другой записью Loader. Fiber'ы Cordis не удерживают npm-спецификаторы этих вложенных плагинов, поэтому эта граница проведена явно; каждый настроенный пакет должен разрешаться из конфигурационного дерева и экспортировать `./typert`.

Пакеты без такого экспорта пропускаются. Разрешение пакетов и импортированные манифесты кэшируются на время жизни процесса, поэтому добавление экспорта требует перезапуска. Некорректный артефакт при уже состоявшемся монтировании срывает активацию; сбой, случившийся позже, лишь журналируется и не мешает регистрироваться остальным пакетам.

## Model Experience

Никакого: загрузчик лишь снабжает [`ctx.typert`](../registry/README.ru.md) данными; любой проекцией, видимой модели, владеют потребители.

#### KV Cache effect

Прямого эффекта нет.

## Известные ограничения и отложенная работа

- Обнаружение импортирует только хостовую грань; клиентским рантаймам до появления эквивалентного обнаружения нужен отдельный владелец композиции.
- Записи Loader обнаруживаются автоматически. Вложенные плагины или плагины вне Loader требуют явной строки `packages` либо прямого владения через `ctx.typert.register()`.
