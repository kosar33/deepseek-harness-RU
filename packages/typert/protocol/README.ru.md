# @deepseek-ai/dsh-typert-protocol

[English](README.md) | [中文](README.zh.md) | Русский

Независимые от компилятора декларации, разделяемые бизнес-пакетами, сгенерированными артефактами Typert, Host Gateway и Client API. Этот пакет владеет базой Remote Service, декораторами, явным запасным связыванием, расширяемыми слиянием картами протокола, дескрипторами вызовов, кодеками и контрактами провайдеров; он не выполняет анализ TypeScript и не регистрирует конкретный Cordis-сервис.

## Удалённые декларации

- `@Remote` помечает публичный метод экземпляра для прямого вызова на его зарегистрированном Cordis-сервисе.
- `@RemoteScope(key)` помечает метод, чей получатель выбирается из объявленного слиянием вида scoped Context.
- `TypertRemoteService` привязывает ключ Cordis, переданный в `super(ctx, serviceKey, options?)`, к тому же namespace протокола по умолчанию.
- `bindTypertRemote(this, serviceKey, options?)` даёт ту же видимую, замороженную привязку для сервиса, который не может унаследоваться от `TypertRemoteService`.
- `remoteMethods(service)` возвращает отсоединённый снапшот в порядке объявления, которым пользуется запасной вариант Gateway (SRC).

Метод Host включается в кооперативную отмену, объявив `signal: AbortSignal` своим последним параметром. `InvocationDescriptor.cancellation` записывает этот зарезервированный пункт внедрения; сигнал никогда не становится JSON-параметром или lookup-полем. SRC распознаёт имя последнего параметра, а строгая генерация вдобавок проверяет глобальный тип `AbortSignal`.

Инициализаторы декораторов удерживают маркеры в приватном для модуля `WeakMap`, ключуемом прототипом Service. Они не добавляют ни символов конструктора, ни свойств прототипа, ни метаданных параметров, ни полей рантайм-рефлексии. `TypertRemoteService` предоставляет ту же публичную readonly-привязку `typertRemote`, которую возвращает явный хелпер.

## Протокол Typert

Бизнес-пакеты расширяют `TypertLookupMap` и `TypertContextMap`, чтобы сопоставлять объекты Host или scoped Context их идентичностям в протоколе. Сгенерированные артефакты расширяют `TypertRemoteMap`, `TypertRemoteScopeMap` и `TypertRemoteNamespaceMap`, так что импорты Client раскрывают только избранные Remote-методы. `InvocationDescriptor` — общая рантайм-форма, используемая реестром, Gateway и Client Remote.

Сборка Host расширяет `TypertRemoteEventSelection` событиями Host, которые она пересылает потребителям, что сужает грань ключей `ctx.remote.$on`; `TypertForwardableEvent` описывает формы, которые однонаправленная доставка вообще способна нести, исключая события, привязанные к Scope, и события с ответом. `TypertClientRemote` несёт обе роли этой поверхности: потребители подписываются через `$on`, а клиентская половина, владеющая приёмником фреймов хоста, передаёт фреймы через `$dispatch`.

Пакеты lookup и Context владеют обеими сторонами своего контракта: слияние деклараций даёт статическую ассоциацию, а провайдеры рантайма регистрируют разрешение идентичности через `ctx.typert`. Провайдер lookup или Host Context поставляет стабильную декларацию и резолвер по умолчанию, тогда как композиция Host может отдельно настроить синхронный или асинхронный резолвер; отказы политики могут применять `TypertLookupFailure`, чтобы нести значение отказа, принадлежащее адаптеру границы. Строгие кодеки несут сгенерированные схемы; кодеки `src-json` обозначают более слабый путь source-launch.

## Известные ограничения и отложенная работа

- Маркеры декораторов содержат только имя метода и режим прямого либо Context-вызова. Рефлексия параметров, результатов, lookup и схем требует конвейера сборки Typert.
- Удалённые декораторы принимают только публичные нестатические методы экземпляра со строковыми именами. Исполнение SRC неспособно представить сигнатуры с перегрузками, деструктуризацией, значениями по умолчанию или rest-параметрами.
