# dsh-home-paths

[English](README.md) | [中文](README.zh.md) | Русский

Общие помощники файловых путей для пользовательских данных DeepSeek Harness.

## Домашний каталог DSH

`resolveDshHome()` разрешает единый корневой домашний каталог DeepSeek Harness. Приоритет от высшего к низшему: явно настроенный путь, `$DSH_HOME`, затем `~/.dsh`. Harness держит все пользовательские данные под одним корнем.

`dshHomePath(...segments)` присоединяет дочерние сегменты к разрешённому домашнему каталогу по платформенным правилам путей Node. Без сегментов возвращается сам домашний каталог.

`dshHomeDisplay()` называет активный корень символически для обращённых к пользователю путей: `~/.dsh` для домашнего каталога по умолчанию, `$DSH_HOME` для любого настроенного. Она никогда не раскрывает абсолютный машинный путь.

`DSH_HOME_DIR_NAME` владеет именем каталога пользовательских данных по умолчанию: `.dsh`.

`defaultDshHome()` возвращает домашний каталог DeepSeek Harness по умолчанию, соединяя домашний каталог операционной системы с `.dsh` по платформенным правилам путей Node.

`expandHomePath()` разворачивает префиксы `~`, `~/...` и виндового вида `~\...` относительно домашнего каталога операционной системы. Пути без тильды и формы `~user/...` остаются нетронутыми.

## Пути наблюдения

`canonicalizeWatchPath()` даёт нативному наблюдателю файловой системы одну стабильную запись его цели. Он разрешает глубочайшего существующего предка через `fs.realpath()` и восстанавливает отсутствующий остаток пути, так что файл или каталог можно взять под наблюдение ещё до их создания. В частности, 8.3-псевдонимы Windows нельзя смешивать с длинными путями, которые выдаёт нативный бэкенд наблюдения.

Этот пакет намеренно мал и свободен от зависимостей внутри harness, чтобы продуктовые пакеты могли разделять соглашения о путях пользовательских данных, не завися друг от друга.

## Известные ограничения и отложенная работа

- **Разворачивание намеренно узко** — только голая `~`, `~/...` и `~\...` используют текущий домашний каталог операционной системы; формы с именем пользователя вроде `~alice/...`, переменные окружения и shell-выражения остаются без изменений.
- **Канонизация только читает и никогда не меняет** — `canonicalizeWatchPath()` выполняет пробы `realpath` и передаёт все ошибки дальше, кроме отсутствия пути; создание каталога, разрешения и политика доверия для итогового пути остаются за вызывающим.
