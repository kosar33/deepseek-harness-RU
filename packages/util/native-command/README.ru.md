# dsh-native-command

[English](README.md) | [中文](README.zh.md) | Русский

**Запускатель `execFile` без оболочки и без единой зависимости**, разделяемый нативными для хоста интеграциями с ОС: один вызов `runNativeCommand(command, args, signal)` порождает исполняемый файл напрямую (никогда не строку оболочки), захватывает stdout/stderr в utf8, передаёт отмену вызывающего в завершение дочернего процесса и прячет мимолётное окно консоли на Windows. Неудачи отклоняются с кодом выхода `code` и обоими захваченными потоками при себе, так что вызывающие классифицируют исход (нет инструмента, отменено, настоящая неудача), ничего не запуская повторно.

Его два потребителя — хостовые нативные интеграции: команды системного выбора каталога в бэкенде [`directory-picker-native`](../../host/directory-picker-native/README.ru.md) и передача «открыть в приложении по умолчанию» на стороне шлюза ([`dsh-host-apiproxy`](../../host/apiproxy/README.ru.md), `host.openPath`). Тип `NativeCommandRunner` — их внедряемая командная граница.

Это **библиотека, а не сервис или плагин**: ни `ctx`, ни регистраций, ни состояния, ни событий.

## API

```ts
import { runNativeCommand, type NativeCommandRunner } from '@deepseek-ai/dsh-native-command'
```

## Model Experience

Никакого: это хостовое subprocess-обслуживание; ничто из этого не достигает запроса к модели.

#### KV Cache effect

Никакого; этот пакет ни собирает, ни отправляет запрос провайдеру.

## Известные ограничения и отложенная работа

- **Вывод не ограничивается** — оба потока буферизуются в памяти без границ; каждый нынешний вызывающий запускает небольшие нативные утилиты, чей вывод — путь или строка ошибки. Примените удержание из `dsh-output-retention`, прежде чем целить этот запускатель в команды со значительным объёмом вывода.
