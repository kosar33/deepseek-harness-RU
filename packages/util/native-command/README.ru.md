# dsh-native-command

[English](README.md) | [中文](README.zh.md) | Русский

**Средство запуска `execFile` без оболочки и без единой зависимости**, общее для интеграций с ОС на стороне хоста: один вызов `runNativeCommand(command, args, signal)` порождает исполняемый файл напрямую (никогда — через строку оболочки), захватывает stdout/stderr в utf8, передаёт отмену вызывающего в завершение дочернего процесса и прячет кратковременное окно консоли на Windows. Неудачи отклоняются с кодом выхода `code` и обоими захваченными потоками в составе ошибки, так что вызывающие классифицируют исход (нет инструмента, отмена, реальный сбой), ничего не запуская повторно.

Его используют две интеграции на стороне хоста: команды системного выбора каталога в бэкенде [`directory-picker-native`](../../host/directory-picker-native/README.ru.md) и передача «открыть в приложении по умолчанию» на стороне шлюза ([`dsh-host-apiproxy`](../../host/apiproxy/README.ru.md), `host.openPath`). Тип `NativeCommandRunner` — их внедряемая командная граница.

Это **библиотека, а не сервис или плагин**: ни `ctx`, ни регистраций, ни состояния, ни событий.

## API

```ts
import { runNativeCommand, type NativeCommandRunner } from '@deepseek-ai/dsh-native-command'
```

## Известные ограничения и отложенная работа

- **Вывод не ограничивается** — оба потока буферизуются в памяти без ограничения объёма; все текущие вызывающие стороны запускают небольшие нативные утилиты, чей вывод — путь или строка ошибки. Примените удержание из `dsh-output-retention`, прежде чем направить этот запускатель на команды со значительным объёмом вывода.
