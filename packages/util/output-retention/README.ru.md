# dsh-output-retention

[English](README.md) | [中文](README.zh.md) | Русский

Библиотека **удержания** с минимальными зависимостями: ограниченный вывод, видимый модели, для инструментов, которые должны ограничивать объём возвращаемого контекста. Вызывающий кладёт элементы или текстовые чанки в ограниченный объект, а затем получает удержанное содержимое плюс точные метаданные об упущенном.

Библиотека отвечает **только** за механический вопрос *«что мы сохранили, а что упустили?»*. Специфичный для инструмента код хранит свою бизнес-семантику: группировку файлов, нумерацию строк, коды выхода, состояния ошибок провайдера, построчное усечение превью, spill-файлы и обращённую к модели прозу. Именно эту границу проводит [Agent Note](../../../.agents/notes/implemented/architecture/2026-07-06-tool-result-retention-library.md).

Это **библиотека, а не сервис или плагин**: ни `ctx`, ни регистраций, ни событий. Единственное состояние — у конкретного retainer (одно накопление), никогда между вызовами. Пакеты инструментов импортируют её напрямую.

## API

```ts
import {
  ItemRetainer, TextRetainer,
  describeOmitted, formatRetentionNotice,
} from '@deepseek-ai/dsh-output-retention'
import type {
  Omitted, PushDecision, RetainedItems, RetainedText,
  ItemRetentionStrategy, TextRetentionStrategy, RetentionNotice,
} from '@deepseek-ai/dsh-output-retention'
```

| Экспорт | Роль |
|---|---|
| `ItemRetainer<T>` | Ограничивает упорядоченные логические единицы (пути, совпадения grep, источники). Только `head`. `push()` → `PushDecision`; `finish()` → `RetainedItems<T>`. |
| `TextRetainer` | Ограничивает байт-ориентированный текстовый поток. `head` / `tail` / `headTail`, границы UTF-8 сохраняются в `finish()`. `push()` → `PushDecision`; `finish()` → `RetainedText`. |
| `describeOmitted(omitted, unit)` | Стандартизованная формулировка об упущенном (`exact` печатает число; `unknown` — нет). |
| `formatRetentionNotice(notice, recovery)` | Соединяет стандартизованную формулировку об упущенном с собственным руководством инструмента по восстановлению. |
| `Omitted` | `none` / `exact` / `unknown` — сколько было упущено. |
| `PushDecision` | `{ kept, truncated }` — результат удержания одного push. |

## Модели ресурсов

Два retainer — отдельные имена, а не один универсальный сборщик, потому что они различаются **моделью ресурсов**.

- **`ItemRetainer` ограничивает упорядоченные логические единицы.** Инструмент поиска может собрать полный набор результатов для восстановления через spill-файл, удерживая лишь первые `maxItems` для превью, видимого модели. Число упущенного точно, потому что вызывающий продолжает передавать каждый наблюдаемый элемент.
- **`TextRetainer` ограничивает байт-ориентированный текст.** `head`, `tail` и `headTail` сохраняют границы UTF-8 в `finish()`; `headTail` — та стратегия, которую `dsh-spill-policy` использует, чтобы строить ограниченное превью вокруг извещения spill-файла.

## `truncated` — факт бюджета, а не «неполнота»

`truncated` означает, что *retainer упустил иначе доступное содержимое из-за бюджета*. Это **не** означает, что upstream был неполон. Неудачи разрешений, пропущенные бинарные файлы, частичные сбои провайдера, нечитаемые кандидаты и неверный UTF-8 остаются в полях домена инструмента — они никогда не попадают в `truncated`. Смешение этих двух значений — та ошибка, к которой больше всего подталкивает именование этой библиотеки; держите их раздельно.

## Байты, а не символы

Текстовые лимиты и `omittedBytes` считают **байты** — ради безопасности процесса и тела (пайп дочернего процесса и тело HTTP — байтовые потоки). Чанк, разрезающий кодпоинт пополам, обрабатывается: `finish()` отрезает частичный кодпоинт на каждом срезе, так что возвращённый текст никогда не вводит символ замены на границе, а две стороны декодируются отдельно, так что кодпоинт никогда не собирается заново через упущенную середину. Посимвольные или построчные бюджеты превью — отдельная забота самого инструмента.

## Привязки инструментов

Текущие потребители удержания используют эти соответствия:

| Инструмент | Retainer и стратегия | Примечания |
|---|---|---|
| `glob` | `ItemRetainer<FsGlobEntry>`, `head` | Собирает полный отсортированный список путей для spill-файла, удерживая первую страницу инлайн. Преобразование путей, пропущенные кандидаты и `incomplete` остаются вне retainer. |
| `grep` | `ItemRetainer<FlatGrepMatch>`, `head` | Собирает совпадения для spill-файла, удерживая первую страницу инлайн. Усечение превью совпадения, группировка, сортировка и `incomplete` остаются вне retainer. |
| `bash` | `TextRetainer`, `tail` или `headTail` | Исполнитель по-прежнему владеет spill-файлами, статусом выхода, сигналом, таймаутом и фоновыми задачами. |
| `web_fetch` | `TextRetainer`, `head` или `headTail` | Лимиты провайдера/ресурса остаются фактами о провайдере; retainer поставляет только удержанный текст и метаданные об упущенном. |
| `web_search` | `ItemRetainer<WebSearchSource>`, `head` | Стандартизует извещение «sources capped», когда провайдеры возвращают больше источников, чем должно войти в результат, видимый модели. |

`read` остаётся вне этой универсальной библиотеки. Его помощник `read-render` владеет специфичным для файла контрактом пагинации — `offset`/`limit`, номера строк, `totalLines`, ошибки выхода `offset` за диапазон, построчное усечение превью и байтовый лимит поверх выбранного окна, — то есть это рендерер окна строк. Один счётчик `Omitted` не может представлять обе стороны этого окна.

## Форма использования

```ts ignore-check
// glob: keep the first page inline while still collecting the full list for spill.
const retainer = new ItemRetainer<FsGlobEntry>({ kind: 'head', maxItems: globMaxResults })
const allEntries: FsGlobEntry[] = []
for await (const entry of candidates) {
  allEntries.push(entry)
  retainer.push(entry)
}
const { items, truncated, omitted } = retainer.finish()

// bash: keep a head + tail, read to process exit.
const out = new TextRetainer({ kind: 'headTail', headBytes: headCap, tailBytes: tailCap })
child.stdout.on('data', (chunk: Buffer) => { out.push(chunk) })
const { text, omittedBytes } = out.finish()

// A footer: the library standardizes the omission clause; the tool owns recovery words.
const footer = formatRetentionNotice(
  { scope: 'grep', strategy: 'head', unit: 'items', limit: grepMaxMatches, kept: items.length, omitted },
  ({ kept }) => `Results capped at ${kept}. Narrow the pattern, path, or include to see more.`,
)
```

## Влияние на модель

Косвенно, через инструменты-потребители, которые рендерят удержанное содержимое и метаданные об упущенном.

#### Влияние на KV-кэш

Прямой инвалидации нет; изменения префикса запроса — забота названного потребителя.

## Известные ограничения и отложенная работа

- **Удержание элементов поддерживает только `head`** — tail, head/tail, пагинация, группировка и семантика полноты провайдера остаются за инструментом.
- **Удержание текста байт-ориентировано** — посимвольные и построчные окна вроде пагинации `read` требуют отдельного рендерера, а срез может отбросить частичные байты границы UTF-8, чтобы возвращённый текст оставался корректным.
