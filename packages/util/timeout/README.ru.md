# dsh-timeout

[English](README.md) | [中文](README.zh.md) | Русский

**Таймингово-классификационная** половина таймаута — библиотека чистых функций без зависимостей (никаких рантаймных зависимостей harness), разделяемая каждой возможностью, которая ограничивает подсказку таймаута вызывающего, взводит дедлайн и позже должна отличить «истёк таймаут» от «отменено».

Она **не владеет завершением**. Раздаваемый ею сигнал только *уведомляет*; фактическая остановка работы остаётся в каждой возможности, потому что этот механизм различается — bash SIGKILL'ает группу процессов ОС, web разбирает сокет `fetch`, — и никакой общий слой не может владеть всеми ими. Это граница, которую проводит [Agent Note](../../../.agents/notes/implemented/architecture/2026-07-06-timeout-deadline-library.md): делите тайминг/классификацию, держите жёсткое завершение локальным.

Это **библиотека, а не сервис или плагин**: ни `ctx`, ничего не регистрирует, не держит состояния, не испускает событий. «Сервис таймаутов» должен был бы понимать, как остановить работу каждой возможности, — ровно то знание, которое микроядро держит вне общих слоёв.

## API

```ts
import { clampTimeout, deadline, idleWatchdog, MAX_TIMER_DELAY_MS, timeoutOf, TimeoutReason } from '@deepseek-ai/dsh-timeout'
```

| Экспорт | Роль |
|---|---|
| `clampTimeout(requested, def, max, name?)` | Валидирует необязательную положительную конечную подсказку вызывающего, заполняет из `def`, ограничивает сверху `max`. Бросает (с `name`) на неположительной/неконечной подсказке. |
| `deadline(upstream, timeoutMs, code)` | Сплавляет отмену `upstream` с таймаутом в один `AbortSignal` (`AbortSignal.any`); таймаут несёт `TimeoutReason`. `[Symbol.dispose]` снимает таймер. |
| `idleWatchdog(upstream, timeoutMs, code)` | Держит один стабильный сплавленный сигнал и взводится, лишь пока ожидается `next()` его охраняемого асинхронного итератора. Разрешение снимает; позднейший спрос или активность `pulse()` взводят вновь; освобождение ресурсов снимает; параллельный спрос отвергается. |
| `MAX_TIMER_DELAY_MS` | Наибольшая задержка, которую Node планирует, не прижимая её к одной миллисекунде (`2_147_483_647`). Конфигурация, владеющая таймерами, **НЕ ДОЛЖНА** её превышать. |
| `timeoutOf(signal \| { reason }, code?)` | Восстанавливает `TimeoutReason` из прерванного сигнала/ошибки, иначе `undefined` — классификатор «таймаут против отмены». Передайте `code`, чтобы сопоставлять только таймер ЭТОГО дедлайна (см. вложенность ниже). |
| `TimeoutReason` | Внутренняя причина (`code` + `timeoutMs`), которой помечается abort по таймауту. Не публичная ошибка — провайдеры переводят её в собственную ошибку/поле. |

## Сентинел `timeoutMs <= 0`

`0` — **внутреннее** значение «без таймаута» для фоновой работы во владении бэкенда (bash `start()`): `deadline()` не взводит таймер и пробрасывает только `upstream`; когда нет и upstream, возвращает никогда не прерывающийся сигнал плюс no-op disposer, так что каждый вызывающий сохраняет одну форму вызова. Внешние подсказки запроса валидируются как **положительные конечные** через `clampTimeout` прежде, чем достичь `deadline`, поэтому `0` никогда не бывает обращённым к модели/плагину значением «отключить таймаут».

## Форма использования

```ts
import { deadline, timeoutOf } from '@deepseek-ai/dsh-timeout'

declare function runWork(options: { signal: AbortSignal }): Promise<unknown>

// Scope-lifetime consumer (foreground bash, one fetch): `using` disposes the timer.
export async function runWithDeadline(upstream: AbortSignal | undefined, timeoutMs: number): Promise<unknown> {
  using d = deadline(upstream, timeoutMs, 'BASH_TIMEOUT')
  const outcome = await runWork({ signal: d.signal })               // work listens on d.signal and terminates itself
  const timedOut = timeoutOf(d.signal, 'BASH_TIMEOUT') !== undefined // classify the first abort, scoped to OUR code
  const aborted = d.signal.aborted && !timedOut                     // mutually exclusive: timeout won, or cancel did
  return { outcome, timedOut, aborted }
}
```

Сигнал только *уведомляет* — вызывающий **ДОЛЖЕН** подключить собственное завершение (`d.signal.addEventListener('abort', kill)`, либо передать `d.signal` в `fetch`). Гонка промиса против таймера разрешила бы вызов инструмента, пока дочерний процесс или сокет продолжает жить; раздача сигнала вынуждает существовать настоящий путь завершения.

Передавайте собственный `code` в `timeoutOf`, чтобы классификация составлялась при вложении. Когда `upstream` сам является сигналом дедлайна, `AbortSignal.any` сохраняет его `TimeoutReason`, если тот таймер сработает первым. Привязка к вашему коду заставляет чужой таймаут читаться как обычную отмену upstream вместо заявления, что истёк локальный таймер.

Для потокового транспорта создайте один `idleWatchdog`, передайте его стабильный `signal` транспорту и вызывайте `watchdog.next(iterator)` на каждом чтении у провайдера. Вызывайте `watchdog.pulse()`, когда активность транспорта не даёт значения итератора. Интервал должен быть положительным, конечным и не больше `MAX_TIMER_DELAY_MS`; иначе Node прижмёт его к одной миллисекунде. Он измеряет только незакрытый спрос, поэтому никакой таймер не тикает, пока код ниже по потоку рендерит или иначе ждёт перед запросом следующего чанка. Примитив по-прежнему только уведомляет, поэтому транспорт обязан наблюдать стабильный сигнал; адаптеры DeepSeek и pi-ai доказывают, что таймаут закрывает их настоящее тело ответа или SDK-запрос.

## Что НЕ получает таймаут

Локальные файловые `read`/`write`/`edit` не принимают `timeoutMs`: файловый ввод-вывод идёт без отсчёта времени, потому что дедлайн убил бы работу, которую ОС всё равно завершит. См. [страницу подсистемы файловой системы](../../../docs/subsystems/filesystem.ru.md).

## Model Experience

Косвенно, через потребителей вроде `dsh-tool-call-timeout-policy`, которые могут заменить результат провайдера удержанной ошибкой таймаута или подавить поздний результат.

#### KV Cache effect

Прямой инвалидации нет; изменения префикса запроса находятся во владении названного потребителя.

## Известные ограничения и отложенная работа

- **Только уведомление** — дедлайн не может остановить работу, игнорирующую его сигнал; каждая возможность по-прежнему нуждается в собственном пути завершения сокета/процесса/задачи.
- **`timeoutMs <= 0` — внутренний словарь** — он отключает локальный таймер только после того, как владеющий бэкенд разрешил политику, и никогда не служит публичной ручкой модели/плагина.
- **Причина первой отмены побеждает в классификации** — когда отмена upstream обгоняет локальный таймер, этот слой не может позже сообщить, что его собственный таймаут тоже успел бы истечь.
- **Idle-watchdog — не полный дедлайн** — он перевзводится на каждый незакрытый спрос итератора и сознательно исключает время размышления потребителя.
