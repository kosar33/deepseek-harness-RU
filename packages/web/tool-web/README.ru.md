# @deepseek-ai/dsh-tool-web

[English](README.md) | [中文](README.zh.md) | Русский

Обращённый к модели набор веб-инструментов — `web_search` и `web_fetch` — поверх [capability seam web](../web/README.md) (`ctx.web`). Он владеет только обращёнными к модели заботами: именами инструментов, JSON-схемами, snake_case-именами аргументов, секциями промпта, границей числа результатов, форматированием результатов, представлением HTML→markdown и проекцией UI-представления — `presentCall`, `presentResult` (карточка результата `card: 'web'`, различаемая по `kind: 'search' | 'fetch'`) и `output.presentationMeta`, который несёт структурные источники поиска или сводку fetch там, где lossy рендер-текст этого не может (см. [Agent Note о карточке веб-результата](../../../.agents/notes/implemented/feature/2026-07-30-web-result-card.md)). Весь доступ в веб идёт через `ctx.web`; этот пакет никогда не импортирует конкретного провайдера. Ни один инструмент не выставляет обращённого к модели таймаута — кооперативный бюджет инструментального вызова у каждого инструмента объявляется здесь через конфигурацию (`fetchTimeoutMs`/`searchTimeoutMs`, прикрепляется как `ToolDefinition.timeoutMs`) и обеспечивается [`@deepseek-ai/dsh-tool-call-timeout-policy`](../../guard/timeout-policy/README.md) (обёртка `tools/execute`). Одиночные операции пробрасывают `exec.signal`; мульти-запросный поиск сплавляет его с отменой батча, так что отказавший запрос прерывает своих соседей.

Каждый инструмент регистрируется независимо; продукт, которому нужен лишь один, отключает другой через конфигурацию (`{ search: false }` / `{ fetch: false }`). Поисковое руководство упоминает `web_fetch`, только когда fetch тоже включён конфигурацией; композиция только с поиском вместо этого велит модели пользоваться вернувшимися сниппетами и цитировать их URL.

## Инструменты

| Tool | Args | Behavior |
|---|---|---|
| `web_search` | `queries` (required string[]) | Обнаружение. Возвращает необязательный ответ плюс URL источников. Запускает от одной до `searchMaxQueries` различных поисков параллельно и сливает их источники в порядке round-robin до применения суммарной границы `searchMaxResults`. Массив из одного элемента выполняет один поиск. Точные дубликаты запросов исполняются однократно. Любой отказавший поиск прерывает остаток батча, который оседает прежде, чем вызов вернёт ошибку. Ни одна из границ не видна модели. |
| `web_fetch` | `url` (string) | Извлекает конкретный URL. HTML-тела рендерятся в markdown (turndown с GFM-таблицами/зачёркиванием); текстовые тела проходят насквозь. Статус вне 2xx сообщается, а не является ошибкой. Таймаут вызова инструмента — политика развёртывания (`dsh-tool-call-timeout-policy`), а не аргумент модели. |

Оба инструмента выбирают параллельное планирование, потому что чтения провайдера возвращают содержимое, не мутируя состояние родительского агента.

Нормализованные результаты сервиса — заодно канонические значения инструментов: `WebSearchResult` и `WebFetchResult`. Нативные рендереры сохраняют текст ответа/источников и извлечённого тела ниже; провайдерские границы поиска/тела остаются пределами добывания, а не только-для-представления усечением.

## Конфигурация

| Key | Default | Meaning |
|---|---|---|
| `search` | `true` | Регистрировать `web_search`. |
| `fetch` | `true` | Регистрировать `web_fetch`. |
| `searchMaxResults` | `8` | Верхняя граница числа источников одного вызова `web_search` (seam усекает каждый провайдерский список; инструмент вдобавок ограничивает суммарный мульти-запросный список). |
| `searchMaxQueries` | `4` | Верхняя граница числа запросов, принимаемых одним вызовом `web_search`. Настроенное значение появляется в его промпт-руководстве и описаниях схемы. |
| `fetchTimeoutMs` | `30000` | Кооперативный таймаутный бюджет (мс) вызова инструмента для `web_fetch`. |
| `searchTimeoutMs` | `30000` | Кооперативный таймаутный бюджет (мс) вызова инструмента для `web_search`. |
| `fetchMaxOutputChars` | `200000` | Предел исходных символов, конвертируемых синхронно, и на один полный вывод `web_fetch` (заголовок, отрендеренное тело и подвал); обрезанное тело получает уведомление об усечении, когда оно помещается. |

`searchMaxQueries` ограничивает принятый массив до дедупликации точных строк, веерного запуска провайдеров и роста суммарного провайдерского ответа; валидация отвергает чрезмерный массив прежде старта любого поиска, затем диспетчеризация оставляет первое вхождение каждого запроса. Вместе с собственными регуляторами каждого провайдера вроде `maxUses` эти независимые настройки и есть поисковые бюджеты продукта; универсальный seam не выставляет внутренней для провайдера нативно-поисковой бухгалтерии. `fetchTimeoutMs`/`searchTimeoutMs` объявляют кооперативный таймаутный бюджет каждого инструмента (прикрепляется как `ToolDefinition.timeoutMs`), обеспечиваемый [`@deepseek-ai/dsh-tool-call-timeout-policy`](../../guard/timeout-policy/README.md); обращённая к модели схема не выставляет таймаутного аргумента. `fetchMaxOutputChars` ограничивает и синхронную конверсионную работу, и полный отрендеренный результат: конвертируется лишь столько исходных символов, а затем заголовок, конвертированный префикс и уведомление об усечении ограничиваются вместе. Значение по умолчанию оставляет запас над стотысносимвольной границей тела локального провайдера, но рендерное расширение всё ещё может заставить финальную границу усечь результат.

```yaml
- id: tool-web
  name: '@deepseek-ai/dsh-tool-web'
```

## Стабильная регистрация

Регистрация инструментов следует продуктовому **включению**, а не доступности бэкенда. Инструмент остаётся видимым, даже когда его избранный провайдер отсутствует, неверно настроен, неоднозначен или временно недоступен; seam разрешает провайдера во время исполнения, а исполнение отказывает со структурным `WebError` (например `WEB_PROVIDER_UNAVAILABLE`, `WEB_PROVIDER_AMBIGUOUS`), который `ToolRuntime.execute()` превращает в ошибочный результат инструмента, читаемый моделью и маршрутизируемый хуками/UI. Это держит схему модели стабильной, не делая порядок загрузки плагинов, состояние учётных данных или тайминги HMR частью обращённого к модели контракта. Чтобы убрать веб-инструмент целиком, отключите его здесь в конфигурации.

Инструмент никогда не вызывает `available()` провайдера и никогда не перечисляет провайдеров — его единственный путь исполнения это `ctx.web.search()` / `ctx.web.fetch()`, а недоступность провайдера доходит до него как структурные коды `WebError`, которые бросает избрание во время исполнения. Избрание провайдера остаётся целиком внутри seam, у одного владельца.

## Model Experience

### Системный промпт

#### Что видит модель

Поиск и fetch добавляют приведённое ниже руководство web-search и web-fetch. Поиск избирает свой текст — с включённым fetch или только-поисковый — из конфигурации во время регистрации. Ограничение инструментов в рамках scope не убирает эти независимо зарегистрированные секции.

##### Руководство web_search при включённом fetch

```markdown
Use the web_search tool to discover current information on the web. The required queries array accepts 1–4 non-empty search queries; use a one-item array for a single search. It returns an optional answer plus a list of source URLs. Follow up with web_fetch when you need the full content of a specific result, and cite the relevant URLs as markdown links.
```

##### Руководство web_search без fetch

```markdown
Use the web_search tool to discover current information on the web. The required queries array accepts 1–4 non-empty search queries; use a one-item array for a single search. It returns an optional answer plus a list of source URLs. Use the returned source snippets when available, and cite the relevant URLs as markdown links.
```

##### Руководство web_fetch

```markdown
Use the web_fetch tool to retrieve the content of a specific HTTP(S) URL (for example a result from web_search). It returns the page content decoded to text. Cite the URL as a markdown link when you use its content.
```

#### Эффект на токены

Фиксированная цена руководства за каждый запрос для каждого включённого конфигурацией инструмента, даже когда ограничение прячет его схему. Переключение fetch или изменение `searchMaxQueries` меняет поисковое руководство; переключение fetch также регистрирует или убирает секцию fetch.

#### KV Cache effect

Стабилен по префиксу, пока включённые инструменты, scope и текст руководства неизменны. Включение конфигурацией — включая переключение ветви поискового руководства fetch, — изменение `searchMaxQueries` или жизненный цикл плагина могут инвалидировать переиспользование от первой изменившейся секции промпта; scoped-ограничения схемы его не убирают.

### Схемы инструментов

#### Что видит модель

Модель видит сгенерированные [схемы `web_search` и `web_fetch`](../../../docs/tool-catalog.md#deepseek-aidsh-tool-web). Границы числа результатов и таймаутов — настройки развёртывания, а не аргументы модели.

#### Эффект на токены

Фиксированная цена схемы за запрос при разрешённом `searchMaxQueries`; отключение конфигурацией убирает и схему, и руководство, а scoped-ограничение — только схему.

#### KV Cache effect

Стабильно по префиксу, пока определения, разрешённая граница запросов и видимость неизменны. Конфигурационное включение, изменение `searchMaxQueries`, жизненный цикл плагина или scoped-ограничения могут инвалидировать переиспользование от первого изменившегося токена схемы.

### Результат поиска

#### Что видит модель

За необязательным принадлежащим провайдеру ответом следуют `Sources:` и зависящие от данных строки формы ровно `- [<title-or-url>](<url>)`, опционально с суффиксом ` — <snippet> (<publishedAt>)`. Мульти-запросный вызов исполняет каждую точную строку запроса однократно, сохраняя её первую позицию; он подписывает каждый провайдерский ответ породившим запросом как markdown-заголовком, дедуплицирует источники по URL и берёт по одному источнику каждого ранга от всех запросов, прежде чем перейти к следующему рангу. Без ответа и без источников результат говорит `No results found.` Ограниченный список добавляет `(Showing the first <count> sources. Refine the query for more.)`; каждый результат оканчивается на `Cite the relevant URLs above as markdown links in your answer.`

#### Эффект на токены

Зависящие от данных результаты пересылаются до компакции; веер запросов ограничен `searchMaxQueries`, а источники — `searchMaxResults`.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Отказ поиска

#### Что видит модель

Если какой-либо запрос в мульти-запросном вызове отказывает, `web_search` прерывает остальные поиски, ждёт оседания каждого начатого поиска, отбрасывает успешные результаты и возвращает `Error: <message>` первого отказа.

#### Эффект на токены

Только удержанный ошибочный результат добавляет токены; отброшенные успешные результаты не входят в историю модели.

#### KV Cache effect

Append-only; ошибка следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Результат fetch

#### Что видит модель

Успешный fetch — это ровно `Fetched <finalUrl> (HTTP <statusCode>)`, пустая строка и принадлежащее провайдеру декодированное тело. Усечение добавляет пустую строку и `(Content truncated. Fetch a more specific URL or section for the full text.)`; отказы становятся `Error: <message>`. Запросы и URL остаются в истории вызовов.

#### Эффект на токены

Провайдерские границы ограничивают размер тела; удержанные аргументы и результаты вызова пересылаются до компакции, а таймаутная политика может заменить поздний результат короткой ошибкой.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

### Ошибки аргументов

#### Что видит модель

Валидация схемы отвергает отсутствующее или не-массивное поле `queries` и не-строковые элементы массива до исполнения. Ошибки значений становятся ровно `Error: queries must contain at least one query`, `Error: queries must contain at most 1 query` при настроенной границе в единицу, `Error: queries must contain at most <count> queries` для больших границ, `Error: each query must be a non-empty string` либо `Error: url must be a non-empty string`.

#### Эффект на токены

Только отказавший вызов добавляет эти удержанные токены.

#### KV Cache effect

Append-only; новое видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Батч-широкого счётчика нативных поисков нет** — `searchMaxQueries` ограничивает вызовы `ctx.web.search`, но провайдер может выполнить несколько нативных поисков внутри каждого вызова. Например, провайдер на модели, настроенный с `maxUses`, может позволить до `searchMaxQueries × maxUses` нативных поисков; `searchMaxResults` ограничивает лишь суммарные источники, возвращённые вызывающему. Развёртывания управляют стоимостью этими независимыми настройками потребителя и провайдера, потому что универсальный seam не знает внутренних для провайдера поисковых единиц.
- **Конверсия HTML→markdown деградирует на входах, которые GFM не может безопасно представить** — [turndown](https://github.com/mixmark-io/turndown) (с GFM-таблицами/зачёркиванием) конвертирует максимум `fetchMaxOutputChars` исходных символов через настоящий DOM. Консервативный лексический охранный уровень 512 пропускает глубоко или неоднозначно вложенные тела как сырой HTML, исключения конверсии делают то же, а `colspan` таблиц игнорируется, потому что у GFM нет представления раскинутых ячеек; эти границы позволяют не блокировать event loop и не раздувать вывод из недоверенного числового атрибута ([архивное решение о зависимости](../../../.agents/notes/archived/simplification/2026-07-26-turndown-for-tool-web-html-markdown.md)).
- **Обращённый к модели API минимален по замыслу, повышения отложены** — `max_results` остаётся конфигурационной границей (не аргументом модели), а `web_fetch` принимает только `url` (без режимов `format`/`prompt`/LLM-суммаризации); оба названы поздними шагами в [Agent Note о seam](../../../.agents/notes/implemented/architecture/2026-06-24-web-capability-seam.md).
- **Нет веб-специфичной политики разрешений** — оба инструмента исполняются, не запрашивая `ctx.approval`; развёртыванию, которому нужна конфирмация, придётся добавить политику `tools/pre-execute`, а пакет не определяет персистентных URL/доменных грант.
