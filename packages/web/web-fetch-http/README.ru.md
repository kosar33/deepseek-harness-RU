# @deepseek-ai/dsh-web-fetch-http

[English](README.md) | [中文](README.zh.md) | Русский

Анонимный публичный HTTP(S) `WebFetchProvider` для [seam'а веб-возможности](../web/README.ru.md) harness (`ctx.web`). Получает конкретный URL и возвращает код статуса плюс ограниченный по объёму декодированный контент.

Это пакет-**реализация**: он регистрирует провайдера в `ctx.web`, не владеет ключом и не регистрирует обращённого к модели потребителя. Это функциональный/namespace-плагин (`inject: ['web']`).

## Разделение ответственности

Провайдер владеет **безопасным получением ресурса**: проверкой URL, HTTP-транспортом, политикой перенаправлений, страховым тайм-аутом ресурса, распространением отмены, лимитами байтов, декодированием charset, классификацией content-type и отказом от двоичных данных. `@deepseek-ai/dsh-tool-web` владеет **представлением** (HTML→markdown, форматирование усечения). Ответ HTTP не-2xx — *результат* (код статуса + декодированное тело), а не ошибка; `WebError` зарезервирован для ситуаций, когда ресурс невозможно безопасно получить или представить.

`timeoutMs` провайдера — страховой тайм-аут ресурса для прямых вызывающих `ctx.web.fetch()` и неверно настроенных развёртываний, а не бюджет обращённого к модели вызова инструмента. [`dsh-tool-call-timeout-policy`](../../guard/timeout-policy/README.ru.md) владеет бюджетом вызова `web_fetch`, взводя `exec.signal`.

В рабочем развёртывании веб-инструмента страховой тайм-аут провайдера ставится выше бюджета инструмента, поэтому вызовы модели обычно возвращают `TOOL_TIMEOUT`. Если внешний дедлайн срабатывает раньше провайдера, тот сообщает `WEB_ABORTED`, и внешняя политика заменяет его на `TOOL_TIMEOUT`. Поэтому `WEB_FETCH_TIMEOUT` идентифицирует прямого сервисного вызывающего, у которого истёк бюджет провайдера.

## Гигиена транспорта

- Принимает только URL со схемами `http:` и `https:`; отвергает учётные данные в URL (`WEB_BLOCKED_URL`) и слишком длинные/некорректные URL (`WEB_INVALID_URL`).
- Соблюдает максимальную длину URL, лимит байтов ответа (`WEB_FETCH_TOO_LARGE`), лимит символов декодированного тела, тайм-аут (`WEB_FETCH_TIMEOUT`) и лимит переходов при перенаправлении.
- Распространяет сигнал отмены вызывающего (`WEB_ABORTED`) на сетевой запрос и потоковое чтение.
- Следует только **same-origin** перенаправлениям; cross-origin перенаправление завершается ошибкой `WEB_REDIRECT_BLOCKED` и требует нового вызова инструмента (как у WebFetch из Claude Code).
- Отправляет явный продуктовый `User-Agent`, никогда не маскируясь под браузер.
- Отвергает неподдерживаемые (например, двоичные) типы содержимого с кодом `WEB_UNSUPPORTED_CONTENT_TYPE`.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---|---|
| `maxUrlLength` | `2048` | Максимальная длина принимаемого URL запроса. |
| `maxResponseBytes` | `5_000_000` | Максимальный размер тела ответа в байтах. |
| `maxBodyChars` | `100_000` | Максимальная длина декодированного тела в символах. |
| `timeoutMs` | `30_000` | Тайм-аут загрузки в диапазоне таймеров Node — страховой механизм для прямых вызывающих `ctx.web.fetch()`, а не бюджет обращённого к модели вызова инструмента (это `dsh-tool-call-timeout-policy`). |
| `maxRedirects` | `5` | Максимум same-origin переходов при перенаправлении (`0` — не следовать ни одному). |
| `userAgent` | `deepseek-harness/…` | Заголовок `User-Agent`. |

Числовые лимиты проверяются при конструировании плагина: каждый лимит, кроме `maxRedirects`, обязан быть положительным конечным числом, а `maxRedirects` — неотрицательным целым. Некорректное значение приводит к броску, а не к молчаливому созданию провайдера с бессмысленными лимитами.

## Влияние на модель

Косвенно, через [`dsh-tool-web`](../tool-web/README.ru.md), который помещает ограниченный `maxBodyChars` декодированный текст этого провайдера или markdown-образный HTML под свою обёртку результата загрузки и сохраняет отказы провайдера, оставляя перенаправления, заголовки и транспортную механику скрытыми.

#### Влияние на KV-кэш

Прямой инвалидации нет; названный потребитель владеет любыми изменениями префикса запроса.

## Известные ограничения и отложенная работа

- **Защита от SSRF / приватных сетей отложена** — нет блокировки приватных, loopback, link-local, multicast или иных непубличных назначений, нет проверки после резолва DNS, нет повторной проверки на каждом переходе (см. [Agent Note о seam'е веб-возможности](../../../.agents/notes/implemented/architecture/2026-06-24-web-capability-seam.md)). Пока она не реализована, этот провайдер — SSRF-примитив и **НЕ ДОЛЖЕН** включаться в развёртывании, которое может достигать чувствительных внутренних сетевых целей.
- **Декодируется только текстовое содержимое** — семейства html/xhtml и `text/*` плюс JSON/XML; отсутствие `Content-Type` или любой двоичный тип приводят к броску `WEB_UNSUPPORTED_CONTENT_TYPE`, а декодирование PDF с извлекаемым текстом названо отложенной работой.
- **Charset берётся только из заголовка `Content-Type`** (по умолчанию UTF-8) — объявление `<meta charset>` в HTML игнорируется, а объявленная, но нераспознанная метка charset приводит к броску, а не к откату.
