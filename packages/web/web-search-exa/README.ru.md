# @deepseek-ai/dsh-web-search-exa

[English](README.md) | [中文](README.zh.md) | Русский

Основанный на [Exa](https://exa.ai) `WebSearchProvider` для [seam'а web-возможности](../web/README.ru.md) (`ctx.web`). Он вызывает конечную точку Exa `POST /search` с содержимым подсветок и отображает плоский массив `results[]` в нормализованный `WebSearchResult` этого seam'а.

Это пакет-**реализация**: он регистрирует провайдера в `ctx.web`, но не владеет ключом `ctx.web` и не регистрирует инструмента, видимого модели (это `@deepseek-ai/dsh-tool-web`). Как и `@deepseek-ai/dsh-llm-deepseek`, это плагин-функция/плагин-пространство имён (`inject: ['web']`), регистрирующий свой бэкенд, а не сервис с default export.

## Конфигурация

| Ключ | Умолчание | Смысл |
|---|---|---|
| `apiKey` | `$EXA_API_KEY` | API-ключ Exa. Пустое или отсутствующее значение делает провайдера недоступным. |
| `baseURL` | `https://api.exa.ai` | База конечной точки; `/search` добавляется в конец. Непарсируемое значение делает провайдера недоступным. |
| `searchType` | `auto` | Режим поиска, отправляемый как `type` Exa: `auto` (решает Exa), `keyword` или `neural`. |
| `numResults` | (не задано) | Число результатов по умолчанию, когда запрос не несёт `maxResults`. Если значение не задано, умолчание не отправляется. Должно быть положительным целым. |
| `highlightsPerResult` | `1` | Запрашиваемое число предложений подсветки на результат (`highlightsPerUrl` Exa). Должно быть положительным целым. |

```yaml
- id: web-search-exa
  name: '@deepseek-ai/dsh-web-search-exa'
  config:
    apiKey: !!js process.env.EXA_API_KEY
```

## Отображение

Exa возвращает плоский `results[]` и не генерирует ответа, поэтому `content` опускается. Каждый результат отображается в `WebSearchSource`: `url` ← `url`, `title` ← `title`, `snippet` ← первая непустая запись `highlights[]` (результат без подсветки не имеет переносимого сниппета и отбрасывается), `publishedAt` ← `publishedDate`. `maxResults` запроса побеждает сконфигурированное умолчание `numResults` и отправляется как `numResults` Exa ради оптимизации стоимости и задержки; окончательную границу принудительно обеспечивает seam. Сбои провайдера (ошибки HTTP, сетевые отказы, непарсируемые или неправильные по форме тела) проявляются как `WebError` `WEB_PROVIDER_ERROR`; прерванный запрос — как `WEB_ABORTED`. Перенаправления HTTP отклоняются до контакта с целевым объектом `Location` и проявляются как `WEB_PROVIDER_ERROR`.

## Влияние на модель

Косвенно, через [`dsh-tool-web`](../tool-web/README.ru.md), который удерживает ограниченные `maxResults` URL, заголовки, первые подсветки и даты публикации этого провайдера либо его точные сбои `Exa search aborted`, `Exa search request failed: <error>` и `Exa returned an unprocessable response body: <error>` под обёрткой ошибок потребителя, тогда как сгенерированные ответы и приватные поля провайдера остаются вне контекста.

#### Влияние на KV-кэш

Прямой инвалидации нет; изменения префикса запроса — забота названного потребителя.

## Известные ограничения и отложенная работа

- **Результат без непустой подсветки отбрасывается целиком** — переносимого сниппета для отображения нет, поэтому источников может вернуться меньше запрошенного числа.
- **Наружу предоставлены только `searchType`/`numResults`/`highlightsPerResult`** — прочие управляющие параметры Exa (livecrawl, категория, фильтры по домену и датам, полнотекстовое содержимое) ждут независимых от провайдера полей Service Definition ([Agent Note о seam'е](../../../.agents/notes/implemented/architecture/2026-06-24-web-capability-seam.md)).
- **Классификация прерывания опирается на форму ошибки** — в `WEB_ABORTED` отображается только `DOMException` с именем `AbortError`; прерывание с пользовательской причиной (например, `TimeoutReason` у `dsh-timeout`) выходит наружу как `WEB_PROVIDER_ERROR`.
