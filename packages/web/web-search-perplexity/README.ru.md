# @deepseek-ai/dsh-web-search-perplexity

[English](README.md) | [中文](README.zh.md) | Русский

`WebSearchProvider` на базе [Perplexity](https://perplexity.ai) для [seam'а веб-возможности](../web/README.ru.md) harness (`ctx.web`). Он вызывает OpenAI-совместимый эндпоинт Perplexity `POST /chat/completions` и отображает сгенерированный ответ плюс цитаты в нормализованный `WebSearchResult` seam'а.

Это пакет-**реализация**: он регистрирует провайдера в `ctx.web`, не владеет ключом и не регистрирует обращённого к модели потребителя. Как и `@deepseek-ai/dsh-llm-deepseek`, это функциональный/namespace-плагин (`inject: ['web']`). OpenAI-совместимый формат протокола — приватная деталь провайдера: он **не** делает этого провайдера зависимым от `ctx.llm`.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---|---|
| `apiKey` | `$PERPLEXITY_API_KEY` | Ключ API Perplexity. Пустой или отсутствующий делает провайдера недоступным. |
| `baseURL` | `https://api.perplexity.ai` | База эндпоинта; `/chat/completions` добавляется в конец. Неразбираемое значение делает провайдера недоступным. |
| `model` | `sonar` | Имя поисковой модели. |
| `maxTokens` | `1024` | Верхняя граница токенов сгенерированного ответа (`max_tokens`). Обязано быть положительным целым. |
| `searchRecency` | (не задано) | Окно актуальности, отправляемое как `search_recency_filter`: `day`, `week`, `month` или `year`. Не задано — фильтр не отправляется. |

```yaml
- id: web-search-perplexity
  name: '@deepseek-ai/dsh-web-search-perplexity'
  config:
    apiKey: !!js process.env.PERPLEXITY_API_KEY
```

## Отображение

`content` ← `choices[0].message.content` (сгенерированный ответ). `sources[]` предпочитает структурированный `search_results[]` (`url`, `title`, `snippet`, `publishedAt` ← `date`) и откатывается к массиву `citations[]` только с URL лишь когда `search_results` отсутствует — такие источники несут только `url`, поэтому `title`/`snippet`/`publishedAt` на seam'е необязательны. Отказы провайдера проявляются как `WebError` `WEB_PROVIDER_ERROR`; отменённый запрос проявляется как `WEB_ABORTED`. HTTP-перенаправления отвергаются до контакта с целью из `Location` и проявляются как `WEB_PROVIDER_ERROR`. У Perplexity нет управления числом результатов, поэтому `maxResults` соблюдается самим seam'ом (усечением `sources[]` с установкой `truncated`).

## Влияние на модель

### Вспомогательный запрос к Perplexity

#### Что видит модель

Отдельная модель Perplexity получает `<query>` дословно как единственное пользовательское сообщение через эндпоинт chat-completions. Этот запрос не является частью контекста модели разговора.

#### Влияние на токены

За каждый поиск расходуются отдельные токены провайдера; `maxTokens` ограничивает сгенерированный ответ.

#### Влияние на KV-кэш

Независимо от кэша запроса разговора. Идентичный запрос по тому же маршруту модели может переиспользовать кэш провайдера; изменившийся запрос или маршрут устанавливает другой префикс.

### Результат инструмента в разговоре, косвенно

#### Что видит модель

Через [`dsh-tool-web`](../tool-web/README.ru.md) модель разговора видит сгенерированный ответ плюс структурные метаданные результата или цитаты из одних URL. Точные отказы этого провайдера — `Perplexity search aborted`, `Perplexity search request failed: <error>` и `Perplexity returned an unprocessable response body: <error>`; HTTP-отказы сохраняют сообщение провайдера. Обёрткой ошибки владеет потребитель.

#### Влияние на токены

Ноль прямых токенов разговора от регистрации. Токены ответа и источников зависят от данных, число источников ограничено сервисом, а удерживаемый результат или ошибка отправляются повторно до компакции.

#### Влияние на KV-кэш

append-only; заново видимое содержимое следует за переиспользуемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Источники из отката цитирований содержат только URL** — когда Perplexity опускает структурированный `search_results[]`, источники не несут `title`/`snippet`/`publishedAt`, поэтому инструмент рисует голые метки имён хостов.
- **Избыточно возвращённые источники всё равно стоят токенов и задержки** — без управления числом результатов на уровне протокола `maxResults` соблюдается лишь постфактум усечением на seam'е.
- **Открыты только `model`/`maxTokens`/`searchRecency`** — прочие поисковые контролы Perplexity (фильтры доменов, размер контекста `web_search_options`, изображения) ждут независимых от провайдера полей Service Definition ([Agent Note о seam'е](../../../.agents/notes/implemented/architecture/2026-06-24-web-capability-seam.md)).
- **Классификация отмены основана на форме ошибки** — в `WEB_ABORTED` отображается только `DOMException` с именем `AbortError`; отмена с произвольной причиной (например, `TimeoutReason` из `dsh-timeout`) проявляется как `WEB_PROVIDER_ERROR`.
