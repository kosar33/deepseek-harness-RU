# @deepseek-ai/dsh-web

[English](README.md) | [中文](README.zh.md) | Русский

**`WebRuntime`** (`ctx.web`) определяет, ЧТО за веб-доступ есть у harness — поиск в вебе и загрузку URL — поверх нескольких провайдеров, не привязывая модельный контракт к форме API одного вендора.

Этот пакет владеет ролью Service Definition веб-возможности. В отличие от shell/fs он охватывает две операции (search и fetch) на одном seam'е, каждая потенциально с несколькими провайдерами:

| Пакет | Роль |
|---|---|
| `@deepseek-ai/dsh-web` (этот пакет) | Service Definition: сервис, реестры провайдеров, политика выбора, словарь запросов/результатов, таксономия `WebError` |
| `@deepseek-ai/dsh-web-search-exa` | Поисковый провайдер: Exa |
| `@deepseek-ai/dsh-web-search-perplexity` | Поисковый провайдер: Perplexity |
| `@deepseek-ai/dsh-web-fetch-http` | Провайдер загрузки: анонимный публичный HTTP(S) |
| `@deepseek-ai/dsh-tool-web` | Consumer: обращённые к модели схемы инструментов `web_search` / `web_fetch` поверх `ctx.web` |

Search и fetch не разделяют ни схемы запроса, ни бизнес-логики, но сознательно являются одним seam'ом: `ctx.web` — единый средний слой веб-доступа с одним владельцем политики выбора провайдера, одним словарём отмены/ошибок и одной продуктовой поверхностью конфигурации «как этот harness достигает веба». Пары методов `Search`/`Fetch` сознательно параллельны.

## Сервисный API (`ctx.web`)

| Член | Семантика |
|---|---|
| `registerSearchProvider(provider)` / `registerFetchProvider(provider)` | Регистрирует бэкенд. Бросает `WebError` `WEB_DUPLICATE_PROVIDER` при дублирующемся id внутри этого вида возможности. Возвращает disposer. Освобождается вместе с вызывающим fiber. |
| `search(request, signal?)` | Резолвит поискового провайдера и выполняет один поиск. Обеспечивает соблюдение `request.maxResults` на результате (усекает `sources[]`, ставит `truncated`). Бросает `WebError`, когда возможность не может выполниться. |
| `fetch(request, signal?)` | Резолвит провайдера загрузки и получает один URL. Ответ не-2xx — результат, а не бросок. Бросает `WebError`, когда ресурс невозможно безопасно получить или представить. |

Провайдеры регистрируют **возможности**, а не инструменты. `dsh-tool-web` — единственный владелец обращённых к модели имён, описаний, руководства для промпта, JSON-схем и представления.

## Выбор

Выбор никогда не зависит от порядка регистрации, конфигурации или HMR. Возможность имеет явный id провайдера (конфиг `searchProvider`/`fetchProvider` либо переменные окружения `$DSH_WEB_SEARCH_PROVIDER`/`$DSH_WEB_FETCH_PROVIDER`, заполняющие те же поля) либо выбирается автоматически, когда зарегистрирован ровно один пригодный провайдер. `search()`/`fetch()` резолвят провайдера во время исполнения:

| Ситуация | Исполнение |
|---|---|
| настроенный id зарегистрирован и `available()` | выполняется этот провайдер |
| настроенный id не зарегистрирован | `WEB_PROVIDER_CONFIGURED_MISSING` |
| настроенный id зарегистрирован, но недоступен | `WEB_PROVIDER_CONFIGURED_UNAVAILABLE` |
| нет id, зарегистрирован ровно один пригодный провайдер | выполняется он |
| нет id, ни одного пригодного провайдера | `WEB_PROVIDER_UNAVAILABLE` |
| нет id, несколько пригодных провайдеров | `WEB_PROVIDER_AMBIGUOUS` |

Ветви отказов бросают `WebError`, чей структурированный код (плюс деталь сообщения — отсутствующий id, множество неоднозначных кандидатов) — то, на чём маршрутизируют прямые вызывающие. Собственный `available()` провайдера — дешёвая локальная проверка (наличие учётных данных, разбираемая конфигурация), которая учитывается при этом выборе во время исполнения, и **НЕ ДОЛЖНА выполнять сетевые вызовы**; `dsh-tool-web` никогда её не вызывает — инструмент исполняется через `ctx.web.search()`/`fetch()` и маршрутизирует по брошенным кодам, поэтому у выбора провайдера один владелец.

## Словарь

`WebSearchRequest` (`query`, `maxResults?`) → `WebSearchResult` (`content?`, `sources[]`, `truncated`); у каждого `WebSearchSource` обязателен `url` и опциональны `title`/`snippet`/`publishedAt` (цитаты Perplexity могут быть только URL). `WebFetchRequest` (`url`) → `WebFetchResult` (итоговый `url`, `statusCode`, `body`, `truncated`); отмена — прямой опциональный аргумент `AbortSignal` у `search()`/`fetch()`. `WebFetchBody` — ЗАКРЫТЫЙ discriminated union (`html` | `text`), определённый здесь: потребители пишут исчерпывающие `switch`, так что новый вид ломает их компиляцию, пока он не обработан. Полные контракты и таксономию кодов `WebError` см. в `src/types.ts`.

## Влияние на модель

Косвенно, через `dsh-tool-web`, который удерживает ограниченные нормализованные данные провайдера или точные отказы «настроенный провайдер», «недоступный провайдер», «нет провайдера», «несколько провайдеров» и `Error: <message>`, тогда как этот реестр сам не добавляет ни промпта, ни схемы.

#### Влияние на KV-кэш

Прямой инвалидации нет; названный потребитель владеет любыми изменениями префикса запроса.

## Известные ограничения и отложенная работа

- **Нет поверхности наблюдения** — ни события смены провайдера, ни запроса статуса возможности; доступность наблюдается только исполнением `search()`/`fetch()` и маршрутизацией брошенных кодов `WebError`, а отказ отсутствия провайдера — обобщённый `WEB_PROVIDER_UNAVAILABLE` без перечисления причин по провайдерам ([Agent Note](../../../.agents/notes/archived/simplification/2026-07-04-drop-unconsumed-web-observation-surface.md)).
- **`WebSearchRequest` несёт только `query` + `maxResults`** — независимые от провайдера управляющие параметры (свежесть, фильтры доменов, региональные подсказки, глубина поиска) отложены, пока и Exa, и Perplexity не смогут честно их поддерживать ([Agent Note о seam'е](../../../.agents/notes/implemented/architecture/2026-06-24-web-capability-seam.md)).
- **У `WebFetchBody` нет ветви `pdf`** — поддержка PDF с извлекаемым текстом названа отложенной работой; закрытый union делает её добавление изменением, контроль которого обеспечивает компиляция, сразу в трёх веб-пакетах.
- **Извлечение страниц силами провайдера вне скоупа `fetch()`** — возможность `web_extract` в стиле Firecrawl/Tavily отложена вместо расширения операции fetch.
