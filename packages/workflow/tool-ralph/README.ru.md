# @deepseek-ai/dsh-tool-ralph

[English](README.md) | [中文](README.zh.md) | Русский

Видимый модели инструмент `ralph` выполняет фиксированный воркфлоу на переднем плане, передающий одну неизменяемую цель последовательности свежих дочерних агентов. Он демонстрирует специализированную политику оркестрации как обычный плагин поверх [`ctx.workflowEngine`](../workflow/README.md) и [`ctx.subagents`](../../subagent/subagent/README.md): ни режим Ralph, ни цикл свежих агентов не добавляются в `agent-loop`, а [домен целей](../../goal/goal/README.md) текущей сессии остаётся независимым. Политику и отложенную работу описывает [Agent Note о Ralph](../../../.agents/notes/implemented/feature/2026-07-19-fresh-agent-ralph-workflow-tool.md).

## Контракт

`ralph({ objective, maxRounds? })` дожидается завершения всего запуска. Значение `maxRounds` из конфигурации развёртывания служит одновременно значением по умолчанию и потолком для переопределения в вызове. Каждый Ralph Round порождает одного дочернего агента через `subagentProvider`; такой провайдер должен существовать, поддерживать структурированный вывод и сообщать `inheritsParentContext: false`. Сконфигурированный провайдер передаётся как `WorkflowStartRequest.subagentProvider`, поэтому фиксированный скрипт не может ни просмотреть, ни изменить маршрутизацию, а обычный инструмент `workflow`, сценарий которого пишет модель, не получает селектора провайдера. Разрешённый предел Round также передаётся как `WorkflowStartRequest.maxTotalAgents`, согласуя фиксированный цикл со страховочным пределом движка на общее число дочерних агентов; движок отклоняет предел Ralph выше своего потолка развёртывания до публикации запуска.

Каждый дочерний агент получает только неизменяемую цель, свой текущий Ralph Round и потолок, инструкцию об общем рабочем пространстве как источнике долговременной памяти и предыдущую структурированную передачу состояния. Рабочее пространство — долговременная память; разговор родителя и сессии предыдущих детей в контекст не попадают. Отчёты содержат `status: continue | complete | blocked`, непустую сводку, свидетельства, следующие шаги и текст блокировки. Семантика каждого статуса и потолок сериализации `maxHandoffChars` проверяются внутри фиксированного воркфлоу и повторно на границе потребителя. Некорректные, отсутствующие или чрезмерно большие отчёты приводят воркфлоу к ошибке вместо усечения или трактовки как исчерпания лимита Round.

Успешный терминальный результат инструмента равен `complete`, `blocked` или `budget-limited` и несёт последний ограниченный отчёт и число запущенных Round. Канонический конверт — это `{ runId, agentsStarted, result }`; подписи завершения и блокировки в его нативном рендерере прямо говорят, что исход сообщил воркер, а не независимая сертификация. `maxResultChars` ограничивает только этот отрендеренный текст вместе с маркером усечения, не изменяя проверенный отчёт ни в каноническом значении, ни в передаче состояния между Round'ами.

Обычный сбой дочернего агента даёт ошибку, называющую несостоявшийся Round и сохраняющую последнюю успешную передачу состояния, если она есть. Ralph не повторяет этот Round. Фатальные сбои старта провайдера, транспорта, воркера или воркфлоу остаются ошибками воркфлоу и могут проявиться раньше, чем фиксированный скрипт успеет вернуть передачу состояния. Отмена — тоже ошибка; частичный результат никогда не считается успехом.

## Жизненный цикл и отмена

Агент вызывающего — родитель каждого свежего дочернего агента: cwd и происхождение сохраняются без копирования разговора. `exec.signal` попадает в движок воркфлоу и дополнительно мостится к `run.cancel()` для независимости реализации. Инструмент ожидает `run.result` и вызывает `run.dispose()` в `finally`, поэтому отменённый родительский шаг дожидается ограниченного по времени завершения движка и quiescence (полного завершения всех жизненных циклов) дочерних агентов, прежде чем вернуться.

## Намерение рендера

Ожидающий вызов — карточка `generic` с заголовком `ralph`; неизменяемая цель служит её `rawInput`. Результат сохраняет карточку `generic`. Обе функции представления зависят только от аргументов инструмента и завершённого конверта инструмента.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---|---|
| `subagentProvider` | `spawn` | Провайдер структурированного вывода для свежих агентов, используемый в каждом Round. |
| `maxRounds` | `256` | Значение по умолчанию и потолок развёртывания для одного запуска Ralph. |
| `maxHandoffChars` | `16384` | Максимум сериализованных символов в одном отчёте Round. |
| `maxResultChars` | `16384` | Максимум символов в полном успешном результате родителя. |

Все значения конфигурации нормализуются и проверяются при применении плагина, включая прямое применение вне нормализации схемы загрузчиком. Возможности провайдера определяются непосредственно перед каждым вызовом, поскольку регистрация провайдеров может меняться в течение жизненного цикла плагинов и при HMR (горячей замене модулей).

## Model Experience

### Системный промпт

#### What the model sees

Каждый родительский запрос в области регистрации этого плагина получает приведённые ниже фиксированные указания по маршрутизации.

##### Рекомендации Ralph

```markdown
Use the ralph tool ONLY when the direct human explicitly asks for a Ralph loop or fresh-agent iterative execution. Each Ralph round starts a fresh child with no conversation seed and uses the shared workspace as durable memory. Completion and blockers are worker reports, not independent evaluation. Use same-session goal tools for ordinary long-running objectives, and plain subagents or workflowEngine for bounded delegation and fan-out.
```

#### Token effect

Небольшая фиксированная стоимость указаний в каждом запросе, пока плагин активен.

#### KV Cache effect

Стабильно по префиксу, пока область плагина и текст указаний не меняются. Активация или освобождение ресурсов может инвалидировать переиспользование из этой секции промпта.

### Схема инструмента

#### What the model sees

Сгенерированная [схема `ralph`](../../../docs/tool-catalog.ru.md#deepseek-aidsh-tool-ralph) раскрывает одну обязательную строку `objective` и одно необязательное число `maxRounds`. Выбор провайдера, размер передачи состояния, схема отчёта, скрипт воркфлоу и поведение оркестрации принадлежат развёртыванию и в схеме вызова отсутствуют.

#### Token effect

Небольшая фиксированная стоимость схемы в каждом запросе, где инструмент видим.

#### KV Cache effect

Стабильно по префиксу, пока определение и видимость не меняются.

### Запросы дочерних агентов и результат родителя

#### What the model sees

Каждый дочерний агент видит автономный фиксированный промпт Round плюс контракт захвата структурированного вывода. Родитель видит только исходный вызов и один терминальный результат, содержащий сообщённый воркером статус, число Round и финальный отчёт с форматированием; промежуточные сообщения и отчёты дочерних агентов в разговор родителя не попадают. Обычный сбой дочернего агента вместо этого даёт ошибку с номером Round и — начиная со второго Round — последнюю успешную передачу состояния.

#### Token effect

Каждый Round оплачивает свежий дочерний контекст. `maxHandoffChars` ограничивает состояние между Round'ами, а `maxResultChars` независимо ограничивает полный успешный текст родителя; работа дочерних агентов остаётся вне родительского контекста.

#### KV Cache effect

У каждого свежего дочернего агента собственный кэш запросов. Результат родителя добавляется после повторно используемого префикса запроса.

## Известные ограничения и отложенная работа

- **Завершение — самодекларация воркера** — независимого оценщика или верификатора, решающего, действительно ли цель достигнута, нет; политика оценщика и продолжение по решению оценщика отложены.
- **Только передний план** — нет ни id задания, ни фонового сбора, ни чекпоинта возобновления процесса, ни планировщика, ни политики старта по настенному времени.
- **Рабочее пространство — единственная память между Round'ами** — один ограниченный отчёт является явной передачей состояния, а незафиксированные в рабочем пространстве диалоговые рассуждения исчезают вместе с каждым дочерним агентом.
- **Один Round — один свежий дочерний агент** — нет ни веера задач внутри Round, ни смены модели или провайдера, ни fork-контекста, ни выбора провайдера модельным вызовом.
- **Обычный сбой дочернего агента терминален для запуска** — фиксированный скрипт сообщает несостоявшийся Round и последнюю успешную передачу состояния, но не повторяет попытку; фатальные сбои инфраструктуры воркфлоу могут завершить запуск до возврата этого состояния.
- **Совокупные усилия ограничивает только число Round** — бюджеты токенов, цены и затраченного времени отложены.
