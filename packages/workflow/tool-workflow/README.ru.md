# @deepseek-ai/dsh-tool-workflow

[English](README.md) | [中文](README.zh.md) | Русский

Видимый модели **инструмент `workflow`**: запускает скрипт оркестрации на JavaScript, который распараллеливает работу по субагентам, и возвращает финальное значение скрипта. Этот пакет владеет видимой модели схемой и жизненным циклом запуска поверх [`ctx.workflowEngine`](../workflow/README.md); разбор и исполнение скрипта, потолки и отмена остаются за seam, а потребитель сохраняет владение схемой для родителя и конвертом результата.

## Что видит модель

Три параметра: `meta` (обязательные данные идентичности: `name`, `description` и необязательные пометки о прогрессе), `script` (обязательное тело на чистом JavaScript — без инструкции `export const meta`; полный контракт написания несёт описание инструмента) и `args` (необязательный JSON-объект, доступный скрипту как глобальная переменная `args`; голый список заворачивайте в поле, чтобы протокольная схема оставалась корректной). Плагин вдобавок добавляет секцию системного промпта `tool:<toolName>` с политикой применения — использовать инструмент только по явной просьбе пользователя о воркфлоу / крупной оркестрации; для одного-двух делегирований предпочесть обычные вызовы субагентов — следуя правилу, по которому руководство по инструменту поставляется вместе с плагином инструмента, а не в персоне развёртывания.

## Жизненный цикл

Сбор синхронен (как у [`dsh-tool-subagent`](../../subagent/tool-subagent/README.ru.md)): `execute` стартует запуск и ожидает `run.result` внутри `try/finally`, который всегда освобождает ресурсы запуска, поэтому скрипт и его дети достигают quiescence на любом пути. `exec.signal` связан с `run.cancel()` (включая случай, когда отмена уже произошла до старта). Причина остановки, отличная от `completed`, превращается в результат `isError`, сообщающий причину, — частичный вывод никогда не выдаётся за успех; выброшенный синхронно из `start()` сбой разбора или `meta` тоже становится `isError`, который модель может исправить. Успех возвращает каноническое `{ runId, agentsStarted, result }`; рендерер Native сохраняет имя из `meta`, число агентов и JSON-значение, усекая только эту проекцию при превышении `maxResultChars`.

При исполнении через корневой транспорт (нет `exec.parent`) инструмент вдобавок проецирует запуск в Session вызывающего Agent'а: начало запуска после возврата `start()`, подходящие начала и завершения участников, отфильтрованные по `run.id`, затем конец запуска — только когда доступен `run.result`, а `dispose()` достиг quiescence. Вложенные вызовы транспорта исполняются нормально, но не создают записей воркфлоу. Первый неудавшийся append в Session отключает дальнейшую запись для этого запуска, испускает одно предупреждение и оставляет либо отсутствие записей, либо корректный непрерывный префикс, не меняя результат инструмента и очистку.

Безопасный для браузера субпуть `@deepseek-ai/dsh-tool-workflow/types` владеет этими четырьмя payload'ами событий, существующими только в журнале, и их объявлением в `SessionEventMap`. Инвариант пакета отвергает двойные старты, непарных участников, терминальные события при открытых участниках и обновления после конца запуска — как на холодной загрузке, так и при живом append — принимая отсутствие терминальных суффиксов.

## Намерение рендера

Решено заранее (см. [Agent Note о намерении рендера](../../../.agents/notes/implemented/architecture/2026-07-02-tool-render-intent-union.md)): карточка `generic` с заголовком `workflow: <meta.name>`, читаемым прямо из `args.meta.name` (представление — чистая функция аргументов и не требует от движка разбора); текст скрипта передаётся как `rawInput`. Результат сохраняет карточку `generic`.

## Конфигурация

| Ключ | По умолчанию | Значение |
|---|---|---|
| `toolName` | `workflow` | Имя регистрируемого инструмента, видимое модели. |
| `maxResultChars` | `50000` | Потолок отрендеренного результата; более длинный JSON усекается с пометкой. |

## Опыт модели

### Системный промпт

#### Что видит модель

Каждый родительский запрос в области регистрации этого плагина получает приведённое ниже руководство по воркфлоу. Ограничение инструментов в области может спрятать схему, не убирая это независимо зарегистрированное руководство.

##### Руководство по воркфлоу

```markdown
Use the <toolName> tool ONLY when the user explicitly asks for a workflow or for large multi-agent orchestration: you write a JavaScript script (the tool description documents the exact format) that fans work out across many subagents with phases and structured results. For one or two delegations, prefer plain subagent calls.
```

#### Влияние на токены

Небольшая фиксированная стоимость руководства в каждом запросе, пока плагин активен.

#### Влияние на KV-кэш

Стабильно по префиксу, пока область плагина и текст руководства не меняются. Активация или освобождение ресурсов могут инвалидировать переиспользование из этой секции промпта.

### Схема инструмента

#### Что видит модель

Когда видима, сгенерированная по умолчанию [схема `workflow`](../../../docs/tool-catalog.md#deepseek-aidsh-tool-workflow) несёт полный контракт хуков и метаданных JavaScript; `toolName` может переименовать определение, а модель отправляет скрипт, метаданные и необязательные `args`.

#### Влияние на токены

Существенная фиксированная стоимость схемы в каждом запросе, где инструмент видим.

#### Влияние на KV-кэш

Стабильно по префиксу, пока `toolName`, определение и видимость не меняются. Переименование, жизненный цикл плагина или ограничения в области могут инвалидировать переиспользование из этой схемы.

### История вызовов инструмента и результат

#### Что видит модель

Полностью написанные моделью скрипт, метаданные и `args` остаются в вызове инструмента ассистента. Успех — это ровно `workflow "<name>" completed (<count> agent<optional-s>).`, перевод строки, `Return value:`, перевод строки и красиво напечатанный зависящий от данных JSON; потолок добавляет `… [truncated: <omitted> more characters]` новой строкой. Неудачи — это ровно `Error: workflow run was cancelled` с необязательным суффиксом ` (<error>)`, `Error: workflow run failed: <error-or-unknown error>` либо защитное `Error: workflow run ended abnormally (<reason>)`; вызов без агента-владельца даёт `Error: workflow tool requires a calling agent (exec.agent was undefined)`. Промежуточные сообщения детей опускаются.

#### Влияние на токены

Токены вызова могут быть велики и остаются до компакции. Отрисовка результата ограничена `maxResultChars`; токены дочерних моделей отделены от удерживаемого контекста родителя.

#### Влияние на KV-кэш

Append-only; новый видимый контент следует за повторно используемым префиксом запроса и не инвалидирует существующие записи KV-кэша.

## Известные ограничения и отложенная работа

- **Ход родителя блокируется до полного завершения воркфлоу** — фонового API старта/опроса нет, а отмена отбрасывает частичный вывод как ошибку.
- **`args` должен быть объектом, а текст результата Native ограничен** — вызывающие заворачивают верхнеуровневые массивы/скаляры в поле; канонический результат воркфлоу остаётся полным, а JSON сверх `maxResultChars` усекается в проекции, видимой модели, а не прячется за дескриптором извлечения.
- **Политика воркфлоу фиксирована на регистрацию инструмента** — выбор провайдера, потолки и имя инструмента являются конфигурацией развёртывания, а не аргументами вызова модели.
- **Долговечные записи верхнеуровневые и только для наблюдения** — вложенные диспетчеризации Code Mode не записываются, а сбой записи намеренно деградирует до неполного префикса, не меняя исполнения.
