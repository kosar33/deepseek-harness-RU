# Wheel-пакет рантайма DeepSeek Harness

[English](README.md) | [中文](README.zh.md) | Русский

Пакет-носитель рантайма для Python SDK (дистрибутив `deepseek-harness-runtime-bin`, модуль `deepseek_harness_runtime`): он находит bundled-бинарники рантайма, которые запускает клиент `deepseek-harness-sdk`, и поставляет конфигурацию по умолчанию, стоящую за запусками без настройки.

## Носители рантайма

Под `src/deepseek_harness_runtime/runtime/` сосуществуют два носителя: обоих внедряет сборка репозитарным скриптом `scripts/build-exe-for-python-sdk.ts`, и обоих игнорирует git:

- **exe (production)** — однофайловый исполняемый файл Node `dsh-jsonrpc-agent-pkg-<platform>-<arch>` (platform: `linux`/`macos`; arch: `x64`/`arm64`) со сопутствующим файлом ripgrep `-rg` под целевую платформу. Сборки macOS также поставляют нативного соседа `-spawn-helper`, которого там использует `node-pty`. Установка Node на целевой машине не нужна. Это единственный носитель, попадающий в wheel-дистрибутивы; sdist этот пакет не публикует.
- **node (dev-only)** — полное deploy-замыкание под `runtime/node/` (`package.json` + `node_modules/`), запускаемое командой `node runtime/node/node_modules/@deepseek-ai/dsh-sdk-jsonrpc-demo/lib/packaged-bin.js` на системном Node >= 22.19. Это сборка текущего checkout из исходников, предназначенная только для разработки и проверки внутри репозитория; автоматически она никогда не выбирается и в дистрибутивы не входит.

Оба носителя содержат один и тот же контент, определённый однажды: [package.json](https://github.com/deepseek-ai/deepseek-harness/blob/master/python/sdk-runtime/package.json) в корне этого пакета — корень развёртывания пайплайна single-exe, чистый манифест зависимостей (собственного кода нет), чьё замыкание зависимостей ЕСТЬ одновременно набор плагинов, компилируемых в exe, и дерево, материализуемое в `runtime/node/`. Добавить плагин в дистрибутив значит дописать там одну строку зависимости и пересобрать.

Bundled-набор плагинов включает `@deepseek-ai/dsh-mcp-client`, поэтому внешний конфиг Cordis может подключаться к MCP-серверам stdio или Streamable HTTP и открывать их инструменты модели. Wheel не bundлит программы MCP-серверов и учётные данные: конфиг stdio задаёт свой исполняемый файл и аргументы, а конфиг Streamable HTTP — URL и заголовки. Мост поддерживает инструменты MCP; MCP Resources и Prompts остаются без поддержки.

Отсутствующий exe вызывает `FileNotFoundError`, перечисляющее оба пути получения: собрать через `scripts/build-exe-for-python-sdk.ts` в checkout deepseek-harness либо установить подходящий платформенный рантайм-wheel, произведённый CI-воркфлоу `build-exe-for-python-sdk`. Отсутствующий dev-only node-носитель называет свой единственный путь — скрипт сборки. Воркфлоу хранит wheel-пакеты, а не автономные архивы исполняемых файлов. Стратегия получения нарочно отделена от интерфейса поиска, чтобы позже её могла заменить загрузка по требованию без изменений в вызывающих.

Каждый wheel содержит ровно один исполняемый файл рантайма и его парный сопутствующий файл ripgrep `-rg`. Wheel macOS содержит вдобавок парного нативного spawn-helper; любой недостающий сопутствующий файл делает установку неполной и оборачивается жёсткой ошибкой запуска, даже для выбранной композиции Cordis, которая не пользуется инструментами поиска по файловой системе или PTY. Linux-wheel не содержат spawn-helper, потому что `node-pty` использует staged-аддон `pty.node` напрямую. Фиксированные теги — `py3-none-manylinux_2_28_x86_64`, `py3-none-manylinux_2_28_aarch64` и `py3-none-macosx_14_0_arm64`; тег macOS консервативно совпадает с deployment target macOS 13.5 bundled-исполняемого файла Node 24. `platforms.json` этого пакета владеет фиксированными парами «тег + имя исполняемого файла», которыми пользуются и сборщик релиза репозитория, и изолированный build hook. Build hook отвергает `py3-none-any`, отсутствующие или множественные исполняемые файлы рантайма, недостающие или лишние сопутствующие файлы, неисполняемые файлы и неподдерживаемые платформенные теги. Корневой `package.json` репозитория задаёт общую версию этого пакета и SDK, и релизный тег `python-v<repository-version>` обязан ей соответствовать.

## API разрешения

- `resolve_bundled_launch_args(mode=None) -> tuple[str, ...]` — кортеж argv, запускающий bundled-рантайм: `(exe_path,)` в режиме exe, `(node_path, bin_js_path)` в режиме node. Выбор режима: явный аргумент > переменная окружения `DSH_RUNTIME_MODE` (`exe` | `node`) > автоматически. Автоматическое разрешение находит ТОЛЬКО production-exe — dev-only node-носитель нужно включать явно, чтобы production-развёртывание никогда молча не ехало на сборке из исходников.
- `bundled_runtime_path() -> Path` — путь к exe платформы (только носитель exe); функция проверяет обязательного соседа `-rg` на каждой платформе и соседа `-spawn-helper` на macOS. У носителя node однопутевого эквивалента нет — запуск идёт через кортеж argv выше.
- `bundled_default_config_path() -> Path` — входящая в репозиторий конфигурация по умолчанию (см. ниже).
- `bundled_package_dir() -> Path` — корень данных установленного пакета.

## Дизайн zero-config

Бинарник рантайма всегда требует явную конфигурацию (`$DSH_CORDIS_CONFIG` либо путь к конфигу позиционным аргументом argv) и без неё громко завершается — эта жёсткая семантика является частью дизайна рантайма, и данный пакет её не смягчает. Бинарник (`dsh-jsonrpc-agent`) загружает только перечисленные в конфиге плагины; обслуживающий интерфейс (stdio-сервер JSON-RPC) сам входит в число его записей (`@deepseek-ai/dsh-sdk-jsonrpc-server`), и без него у запущенного агента нет канала наружу. Этот пакет хранит в репозитории `runtime/cordis.yml` с записью JSON-RPC-сервера, ядром агента, предзагруженным адаптером DeepSeek, персистентностью JSONL, явно собранной семантической политикой чекпоинтов, локальным bash и локальным файловым провайдером для ограниченной загрузки инструкций рабочей области. Бэкенд персистентности владеет долговременным хранилищем, а отдельная политика выбирает чекпоинты запроса, диспетчеризации инструмента и завершённого шага. Адаптер читает `DEEPSEEK_API_KEY` и `DEEPSEEK_BASE_URL`, а персистентность, bash и файловый провайдер используют `DSH_SESSION_ROOT` и `DSH_CWD` с fallback на ручной запуск. Когда вызывающий не пользуется явным каналом конфигурации, клиент `deepseek_harness` внедряет путь к этому файлу через `DSH_CORDIS_CONFIG` (условия внедрения: [README sdk](https://github.com/deepseek-ai/deepseek-harness/blob/master/python/sdk/README.ru.md)). Zero-config, таким образом, — это явная видимая передача параметра в обёртке, а не скрытый fallback в рантайме.
